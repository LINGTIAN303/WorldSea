# R3-b2 · 双栏分离式批计划（第六形态）

> 用户 2026-10-20 追加：在原本平铺形态上，**保留左侧芽侧栏**，在视图另一侧建立独立的**语义域侧栏**；右侧栏复用左侧栏的样式与交互。
> 与 R3-b 的区别：R3-b 是「域列 + 芽列同侧」的导航组；R3-b2 是**两个独立侧栏分居两侧**。R3-c 后移到本批之后。
>
> **执行状态（2026-10-20）**：第六形态已实现；浏览器预览通过（双侧栏、域轮盘过滤、左右互换、双侧收起）；待用户真机走查。

## 一、形态定义

- 左侧（或 `sidebarPosition` 指定侧）= 原本平铺芽侧栏（物理轮盘，`SidebarV2` 零改动）。
- 另一侧 = 语义域侧栏，复用同一套侧栏壳（宽度 / 底色 / 圆角 / 头部收起 / 底部 AppMenu）与**同一套物理轮盘交互**。
- 域侧栏选择域 → 左侧平铺芽侧栏只显示该域芽；选「全部」恢复全部。
- `sidebarPosition=left` → 芽左、域右；`right` → 芽右、域左（永远分居两侧，避免第三面板冲突）。
- 两侧共用 `uiStore.sidebarCollapsed`：收起时两侧都收成 36px 窄条，展开恢复。

## 二、架构

```text
Shell.vue
 └─ SidebarHost.vue
     ├─ SidebarV2.vue          // 平铺芽侧栏（split 时仍原样使用）
     └─ SplitNav.vue           // split 专用编排
         ├─ SidebarV2.vue      // 芽侧栏（通过 viewOrder 过滤）
         └─ DomainSidebar.vue  // 域侧栏：同壳 + 域物理轮盘
```

- `viewOrder.ts`：新增 `allVisibleViewsInSidebarOrder()` 与过滤版 `visibleViewsInSidebarOrder()`；仅当 `sproutNavMode==='split'` 且域不是 all 时过滤，`SidebarV2` 无需改动。
- `SplitNav.vue`：计算全量可见芽、域映射、域过滤；监听当前视图跨域时更新过滤；域为空时回退「全部」。
- `DomainSidebar.vue`：复用 `useSidebarPhysics` / `useSidebarInteraction`，渲染域轮盘；壳样式与 `SidebarV2` 对齐（220px / 36px、头部 40、底部 AppMenu）。
- `ViewContainer.vue`：split 模式同时左右让位（220px / 收起 36px）；其余模式不变。
- `SidebarHost.vue`：`flat`/`split` 渲染 `SidebarV2`；`split` 另渲染 `DomainSidebar`；其余模式仍走 `SproutNav`。
- 设置「芽导航形态」增加「双栏分离式」。

## 三、交互

- 域轮盘：滚轮 / 拖拽 / 点击非中心项 → 落定域，更新过滤；中心项点击只 pulse（与左侧一致）。
- 左侧芽轮盘：列表由 `viewOrder` 过滤；当前芽在域内时保持，不在时由 `SidebarV2` 既有 watch 落到域内第一个芽。
- 域轮盘当前域高亮；左右侧栏收起/展开同步；底部 AppMenu 两侧一致。
- 「全部」/记住上次域 / `unclassified` 只在全部，继续沿用 R3-a 口径。
- 不做域内拖拽重排、收藏/最近、工具域折叠、管理入口（R3-c）。

## 六、风险

1. 左右各 220px 会明显压缩主区；窄窗需 R3-c 降级。
2. 域轮盘复制左侧物理逻辑；需与左侧行为对齐（滚轮/拖拽/落定/收起）。
3. `viewOrder` 过滤会改变 `SidebarV2` 的列表长度；其既有 watch 会在当前芽不在域内时落到域内第一个芽，属于本形态的预期行为。
4. 两侧共用 `sidebarCollapsed`；若后续要独立收起，R3-c 再加分状态。
