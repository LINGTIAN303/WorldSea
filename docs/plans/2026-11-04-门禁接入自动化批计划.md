# 门禁接入自动化批计划（2026-11-04）

> **来源**：[架构策略与检查器](../details/架构/架构策略与检查器.md) §六 A4 挂账「检查器未接入提交前钩子」。该挂账自 2026-09-21 起存在，[主计划前置 · 风险点清理批](已完成/2026-11-03-主计划前置-风险点清理批计划.md) 复盘时把它列为「**优先级应上调**」——因为基线 16 天未更新、积压 10 项红，全靠手工跑门禁才暴露。
>
> 紧接着的[文件规模债务拆分批](2026-11-04-文件规模债务拆分批计划.md)再次印证同一风险：债务被显式登记后无人跟踪，直到有人想起来跑一次 `arch:check`。

## 一、现状实测（开工前）

| 门禁 | 脚本 | 耗时 | 退出码语义 | 是否有效 |
|---|---|---:|---|---|
| 架构检查 | `scripts/architecture/check.mjs` | 0.3s | 违规 → 2 | ✅ |
| dsh fork 台账 | `scripts/check-dsh-fork-ledger.mjs` | 0.28s | 不一致 → 1 | ✅ |
| 样式一致性 | `scripts/style-conformance/check.mjs` | 0.45s | 超基线 → 1 | ✅ |
| 文档链接 | `scripts/check-doc-links.mjs` | 0.73s | **恒为 0** | ❌ **作为门禁完全无效** |

**三个问题**：

1. **`check-doc-links.mjs` 没有 `process.exit`** —— 无论断链多少都返回 0。它一直是「报告工具」而非「门禁」。
2. **`style:check` 开工即红** —— `hex 718 > 基线 711`、`rgba 166 > 基线 164`。基线最后一次更新是 `ee8e7f9`（O2–O4 验收），此后背景族、字体、快捷键等批次持续加裸色值，属**长期渐进漂移**，非单一批次引入。
3. **CI 几乎从不触发** —— `ci.yml` 的 `on.push.branches: [main]`，但实际开发在 `feat/ui-parallel` 上，**领先 main 242 个提交**。加了 CI 也跑不到。

## 二、落法

### 2.1 修 `doc-links` 退出码（前置）

补 `process.exit(missing.length > 0 || absolute.length > 0 ? 1 : 0)`——与另外三条门禁一致：非零 = 不通过。疑似误报不影响判定。

### 2.2 统一入口 `scripts/gate.mjs`

四条门禁各自独立、此前全靠人记得手跑。新增统一入口，既给钩子用也给人用：

- 顺序跑四项，逐项打印耗时
- 失败时把子脚本输出原样打出（成功时只在 `--verbose` 下展示，避免日常刷屏）
- 非 git 工作区（源码包）自动跳过 `fork:check`（它依赖 `git diff <基线>`）
- `--list` 只列检查项

### 2.3 git 钩子（`.githooks/`）

| 钩子 | 跑什么 | 耗时 |
|---|---|---:|
| `pre-commit` | `scripts/gate.mjs` 四项 | ≈1.8 秒 |
| `pre-push` | 四项 + `pnpm typecheck:tauri` | ≈60–90 秒 |

类型检查放 pre-push 而非 pre-commit，是为了不拖慢每次提交。

**启用方式**：`git config core.hooksPath .githooks`。git 出于安全不执行版本库里的钩子，必须显式设置——故提供 `scripts/install-git-hooks.mjs`（`pnpm hooks:install` / `--status` / `--remove`），并挂在 package.json 的 `prepare` 生命周期上，`pnpm install` 时自动启用。

**`prepare` 的容错**：CI 与源码包里没有 `.git` 属正常，脚本遇到这种情况**只提示不失败**，否则会中断 `pnpm install`。

**逃生门**：`SKIP_GATES=1 git commit/push ...`。保留逃生门是因为钩子可能因环境问题（node 缺失、编码）误拦，但默认路径是拦截。

### 2.4 CI 补 gates job + 放开触发面

- `on.push.branches` 由 `[main]` 改为 `['**']`——否则长期开发分支永远得不到校验
- 新增 `gates` job 跑 `pnpm gate`，与本地钩子**同一套脚本**，保证「本地过了 = CI 也过」，不出现两套口径
- `checkout` 用 `fetch-depth: 0`：`fork:check` 要 `git diff <基线提交>`，浅克隆取不到历史

### 2.5 `style:check` 基线收紧到实测

漂移是背景族/字体/快捷键批次的真实增长（裸色值分散在 20+ 个文件，最大来源 `field-matrix/styles/matrix.css` 102 处、`styles/theme.css` 83 处）。本批**不做**换语义令牌的大改（那是独立工程），只做两件事：

1. 基线更新为实测值：`hex 711→718`、`rgba 164→166`、`boxShadow 146→146`（不变）、`backdropFilter 10→8`（**收紧**）
2. 在 [架构策略与检查器](../details/架构/架构策略与检查器.md) 登记来历与待偿性质

> **口径说明**：这里 `hex`/`rgba` 是**放宽**，`backdropFilter` 是**收紧**。放宽的两项是真实超限（非误判），且已在文档里显式登记为待偿债务——不是「调阈值让门禁变绿」了事。

## 四、遗留与建议

1. **`hex` / `rgba` 是放宽而非清零**。这两卷的真实解法是把 718 处裸色值换成 `theme.css` 的语义令牌，涉及 20+ 文件、且需要逐处核对视觉，属独立批次。本批只做了「让门禁能如实反映现状并不再继续恶化」。
2. **钩子可被 `--no-verify` 绕过**（git 原生行为，无法禁止）。真正的硬约束是 CI 的 `gates` job——但前提是仓库确实跑 GitHub Actions；若实际用 cnb（本仓有 `cnb` remote），需要在那侧另配一份。
3. **CI 触发面放开到 `['**']` 会增加 Actions 用量**。若只想约束主分支，可改回 `[main, 'feat/**']` 这类白名单。
4. **未接 vitest / cargo 测试进门禁**——按用户裁定「只接快门禁 + typecheck」。测试仍靠手动 `pnpm test:run`。
