# 剪「自定义模块」批计划（official.module-builder 与模块运行时机器）

> **来源**：用户 2026-09-25 走查 DA 批后裁定——「自定义模块这个芽可以剪掉，因为它只是我早期想着让用户能有个手动创建芽的一个路径构想，现在可以说无用了，且连半成品级别都未达到」。
> **裁定四项**（同轮拍板）：① **彻底剪**（芽 + 机器 + 类型/序列化/导入导出钩子 + 代理面工具与指南 + 设置项）② **保留「自定义视窗」**（`official.custom`，与模块机器无关）③ 项目库的 `modules` 表声明**保留不动**（既有库兼容）④（第三/四项属 B 批口径，见 B 计划）。
> **边界**：`worldsea-core`（旧 Rust 引擎）里的同名 `modules` 面**不在范围**（无 Tauri 命令暴露、非现实现；随 C 批打包一并议）。

## 二、保留面（明确不动的）

- **`official.custom`（自定义视窗）**：自持 dashboard 实现，与模块机器零依赖（已核实：全目录无 `ModuleRuntime/ModuleViewRegistry/moduleStore/CustomModule` 命中）。
- **ui-kit 图标键 `'module-builder'`**：被技能默认图标（`skills/manifest.ts`、`creator.ts`、`platform-adapters.ts`）与「布局管理」菜单共用，**不是芽引用**。
- **项目库 schema**：`entity-core/src/core/database.ts` 的 `modules: 'id, active, source'` 声明与 `ProjectMigration` 的表拷贝——既有库兼容，留（表在，读写路径无）。
- **既有项目目录里的 `modules/` 文件**：不主动清理（导入侧不再消费；`manifest.moduleCount` 字段容忍残留）。
- 历史计划/迁移留档文档：不改（`docs/plans/已完成/*`、`docs/details/端分离/*`、2026-09 前的调研与规格）。
