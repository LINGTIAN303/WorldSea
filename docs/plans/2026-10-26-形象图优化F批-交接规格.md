## 一、F1 资产库复用

**目标**：同一项目内跨实体复用已导入的资产——形象 Tab 增加「从资产库选」入口，不再每实体重复上传。

**实施**：
1. `AssetField.vue` 增加「从资产库选」按钮（与「重新选择」并列）→ 打开资产选择弹层（新组件 `AssetLibraryPicker.vue`，plugin-sdk，Teleport 弹层样式参考 MotionEditor 的 me-overlay）。
2. **资产列举函数放 entity-core**（依赖方向约束：plugin-sdk 组件不得 import `apps/tauri/src` 下的模块——`imageAssets.listAssetFiles` 在 apps 层，**不能直接复用**）——在 `assetImport.ts` 新增 `listProjectAssets(kind: AssetKind)`：`resolveEntityDataDir()` → `invoke('cmd_fs_list', { path: root + '/assets' })` → 按 `ASSET_KIND_EXTS[kind]` 过滤扩展名 → 返回 `{ path, name, size, modified }[]`（mtime 降序）。选择器选中 → `convertFileSrc(path)` 生成 asset URL（entity-core 已依赖 `@tauri-apps/api/core`）→ emit `update:value`（**不 emit update:kind**——选中后过 AssetField 现有 refineKind 修正 png/webp 动图）。
3. 引用共享语义：多实体引用同一 asset URL **合法且被孤儿清理覆盖**（`NotebookView.onCleanOrphanAssets` 的引用集含顶层 portrait/videoAsset/coverImage/avatar——**不要动这个集合**，新引用字段若新增须同步加入）。
4. 可选增强（低成本）：选择器行尾显示引用计数（`collectAssetDiskPaths` 对全实体 properties+顶层字段统计该路径出现次数）。

**验收**：实体 A 上传 GIF → 实体 B 打开形象 Tab「从资产库选」→ 选中该 GIF → B 的 portrait 生效且悬停预览正常；资产文件只有一个；孤儿清理不误删（两实体都在引用集内）。

## 二、F2 编辑器与动效增强

**目标**：MotionEditor 草稿撤销/重做、动效模板一键套用、缓动函数。

**实施**：
1. **撤销/重做**（MotionEditor 内）：草稿快照栈——`watch(draft 深变化, push snapshot)`（structuredClone，上限 50 截尾）；Ctrl+Z / Ctrl+Y（编辑器打开期间监听，Esc 已占用先保存关闭——按键分层：Ctrl+Z 仅 editorOpen 时）；UI：工具栏 ↺/↷ 两按钮。注意快照恢复=替换 draft 内容（regions/tracks 数组 splice 重建，保持 reactive 引用不换）。
2. **动效模板**：MotionEditorSide 轨迹区加「模板」下拉，预置（应用=覆盖选中轨迹参数，motions 写入 draft）：
   - 头部摆动：dy=±3、duration 2.4s、alternate、loop
   - 呼吸：scale 1→1.04、duration 3s、alternate、loop
   - 漂浮：dy=0→-6、duration 4s、alternate、loop、ease-in-out
   - 眨眼：dy=0→2、duration 0.28s、不 loop 不 alternate（配合 loop 轨迹由外部触发——保持简单：也提供 loop 版 duration 4s 内 8% 时间眨——首版给简单参数版即可）
3. **缓动**：`MotionTrack.easing?: 'linear' | 'ease-in' | 'ease-out' | 'ease-in-out'`（缺省 linear）——`trackToKeyframes`（motionMath）在**每帧**对象上带 `easing`（WAAPI 关键帧级 easing=到达该帧的缓动，首帧不生效属正常）；多关键帧时帧间缓动=各帧 easing（时间轴选中帧可设，或轨迹级统一——**选轨迹级**，简单）；MotionTimeline/MotionEditorSide 表单加下拉。测试：trackToKeyframes 透传 easing 断言。
4. 模板应用与缓动均落 portraitMeta.motion，无 schema 变更（easing 是 MotionTrack 新可选字段，types 补一行）。

**验收**：编辑器 Ctrl+Z 逐步回退拖拽的区域位置；套「呼吸」模板预览立即可见缓入缓出；保存后悬停预览缓动生效。

## 三、F3 视口感知渲染优化

**目标**：网格滚动时视口外的重型渲染（model-viewer 3D 上下文、视频解码）不占资源；20+ 卡流畅。

**实施**：
1. 新 composable `packages/plugin-sdk/src/composables/useInViewport.ts`：IntersectionObserver（root=最近滚动祖先或 null=视口；rootMargin '200px' 预载缓冲；单实例单 observer 多注册）。jsdom 无 IntersectionObserver——测试环境 shim（`vi.stubGlobal` 或组件内 `typeof IntersectionObserver !== 'undefined'` 兜底恒 true）。
2. **EntityCardCover 的 PortraitRenderer 分支**（模型/Lottie 封面）：`v-if="inViewport"`——视口外卸载 PortraitRenderer（模型 webgl 上下文随卸载释放），视口内重新挂载（模型加载有浏览器缓存，重挂快）。封面区域给占位背景（现有 pr-loading 样式复用或纯色）。
3. **视频封面**：已有滚动暂停（useCardVideoScrollPause）——本批只对 model/Lottie 做；video 解码 paused 已省（无需 additional）。
4. **悬停预览框/追踪浮层不在优化范围**（单实例）。

**验收**：网格 20+ 模型卡滚动流畅度可感提升（任务管理器 GPU 占用对比）；滚回视口模型恢复渲染；功能回归（悬停预览/Alt 拖拽/动作播放不受影响——**特别验证 hover 三层防护未被破坏**：视口外卸载重挂后 EntityCard 的 over/out 判定链不变——判定在卡片 wrapper 上，不在 PortraitRenderer 内，理论无涉）。

## 四、F4 模型动作编排与 Lottie 控制

**目标**：模型多动作序列衔接播放；Lottie 播放控制（暂停/恢复/重播）。

**实施**：
1. **动作序列**：`ModelActionConfig` 扩展 `sequence?: string[]`（存在时 hover/click 触发按序播放）：
   - PortraitRenderer.playModel 改：sequence 存在 → 依序 `setAttribute('animation-name', name)` + `play()`，监听 model-viewer 的 `finished` 事件（addEventListener('finished')，model-viewer 标准事件）播下一个；全序列完停在末帧；期间再触发 play 则从头。
   - 配置 UI：EntityCoverPanel 模型动作区加「序列」多选（从 availableAnimations 里按序挑选——简化首版：序列编辑=按 availableAnimations 顺序的复选列表+上移下移，或「当前下拉选中即追加」按钮模式；**推荐**：小型有序标签列表（点动作名追加、点标签移除），控件成本最低）。
   - 单动作绑定（hover/click 单值）与序列并存语义：sequence 优先。
2. **Lottie 控制**：PortraitRenderer expose `pause()` / `resume()`（内部映射 lottie-web AnimationItem 的 `pause()` / `play()`——lottie API 无 resume 命名）；EntityFollower 浮层加微型控制条（播放/暂停小按钮，仅 lottie kind 显示——`entity.portraitKind === 'lottie'` 条件渲染；图标用 WsIcon name="play"/"pause"）。悬停预览框 pointer-events:none 不加控制（保持不挡卡片）。

**验收**：GLB 带 2+ 动作者配序列 [Come, Idleshow]，点击浮层模型依次播放两动作；Lottie 浮层可暂停/恢复。
