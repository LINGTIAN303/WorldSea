## 二、第 0 步取证（2026-09-30，全部源码级）

1. **对齐目标**（工作台窗 `apps/tauri/src/ui/layout/TitleBar.vue:139-149`）：四键 = Ctrl+M 最小化 / F10 最大化还原 / F11 全屏 / Ctrl+W 关闭；守卫 = IME（`isComposing || keyCode===229`）+ 逐键修饰判据（`m`/`w`：mod 且无 alt/shift；`f10`：无任何修饰）；相位 = window 冒泡。
2. **冲突面（dsh 侧）**：快捷键 runtime = **web**（`dsh/packages/client/shortcuts/src/client/dom.ts:19`：`documentElement.dataset.platform` 缺席 → web）→ dsh 的 `page.close` 在 web 档默认 **Ctrl+Alt+W**（`ui-sidebar-right/src/client/shortcuts.ts:65-97`），**裸 Ctrl+W 无绑定**；全树 src 无 F10 / Ctrl+M / Ctrl+Tab 默认绑定。终端局部语义：web 档终端保留 Ctrl+W/R 为局部输入（`shortcuts/README.zh.md:54`；xterm 的 cancel 行为随 `cancelEvents` 配置而异，故**不依赖上游中止**、自行让行）——Ctrl+M＝回车、Ctrl+W＝删词（shell）、F10 是 TUI 功能键，全部让行。
3. **G1-c 落点**：工作台窗 `decorations(false)`（`workspace_window.rs:208`）、全屏由页面 `TitleBar.vue` 的 F11 自管（`appWindow.setFullscreen`）——形态改动在页内，壳零改动；`.shell` flex 纵向 + `.shell-body flex:1` → 隐栏后内容区自然接管全高。
4. **★ 取证时发现的隐藏雷（G1-b 护栏）**：空间切换的几何转移未考虑全屏窗——「工作台（非全屏）→ 切回 Agent（仍全屏）」方向会给全屏主窗写 `set_position`/`set_size`（可能顶掉全屏/成怪态）；反向也会把全屏的屏尺寸当几何转移。处置 = 纯判据 `geometry_transfer_skipped`（来源最小化 / 来源全屏 / 目标全屏 → 跳过），全屏态**不随切换转移**（每窗各自保有，切回仍是全屏）。

## 六、走查发现与修复（2026-09-30，同日）

**用户报三现象**：① 全屏（dsh 侧）中按 `Ctrl+Tab` 切到工作台后，进一步按 `F11` → **「双窗」**（两个窗同时可见）；② `F10` 最大化 → `F11` 全屏 → `F11` 退出 → 也出现**「双窗」**；③ 最大化状态下进全屏**非正常全屏**——屏幕左侧留出任务栏原位置的条带（截图留档）。

**第 0 步取证（新工具/新事实）**：
- **Windows 窗口探针**（`.workbuddy/win-probe.mjs`，node 包装 PowerShell `-EncodedCommand`——绕开 `.ps1 -File` 的 ANSI 解码与进程查找怪癖）：枚举本进程全部 `Tauri Window` 的 **role / 可见性 / 最小化 / 矩形 / win32 style**（style 去 `WS_OVERLAPPEDWINDOW` 即 tao 全屏态、含 `WS_MAXIMIZE` 即 max 标记）——**隐藏 WebView2 窗口的 `document.visibilityState` 不可靠**，此探针是本次全部分析的地面真相。
- **tao 全屏实现研读**（`tao-0.35.3/src/platform_impl/windows/window.rs`）：Borderless 全屏**不脱最大化**——直接在最大化窗上 `SetWindowPos` 到监视器矩形，会被 Windows 的「最大化约束」顶回工作区（= 现象 ③ 的条带），并残留 `is_maximized()=true` 的 **max+全屏坏组合**（全屏窗几何读回 `-32000` 最小化占位——壳日志的 `199x34@-32000,-32000 全屏` 即此）；退出全屏用 `SetWindowPlacement` 回放进入时的 placement。
- **竞态实测**：`cmd_shell_space_switch` 是 async 命令且**无互斥**——6 连发（单 tick 交替目标）的**完成序 ≠ 提交序**（日志同向连发可见；终态多次违背最后一条指令）。交错最坏序列可达「双双可见 / 双双隐藏」。→ **「双窗」根因裁定为空间切换竞态**（用户连按/两窗交替触发即成）；现象 ① 里的「F11 出现第二窗」系竞态后的残留态被后续操作暴露。

**修复（commit 见下）**：
1. **空间切换互斥**（`workspace_window.rs`）：`SPACE_SWITCH_LOCK` 串行化（每对 show/hide 原子成对）；**死锁纪律**——主线程调用方（托盘 / CloseRequested）不得阻塞等锁（窗口操作要回主线程消息泵），托盘与 `hide_and_back_to_space` 改经 `request_space_switch` 投递后台线程，`dispatch_workbench` 整段移入后台线程。
2. **进全屏先脱最大化**（`shell_bridge::set_fullscreen_safely`，三入口共用：F11 命令 / 菜单 / 工作台窗页内 F11）——现象 ③ 根因级修复（退出全屏回普通态；不自动恢复最大化，如需要再议）。
3. **条件化 unminimize**（`ensure_target_visible`：仅确实最小化才 restore——对全屏/普通窗的无谓 SW_RESTORE 一并消除）。
4. **切换后状态对日志**（`切换后 main(vis/max/fs) workspace(vis/max/fs)`）：正常恒恰一侧 `vis=true`——下次同类现象自证。

**验证**：反证 **15/15**（含反证逮到的断言不敏感一处：M14 的裸子串被 `snapshot()` 同名文本假满足 → 改整行守卫）；cargo **110/0** · vitest **792** · fork 11=11 · arch 0 · 断链 0 · vue-tsc 0。**CDP 实测**：F11 全屏 `max:false + 0,0 全幅`（无条带）；3 轮 6 连发 → **18 条「切换后」状态对恒恰一侧可见**（双窗/双隐零复现）。已知语义：连发时的终态 = 串行执行序的最后一个（非严格提交序）——人类节奏单发无此问题，登记为已知边界。

**复验清单（②轮，用户 2026-09-30）**：① 全屏 Ctrl+Tab → F11 不再出双窗；② F10→F11→F11 不再出双窗；③ 最大化后 F11 = 正常全屏（无任务栏条）、退出回普通态；④ 回归 §五 五项。

**收口（2026-09-30）**：用户复验后反馈**仍有残留现象**（「还是不太行」，未细述；判为「没什么大碍」）→ **用户拍板：直接记通过、暂不追**。残留作为**已知边界**登记，留待「快捷键系统」议题一并或另行处置；本批取证链、修复与验证（反证 15/15 · CDP 状态对实测）已全部留档，复现手段齐备（`.workbuddy/win-probe.mjs` + 壳日志「切换后 main(…) workspace(…)」状态对行）。**本批完结。**
