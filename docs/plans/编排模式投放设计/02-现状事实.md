## 四、运行机制事实（对应 B0-1 / B0-2 / B0-3 / B0-21）

主循环（`crates/agent-kernel/src/orchestrator.rs` run L311-550）：

- **串行 DAG 遍历**，无 fork/join（L355 注释明示"并发分支留待阶段 2.3"——MultiAgent 的并发在节点内部自实现：N 个 AgentLoop + mpsc + SharedBlackboard）。
- **下一跳双机制**：节点显式 `next_node_id` 优先（L486），否则按边查找——边可带条件闭包（`with_condition`，L20-64）。
- **四重保护**：① abort 检查 ② max_iterations 默认 50（L329）③ 可选 timeout_ms（超时→Timeout 状态）④ 无进展死循环检测：同节点连续 **10** 次无进展访问判死循环（L367，进展 = messages / plan / reflections 长度三元组增长）。
- 节点执行期间持有 state 锁（L453-470，节点内并发需自行 clone）。
- NodeStatus 四出口：Continue（可带显式下一跳）/ Done / Aborted / Error。

**pause / resume 是空壳存根**（L558-565 仅 debug 日志，注释"阶段 1.3 补完"未兑现）——A5 干预能力的现状底线：中止已有，暂停没有。

**abort 穿透**：`orchestrator.abort()` 置 `aborted: AsyncMutex<bool>` → `AbortChecker` → `NodeContext.abort_check`（节点执行中可见）。

**快照 / 恢复 API 已有**：`get_snapshot() / restore(OrchestratorState)`（L573-580）——但无持久化接线（内存态）。

**最终消息提取**：取 state 中最后一条 assistant 消息（L522-531）。

**SubAgentPool**（`crates/agent-kernel/src/sub_agent_pool.rs`）：懒加载 / 规格指纹复用 / 变更重建+上下文迁移 / 白名单工具隔离。

## 十一、事实对钥匙问题的直接输入

- **D0-9（链的性质）**：现状底色 = **串行 DAG 铁轨**（条件边 + 显式改道），无图宿主级 fork/join；并发只存在于节点内部（MultiAgent / ToT beam）。"流水线"是现实现的自然语言；"树 / 图"是节点内形态。
- **B0-1（运行单元）**：run_id 不存在，事件按 session 作用域；重跑 = 重新构图重新 run（无续跑）；快照 API 有但无接线。OrchestrationRun（B8 倾向）是纯新增物。
- **D0-15（段间交接物）**：当前唯一交接介质 = `OrchestratorState`（messages / plan / reflections 等，经 state 锁在节点间传递）；计划有类型化 PlanItem，其余多为字符串消息。
- **A1（触发模型）**：双入口现状（send_message 直答 vs 面板手动 orchestrator_run_*）；A3 判型链路已在 send_message 侧存在，自动接线缺口 = 判型结果 → 编排链路的路由。
- **B7（轨迹事件）**：骨架原子已存在（OrchestratorStart/End + NodeStart/End 带 summary / duration），缺口 = run_id 归属 + phase 语义 + 管线级 started/finished；细节事件族无需动。
- **A5（干预）**：中止已全链路可用；暂停是空壳；跳过 / 回退无任何基础。
- **C0-17（产品性格）**：Supervisor 默认 1 轮、Refine 3 次、评审理由 / 委派 reasoning 字段已存在——"可解释"的数据底子比预想厚。
