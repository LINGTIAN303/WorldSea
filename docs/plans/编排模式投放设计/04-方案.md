## 一、方案总览

**电梯陈述**："你只管说，它自己会组织——而你能看懂它是怎么组织的。"

**一句话架构**：用户发请求 → 判型选链（run 的形状）→ 声明式管线推进（阶段交接物流动）→ 迹线实时呈现（分级透明）→ 必收敛出结论（超限=收敛、降级有物）。

**核心模型四件**：

| 件 | 是什么 | 定案 |
|----|--------|------|
| **run** | 请求级编排上下文实体（含子 run 树） | B22 |
| **链** | 声明式管线定义（条件支路 + 门 + 收敛） | D15/D21/D23 |
| **物** | 段间交接物（类型化信封） | D23 |
| **迹线** | 前端编排段 + 右栏详图 | A1-A6/A0-* |

**三张力元规则**（贯穿全部实现决策）：

- 无感 vs 透明 → **分级透明**：透明度跟随实际编排量（退化 run 无感 / 单链折叠起步 / 深水区入口卡）
- 声明化 vs 代码化 → **骨架声明化 + 血肉代码化**：管线拓扑与门声明；模式策略代码
- 稳定 vs 演化 → **契约稳、组合演**：事件族/ArtifactKind/run_id 只加不改；链族与模式可增删

## 三、核心契约（三张表 + 事件族）

### 3.1 OrchestrationRun 实体（B22 / B8）

驻 `agent-commands` 内存（HashMap 注册表）；多阶段/深水区 run 懒持久 SQLite（表结构 v1.5 施工时定：新 `runs` 表或扩展 `long_tasks`）。

```rust
struct OrchestrationRun {
    run_id: String,            // uuid，事件/迹线/中止聚合键
    session_id: String,        // 会话归属（会话 1:N run，v1 顶层串行）
    parent_run_id: Option<String>, // 子 run 树（委派生成，层级 ≤3）
    status: RunStatus,         // Running | Completed | Aborted | Error | Timeout | Interrupted
    pipeline: PipelineId,      // 判型选中的管线形状（预设 id）
    phase_cursor: PhaseId,     // 当前阶段指针
    artifacts: Vec<HandoverArtifact>, // 交接物区（§3.2）
    decisions: Vec<DecisionRecord>,   // 决策记录（判型理由/委派 reasoning）
    started_at / finished_at,  // 时长统计（子 run 可见"谁干了多久"）
}
```

状态机：`Running → Completed(reason) | Aborted | Error | Timeout | Interrupted`；abort 父 run 递归中止活跃子孙；重启 = 内存 run 蒸发（会话历史只剩消息）。

**收敛 reason 枚举**（B0-4/D0-4，六值）：`goal_reached / threshold_met / limit_reached / no_progress / aborted / degraded`——各模式内部终止条件向枚举映射（ToT GoalReached→goal_reached、ScoreConverged→threshold_met、MaxDepth→limit_reached、NoCandidates→no_progress；MultiAgent 三收敛同理），映射表随管线定义声明。

### 3.2 HandoverArtifact 交接物（D23）

类型驻 `agent-kernel/src/types.rs`；节点经 `NodeResult.artifact: Option<HandoverArtifact>` 显式输出；主循环收物 → ①存 run 交接物区 ②发 phase_result 事件（只带 artifact_id + summary）。

```rust
struct HandoverArtifact {
    artifact_id: String, run_id: String, from_node: NodeId,
    kind: ArtifactKind,          // ↓ 九种
    summary: String,             // 一句话（迹线与事件用）
    produced_at: Timestamp,
}

enum ArtifactKind {
    Plan(Vec<PlanItem>),                     // 已有类型升格
    Reflection(ReflectionResult),            // 已有类型升格
    Routing { decision: RouterDecision, reason: Option<String> }, // 已有类型升格
    Execution { step_results: Vec<StepResult>, status: ExecStatus },
    Delegation { sub_run_id: String, task: String, output: String }, // 挂子 run 树
    Exploration { best_path: String, score: u8, explored: usize, term_reason: String },
    Aggregation { content: String, sources: Vec<String> },            // GoT
    Convergence { final_result: String, reason: String },             // MultiAgent
    Degraded { from: PhaseId, reason: String, partial: Option<String> }, // 降级一等物
}
```

**双层校验**：构图期硬校验（管线边声明接受的 kind，不匹配拒绝构图——每条非法组合一条拒绝用例）+ 运行期软校验（物缺失 → 声明式降级支路产出 Degraded 物）。

**粒度**：物 = 阶段级（Execute 各步聚合为一个 Execution 物）；终局结论 = run.final_message，不另设结论物。

### 3.3 模式注册表（C0-3 / C0-11 / C0-15）

轻量静态注册：后端一张表 + 前端一份 TS 清单（内容同构，序列化同步）；新增模式改 **2 处**（注册项 + 模式实现），取代现状 8 处贯穿改动。

```rust
struct PatternRegistryEntry {
    pattern_id: String,          // "plan" | "tot" | "got" | ...
    display: PatternDisplay,     // 名称 + 能力语义分组（探索/协作/规划/评审，C14）
    entry_command: Option<String>,   // 手动命令（/plan 等；无则仅自动触发）
    run_command: String,         // orchestrator_run_* 
    event_family: Vec<EventType>,    // 轨迹事件 + 细节事件族
    artifact_kind: ArtifactKind,     // 该模式产出的物类型
    config_defaults: PatternConfig, // 次数参数等数据面（C0-5：配置化）
    detail_component: Option<String>, // 详图组件 id（深水区模式；A4）
}
```

注册项 = 五触点检查单（命令/事件/物/配置/详图）；**② 事件族与 ③ 物为 v1 硬性补齐项**（全模式必接必产）。五件套（策略/配置/事件/错误/测试）为立项标准，multi_agent 为样板。

### 3.4 轨迹事件族 orchestration_trace（B7 / C13）

在现有事件流之上新增（细节事件族全保留，骨架 + 细节双层并存）；全部携带 `run_id`：

```
pipe_started  { run_id, pipeline, 判型理由 }
phase_entered { run_id, phase, reason }
phase_result  { run_id, phase, status, summary, artifact_id }
pipe_finished { run_id, status, reason(六值枚举), final_message }
```

前端新增 `useOrchestrationTrace`（按 run_id 聚合：请求 → 阶段 → 物摘要/理由 → 结论）；现有模式 composable 收敛为"详图数据源"。事件族 additive 版本化（只加不改，废弃 deprecated 标注）。

## 四、管线定义与链族（D15 / D21 / A1）

### 4.1 预设映射表（A3 四管线 ↔ D15 链族）

判型词汇表收敛为一张映射表；D15 声明式管线定义是唯一拓扑源；未来加管线 = 加预设。

| 判型输出 | 链族预设 | run 形状 |
|---------|---------|---------|
| Query | 快问答链 | 退化 run（单阶段 react，无编排段） |
| Research | 规划型链 + GoT 聚合位 + Reflection | Plan→Execute(多源检索)→GoT→Reflection |
| Experiment | 规划型链 + Refine 迭代环 | Plan→Execute(代码实验)→Reflection→Refine(条件) |
| Compose | 规划型链 + Reflection | Plan(大纲)→Execute(分章)→Reflection(一致性) |

**委派型/求解探索型链不在预设内**——由执行反馈动态触发（Execute 中判定需委派→挂委派位；判为多解型→换 ToT 工位）。

**长度优先级**（D0-22）：命令强制 > 判型自适应 > 次数上限兜底。阶段数不设独立参数（D0-12：预设链最长 5 阶段位 + 循环受既有上限约束）。

### 4.2 门清单（D21）

门 = 构图时声明的干预点（非运行时任意插入）：

| 门 | 版本 | 实现 |
|----|------|------|
| 中止门 | v1 | abort 递归穿透 run 树（已有） |
| 插话门 | v1 | steer 队列化到节点边界（Windsurf 排队消息模式） |
| 计划批准门 | v2 | 借 ConfirmationBroker 实现（不依赖 pause 空壳） |
| 评审否决门 | v2 | Reflection 分数+issues 数据已有 |

### 4.3 铁轨与可变点（D0-8）

铁轨 = 声明支路（管线定义里的条件边）；可变点 = 入口判型 + 门上决策 + 节点内策略（探索算法/委派选择/评审标准）。**运行时不改拓扑**（D0-21：执行中不插入新阶段；临时加深 = 命令覆盖重发新 run）。

## 五、前端形态规格（A 域结论）

### 5.1 编排段（对话流内）

- **位置**：对话流内特殊消息单元，一次请求一个编排段；最终回答作为段后正常消息落回对话区（A0-1/A3）
- **时态规则**（A0-3/A0-5）：运行中逐步展开 → 完成后自动收拢为折叠任务流 + 最终输出 → 历史可重新展开；手动选择优先（记忆至会话视图状态，跨态一致）
- **折叠态**：判型结论 + 阶段摘要行 + 统计（N 步骤/M 工具/耗时，Cursor 范式）
- **展开态**：阶段卡序列（纵向步骤卡，状态点+WsIcon 双编码）+ 物摘要 + 详图入口卡
- **首次弱提示**：迹线首次出现时一行"这是你的请求被处理的过程，点击可展开"，仅首次（localStorage）（A0-16）
- **分级透明**（A0-12）：退化 run 不渲染编排段；呈现由编排事实驱动，不做用户设置

### 5.2 详图（右栏面板驱动，A0-6）

点击迹线入口卡 → 右栏 ExecPanel 自动切到对应详图（ThoughtTree / MultiAgent 黑板 / 子 run 树）；**组件零重写**（OrchestratorPanel/MultiAgentPanel 已事件驱动）；现有 11 tab 保留为过渡期直达入口（遥测后定去留）。可访问性：聚焦单元 = 迹线阶段卡（DOM 全键盘）+ 详图关键节点（最优路径/活跃节点 tabindex）（A0-7）。

### 5.3 等待感与错误（A0-13/A0-14）

- 可预测性四件套：阶段卡实时推进 + "已学到+下一步"双行叙事（Gemini 范式）+ 子 run 名与耗时 + 统计行；**不做 ETA/百分比**
- 错误：迹线内呈现永不弹窗；失败/降级 = 状态点变色 + 一句原因（物 summary）；部分进度可见保留；出口永远给路（命令覆盖提示文案）

### 5.4 样式基线（A0-8~11，实现期可自主微调）

扩展现有极简语言（非新子系统）；迹线索引级 12-13px / 详图内容级；状态点（色）+ WsIcon（形）双编码；动效仅状态点流转 + 新阶段滑入（≤200ms）；图形用色全入 token 体系（禁写死颜色）。

## 七、验证基准（E19 细化）

五条基准任务（A0-17，覆盖四链族 + 降级）：

| # | 任务 | 验证 |
|---|------|------|
| ① | 快问答 | **不出现**编排段（无感原则） |
| ② | 规划型 | 完整迹线渲染正确（判型→计划→执行→评审→结论，含理由） |
| ③ | 委派型 | 子 run 树可视化正确（谁被委派、干了多久） |
| ④ | 探索型 | 入口卡 + 详图展开正确（ToT 树 + 最优路径） |
| ⑤ | 降级路径 | ToT 超时→Degraded 物可见可追溯（原因+部分结果） |

三项承诺验收（B0-18/19）：① 可解释 = 任务②迹线完整 ② 连续 = LoopEng 现有测试 ③ 故障可见 = 任务⑤。用户走查：5 分钟能答"这条请求刚才经历了什么"。链路完整性 = 保证（构图期校验可验证）；内容质量 = 尽力而为（免责：幻觉/外部副作用/意图误读）。
