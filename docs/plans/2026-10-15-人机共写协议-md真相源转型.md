## 一、决策记录

### 1.1 起点问题（2026-10-13 提出）

用户观察：编辑态与预览态未分离（md 在编辑态即被渲染、分栏两侧都渲染）。取证结论：TipTap（ProseMirror）富文本内核下「编辑即渲染」是 WYSIWYG 范式本义；预览态与编辑态渲染同源（同一份 HTML）；md 原文在「装载网关」与「输入规则」两个门口即被消费，入库后不复存在。

### 1.2 三轮评估收敛

| 轮 | 输入 | 结论要点 |
|---|---|---|
| 一 | 范式方案空间（A / A+ / B1 / C / D1 / D2） | B1（HTML 源 + 双模式）深层不自洽——源码编辑要求 md 完备 ⇒ 被迫方言化 ⇒ md 事实上成为真相源 ⇒ **收敛至 D1**（md 源双模式＝Joplin 模式） |

### 2.1 目标

- **G1 Agent 读写无损**：Agent 经工具面读写的 md 与存储逐字节一致（零转换、原文守恒）；

## 三、人机共写协议（核心规范）

### 3.1 真相源与视图模型

```
真相源（唯一）：properties.content = md 文本
    ↑ 序列化（PM→md）      ↓ 解析（md→PM / md→HTML）
富文本视图（TipTap/ProseMirror） · 预览视图 · 源码视图（块 3，后置）
```

- **纪律 1**：落库形态＝md；所有视图的编辑产物必须先序列化为 md 再落库；
- **纪律 2**：任何视图不得以自身格式落库（**禁止再出现 HTML 落库**）；
- **纪律 3**：解析 / 渲染层永远从 md 出发（单向数据流），不做「双源同步」。

**HTML 的角色澄清（2026-10-15 讨论补记，防混淆）**：本协议「去 HTML 化」的范围**严格限于存储真相源**（`properties.content` 的落库格式）；HTML 在其余角色上**完全保留、且不可或缺**——

1. **渲染中间态（视图层，永久保留）**：md 语法要渲染，必经之路就是「md → HTML（或等价 DOM）」——编辑器装载、预览态渲染全走这条链（marked 管道现成复用）。**不存在也不需要「无 HTML 的 md 直渲」**——「直渲」是对 md 渲染机制的误读；
2. **导出 / 转换中间态（保留）**：DOCX 导出＝md →(marked)→ HTML →(IR)→ docx；未来 PDF 导出同理。跨格式转换继续以 HTML 为中间表示；
3. **素材面板四渲染器（docx / xlsx / pdf / pptx 预览）**：渲染对象是**磁盘文件本身**（二进制进、画面出），与笔记的存储格式无关——本转型对其**零影响**。

> 一句话：**换掉的是「存什么」（HTML→md），不是「怎么渲染」（继续走 HTML）。**

### 3.2 方言规范（WorldSea Markdown＝GFM 基线 + 扩展）

**基线**：CommonMark + GFM（表格 / 任务列表 / 删除线 / 自动链接）+ 软换行语义沿用现状（`breaks`）。

**扩展语法（方言）与裁决表**：

| # | 能力 | 文本形态（md 表示） | 处置 | 状态 |
|---|---|---|---|---|
| D-1 | 双链 | `[[笔记名]]` | 解析派生 note_link＋编辑器渲染为链接节点 | 确定（Obsidian 惯例） |
| D-2 | 实体 mention | `@实体名`（文本直写，解析匹配） | 命中→渲染为 mention；未命中→字面文本 | **已裁决 A**（2026-10-15：按推荐采纳——`@实体名` 文本解析；id 结构保证交引用重写器） |
| D-3 | 图片尺寸 / 对齐 | 基础＝`![alt](src)`；尺寸与对齐＝**内嵌 HTML** `<img width height style data-align>`（标准语法，marked 透传；非私有方言） | **已裁决 B**（2026-10-15：按推荐采纳「内嵌 HTML」——尺寸/对齐属「可能离开系统」的呈现信息，走标准） |
| D-4 | 表格列宽 | md 表格无列宽语法 | 降级：重开按默认列宽 | **已裁决 C**（2026-10-15：按推荐采纳——接受降级） |
| D-5 | 任务列表 | `- [ ]` / `- [x]` | GFM 原生 | 确定 |
| D-6 | 代码块 | ```lang 围栏 | 原生；语言集沿用现 14 语言清单（`codeBlockExt.ts`） | 确定 |
| D-7 | 图片（基础） | `![alt](src)` | 原生；base64 / assets 路径策略沿用现状 | 确定 |
| D-8 | 公式 / Mermaid（预留） | `$$…$$` / ```mermaid 围栏 | 本期不做，位置预留（Joplin 实证：fenced 插件兼容性最佳） | 预留 |
| D-9 | 折叠块 / Callout（预留） | Obsidian 式 `> [!note]` | 本期不做 | 预留 |

**注**：mention 解析的歧义与改名场景见 §3.5 / §3.6。

**转义纪律（2026-10-15 实现实证，块 1 阶段 1）**：方言标记产生「字面回退」时，引擎自动转义 md 语法字符防 re-parse 歧义——如未命中的 `[[X]]` 落库为 `\[\[X\]\]`（渲染显示不变；恢复链接经编辑态 `[[` 弹层重建）。`@` 非 md 语法字符、不转义——未命中的 `@名` 以原文落库，实体创建后**下次装载自动恢复为 mention**。两种方言的可恢复性按语法本质不对称（`[[` 是链接语法字符，不转义会被内置规则拆解，必须转义锁字面；`@` 无此问题）。

### 3.3 Agent 写入语法子集（规范形态）

目的：从源头降低格式漂移（LLM 输出的 md 变体多：列表符号、空行位置、表格分隔等）。

- **规范形态**（Agent 应写）：
  - 列表符号统一 `- `；有序列表 `1. `；任务 `- [ ]` / `- [x]`；
  - 强调统一 `**`；行内代码反引号；标题 `# `（1–6 级，行首 + 空格）；
  - 块间单空行；表格用标准 GFM（表头 + 分隔行 + 数据行，行间无空行）；
  - 图片 `![alt](src)`；围栏 ```lang；双链 `[[笔记名]]`；mention `@实体名`（随 D-1 / D-2 裁决）。
- **工具面契约**：实体写入工具的 content 字段**收 md 文本、返回 md 原文**（原文守恒——不再做「归一/清洗」）；工具描述附「规范形态」指引段（经 dsh 系统提示注入）。
- **保真原则**：Agent 写入**不触发规范化重写**（写什么存什么）；「规范形态」靠提示约定 + 解析层宽容，而非落库改写。

### 3.4 解析派生规则（连接即内容的函数）

- **派生对象（一期）**：`note_link` 关系（`[[ ]]` 扫描）；mention 仅解析显示（不建关系，沿用现状语义）。
- **扫描时机**：① 笔记装载时（编辑器 / 预览渲染前）；② 保存后（防抖落库后触发）；③ 启动增量扫描（只扫 updatedAt > 上次扫描点的笔记）。
- **重算语义**：某笔记的关系集 ＝ f(其 content 文本)；重算＝全删该源笔记的派生关系 + 重插；**幂等、可重放**。
- **与现机制的关系**：编辑器 `[[` 弹层交互保留（选笔记插入节点），但**建联统一由解析派生**（序列化落库后的 `[[名]]` 文本为唯一输入）——消除「删 mark 不清理关系」类漂移（现挂账，见 `useNoteEditor.ts` 注释）。
- **性能**：单笔记扫描为线性文本扫描（μs–ms 级）；启动增量只扫变更集。
- **降级**：解析失败（语法残破）不阻断装载——该段降级字面文本。
- **【已落地 2026-10-15（块 2 阶段 1-2）】**：实现＝`backlinkDerive.ts`（语法感知扫描（围栏/反引号区排除）+ 三态解析（hit/miss/ambiguous）+ diff 重算（幂等、无变化零写入）+ skipUndo 写入 + 同笔记串行队列）；三时机＝**保存后**（persistContent 收口——内容落库唯一出口）/ **装载时** / **进视图全量 + 孤儿清理**（实现级强化替代「启动增量扫描」——无状态自愈，见块 2 批计划 §2.4）；code 型笔记不参与派生（content 非 md）。

### 3.5 引用重写器（改名治理）

- **触发**：笔记改名 /（未来）实体改名影响 mention 时。
- **策略选项**：
  - **S-1 全库重写**：扫描所有笔记，`[[旧名]] → [[新名]]`（Obsidian 默认行为）；代价＝全库写放大；
  - **S-2 容错共存**：不重写，旧引用成「未解析链接」，UI 提示修复；代价＝人工。
- **已裁决 D**（2026-10-15：按推荐采纳 **S-1 全库重写**；重写走归一事务 + 单条撤销）。
- 边界：重写器与搜索 / 快照类机制的联动在块 2 细化。
- **【已落地 2026-10-15（块 2 阶段 3）】**：实现＝`backlinkDerive.rewriteNoteRefs`（与派生扫描同状态机——代码块/反引号区不触碰、转义形态不动）+ `applyNoteRename`（改名本体 + 全部重写打进**同一条撤销记录**——一次 Ctrl+Z 整体回退；关系存 id 不存名，回退后天然一致）。触发＝`NotebookView.flushPendingWrites` 改名检测。mention 侧实体改名重写为非目标（「未来」项）。

### 3.6 歧义策略（重名）

- 场景：`[[同名笔记]]` / `@同名实体` 多匹配。
- **策略**：不自动猜测；呈现「歧义态」（编辑器高亮 + 候选提示；关系暂不建立或按裁决挂起）。
- **已裁决 E**（2026-10-15：按推荐采纳 **提示消歧**——不自动猜，弃「按创建时间首匹配」案）。
- 说明：笔记重名现状允许（无唯一约束）；本协议不引入强制唯一（保持轻量），以提示引导消歧。
- **【已落地 2026-10-15（块 2 阶段 1-2）】**：派生侧＝歧义**不建关系**（`resolveNoteRef` 三态解析显性化）；编辑器侧高亮 / 候选提示按拍板**后置**（一期只做派生正确性——块 2 批计划 §2.7）。

### 3.7 容错策略（迁移现装载网关资产）

- 现 `contentNormalize.ts`（`apps/tauri/src/world/plugins/notebook/contentNormalize.ts`）的容错能力整体迁移至解析层：
  - 「空行断表格」修复（LLM 输出漂移实锤，2026-10-12 走查经验）；
  - 未闭合围栏降级（整段转义）；
  - 任务列表兼容形态（marked `<li><input>` 形态 → taskItem 的兼容收窄为 md 语法直解）。
- **边界**：容错只作用于「解析 / 渲染」通路；**不改写存储文本**（保真原则，与 §3.3 一致）。

## 六、风险清单

1. **PM→md 序列化保真**（核心工程风险）——以 roundtrip 测试矩阵对冲；
2. **规范化争议**（用户 / Agent 对「符号被重写」的接受度）——协议明确 + 编辑器内提示；
3. **解析派生的一致性边界**（扫描时机遗漏、并发写）——store 单线程串行 + 幂等重算对冲；
4. **Agent 漂移的持续容错成本**——容错层常驻（§3.7）；
5. **全链路翻修的回归面**（HTML 假设散布）——以测试基线翻改为验收锚点。
