# B 批计划（正式化第二棵树：依赖口径 + 目录 + 清单/装载器 + 作用域注册面）

> **来源**：双 Cordis Spike 四选项的 B（[Spike 计划](2026-09-25-双Cordis-Spike批计划.md) §五）。
> **用户 2026-09-25 拍板两项口径**：① cordis 依赖 = **自 vendor**；② 插件装载 = **构建期静态清单**（`import.meta.glob`）。
> A（能力桥）与 D（视图生命周期收口）已落，本批把 Spike 的**临时口径**收敛为正式形态：相对引用 `dsh/vendor` → 自 vendor；`workspace/spike/` → `src/world/`；无清单/无装载器 → 清单规范 + 装载器；`pluginAPI.currentPluginId` 全局单值 → 按插件作用域注册面。

## 一、依赖口径（自 vendor，已核事实）

| 事实 | 值 |
|---|---|
| npm 公开面 | `cordis` 最新 **4.0.0-rc.10**（**无 4.0.4**）；`@cordisjs/core` = 3.18.1 → 不能直接 npm 依赖 |
| dsh 侧副本 | `dsh/vendor/cordis` = `@deepseek-ai/cordis@4.0.4`（MIT，Shigma，仓 = deepseek-harness；含 `lib/` 产物 + `src/`） |
| 依赖面 | `cordis/lib/index.js` 仅外部 import **`@deepseek-ai/cosmokit`** 一个；`cosmokit/lib/index.js` **零外部 import**（自持，17KB） |
| 体积 | cordis 60KB + cosmokit 17KB（产物单文件，合计 ~77KB） |

**落法**：`apps/tauri/src/world/vendor/` 下放两包的 `lib/index.js` + `LICENSE` + 一份 `README.md`（来源/版本/同步办法/MIT）；**只 vendor 产物 JS**（不搬 `src/` 与 `.d.ts`——架构门禁会扫 `.ts`，且我们只用其子集）。解析靠**别名**：`@deepseek-ai/cordis` / `@deepseek-ai/cosmokit` → vendor 产物（工作台 `vite.config.ts` + 根 `vitest.config.ts` 两处同口径）；类型面自写最小声明 `vendor/cordis.d.ts`（沿用 Spike 已验证的形状：`Context/provide/get/plugin/effect/on` + 插件 `{name,inject,apply}`）。

## 二、目录（正式模块）

```
apps/tauri/src/world/                # 第二棵树（世界语义）正式模块
├── index.ts        # 启树入口：startWorldTree()（幂等）/ 拆树；从 workspace 入口调用
├── tree.ts         # 建 Context + 本树服务 provide + 插件装配/拆除（fiber 句柄）
├── manifest.ts     # 插件清单规范 + 校验（id/name/version/entry/requires；非法即拒并留痕）
├── loader.ts       # 构建期静态清单：import.meta.glob('../world/plugins/*/index.ts') → 校验 → 依赖序装载（失败隔离）
├── registry.ts     # **按插件作用域注册面**：runInPluginScope(pluginId, fn)（临时切换 currentPluginId 并恢复）+ registerViewFor(pluginId, view)
├── plugins/        # 树自带插件（首个 = Spike 转正的「探针面板」示例插件）
├── dev/probe.ts    # `__WS_VIEWS_PROBE__` 三面探针（从 Spike 文件迁出，随 opt-in 开关装载）
└── vendor/         # cordis + cosmokit 产物 + LICENSE + README + cordis.d.ts
```
- `apps/tauri/workspace/spike/cordis-spike.ts` **退役**（内容迁入 `src/world/`；`workspace/main.ts` 改为调 `startWorldTree()`）。
- 树的插件清单为**构建期静态**（rolldown 静态分析 + 代码分割），零运行时 IO、零新权限面。

## 三、作用域注册面（修 `currentPluginId` 全局单值）

现状：`pluginAPI.registerView` 会把视图 `pluginId` 覆写为「最后一次 activate 的芽」→ 树的插件身份会错乱（Spike 靠显示侧注册绕过、探针手动归零，均为临时口径）。
本批：`PluginAPI` 增 `getPluginId()` 与 `withPluginScope(pluginId, fn)`（进入备份、退出恢复，**同步语义**）；树的 `world/registry.ts` 提供 `registerViewFor / unregisterViewFor / registerPluginCleanup / runPluginCleanups`，全部走该原语。
**施工中收窄**：原计划「给 `PluginManager.activate` 也走同一原语」**未做**——其 activate 是 async，跨 await 持全局态会把「恢复」推后（行为变更风险大于收益）；官方芽注册的既有语义保持原样，树侧靠作用域原语自洽（已由真机取证：树视图 `pluginId = ws.spike.panel`，与相邻官方芽注册互不干扰）。留作 F 类收口项。
**另补一处口径**（旧过滤器的隐藏缺陷）：侧栏/设置此前写 `!pluginId || isActive(pluginId)`——树的插件 id 不在官方芽清单 → `isActive` 恒 false → 树视图被**误隐藏**；现收敛为 `stores/viewVisibility.ts` 的 `isViewVisible`（无归属→显示；清单内→按启停；**清单外→显示**），单测含「清单内启停仍生效」的反向断言。

## 四、开发期热重载（最小）

`index.ts` 挂 `import.meta.hot?.accept`：模块更新 → 拆树（走 `dispose` 路径）→ 重新起树 + 装载；日志留 `[world-tree] reload`。不做「单插件热替换」（留给后续）。

## 五、验收门

1. **单测**（vitest，新增）：`manifest.spec`（形状/必填/非法 id 与未知 field 拒）· `loader.spec`（依赖序、缺失依赖拒、单插件装载失败隔离不影响他者）· `registry.spec`（作用域视图 pluginId 正确 + 退出恢复）。`viewSync/pluginViewLifecycle` 既有 spec 全绿。
2. **反证**（变异注入）：
   - 清单塞一条非法插件 → 装载器**拒绝且报红**（不静默跳过）；其余插件仍装载。
   - 缺依赖的插件 → 拒绝 + 留痕；依赖满足时才装载。
   - 作用域反证：不经 `runInPluginScope` 注册 → 视图 `pluginId` 为「最后 activate 的芽」（旧病复现）；经作用域注册 → 恒为插件自身 id。
3. **依赖口径反证**：全仓不再有 `dsh/vendor` 引用（`grep -rn "dsh/vendor" apps/` 为空）；工作台产物构建通过（别名命中，含 cordis 的 `@deepseek-ai/cosmokit` 内部依赖）。
4. **真机**：重载工作台 → `[world-tree]` 启动行 + 插件装载行；侧栏出现「Cordis Spike」条目（示例插件注册的视图）；`world.views.list` 含该视图且 `pluginId` 为树插件 id（与 A 批串上）；探针 `dispose()` → 视图消失、`lingering` 为空；热重载（改插件文件）→ 树重建日志 + 视图仍在（不重复堆积）。
5. **门禁**：`vue-tsc` 0 · vitest 全绿 · arch 0（vendor 只放 `.js`，不进扫描面；若新增目录需在 `architecture-policy.json` 的 modules 里登记 `world` 模块与其依赖边）· 断链 0。

## 六、边界与遗留

- **C（迁真芽）不在本批**：真芽迁移涉及 store 解耦与依赖注入切分，单独立批（用户已定「先 B」）。
- **不做**：清单的外部投放（运行时读 JSON）、插件级信任/权限模型（生态化再议）、`dsh` 侧接入载体（Node 侧载体仍是 D2 前置）。
- **`pluginAPI` 的 getter**：本批已加 `getPluginId()` 与 `withPluginScope()`（测试锁）。
- **`PluginManager.activate` 未改**（见 §三·施工中收窄）：官方芽的「全局 set」语义保持；若将来要收敛，需先让 activate 的注册段同步化。
