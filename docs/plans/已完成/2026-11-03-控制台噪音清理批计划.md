# 控制台噪音清理批计划（inspector 403 + Rust 死代码）

> 起因：主计划完成后用户走查发现两条控制台/构建产物噪音（2026-11-03）。
> 判定：**两条性质不同**——一条是本人上一批引入的代码缺陷，一条是壳换载体后的既有集成缺口。
> 基线：`cd5b22f`；本批不改任何产品行为。

## 一、问题与根因

### P1 · 页面控制台 `ws://127.0.0.1:<port>/ingest` 403

**症状**：每次页面重载刷一条 `WebSocket connection to 'ws://127.0.0.1:9231/ingest' failed: Error during WebSocket handshake: Unexpected response code: 403`。

**来源定位**：`/ingest` 属于 `dsh/packages/experimental/inspector`（Host 调试面板）的 Worker 端点；该插件的 profile bundle `@deepseek-ai/dsh-experimental-inspector-profile` **确实在运行时 profile 的 bundles 列表里**（已核实 `%APPDATA%/com.worldsea.desktop/dsh-home/profiles/web/package.json`）。

**根因**（`dsh/packages/experimental/inspector/src/worker/bridge/endpoint.ts:219-233` 的 `authorizedClient`）：ingest 握手只接受 loopback origin——

```
localhost / 127.0.0.1 / [::1] / ::1
```

而**壳页面的 origin 是 `http://worldsea.localhost`**（wry 自定义协议 workaround 形态，见 [dsh-bridge 注释〔自定义协议落形〕](../../details/注释/tauri/dsh-bridge.md)）→ 不在白名单 → 直接 403。

**为什么上游没这问题**：官方 Electron 桌面端的页面 origin 就是 `http://127.0.0.1:<port>`，天然命中 loopback 白名单。**这是「壳换掉载体后 origin 变了」的集成缺口，不是 inspector 的缺陷。**

**影响面**：仅实验性调试通道（把页面作为 Client source 接入 Host 调试器）。**不影响任何产品功能**；但每次重载刷一条错误，干扰排障。

### P2 · `cargo build` 两条警告

```
warning: unused import: `path_allowed`            (dsh_proxy.rs:49)
warning: function `path_allowed` is never used    (dsh_gate.rs:69)
```

**根因**：上一批（[壳插件前缀白名单运行时化](2026-11-03-壳插件前缀白名单运行时化批计划.md)）把闸门从 `path_allowed`（布尔）改为 `path_verdict`（三态：`Static`/`Runtime`/`Unknown`）后，`path_allowed` **只剩测试在用**，但生产代码仍在 `pub(crate) use` 里导出它 → 未使用导入 + 死代码双警告。**属上一批遗留的代码缺陷。**

## 二、处置

### P1 · overlay 补 `clientOrigins`（不动 dsh 树）

在 `apps/tauri/dsh-overlay.yml` 增第 4 条：

```yaml
- id: experimental-inspector
  config:
    captureFetch: true
    clientOrigins:
      - http://worldsea.localhost
```

**两处必须写对的细节**：

1. **`captureFetch: true` 必须一并写回**——patch 的 config 是**整体替换**而非深合并（`dsh/packages/boot/app-boot/src/config-schema/document.ts:159`：「A patch config replaces the whole config」），漏写会丢掉 inspector-profile 原有的抓取开关。
2. **origin 必须是 canonical 形态**——`controller.ts:175` 校验 `new URL(origin).origin === origin`；实测 `http://worldsea.localhost` 通过，而带尾斜杠的 `http://worldsea.localhost/` **会被拒**。

**机制验证**：`app-boot/tests/config-reload.spec.ts` 的「lets a later patch configure or disable a row an earlier patch inserted」用例通过 → overlay 能配置 bundle 插入的行。

### P2 · `#[cfg(test)]` 收窄

`dsh_gate.rs` 的 `path_allowed` 与 `dsh_proxy.rs` 的再导出均加 `#[cfg(test)]`：生产构建不编译该函数，测试仍可用。

**保留而非删除的理由**：测试里有 14 处断言用布尔形态读起来更直白；且它的注释已写明「生产路径必须区分 `Unknown`，不能用布尔判定替代」，避免后人误用。

重启壳后打开页面控制台：

1. **不再出现** `ws://127.0.0.1:<port>/ingest` 的 403 行（预期：握手成功，或至少不再是 403）；

## 五、风险与边界

| # | 项 | 说明 |
|---|---|---|
| R1 | 打开 ingest 通道 = 扩大调试面 | 仅接受 `http://worldsea.localhost` 这一精确 origin，不是通配；且 inspector 本身已有 `clientToken`（握手子协议）二次校验 |
| R2 | inspector 是实验性插件 | 上游可能重构其配置面；本改动是**用户层 overlay**，不碰 dsh 树，追版时不会冲突 |
| R3 | 若上游变更 origin 判定 | 届时 overlay 的 `clientOrigins` 可能失效——但那时上游多半已修复，重评即可 |
