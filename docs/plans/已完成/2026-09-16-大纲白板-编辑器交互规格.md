# 大纲白板 · 编辑器交互规格

> **定位**：白板**壳**的交互规格。分工——本文管「**怎么画、怎么放、怎么选、怎么存**」（画布、区、容器、选择、撤销、保存、快捷键）；[表现形式规格](2026-09-16-大纲白板-表现形式规格.md) 管「**组件长什么样**」（内容映射、编辑能力、导出）。
> **状态**：**规格已成文，待裁定项全部清零（09-16，见 §十一）**——七项裁定 + 入口合并（**右栏为节点入板唯一入口**，列首版实现）。**未改任何代码。**

## 〇、舞台与层级

### 0.1 两层结构（列表层 → 编辑器层）

| 层 | 形态 | 说明 |
| --- | --- | --- |
| 白板列表 | 卡片网格 + 新建按钮 | 照 `manuscript` 芽的**书籍卡片网格**先例（两层导航），复用既有交互语言 |
| 白板编辑器 | **全屏画布** + 悬浮工具条 + **右栏节点侧栏**（可折叠） | 视图注册 `toolbar: 'overlay'`，与 `graph` / `drawing` 芽一致；属性条悬浮、节点侧栏常驻右侧 |
| **右栏（节点侧栏）** | 大纲节点层级树 + 搜索框 + 节点入板入口 | **09-16 裁定新增**（负责人：拖拽源「从左栏改为右栏」）：右栏是**唯一**的「把已有节点放进画布」的入口；可折叠；左栏不设节点列表 |

**编辑器布局**（**09-16 施工分解修正**）：**视图工具条（`toolbar: 'bar'`，44px）** + 画布区（`flex:1`）+ **右栏**（240px、可折叠）。
修正原因：项目 27 个官方芽**均为单视图**（每芽 `api.registerView` 调用 1 次），故白板采用「**一个视图内两层导航**」（照 `manuscript` 先例）。视图工具条为 `bar`——列表层放新建/排序，编辑器层放返回列表 · 白板名 · 保存状态三态 · 折叠右栏；画布内的工具（画区 / 吸附开关 / 缩放 / 适配全部）是**画布级悬浮条**（画布区内的绝对定位元素，**不依赖视图 toolbar 机制**）。属性条仍为悬浮；**右栏专职节点侧栏**，不兼属性面板。

**右栏为什么放右侧**：拖拽源与画布同处编辑器内 → 属**同视图 DnD**，比跨视图拖拽（从芽外左栏拖入）成本低得多；左栏留空，画布可最大化使用。

**右栏内容与状态**：层级树（按 `parentId` 折叠）· 搜索过滤 · **「已在板上」标记**（该节点已有容器时置灰 + 提示；容器删除后标记自动恢复）。

**右栏的三种入口行为**（09-16 合并冗余入口后）：

| 操作 | 行为 |
| --- | --- |
| **拖**节点项到画布 | 在**落点**创建容器；落在区内 → 归属该区；落在已有容器上 → 不堆叠（忽略或落到附近） |
| **单击或双击**节点项 | 落到**视口中心**（快捷路径，不牺牲键盘可用性）。**2026-10-24（13-A）对齐**：原规格只写双击，实际实现单击与双击同效；用户拍板保留单击（现有快路径），规格据此更新 |
| 操作**已在板上**的节点 | 拖拽、单击或双击**均转为「定位并选中其已有容器」**（不创建第二个容器——与「同板内一节点仅一容器」规则闭合） |
| **拖**节点项到**另一节点项**上 | **层级重排**（09-16 入口整合新增）：目标行上 1/4 插到其**前**、下 1/4 插到其**后**、中间**成为其子节点**；写回 `parentId` + `order` 并归一化同胞，同步 `parent_child` 关系；与「拖到画布 = 入板」按 drop 落点分流，互不误吞 |

> **层级重排为什么在右栏**：原独立大纲树视图已下线（入口整合，见施工分解 §八），「拖拽调整层级与顺序」的能力必须留有去处，故落在右栏树上。该操作**可被 `Ctrl+Z` 撤销**——白板撤销栈已从「纯布局」升级为「布局 + 层级」通用快照（见 §六）。

**白板卡片**显示：白板名 · 容器数 · 缩略图 · 更新时间。悬停显示操作：重命名 / 删除 / 复制（复制挂账）。
**排序**：按更新时间倒序（手动排序挂账）。
**空态**：无白板 → 「新建第一块白板」。

### 0.2 渲染技术选型：**DOM 绝对定位 + transform 缩放**（技术侧拍板）

| 方案 | 优 | 劣 |
| --- | --- | --- |
| Canvas（如 `canvas-engine/tree` 的 `useTreeCanvas`） | 大量图元性能好（图谱 500 节点阈值，`useGraphData.ts:39`） | **无法承载就地编辑控件**；表格式组件无法复用 `DataTable.vue`；文字排版/无障碍需自绘 |
| **DOM 绝对定位（选定）** | 组件是真实 DOM → 双击就地编辑、复用 `ws-*` 设计令牌、**表格式直接复用 `DataTable.vue`**（09-16 规格 §3.2 强制要求）、键盘与无障碍天然 | 容器数极大时性能下降 |

**依据**：① 表格式组件必须复用 `DataTable.vue`（DOM 组件）；② 标题式/句子式都是**就地型**，需要真实输入控件；③ 白板容器规模是「几十—几百」，远低于图谱的 500 阈值；④ 项目已有 DOM 搭建先例，`module-builder` 的 `SlotView.vue` 即 DOM（反复嵌套的 div + class），而 `tactical-board` 走 Canvas 是因为棋盘需要像素级绘制。
**兜底**：若未来单板容器数破千，再考虑「DOM + Canvas 分层混合」，不在初期设计。

### 0.3 舞台层级

```
背景（点阵网格，可关）
 └ 区 section（可选，虚线框 + 标题）
    └ 容器 container（实心卡：容器头 + 组件区）
       └ 组件 component（表现形式实例）
```

## 一、视口操作

| 操作 | 行为 | 备注 |
| --- | --- | --- |
| 滚轮 | **缩放**（以指针为中心） | 与项目既有画布一致：`canvas-engine/core/useCanvas.ts:69-80` 即滚轮缩放。若你更习惯「滚轮平移 + Ctrl 缩放」（Figma 式），此项可推翻 |
| `Space` + 拖拽 | 平移 | 光标切换为 `grab` / `grabbing` |
| 中键拖拽 | 平移 | 同上 |
| `Ctrl+0` | 重置为 100% | |
| `Shift+1` | **适配全部**（zoom to fit，含全部容器与区） | |
| `Ctrl+=` / `Ctrl+-` | 以视口中心缩放 | |

**缩放范围**：0.2 – 2.5（比 `useCanvas` 的 0.1–5 收紧——白板内容以文字为主，过大过小都无意义）。
**视口持久化**：`viewport{zoom,panX,panY}` 存白板实体（§8.10.2），下次打开恢复原位。

**网格与吸附**（「半自由」落地的关键）：
- 背景点阵网格，默认开（白板级开关）。
- 拖动容器/区时显示与其他容器的**对齐辅助线**（左/中/右、上/中/下），吸附阈值 **6px**。
- 白板级配置 `snap`：`guides`（默认，只吸辅助线）｜`grid`（吸网格）｜`off`。

## 二、区（Section）

| 项 | 规格 |
| --- | --- |
| 创建 | 工具条「画区」→ 画布上拖出矩形；或选中空白处按 `S` 创建默认尺寸区 |
| 命名 | 双击区标题就地改名（同「就地形」约定） |
| 属性 | 名称 · 排列（`free`/`vertical`/`horizontal`/`grid`，默认 `free`）· 尺寸 · 视觉弱色（不抢容器） |
| 移动 | 拖动区体 → **区内容器整体移动**（关键语义） |
| 调整尺寸 | `free`：容器保持相对位置不变；`vertical`/`horizontal`：**显式提示会重排**后按 gap 排列（可撤销） |
| 删除 | 弹层二选一：「仅删区，容器落回画布」 / 「连同区内容器一起删」 |
| 嵌套 | **首版不支持**（避免层级爆炸；挂账） |

## 三、容器（Container）

| 项 | 规格 |
| --- | --- |
| 创建 | ① **右栏拖节点到画布**（落点即容器位置） ② 空白处**双击** = 新建节点 + 容器（一步到位） ③ **右栏双击节点项** = 落到视口中心 ④ 工具条节点选择器弹层 **已取消**（09-16 合并冗余入口：右栏已承担该职责，省一套弹层与搜索实现）。**「跨视图 DnD（从芽外左栏拖入）」已失效并待重定义**（见 §0.1 与变更记录十次）。**拖放落地四条要求（09-17 加固）**：⓪ **平台前提**：窗口必须 `dragDropEnabled: false`——Tauri v2 默认 true，宿主会在 Windows 上装原生 OLE 拖放处理器，**在 webview 看到之前吃掉拖放事件**（症状：起手光标即 🚫、`dragstart` 触发但 `dragover`/`drop`/`dragleave` 全不触发；官方文档原文 *"Disabling it is required to use HTML5 drag and drop on the frontend on Windows."*）。**此项影响全 app 的 HTML5 拖拽**（不止本芽：module-builder 工具箱、notebook 的 vuedraggable、ChatInput 文件拖入同理）；关掉后需 `composables/dragDropGuard.ts` 兜住「文件拖到非落点区 → webview 导航」。① 目标侧 `dragover` **必须 `preventDefault()`**（不调用则永不触发 `drop`）② 目标侧必须设 `dropEffect`（与源侧 `effectAllowed='copy'` 对齐；不设时 Windows 显示「禁止」光标）③ 用 `dataTransfer.types` 判定载荷（dragover 阶段读不到数据），只对**本芽 MIME** 点亮落点反馈（虚线内边框 + `cursor: copy`）；非本类型不点亮但仍 `preventDefault` |
| 容器头 | 节点类型图标（`WsIcon`，禁 emoji）+ 状态色点 + 操作条（加组件 / 折叠 / 删除） |
| 移动 | 拖拽（配辅助线吸附）；拖入区 = 归属该区；拖出区 = 脱离 |
| 尺寸 | 右下角手柄调整宽高；未调整 = **内容自适应** |
| 折叠 | 容器头「折叠」→ 只显示第一个组件（通常是标题式），用于大板降噪 |
| 删除 | `Delete` 或操作条「✕」→ **只删容器，不删节点**（必须有提示文案，避免误以为删了节点） |
| 复制 | 首版不做（挂账） |
| 跳转正文 | 若节点 `properties.manuscriptId` 有值 → 容器头提供「打开正文」动作（复用 `ws-navigate`，`OutlineView.vue:299-303` 同链） |

## 四、组件的添加与删除

| 项 | 规格 |
| --- | --- |
| 添加 | 容器操作条「加组件」→ 弹出形式选择菜单：按 `FormDefinition` 注册表渲染（`label` + `icon` + 一句说明 + `kind` 标记派生型/就地型） |
| 排列 | 容器内按 `order` **垂直堆叠**；容器内拖拽调整顺序（组件级 DnD） |
| 删除 | 组件悬停显示「移除」 |
| 重复约束 | **待裁定**：同一容器内同种形式是否允许重复（与表现形式规格 §1.4-4 / §2.4-5 是同一条规则） |
| 空容器 | 显示引导「添加表现形式」（点击即打开形式菜单） |
| 新增形式的扩展点 | 注册表即扩展点——新增一种形式 = 注册一个 `FormDefinition`，**不改编辑器代码** |

## 五、选择与操作条

| 项 | 规格 |
| --- | --- |

## 六、撤销 / 重做

| 项 | 规格 |
| --- | --- |
| 快捷键 | `Ctrl+Z` 撤销 / `Ctrl+Shift+Z`（或 `Ctrl+Y`）重做 |
| 栈内容 | 布局操作（移动 / 缩放 / 增删容器与区 / 改配置）**＋ 内容写入**（就地编辑），**统一单步** |
| 栈深度 | 50 步（对齐 `canvas-engine/core/useCanvas.ts:54` 的 `maxHistory` 惯例） |
| 与实体 store 撤销的关系 | **白板栈独立**，不改动实体侧撤销历史。做法：内容写入带 `skipUndo`（笔记本芽 8b180ce 先例，见表现形式规格 §0.3）——即**撤销以白板编辑器为准**，避免按 `Ctrl+Z` 撤销到别的芽的操作 |

## 七、保存与状态提示

| 项 | 规格 |
| --- | --- |
| 布局变更 | 防抖（≥500ms，对齐 `drawing` 的 `AUTOSAVE_DELAY`）→ 写白板实体 `properties.layout` |
| 内容写入 | 400ms 防抖 + `skipUndo`（形式规格 §0.3） |
| 状态提示 | 顶部三态「保存中… / 已保存 / 保存失败」（复用 `mindmap` 的 `saveState` 三态形态：`mindmapStore.ts:23`） |
| 退出编辑器 | **立即落盘**（不等防抖）+ 生成缩略图 |
| 缩略图 | 生成时机与落盘方式**待定**（`drawing` 芽有 `thumbnail` 字段先例：`drawing/index.ts:44`，施工时对齐其实现） |
| 保存失败 | 提示 + 保留内存草稿并允许重试（不静默丢数据） |

## 十、与既有芽/链路的关系

| 对象 | 关系 |
| --- | --- |
| 树视图 | **并存**（§8.10.5-F）：树 = 结构保真视图，白板 = 表现自由视图 |
| 章节（manuscript） | 容器可跳正文（`manuscriptId`）；**白板不改 `order`、不生成章节** |
| 实体属性面板 | 容器属性（尺寸/折叠）与节点属性（`status` / `storylines` / `wordCount` / `manuscriptId`）**分属两处**：容器属性走属性面板的「容器尺寸」区；**节点属性 09-17 起也走属性面板**（「节点属性」区）——原「节点属性走实体侧表单」已失效，因为承载该表单的旧树视图已随体检删除（详见施工分解 §十五与 §14.1）。字段写入做 `properties` **合并**并登记白板撤销栈一步 |
| Agent | `outline` 8 动作不变；白板级 Agent 动作（如「把某支摆成一块板」）挂账 |
| 导出 | 表现形式决定导出形态（§8.10.5-G）；**白板布局本身不导出**（只影响呈现），导出按节点的语义顺序进行。**已实现（09-17 批次 5）**：入口＝编辑器工具条导出按钮；范围为**全部节点**（未入板按默认标题式） |

## 十三、右键菜单（09-17 新增，四级上下文）

### 13.0 为什么需要（以及为什么白板特别需要）

**现状取证**：`App.vue` 全局 `preventDefault` 掉原生右键菜单，而既有的 `GlobalEditMenu` **只在输入元素上弹**（撤销/剪切/粘贴那套）。故在此之前，白板画布右键是**死区**——不是「少了个菜单」，而是右键这个输入通道在白板里完全没用起来。

三条**白板特有**的理由（不是「别的芽有所以也要有」）：

1. **白板是唯一会缩放的视图** —— 缩到 40% 时容器头上那些 16px 小按钮已经点不准，而右键菜单的命中区域是整块容器。
2. **属性面板可关闭**（`inspectorClosed`）—— 关掉后容器尺寸 / 恢复自适应 / 组件排序就**全无入口**。
3. **多个关键交互是隐藏的**（双击空白新建、双击区标题改名、双击节点项入板）—— 右键菜单是它们的**可发现性出口**。

### 13.1 设计原则（三条）

| # | 原则 | 含义 |
| --- | --- | --- |
| 1 | **不做工具条的副本** | 能一键点到的不进菜单；菜单只放「上下文就近」与「没有常驻入口」的动作 |
| 2 | **严格按落点分流** | 一级上下文一套菜单，不做「万能大菜单」 |
| 3 | **危险动作永远最后 + 标记 `danger`** | 由组件标红，与 `PanelContextMenu` 的既有先例一致 |

### 13.2 落点约定（实现层）

可右键的元素标注 `data-ctx`（层级）+ `data-ctx-id`（标识），解析时用 `closest` 取**最内层**：

| 落点 | 标注 | 备注 |
| --- | --- | --- |
| 组件行 | `data-ctx="component"` + `data-ctx-id=<componentId>` | 容器 id 从**祖先**读（不重复标注） |
| 容器 | `data-ctx="container"` + `data-ctx-id=<containerId>` | |
| 区 | `data-ctx="section"` + `data-ctx-id=<sectionId>` | |
| 画布空白 | **无需标注** | 无标注一律视为画布空白 |

> 区与容器在 DOM 上是**兄弟**（§十二-#11），故容器不会误命中区；组件行在容器内，`closest` 天然最内层优先。

### 13.3 四级菜单内容

| 落点 | 菜单项（`sep` 表示其前有分隔线） |
| --- | --- |
| **画布空白**（视图级） | 新建节点并放置 · `sep` 适配全部 `Shift+1` · 缩放至 100% · `sep` 显示网格（✓） · 吸附：关闭 / 网格 / 辅助线（radio ✓） |
| **区**（区域整理） | 重命名区 · 重排区内容器 · 适配到该区 · `sep` 删除区（danger） |
| **容器**（节点与容器，**条目最多**） | 打开正文 · 在右栏中定位 · 添加表现形式 · `sep` 折叠/展开 · 恢复内容自适应 · `sep` 移除容器（danger） |
| **组件行**（单个形式） | 在属性面板中配置 · `sep` 上移 · 下移 · `sep` 移除该形式（danger） |

五条**状态相关**的行为（不是隐藏，而是禁用/改标签——保持菜单结构稳定、位置可预期）：

- 无关联章节 → 「打开正文」**禁用**；
- 已是内容自适应 → 「恢复内容自适应」**禁用**；
- 折叠态 → 该项标签变「展开」（同一动作，标签随状态）；
- 首个组件不能「上移」、末个不能「下移」；
- **悬空容器（节点已删）→ 菜单只剩「清理此容器」一项**——其余项对没有节点的容器毫无意义，这才是上下文菜单该有的正确性。

### 13.4 明确**不放进**菜单

| 不放入 | 理由 |
| --- | --- |
| 白板级动作（重命名白板 / 导出 / 删除白板） | 那属**列表层与视图工具条**；画布右键只管画布里的东西 |
| 清理悬空容器（全局） | 低频且悬浮条已有；只有**右键悬空容器本身**时才提供「清理此容器」 |
| 框选 / 多选 | §十一-4 已裁定首版不做，菜单不引入新交互模型 |
| 复制容器 / 粘贴 | 09-17 拍板**本轮不做**（唯一的新能力留给下一轮，避免同时引入剪贴板语义） |
| ~~段落式~~ | **已取消（09-18）**：随 Q1 裁定（大纲＝纯结构层）+ `content` 字段删除；需要长文走 manuscript（见 [表现形式规格](2026-09-16-大纲白板-表现形式规格.md) §七） |

### 13.5 与既有入口的关系（避免「两套实现」）

菜单项**全部复用**已实现的动作，不新增数据路径：`fitAll` / `onSetSnap` / `onToggleGrid` / `onCreateNodeAt` / `onRearrangeSection` / `askRemoveSection` / `onOpenManuscript` / `onToggleCollapse` / `layoutApi.resizeContainer(id, undefined)` / `onRemoveContainer` / `onRemoveComponentInContainer` / `layoutApi.reorderContainerComponents` 均是既有函数。

三处需要**触发子组件内部交互态**的，用「递增 token 信号」传递（`{ id, token }`，保证重复触发同一目标也生效）：

| 菜单项 | 子组件 | 机制 |
| --- | --- | --- |
| 重命名区 | `BoardSectionView` | `renameSignal` → 进入就地改名（与双击**同一路径**） |
| 添加表现形式 | `BoardContainerView` | `openFormSignal` → 展开既有形式选择菜单 |
| 在右栏中定位 | `NodeSidebar` | `revealSignal` → 展开祖先链 + 清空搜索 + `scrollIntoView` + 1.2s 高亮 |

**「上移 / 下移」的定位**：它是既有**组件 DnD 排序**的键盘可达替代（无障碍），不是新的排序模型。

### 13.6 交互细节

- **键盘可达**：`↑↓` 在**未禁用**项间移动（跨过禁用项、循环回绕、无高亮时首次按键跳到边界）、`Enter`/`Space` 执行、`Esc` 关闭。判定抽成纯函数 `nextEnabledIndex`。
- **定位钳位**：右下越界时向左上翻，保证菜单完整可见（复用纯函数 `clampMenuPosition`，不再各处手写）。
- **选中联动**：右键容器/组件行**先选中该容器并展开属性面板** —— 使「右键 → 在属性面板中配置」这条链路无需额外约定。
- **层级**：菜单 Teleport 到 body，`z-index` 用 `var(--z-dropdown)`（**不再硬编码**，此前的无令牌档是不重复的既有欠账）。
- **可测性**：菜单内容是数据 → `buildMenuItems(target, state)` 纯函数；落点解析、定位钳位、键盘导航同样纯函数化，共 31 条单测覆盖。

## 十四、章节关联与右栏「章节」tab（09-18 新增）

### 14.0 背景：一条**双向断裂**的关系（取证结论）

「大纲节点 ↔ 章节（manuscript）」这条关系此前**存储双轨且无人同步**：

| 方向 | 字段 | 谁在写 | 谁在读 |
| --- | --- | --- | --- |
| 章节 → 节点 | `manuscript.properties.outlineNodeId` | 章节右键「关联大纲节点」 | `ManuscriptView` 的按节点筛选 |
| 节点 → 章节 | `outline_node.properties.manuscriptId` | 白板属性面板**手填 ID** | 白板容器「打开正文」按钮 |

**全仓没有任何代码同步这两个字段**，后果是双向不可见：

- 章节侧关联了节点 → 白板的「打开正文」**不亮**；
- 大纲侧填了章节 ID → 章节侧的筛选**看不到**。

> 附注：09-17 新增的「节点属性」区把「手填 `manuscriptId`」作为常驻入口，等于把这个缺陷**常规化**了。本轮一并收口。

### 14.1 收敛策略（负责人 09-18 拍板）

**保留两个字段，但把「关联 / 解除」收敛到唯一写入入口** `@/entity/chapterLink`：

| 函数 | 职责 |
| --- | --- |
| `linkChapterToNode(store, chapterId, nodeId)` | 双侧同写 + 按 **1:1 语义清理两侧旧关联**；幂等 |
| `unlinkChapter(store, chapterId)` | 从章节侧解除（两侧字段都清；**实体都不删**） |
| `unlinkNode(store, nodeId)` | 从节点侧解除（同上） |
| `buildChapterLinkIndex(entities)` | 只读汇总双侧映射（「已关联」标记与反查用） |

- **1:1 语义**：一个章节只属于一个节点，反之亦然。建立新关联时必须清两侧旧值，否则会出现「章节 A 指向节点 N，而 N 指向章节 B」。
- **不删实体**：解除关联是纯关系操作（与「删书不删章」同一纪律）。
- **冗余仍在但一致性由代码保证**：不再靠「每个写入点记得同步」的纪律维持。
- 语义上更正确的做法是走 relations 关系表，但需要先补 `outline_node ↔ manuscript` 关系类型——该前置**未拍板**（与「关联实体徽章 / `link_entity`」同一项）。故本模块是**过渡实现**，将来换掉其实现即可，调用方不必改。

### 14.2 入口：右栏「章节」tab

右栏由单一「节点」列表改为**两个 tab**（节点 / 章节），交互语言与节点 tab 一致：

| 操作 | 行为 |
| --- | --- |
| 拖章节到**画布空白** | 新建节点（名字与描述取自章节）+ 建容器 + 建立关联 |
| 拖章节到**已有容器**上 | **只建立关联**（不新建节点）——容器是「关联到哪」的天然表达 |
| 拖章节到**右栏节点项**上 | 把该章节关联到该节点（比「先入板再拖到容器上」更直接，节点未入板时也能用） |
| 双击 / 单击章节 | 落到视口中心（复用节点入板的同一居中算法） |
| 搜索 | 命中章节名 / 描述 / 状态；切 tab 时清空搜索（两个来源的过滤词互不继承） |

**「已关联」标记**：章节行显示其关联到的节点名（**双侧汇总**——历史数据可能只有一侧有值，只看一侧会把已关联的显示成未关联）。

**为什么不做「从正文芽往白板拖」**（原 ③ 的字面形态）：

1. workbench 的 `Shell.vue` 只有**一个** `ViewContainer`，**没有第二视图位** → 源与目标无法同时出现在屏幕上；只有 Agent 空间右栏的 `CreationPanel` 能独立渲染另一个芽的视图。
2. 章节列表用 `vuedraggable`（Sortable 内部即 HTML5 DnD），让它同时充当**外部**拖拽源需在 `dragstart` 追加 MIME 且不与 Sortable 抢手势，有真机踩坑风险。

故选择**同视图**的右栏 tab（任何壳里都能用），痛点的解法不依赖「两个视图恰好并排」。

### 14.3 读章节的正确姿势（框架级约束）

右栏章节列表必须用 **`es.getAllEntities()`**（只读、直接委托 storage）过滤 `type === 'manuscript'`。

**不能用 `es.loadByType('manuscript')`**：它内部 `setAll(getEntitiesByType(type))` 会把 store 的 `entities` **收窄**成该类型、**挤掉其它芽的实体**（大纲节点会一起消失）。这是框架级陷阱（施工分解 §十三 A-7），本章节 tab 正是踩点。

### 14.4 操作路径变更（需知悉）

1. **属性面板「关联章节」不再是输入框** —— 改为**只读展示章节名 + 「解除」按钮**。手填 ID 正是双轨缺陷的入口（且用户看不到 ID 是什么），故移除。
2. **新增右栏「章节」tab** —— 右栏从单一列表变为两个来源。
3. **章节右键「关联大纲节点」的行为变了** —— 现在同时写双侧（此前只写章节侧）。

### 14.5 已知限制

- **关联操作不进白板撤销栈**（有意）：撤销条目是**单实体字段**语义（`field` 类型），而关联是一次「多实体原子操作」（章节 + 节点 + 可能清理两侧旧关联）。关联幂等且可逆（再关联 / 解除即可），故本轮不扩撤销条目类型。
- **`ManuscriptView` 按节点筛选仍读章节侧字段**（`outlineNodeId`）—— 因为唯一写入入口保证双侧一致，故该读取路径无需改；若将来改为单轨，这里要一起动。
