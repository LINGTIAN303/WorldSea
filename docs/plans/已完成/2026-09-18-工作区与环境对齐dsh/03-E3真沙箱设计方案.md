## 零、先读：一句总判断

**机制上采纳 dsh 的 Windows 落地路线，语义上不照搬其模式词汇。**

- 机制：`WRITE_RESTRICTED` 受限令牌（`CreateRestrictedToken`）+ 工作区 / 私有临时目录 ACL 授予——命令的**文件写效应**被系统级约束为「read-only（无写）」或「workspace-write（写 = 工作区 + 私有 temp）」；**读与网络不受限**（写-交叉检查只作用于写类访问）。
- 语义：模式由本侧三档**派生**（plan → read-only；interact / autopilot → workspace-write），**不新增用户可见档位、不改审批链、不改规则引擎**（锁 > 白名单 > 档位）——白名单只影响审批，**不放宽 ACL 边界**。

与 02 §四 排除项「沙箱三模式语义照搬」的关系：排除的是**用户可见语义**（把三模式当档位体系暴露）；`read-only / workspace-write` 在本设计里是**执行引擎内部的文件效应策略词汇**，不暴露给用户——两者不冲突（§4.1）。

## 一、目标与边界

### 1.1 现状缺口（为什么要有 E3）

| 层 | 现状 | 状态 |
|---|---|---|
| 进程树 | Job object 整树回收（P1，`crates/agent-commands/src/job.rs`） | 已闭环 |
| 环境 | E1 清洗同源（kernel `env_scrub`，工具 / PTY / MCP 三族） | 已闭环 |
| 审批 | 三档 + 规则引擎 + 四值审批（2026-09-17） | 已闭环，但属**发起前**的软边界 |
| cwd | 词法越界拒绝（`resolve_command_cwd`，`crates/agent-commands/src/terminal.rs:311-329`） | 只约束启动 cwd，不约束命令内部行为 |
| **文件效应** | **无强制** | **E3 缺口**：命令一旦放行，可读写任意路径——`powershell -Command "Remove-Item ..."`、脚本写系统目录等不在任何硬边界内，现靠 L2/L3 词法扫描 + 审批兜底（皆可绕过/可批，属软约束） |

### 1.2 本设计的目标（承诺清单）

1. **写边界**：Agent 命令对工作区外路径的写（创建 / 修改 / 删除）被**操作系统拒绝**，不再依赖字符串判定。
2. **失败关闭**：沙箱不可用 → Agent 命令**拒绝执行**（绝不静默裸跑）。
3. **档位派生**：plan → read-only；interact / autopilot → workspace-write（无新增用户概念）。
4. **私有临时目录**：每「会话 × 工作区」随机私有 temp（TMP/TEMP 重写），ACE 可撤销、会话间互不可写。
5. **零语义冲突**：Job 回收保留；锁 / 白名单 / 审批四值 / 三档语义全不变。

### 1.3 明确不做（防范围蔓延）

| 项 | 理由 |
|---|---|
| 读边界的系统级强制（命令的读拒止） | 需逐路径读授予（身份路线代价）或逐路径 deny-only SID；dsh 亦不做；读锁维持现状（词法 + 审批） |
| 网络限制 | npm / pip / git 正常需要联网；dsh 明确「网络与进程可见性不在沙箱词汇内」。列为拍板点 D4 |
| 沙箱三模式作为用户可见语义 | 02 §四 已排除；本设计仅内部词汇 |
| 面板路径（用户驱动终端）强制 | 与 W3 先例一致：Agent 路径收紧、面板路径放行（`Tool::execute` 无 ctx 入口，`terminal.rs:443-447`） |
| Unix Landlock 同期 | 本期只补 Unix pgroup 欠账；Landlock 挂后续（拍板点 D7） |
| MCP / LSP / office 等宿主侧进程 | 非 Agent 命令链，另议 |

## 三、Windows 方案对比

### 3.1 候选机制

| # | 机制 | 边界语义 | OS 门槛 | 实现成本 | 结论 |
|---|---|---|---|---|---|
| A | **WRITE_RESTRICTED 受限令牌 + ACL 授予**（dsh 路线） | 仅限**写**（两次访问检查交叉）；读 / 网络 / 进程可见性不碰；工作区与私有 temp 两个能力 SID | `CreateRestrictedToken` 为远古 API（`WRITE_RESTRICTED` Vista+），Win10/11 无碍 | 中：令牌派生 + DACL 授予/撤销 + 受限 spawn 三件套 | **推荐** |
| B | 低完整性级别（Low IL）+ 工作区 Low 写强制标签（Chrome 手法） | 完整性标签是**对象级持久**语义（含跨级别读写策略），粒度粗；需维护强制标签 SACL；对既有工具链副作用面更大 | Vista+ | 中 | 备选；不选（§3.3） |
| C | AppContainer | 读 / 写 / 网络全为显式授予——任意路径读需全盘 ACE 铺开 | Win 8+ | 高（能力 SID + 逐路径授予 + 兼容面大） | 排除（与「命令任意读」模型冲突） |
| D | mxc / 进程容器 | 依赖新 OS 层（T1 需 25H2+ 且特性开启；T3 回落即 AppContainer 同款） | 24H2+ / 25H2+ | 高 | 排除（OS 底线 + 同 C 的读授予代价） |
| E | 仅 Job object（现状 P1） | 无文件效应边界 | — | 0 | 基线；E3 要补的正是 A |

### 3.2 dsh 侧事实（取证，可直接复用的落地细节）

- **机制**：`CreateRestrictedToken`，flags = `WRITE_RESTRICTED | DISABLE_MAX_PRIVILEGE | LUA_TOKEN`；Windows 做**两次访问检查**（正常 SID + 限制 SID），写类访问需两者皆过 → 读保留调用者既有可读面、写必须在能力 ACE 上命中（决策记录「How the restriction works」节）。
- **令牌清单**：read-only = [logon SID, Everyone]；workspace-write = 前者 + 工作区 SID + 私有 temp SID。**logon SID + Everyone 是保活不变量**——缺则早期 DLL 初始化失败（`0xC0000142`）、CNG 崩溃 pwsh（`0xE0434352`）。
- **SID 派生**：工作区 SID = sha256(规范化工作区路径) → `S-1-4-x-y` 确定性派生（跨会话复用缓存，**常驻 ACE**，exact-ACE skip 免重复传播）；私有 temp SID 由随机 temp 路径派生、**可撤销**（每「活会话 × 工作区」唯一，会话间不共享）。
- **令牌默认 DACL**：`SetTokenInformation(TokenDefaultDacl)` 挂 temp SID → 子进程新建对象不带共享工作区能力（防兄弟 temp 互写）。
- **边界如实上报 `partial`**：Everyone 保活导致「授予 Everyone 写的外部对象」仍可写；NTFS 硬链接是**同一文件对象的别名**（工作区内硬链接指向外部同一文件时该别名可写）——两者不可用本机制闭合。
- **明确不做**：读 / 网络 / 进程可见性；`Authenticated Users` 缺席导致 CIM/WMI 不可用（顺带关闭 C:\ 根建树逃逸）；`INTERACTIVE/LOCAL` 缺席导致 Public 树写被拒。
- **失败关闭**：任一 Win32 调用失败 → 抛错不 spawn；runner 自身失败 → stderr 签名 + exit 127（与「命令被拒」区分开）。
- **已知代价**：工作区 ACE **首次授予是急切全树传播**（`SetNamedSecurityInfoW` 立即遍历全部后代，大工作区可达几十秒）——每工作区每机器一次。
- **权限前提**：受限令牌是**调用方自身令牌的受限版本**时，`CreateProcessAsUserW` 不需要 SeAssignPrimaryToken/SeIncreaseQuota 特权——普通用户态应用（本侧形态）可用，无需提权。

### 3.3 为什么不选 Low IL / AppContainer（一句话版）

两者都是**身份路线**：以「新身份零权限」为起点，读也要逐路径开回——与「命令仍需任意读」的模型冲突（dsh 决策记录同款论证）。受限令牌的写-交叉检查**只需写侧授权**，读零成本。Low IL 另叠加对象级完整性标签语义，对既有工具链（安装器、包管理器）副作用面更大，而收益（同为只写边界）不增。

## 四、设计

### 4.1 模式词汇与档位派生

内部词汇（引擎侧，不暴露）：

```
SandboxMode = ReadOnly | WorkspaceWrite     // 文件写效应策略；非 dsh 用户语义
约束范围：只限【文件写效应】；读 / 网络 / 进程可见性不在词表内
```

派生（硬映射，无新增用户开关）：

| 档位 | 沙箱模式 | 语义 |
|---|---|---|
| plan | ReadOnly | 只读研究：命令即便获批执行也无写权限（双保险） |
| interact（默认） | WorkspaceWrite | 写 = 工作区 + 私有 temp；工作区外写被 OS 拒 |
| autopilot | WorkspaceWrite | 同上（autopilot 的「免确认」因此有硬边界兜底） |
| 面板 / 无档位上下文 | 不启用（None） | 用户驱动路径，维持现状（同 W3 先例） |

### 4.2 决议点与数据流

```
AgentLoop.tool_ctx()（agent/tools.rs:435）            ← 逐调用构造，知晓会话档位
  └─ 决议纯函数 sandbox_policy(level, workdir) → SandboxSpec { mode, root }
      └─ ToolContext.sandbox: Option<SandboxSpec>     ← 新增字段（Default 兼容）
          └─ terminal.rs 三个 spawn 站点读戳记
              ├─ Some(spec) → 受限 spawn（fail-closed）
              └─ None      → 现状路径（面板）
```

- 决议落 kernel（纯函数 + 单测矩阵）；执行落 agent-commands（受限 spawn 原语）——**决议与执行分离**，为 Unix 后端（§4.8）与 E2 预设（§4.7）留位。
- 施工期先查清项：`ConfirmationPolicy` 在 `tool_ctx()` 调用栈的可达方式（若需把档位镜像进 `AgentLoop` 字段，与 W2① `project_id` 镜像同法）。

### 4.3 与规则引擎 / 审批链的关系（层级不变，新增执行层硬边界）

```
层级（自上而下）：
  锁（上锁名单）        —— 硬约束，语义不变（命中即拦，read/command/write 三维）
  白名单（Allow）       —— 只影响【审批】：命中免问；【不放宽沙箱边界】
  档位默认策略          —— 决定沙箱模式（§4.1）
  审批链（四值 HITL）   —— 不变：在【发起前】裁决要不要跑
  ────────────── 执行层 ──────────────
  沙箱（E3 新增）       —— 在【执行中】约束「跑起来后能写哪里」（最后一道硬边界）
```

原则声明（防误读，呼应 02 §八 的语义修正教训）：

- 沙箱是**后置硬边界**，不替代审批；被沙箱拒绝的命令**不自动重试**（提权路径见拍板点 D8）。
- 白名单 + 沙箱组合语义 = 「免问执行 + 写受限」；用户若因沙箱拒绝想放行**工作区外**的写，那属于**改边界**（未来提权设计），不是白名单语义。
- 锁的 `write/command` 维度维持「发起前拦截」；锁的 `read` 维度**不被沙箱增强**（读不设界，§1.3）。

### 4.4 与 Job object 的耦合

- 受限子进程照常挂 `KILL_ON_JOB_CLOSE` Job（P1 语义不变：正常 / 超时 / 取消均整树回收）。
- 施工期顺带收口竞态：**挂起创建（CREATE_SUSPENDED）→ assign Job → resume**——替代现状「spawn 后 assign」（`terminal.rs:124-133`）。
- 两者正交：令牌管访问检查，Job 管生命周期，无冲突。

### 4.5 ACL 授予生命周期（服务端）

| 对象 | SID 派生 | ACE 性质 | 生命周期 |
|---|---|---|---|
| 工作区根 | `sha256(规范化 root)` → `S-1-4-x-y`（确定性） | 可继承写 ACE，**常驻**（即跨会话复用缓存） | 首次授予一次（急切全树传播）；幂等 exact-ACE skip；提供程序内撤销入口（§六 R6） |
| 私有 temp（两形态，E3-3 定案） | 随机 temp 路径派生（命令族 = 每工作区 `pid-hash`；PTY 会话 = 每会话 `pty-<uuid>`） | 写 ACE，**可撤销**；TMP/TEMP 重写到该目录 | 命令族：进程级（随缓存常驻至进程退出）；**PTY 会话：会话销毁撤销**（`SessionTemp::revoke_and_remove` 撤 ACE + 删目录）；崩溃残渣惰性无害（新会话新目录新 SID） |

- **拒绝重叠**：temp 目录必须与工作区**互不包含**（否则工作区可继承 ACE 蔓延到 temp 树 / 或 temp ACE 落入工作区语义）——dsh 同规则。本侧落 `%TEMP%/worldsea-sandbox/<rand>`（**不用**工作区内 `agent-tmp`：它落在工作区树内，违反互不包含）。
- 工作区 root 取 `ctx.workdir`（切换目录后跟随；每个新 root 首授一次）。
- 授予/撤销走进程级单例（Mutex + 每工作区缓存），防并行工具执行竞态（§六 R8）。

### 4.6 失败关闭语义与演进路径

| 场景 | 行为 |
|---|---|
| 令牌派生 / ACL 授予 / 受限 spawn 任一失败（Agent 路径） | **拒绝执行**，工具结果返回明确错误（沙箱不可用），不裸跑 |
| 同上（面板路径，无戳记） | 维持现状（不启用沙箱，用户驱动） |
| 受限子进程的命令**被拒**（写越界） | 命令照常返回非零退出 + stderr（Access denied 类）→ **E3-4 已落地**：结果附 `sandbox_hint`（「沙箱拒绝：…当前沙箱模式 <mode>」）+ `__meta.sandbox_denied`（前端工具行警示徽标）；方言识别从简（四类字样），不做 dsh 式逐后端精确分类 |
| portable-pty 回落后端（无法注入令牌） | **E3-3 定案**：Agent 受限路径走 passthrough 专用通路、**不回落**（失败即 fail-closed 拒绝创建——回落到无令牌 PTY 即边界旁路）；面板 / 非 Windows 路径维持既有回落 |
| 平台非 Windows | 本期不启用；Agent 路径行为 = 现状（Unix 侧见 §4.8） |

### 4.7 E2 预设位预留（只留形状，不实现）

- 预留接口形状：`SandboxSpec` 由 `sandbox_policy(档位, 工作区, [可选显式覆写])` 产出——参照 dsh per-call policy resolver（`resolve(request)` 显式决议，不做隐藏 default）。
- E2 将来 = 把「档位 × 沙箱模式 × 审批策略」打成一个名字，**在 resolver 之上加一层命名映射**，执行层零改动。
- 本期不做：预设 UI / 存储 / 命名；也不做「沙箱内命令自动放行」这类审批降级（属 UX 路径变化，见拍板点 D8）。

## 八、验证与真机走查预案（施工期细化）

**通过标准（每期）**：

  1. 工作区内写（`echo x > file`、常规 git 操作）→ 成功；
  2. 工作区外写（如 `echo x > %USERPROFILE%\ws-sandbox-test.txt`）→ 失败（Access denied 类）；

## 九、与 dsh 的差异登记（有意偏离）

| 维度 | dsh | 本设计 | 说明 |
|---|---|---|---|
| 模式语义 | 用户 / 会话级三模式 + 每调用覆写 | 内部两模式，由三档派生；覆写留 E2 | 02 §四 排除项范围内的「不照搬」 | 
| 默认 | read-only（fail-safe 默认） | interact 默认档 → workspace-write | 本侧产品默认档是交互，plan 才是只读 |

### E3-2 spike（2026-09-18 完成 · 机制真机验证，未接入工具链）

**范围**：受限令牌派生 / 能力 SID（`S-1-4-x-y`）/ 目录写 ACE 授予与撤销（exact-ACE skip）/ 受限 spawn（管道 stdio + 挂起创建 → Job → resume）/ ConPTY 挂载探查（R2 前置）/ WSL 通道探查（R4）。

**落地**：

- 新增 `crates/agent-commands/src/sandbox/{mod,win}.rs`：`OwnedSid`（Everyone / 路径派生）、`RestrictedToken`（`WRITE_RESTRICTED | DISABLE_MAX_PRIVILEGE | LUA_TOKEN` + logon SID 保活）、`grant_write`/`revoke_write`（`SetEntriesInAclW` + `SetNamedSecurityInfoW`，已存在同 SID ACE 跳过）、`spawn_confined`（匿名管道 stdio + 挂起创建 → Job → resume）+ 10 项**真机**测试。
- `pty/conpty_passthrough`：`spawn_with_token`（E3-3 接线点，`CreateProcessAsUserW` 分支）；`job.rs`：`assign_handle`（挂起期挂接，收口 P1「spawn 后 assign」竞态）；`Cargo.toml`：windows-sys 增 `Win32_Security_Authorization` feature。

**真机结论（本机 Windows 10.0.26340）**：

| # | 项 | 结论 |
|---|---|---|
| 1 | 写边界（workspace-write） | 区内写 ✅ / 区外写 ❌（系统拒绝）/ 任意路径读 ✅ / 授予幂等 ✅ |
| 2 | read-only | 子进程正常启动（保活 SID 有效）且全部写被拒 ✅ |
| 3 | 私有 temp | TMP/TEMP 重写 ✅ / 私有 temp 可写 ✅ / 兄弟 temp 不可写 ✅ |
| 4 | 控制台标志 | `CREATE_NO_WINDOW` → `0xC0000142`（**与 dsh 记录一致**：受限令牌下不可用）；无标志与 `DETACHED_PROCESS` 可用 → 初判「GUI 场景选 `DETACHED_PROCESS`」——**收口期修正**（DETACHED 与 powershell 不兼容，非受限亦复现）：最终定案 **flags=0**，见下方「E3-2 收口」 |
| 5 | **R2 ConPTY×受限令牌** | **可用**（shell 可交互 + 越界写被拒）——dsh 未验证项实测通过，**E3-3 路线成立** |
| 6 | **R4 WSL 通道** | **受限令牌下 `wsl.exe` 无法启动**（`Wsl/Service/CreateInstance/E_ACCESSDENIED`）→ bash 工具（Windows 经 wsl）在受限模式下不可用，**D9 据此裁定**。**补探**：把 `INTERACTIVE`（`S-1-5-4`）加入限制 SID 仍 `E_ACCESSDENIED` → **非令牌清单可调节**（WSL 服务对受限令牌的硬拒绝），D9 不保留「放宽令牌」选项 |

**实现要点（施工沉淀，供 E3-2 收口 / E3-3 复用）**：

- `OpenProcessToken` 必须带 **`TOKEN_ASSIGN_PRIMARY`**（缺失 → `CreateProcessAsUserW` 直接「拒绝访问 5」；dsh 同口径）。
- cmd 命令串**不做 `\"` 转义**（cmd 不识别 C 运行时转义，会把路径解析坏）——受限 spawn 用 `cmd.exe /D /S /C "<command>"`（命令原样嵌入，`/S` 剥首尾引号、`/D` 跳过 AutoRun）。
- 传 `CreateProcess` 的 cwd **不能带 `\\?\` 前缀**（cmd 视为 UNC 路径拒绝）——本侧 W1 规范化已剥前缀，E3-2 接线须沿用。
- ConPTY 挂载需 DSR 应答（既有 `spawn_passthrough` 已含；新接线不得绕过）。
- 受限子进程 Job 挂接改**挂起创建期**（`assign_handle`），assign 失败仍按 P1 口径「告警不阻塞」。

**验证**：agent-commands **206/0**（+10 真机 spike 测试）· kernel 305/0 · src-tauri 48/0（单线程）· 前端未触碰。

**未纳入（E3-2 收口，下一步）**：工具链接线（三 spawn 站点改走受限 spawn + fail-closed 拒绝语义 + 每工作区授予缓存注册表 + 私有 temp 生命周期与 TMP/TEMP 重写落地 + 面板路径显式不受限 + `DETACHED_PROCESS` 选型落地）+ 真机走查。WSL 通道策略按 D9 裁定执行。

### E3-2 收口（2026-09-18 完成 · 工具链接线）

**范围**：命令族两站点接线（execute_command / powershell）+ D9 bash fail-closed + PTY 通道「E3-3 前」fail-closed + 每工作区授予缓存 + 私有 temp 生命周期 + 控制台标志定案。

**落地**：

- `sandbox/win.rs`：`workspace_sandbox`（**每工作区进程级缓存**：工作区 SID 常驻 ACE + 私有 temp 随机目录与可撤销 ACE；互不包含约束）+ `spawn_confined_command`（两态入口；WorkspaceWrite 追加 TMP/TEMP 重写到私有 temp）+ `cmdline_for_cmd` / `cmdline_from_argv`（命令行构造两形态）。
- `sandbox/mod.rs`：`CommandChild` 统一子进程形状（受限 / 普通两通路同接口：take_stdout/take_stderr / wait_timeout / kill）+ `WaitOutcome`。
- `terminal.rs`：`spawn_command_child`（受限通路 **fail-closed** 拒绝并给明确错误；普通通路保持既有语义——调用方自建 Command，bash/powershell 形态不变）+ `pty_confined_gate`（PTY 创建 / 执行 / 输入三入口 fail-closed）+ D9 bash 拒绝文案。
- 边界说明：面板路径（无 ctx → 无戳记）与 Unix（不启用）均走普通通路——与 W3 先例一致。

**控制台标志定案（修正 spike 初判）**：

| 方案 | cmd | powershell | 结论 |
|---|---|---|---|
| **flags=0**（与 std 普通通路同口径） | ✅ | ✅ | **采用**——std 只加 `CREATE_UNICODE_ENVIRONMENT`；控制台行为与既有普通通路完全一致 |
| `CREATE_NO_WINDOW` | ❌ `0xC0000142` | ❌ `0xC0000142` | 受限令牌下不可用 |
| `DETACHED_PROCESS` | ✅ | ❌ 静默不执行（**非受限亦复现**，与令牌无关） | 排除 |

**验证**：agent-commands **214/0**（+8 收口契约测试；含真机：写边界三态 / plan 只读 / 沙箱不可用 fail-closed / powershell 受限执行 / D9 与 PTY 拒绝）· kernel 305/0 · src-tauri `cargo check` 通过 · 前端未触碰。
