# 第四域对照与建议清单：工作区与环境（对齐 / 新增 / 增强）

> status: 已完成

> 用途：把「工作区与环境对齐 dsh」收敛为可拍板、可施工的清单。流程：本文档 → §五 决策点拍板 → 立项施工（每项配契约测试 + 基线验证 + 真机走查）。
> 归口：三桶分类——**对齐**（本侧已有对应能力、设计/契约与 dsh 有差距）｜**新增**（dsh 有、本侧没有且有立项理由）｜**修复**（对照中发现的现存缺陷）。

## 零、总体判断（先读这段）

| 域 | 一句话判断 |
|---|---|
| 工作区域 | **骨相比 dsh 更重，身份却更松**：本侧 workspace 是 DB 实体（承担会话分组 / 记忆隔离 / 索引归属 / 场景身份），比 dsh 的纯导航实体承载更多；但 `root` 字符串**无规范化**（同一目录可分裂出多条记录），会话侧 `workdir / workspace_id / project_id / scene_id` 四列并存、运行时 `workdir` 可变——「单一事实源」缺位。dsh 反而是「一个不可变 cwd 走天下」。 |
| 环境域 | **机制已建，口径分裂**：受限执行（Job object / 环境清理 / 三档 + 规则引擎）P0+P1 已完成，骨架与 dsh 的「fail-safe + 分层裁决」同构；差距集中在——① 环境清洗**两套口径**（MCP 侧已用 dsh 式启发式，terminal 侧仍是 15 项名单）；② 无工作区时**恒放行**（dsh fail-safe 收紧）；③ 命令的文件效应无沙箱强制（本侧现状，dsh 有 ACL/Landlock 类后端，属远期）。 |

对齐不是照抄：dsh 的「工作区对模型不可见 + cwd 不可变」服务于通用编程 harness 的稳定锚点；本侧 workspace 承担记忆隔离 / 场景身份 / 项目锚点等产品语义，**部分差异是刻意的**（见 §四 排除项 / W4）。

## 二、对照矩阵（语义 / 契约 / 设计 三层）

### 2.1 工作区域

| 层 | dsh | 本侧 | 判定 |
|---|---|---|---|
| 语义 | 工作区 = 宿主侧会话分组 / 导航实体（模型不可见）；执行边界 = 不可变 `SessionHeader.cwd` | 工作区 = DB 实体，承担分组 + 记忆隔离 + 索引归属 + 场景身份；`workspace_id` 进工具上下文（模型侧工具可见） | **有意偏离**（产品语义不同，W4 登记）；能力面更重 |
| 契约 | `path` 创建时 realpath 规范化一次、永不改写；`WorkspaceId` uuid ≠ 路径；成员资格 = cwd realpath 相等 | `(root, scene_id)` 复合身份（场景维度是本侧独有）；**root 无规范化**；会话四列并存，恢复走 workspace_id 兜底 | **有差距**（W1 身份规范化 / W2 单一事实源） |
| 设计 | create 幂等 / delete 留目录与日志 / 崩溃恢复 / 启动自动分组；子 Agent 继承父 cwd | `ensure_workspace` 幂等 upsert；子 Agent 共享 + 目录引导（temp_dir 强隔离未启用）；前端面未收（按项目过滤 / 空壳命令） | **部分同构**，收尾欠账（W6） |

### 2.2 环境域

| 层 | dsh | 本侧 | 判定 |
|---|---|---|---|
| 语义 | 执行基准 = 不可变 cwd；沙箱默认 read-only（fail-safe）；审批 fail-closed 仅 allowed-once | 执行基准 = 可变的 `AgentLoop.workdir`；无工作区恒放行（fail-open）；审批四值已对齐（非 fail-closed：skipped/timeout 可继续） | **有差距**（W3 fail-safe；审批语义本侧更宽，已拍板） |
| 契约 | `resolveWorkdir` 三级（显式 > policy root > session cwd）；`scrubbedParentEnv` 启发式通配 + 显式 env 后合并 | cwd 来自 AgentLoop 字段注入；清洗两套口径（MCP 启发式 / terminal 名单式）；显式 env 后合并（一致） | **部分同构**（E1 口径统一） |

## 三、建议清单

### 3.1 工作区域（W）

#### W1 工作区路径身份规范化（realpath 锚定）【对齐·契约】

- dsh：`path` 创建时 `fs.realpath` 规范化一次、之后永不改写；`WorkspaceId` 与路径解耦（路径会变、锚点要稳）。
- 本侧：`upsert_workspace` 原样存 `root` 字符串——同一目录经不同写法（大小写 / 短名 / `..` / 符号链接 / 尾斜杠）会生成**多条 workspace 记录**；下游三处都会分叉：会话分组、记忆隔离（A1 丁3 按 project 分片）、文件索引归属（按 workdir 指纹命名）。
- 立项理由：身份分裂是**静默**的（不报错、只分叉），事后排查成本高；对齐 dsh 的「一次规范化」成本极小。**保留** (root, scene_id) 复合身份（场景维度是本侧产品语义，dsh 无）。
- 改动面：小——`ensure_workspace` / `upsert_workspace` 入口规范化（canonicalize 失败回落原值）+ 契约测试（大小写 / `..` / 尾斜杠 / 不存在的路径）。存量行不迁移（项目无在用用户）；冲突合并留可选。
- 建议：**做**（小-中，低风险）。

#### W2 会话↔工作区单一事实源【对齐·设计】

- dsh：`session.header.cwd` 不可变且是唯一锚（沙箱根 / shell workdir / 成员判据全取它）。
- 本侧：会话四列（`workdir / workspace_id / project_id / scene_id`）并存；恢复走 `workspace_id → root` 兜底；`ToolContext` 同时带 `workdir + workspace_id`；`project_id` **恒 None**（工具侧看不到项目归属）；运行时 `set_config` 改 `workdir` 只动内存字段——「切换目录」后 session 记录 / loop 字段 / workspace 实体三处是否同写，需要核实（潜在静默不一致）。
- 立项理由：多锚并存 = 「会话记录说 A、工具边界在 B」的静默漂移；这是工作区域的根问题。但改它涉及数据模型 / 工具上下文契约，需单独立项。
- 改动面：① 小步（身份一致性：读路径统一走 workspace 实体 + `tool_ctx` 填实 `project_id` + 切换目录写路径核实）；② 完整收敛（workdir 降为派生缓存）中-大。
- 建议：**①可选做；②单列**（涉及数据模型与工具契约，需授权）。

#### W3 无工作区 fail-open 兜底【修复·安全】

- dsh：无 `workspaceRoot` 时默认 read-only（fail-safe），策略解析失败一律收紧。
- 本侧：`workdir=None` → `is_within_workdir` 恒 `true`、`resolve_path` 相对路径原样（`tool_context.rs:71-98`）——边界整体消失；`None` 是承认的兼容态且**群聊会话正以 None 建立**（先查清其工具可达面）。
- 立项理由：风险不在当前行为，而在「装配失败 / 旧数据 / 新会话类型」时边界**无声消失**；应改为 fail-safe（拒绝写 / 命令，或回落受管草稿区）。
- 改动面：小-中（`ToolContext` 判定 + 工具层 + 契约测试）；**先查清**：哪些会话 / 路径会出现 None、可达哪些工具（群聊 / 恢复失败 / 旧数据）。
- 建议：**先查清，再做**。

#### W4 工作区对模型可见性定位【决策项·登记】

- dsh：工作区是宿主侧实体，**刻意**对模型不可见（无工具 / 无提示词 / 无事件）。
- 本侧：`workspace_id` 已进 `ToolContext`（模型侧工具可消费）。
- 建议：**保持现状并登记为有意偏离**（本侧 workspace 是产品语义实体，非纯导航）；红线：维持现状（id 可进工具上下文，不进系统提示词）。若拍板改变，属新立项。

#### W5 子 Agent 工作区策略【对齐·保持】

- dsh：子 Agent 继承父 cwd、不建独立工作区。
- 本侧：默认共享主 workdir + `agent-tmp/sub-{id}` 目录引导；`temp_dir` 强隔离已备未启用。
- 建议：**保持**（主线已对齐 dsh 的「继承」）；强隔离如启用属能力扩展，另议。

#### W6 前端面旧账：会话归属呈现 + `cmd_switch_project` 去空壳【修复·既有待办】

> **语义修正（2026-09-18 施工期回查 dsh 源码）**：原表述「会话列表按项目过滤」易读作「隐藏他项目会话」；dsh 实际语义为**全量可见 + 按项目分组 + Ungrouped 兜底**（隐藏属用户显式单会话操作）。施工按 dsh 对齐落地，详见 §八 W6 记录。

- 来源：workspace 统一线收尾项（`WORKSTREAMS.md` workspace 行）+ [workspace-unification-plan](../workspace-unification-plan.md) §收尾；`cmd_switch_project` 现为空壳（只打日志返回 Ok）。
- 立项理由：锚点（`project_id`）已入库但消费不力——归属呈现与记忆隔离两条链该接的接上（记忆隔离已随 A1 丁3 落地）。
- 改动面：小（命令层删空壳；会话列表**无需过滤**——按目录/项目分组呈现即可，dsh 语义见上方修正注记，**先查清消费面**）。
- 建议：**做**（先查清后动手）。

### 3.2 环境域（E）

#### E1 环境变量清洗口径统一（名单式 → 启发式）【对齐·安全】

- dsh：subprocess seam 统一按名启发式剔除 `*KEY* / *PASSWORD* / *SECRET* / *TOKEN*`（+ `DSH_*`），显式 env 清洗后合并。
- 本侧：**两套口径**——MCP stdio 已对齐启发式（`mcp_client.rs:93-101` + `:586-597`）；terminal / shell 仍是 **15 项名单**（`terminal.rs:108-124`）——新供应商变量（各类 `*_API_KEY` / `*_TOKEN` / 自定义密钥）不在名单即**泄漏给 Agent 命令**。
- 立项理由：同仓两套口径本身是漂移源；命令执行是最常用泄漏路径（Agent 可跑 `env` / `gh` / `aws`）。显式 env 覆盖语义两侧一致，保留。
- 改动面：小——抽共享判定（落 agent-commands 或 kernel，src-tauri 复用）+ terminal 两处升级 + 单测（通配命中 / 显式覆盖 / PATH 保留）。
- 建议：**优先做**（小，安全）。

#### E2 权限 / 沙箱具名预设【对齐·设计】

- dsh：`permission-presets` 把沙箱模式 × 审批策略打包为具名预设（默认 `workspace-write + ask`）。
- 本侧：三档（plan / interact / autopilot）+ 规则引擎（锁 / 白名单）已在，交互上「档位即预设」；打包的主要收益是**命名与默认组合的显性化**。
- 建议：**缓做 / 挂账**（形态收益有限；规则引擎已比 dsh 更细）。

#### E3 命令文件效应边界（真沙箱）【远期·挂账】

- dsh：`sandbox-local` 用 bwrap / Landlock / Seatbelt / Windows ACL 强制文件效应；`fs-sandbox` 管写入边界（读不受限）。
- 本侧：P1 只有进程树回收（Job object）+ 环境清理 + cwd 词法边界；**命令本身可读写任意路径**（靠 L1 HITL / L2 敏感目录 / L3 项目数据三层守卫兜）；Unix pgroup 未做。
- 建议：**挂账**（远期 P2；Windows 受限令牌 / ACL 方案复杂度高，现有三层守卫已覆盖主要风险面）。

#### E4 目录级规则链注入（AGENTS.md 链）【评估·低优先】

- dsh：`$DSH_HOME/AGENTS.md` + 从 `.git` 根到 session cwd 的 `AGENTS.md/CLAUDE.md` 链（宽→窄）。
- 本侧：八文件规则体系（WORLDSEA + 全局 / 项目双层），**无目录级链式规则**。
- 建议：**挂账**（先评估需求；如做，属规则体系扩展而非对齐）。

## 四、排除项（明确不做，防范围蔓延）

| 项 | 排除理由 |
|---|---|
| WorkspaceRegistry 宿主实体整体形态（模型不可见 + 纯导航） | 本侧 workspace 承担记忆隔离 / 场景身份 / 索引归属 / 项目锚点，产品语义不同（W4 登记为有意偏离） |
| `session.cwd` 不可变 | 本侧「切换目录」是产品功能（`set_config` 承载）；改为不可变会砍功能，且与场景模式冲突 |
| 沙箱三模式语义照搬（read-only / workspace-write / danger-full-access） | 与三档 `plan / interact / autopilot` 不等价（本侧档位 + 规则引擎更细，已拍板 v2 设计） |
| 每次调用全新 shell | 本侧 PTY 持久会话是产品能力（终端面板）；命令工具与 PTY 分工明确 |
| `DSH_*` 受管变量族（DSH_HOME / DSH_SHELL / DSH_SESSION_ID） | 无对应需求；本侧会话上下文经 ToolContext / 事件通道承载，不走环境变量 |
| workspace fork / snapshot / checkpoint | 两侧均无此机制，无差可对 |
| 审批语义收紧为 fail-closed（仅 allowed-once） | 本侧四值（approved/denied/skipped/timeout）已拍板落地（2026-09-17 D8）；本侧允许 skipped/timeout 继续是产品决策 |

### W3 无工作区 fail-open 兜底（2026-09-18 完成 · 批次 D）

**查清结论（关键）**：

1. `workdir=None` 的真实来源：**群聊参与者会话显式传 None**（`lib.rs`）+ 旧数据/装配异常；且 `resolve_scenario(None)` 回落到**默认 world 场景** → 工具白名单 = `SYSTEM_BASE_TOOLS` ∪ world 工具（含 bash/powershell/read_file/write_file/…）→ 群聊参与者 LLM **实际可达** fs / 命令工具，而旧语义下边界整体消失（`is_within_workdir` 恒 true、相对路径按**进程 cwd** 解析）。
2. **执行路径分叉**：Agent 主链走 `execute_with_ctx`（带 ctx）；终端面板走 `TerminalService` 直调 `.execute()`（无 ctx，用户驱动）——守卫必须只落在 ctx 路径，否则会打断面板的单次命令执行。

**落地（对齐 dsh「无 workspaceRoot 一律收紧」）**：

- `fs_tools::require_workdir(ctx)`：无工作区 → `ToolError`（含引导文案「未绑定工作区…项目=目录」）。
- fs 全族 8 工具（read/write/edit/edit_diff/list/search/grep/find）：`execute_with_ctx` 入口统一守卫（其 `execute` 本就走默认 ctx → 一并收紧）。
- 命令族：`ExecuteCommandTool` 与 `ShellExecTool`（bash/powershell）各自在 `execute_with_ctx` 入口守卫（`resolve_command_cwd` 继续负责 cwd 越界判定）；`execute()` 无 ctx 入口保持旧行为（**终端面板路径**，注释显式说明）。
- PTY 会话族：`shell_session_create` / `shell_session_exec` / `shell_session_input` 入口守卫；**create 另与命令工具同口径**——cwd 缺省注入 workdir、显式越界拒绝（PTY 会话默认落在工作区内）。
- 契约测试 +3 / 改写 1：fs 无工作区拒绝（原「None 放行」测试改判）、命令与 PTY 无工作区拒绝、PTY cwd 注入与越界拒绝；bash/powershell 三个既有测试改为注入工作区 ctx。

**验证**：agent-commands **193/0**（+2，另 1 改写 + 3 适配）· kernel 未触碰 · src-tauri `cargo check` 通过。

**边界说明（如实登记）**：守卫落在 `execute_with_ctx`（Agent 执行路径）；`Tool::execute`（无 ctx 的 legacy 入口）仅终端面板使用且**有意放行**（用户驱动，不受 Agent fail-safe 约束）。

### W2② workdir 派生缓存收敛（2026-09-18 完成 · 挂账项①）

**性质（对齐收敛，非破坏性）**：**不动 schema、不删列、不改 `SessionInfo` / `ToolContext` 契约**——把 `workdir` 列的语义从「双轨兼容层」明确为**派生缓存**，并补上收敛链缺失的一环：存量漂移的**写穿矫正**。

**查清结论**：写路径三处已全部双写（建会话 / 切目录 `update_session_workdir` / 主权自愈）；读路径已实体优先（`list_sessions` / `restore_sessions`，W2①）；**唯一缺口**——`list_sessions` 只在**内存**矫正、不写盘，`restore_sessions` 也只在主权自愈场景写穿 → 「实体 root ≠ 缓存列」的存量会**每次读都矫正、DB 永远脏**。
