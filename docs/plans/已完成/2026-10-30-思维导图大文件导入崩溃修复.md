# 思维导图大文件导入崩溃修复（STATUS_STACK_OVERFLOW）

> 2026-10-30 立项。用户在思维导图芽导入 worldsea-codex.md（306KB / 6901 行）后整页崩溃（WebView2 渲染进程
> STATUS_STACK_OVERFLOW「此页存在问题」）。走查方式：Agent 自走查（用户确认后免走查收尾）。

## 一、根因（实测数据）

- **解析器纯文本行级联下沉**：`parseLines` 对普通文本行的规则是「挂在上一行下（depth = 上一行 + 1）」，
  连续多行纯文本（实体多段描述）逐行比上一行深一层——用户文件堆出 **6901 节点 / 1097 层**链
  （实测复算确认）。
- **mind-elixir 按树深度嵌套 DOM**：千层嵌套直接打爆 WebView2 渲染进程原生栈 → 整页崩溃。
- **带毒锁死**：导入数据在 `mind.init` 前已落库（createDoc → persistDocData → openDoc → init），
  崩溃后刷新会在加载时再崩，视图被带毒文档锁死。
- 附带观察：控制台 `Added non-passive event listener to wheel` 为 mind-elixir 内部监听（性能提示，
  非崩溃原因，库内部实现不在本批处置范围）。

## 二、修复（三层）

1. **解析级联修复**（mindmapMarkdown.ts）：纯文本行统一挂在**最近一个结构行**（标题/列表）下作兄弟
   节点——深度由「行数」变为「标题嵌套 + 缩进级」有界；多段描述落成兄弟节点（语义也更合理）。
2. **导入护栏**（`findImportViolation`）：导入/粘贴前校验——节点 ≤2000、层级 ≤40，超限拒绝并给
   拆分/精简建议（`MINDMAP_MAX_NODES` / `MINDMAP_MAX_DEPTH`）。
3. **加载护栏**（`mindElixirStats` + openDoc 守卫）：打开已存文档用放宽阈值（节点 ≤5000、层级 ≤200），
   只挡真正会崩的旧数据；用户本次崩溃产生的带毒文档「worldsea-codex」（6901/1097）被拦截并提示
   可从文档列表删除——**已带毒文档的恢复路径闭环**。
4. 粘贴护栏额外校验「当前文档节点数 + 粘贴节点数」合并规模。
