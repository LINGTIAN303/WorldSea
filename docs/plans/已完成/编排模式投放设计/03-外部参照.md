## 一、逐产品形态卡（7 家）

### 1. Claude / Claude Code

| 维度 | 形态 |
|------|------|
| 过程形态 | 对话流内"迹线行 + 折叠块"混合：工具调用 = 单行摘要（工具名 + 参数预览 + 状态图标），thinking = 可折叠块，TodoList 内嵌对话流 |
| 折叠策略 | thinking 默认折叠；折叠摘要按 markdown 渲染、**保持可读至少 3 秒、截断至 10 行**；Ctrl+O 切换 verbose |
| 等待感 | 流式逐行输出（无死空气）；后台任务 Ctrl+B + `/tasks` 查看；Esc 中断且回合保留；双 Esc 回溯 |
| 错误呈现 | 部分失败如实报告（含已完成中间步骤）；反面：Opus 4.7/4.8 thinking 空块事件——静默降级，UI 无内容可渲染（社区大量投诉） |
| 可借鉴 | ①"10 行 + 3 秒"折叠摘要规格（罕见的精确量化设计，可直接抄）；② 社区公认痛点（issue #24537 聚合 20+）：**对话流塞 agent 树 / 资源指标 = 过载，官方方向"分离而非删减"**——与本项目"统一迹线 + 按需详图"互为印证；③ 已知弱点：并行 subagent 无进度条、无中间输出直到全部完成 |

### 2. ChatGPT（Deep Research + thinking）

| 维度 | 形态 |
|------|------|
| 过程形态 | "计划消息 + 可展开过程面板 + 折叠遗迹"三段式：研究计划先以普通文本消息呈现并**要求用户反馈/批准**；执行中步骤显示在右侧 Activity panel 实时更新；完成后折叠为对话内紧凑组件 |
| 折叠策略 | **运行时展开、完成后自动收拢**的时态分离；普通 thinking = "Thought for N seconds" 折叠行（全行业标配句式） |
| 等待感 | 5-30 分钟长任务靠 Activity 面板分阶段实时更新 |
| 错误呈现 | 反面：GPT-5.6 卡"Thinking"时 Activity 侧栏不可访问——**过程面板与过程同生共死**是脆弱设计 |
| 可借鉴 | ① **计划批准的对话式暂停点**（普通消息呈现计划、普通消息回应批准，无需专用控件）——成本低、控制感强；②"运行时展开 / 完成后折叠"时态规则与编排段生命周期直接对应；③ 桌面 app 反面教材（2026-07 官方承认 "kind of a mess"）：agentic 能力做成独立 Tab 导致迷失，回归方向 **tab-free 无缝融入主对话** |

### 3. Cursor（agent mode）

| 维度 | 形态 |
|------|------|
| 过程形态 | 对话流内步骤行 + 独立 Agents Window 双层：聊天内 `Read xx.md` / `Searched for 'xx'` / `Thought 5s` 迹线行 + diff 卡；Agents Window 左侧多工作区并行 agent 面板 + 右侧检查面板 |
| 折叠策略 | **密度三档可调**（3.4 版"紧凑型对话"）：紧凑（最少工具跟踪）/ 平衡（重要中间步骤）/ 详细（近乎完整）——用户自选信息密度 |
| 等待感 | 统计摘要行（`Explored 12 files, 4 searches`）+ 工时（`Worked for 14m 22s`）+ **中途文字摘要**（一句话汇报当前意图）+ 完成后 Summary |
| 错误呈现 | 后台任务可靠性修复（恢复失败、中断边缘情况）在 changelog 高频出现——多 agent 状态恢复是工程难点 |
| 可借鉴 | ① **密度三档**是 13 模式最直接参照（编排复杂度跨度大，可"按编排模式默认档 + 用户全局覆盖"）；② 统计摘要行 = 低成本高信息的折叠态内容范本；③ 中途摘要填补长任务等待感 |

### 4. Windsurf Cascade

| 维度 | 形态 |
|------|------|
| 过程形态 | 对话流内 Todo list 物化 + 后台双 agent 分层：专门的 planning agent 在后台持续细化长期计划，前台模型只执行短期动作——计划随新信息自动更新 |
| 折叠策略 | 编辑 / 命令以可点击条目呈现（编辑可展开 diff，命令可展开输出）；计划 / Todo 常驻对话流 |
| 等待感 | **Queued Messages**：agent 工作中可继续输入排队消息，完成后按序执行——把"等待"变成"继续指挥"；命名检查点支持任意回退 |
| 错误呈现 | 规划复杂变更时 UI 偶发卡顿；MCP 错误信息晦涩 |
| 可借鉴 | ① "规划 agent 与执行 agent 分离 + Todo 物化"与规划 / 委派 / 评审模式天然同构——**编排中间产物（计划、委派清单、评审结论）应结构化呈现且可干预**；② 排队消息是"长任务等待感"的最佳答案之一；③ 计划自动修订 = "计划是一等公民而非一次性文本" |

### 5. Devin

| 维度 | 形态 |
|------|------|
| 过程形态 | "聊天 worklog + 统一进度 Tab + 专用工具面板"三层：聊天流以折叠"进度更新"条目穿插；点击打开统一视图（shell / 编辑 / 浏览器活动汇聚一处）；可实时观看甚至**接管**（take over）；子 Devin 会话在侧栏显示为嵌套树（2026-08 起） |
| 折叠策略 | 聊天内折叠条目 + 专用 Tab 看全程——**对话看梗概、Tab 看全程** |
| 等待感 | 命令历史带**时间导航**（点击命令跳转会话中的时间点，可回放）；旁聊 `/btw` 不打断主任务提问；Ask / Agent 模式分离 |
| 错误呈现 | **行业标杆：模型降级 / 恢复主动通知用户**（2026-08-19 更新）；CI 失败行可直接跳转展开的 checks |
| 可借鉴 | ① "聊天流折叠条目 + 统一进度视图"双层与"编排段 + 详图"**几乎同构，是 7 家中最接近的参照**；② 模型降级主动通知——涉及模型路由 / 降级时应显式告知而非静默切换（对应 B9 降级可见）；③ 时间导航适配多阶段回放；④ 旁聊机制解耦"对过程的疑问"与"任务本身" |

### 6. Manus

| 维度 | 形态 |
|------|------|
| 过程形态 | 双栏全透明直播：左侧聊天流（Research Steps 占大量篇幅，研究计划展示但**不暂停等确认**）+ 右侧"Manus's Computer"实时计算机视图直播 |
| 折叠策略 | 过程默认大比例展开（过程即产品）；可离开——任务云端异步执行，完成后通知 |
| 等待感 | 实时直播 + 异步解耦；可随时暂停 / 重定向 / 接管 |
| 错误呈现 | 靠过程透明兜底；但 CMU 可用性研究（N=31）指出失败时用户仍难判断该不该干预 |
| 可借鉴 | ① Take Over 中途接管 = 过程可视化的落点（可视化不只是看，最终为了能介入）；② **反面参照**：常规浏览阶段直播视图价值骤减（"为透明而透明"的空间成本）——"按需详图"优于"全程直播"；③ 反面参照：计划不暂停依赖模型决策质量，容错低于确认式；④ 多中间文档稀释主交付物焦点——编排段应保持一条主迹线，分叉产物收纳为子节点 |

### 7. Gemini Deep Research

| 维度 | 形态 |
|------|------|
| 过程形态 | 双栏分离 + 结果优先：主对话栏干净；研究计划以 tool result 卡片呈现（带 Edit plan / Start research 按钮）；进度在次级"Thoughts 思考面板"——追踪"模型当前学到的内容 + 预计执行的下一个动作" |
| 折叠策略 | 过程默认收进次级面板（不进对话流）；对话流中仅留紧凑入口 |
| 等待感 | 思考面板以**"已学到什么 → 下一步做什么"双行叙事**滚动更新——等待感的本质是让用户能预测，而非看到一切 |
| 错误呈现 | 来源质量不均且系统不独立验证——验证负担转嫁给用户 |
| 可借鉴 | ① 双行叙事非常适合作为编排段**折叠态的内容模板**；② 双栏"对话干净、过程隔离"是统一迹线的另一种实现（对话流内折叠 vs 对话流外面板——A3 布局问题的参照两端）；③ 反面参照：完成后步骤埋在报告下方，**过程一旦结束就难以回看** |

## 二、反模式清单（12 条）

1. **过程压倒结果**：Research Steps 占大量屏幕、中间文档稀释主交付物（Manus）；步骤埋报告下方（Gemini）→ 答案永远第一视觉层级，过程永远可收纳。
2. **剧场感信任信号**：动画 thinking 指示器、置信度百分比、AI 生成的"解释"段落——用户很快发现与"结果对不对"不相关，变成噪音再变成摩擦。信号必须从使用中涌现（真实统计、真实耗时），不能是纯装饰。
3. **死空气黑盒**：30 秒 spinner = agent 被关掉；过程面板与过程同生共死（ChatGPT 实测）→ 工具执行期间必须发状态事件。
4. **对话流塞编排细节**：Claude Code 社区公认痛点（#24537 聚合 20+ issue）→ 正确答案是**分离而非删减**（separation, not subtraction）。
5. **模式 / Tab 碎片化**：ChatGPT 桌面 Tab 化失败回归 tab-free——与"快问答无感、编排段内嵌"方向一致的教训（直接印证 A1）。
6. **静默降级 / 静默重试**：Opus thinking 空块事件；原则："永不静默重试，失败要说明正在再试"。正例是 Devin 模型降级主动通知（对应 B9）。
7. **状态时态不一致**：thinking 流式时全展开、重启后折叠、无持久设置——展开 / 折叠行为跨"运行中 / 已完成 / 历史回看"三态必须一致且可持久化（对应 A0-3 生命周期）。
8. **一次性倾倒全量迹线**：用户说"不信任"时本能反应是全展示——"这几乎总是错的"。渐进披露：大多数用户从不打开最深层，**但知道它存在本身就能建立信任**。
9. **同一信息多处重复**：sources 在单条响应出现 2-3 次 → 重构为"thinking 块 → 答案 → 来源"各出现一次。
10. **过程面板与过程同生共死**：过程出错 / 卡死时面板也随之不可访问——面板可用性要与执行状态解耦。
11. **全局单一自主性开关**："Auto 模式"开 / 关过于粗暴，正确形态是**按动作类别的策略**（只读自由执行 / 写操作起草后确认 / 不可逆总是确认），且边界在 UI 里可见（对应 A0-4 交互层级）。
12. **为透明而透明的全程直播**：常规阶段直播价值骤减却持续占据半屏——信息密度应随阶段自适应，而非恒定铺满。

## 三、通用设计原则（8 条）

1. **三层渐进披露**（三篇文章独立提出同构方案，行业共识）：
   - Layer 1 答案（+ 人类可读的置信信号）——80% 用户 80% 时间所需；
   - Layer 2 证据摘要（做了什么的一句话平实说明 + 引用 / 关键中间产物）——**用户实际阅读的层**；
   - Layer 3 完整审计迹线（每个工具调用含参数与响应、时序、模型选择）——供调试 / 审计，"从不强制展示，但存在即信任"。
   - 实证：某采购 agent 仅加 Layer 1+2，采用率 6 周内 12% → 67%，模型未变。
2. **可读性三件套**：实时状态指示器（thinking / executing / waiting / paused / done 五态可辨）、**人类语言的审计迹线**（"已发送审批请求给 finance@…"而非"POST /api/... 200 OK"）、选择性推理透明（高风险决策显示 1-2 个关键影响因素，不倾倒 CoT）。
3. **等待感的本质是可预测性**：流式输出消除死空气；"已学到 + 下一步"双行叙事让用户能预期；统计摘要行 + 中途意图汇报；排队消息把等待变成继续指挥；异步通知解除在屏等待（对应 A0-13）。
4. **时态规则**：过程"运行时可展开观察、完成后自动折叠成紧凑遗迹、历史中可回放"（对应 A0-3 / A2 的生命周期设计）。
5. **计划是一等公民**：或物化为可编辑 Todo（Windsurf，随执行自动修订）、或作为确认暂停点（ChatGPT / Gemini 的 plan card）——编排中间产物应结构化呈现且可干预，而非纯文本流（对应 D15 / A2）。
6. **错误透明四要素**：区分"什么失败了"（技术）与"对用户意味着什么"（影响）；给出具体下一步（重试 / 换路径 / 升级人工）；**可见地保留部分进度**（10 步做了 7 步要显示那 7 步）；降级 / 恢复主动通知（对应 B9 / A0-14）。
7. **可逆性是最通用的信任机制**：undo / checkpoint 降低"事前焦虑"，使用户愿意授予更高自治度（对应 A5 的 v2 回退）。
8. **透明度 ≠ 信息量，而是"对的信息在对的时刻"**：设计挑战已从"AI 能不能做"转向"用户能否理解并信任 AI 做了什么"（对应 A0-12 透明度上限）。

## 四、对本产品的投影（开放问题，不定案）

1. **方向被强印证**：ChatGPT 桌面回归 tab-free 融合、Claude Code 社区"分离而非删减"、Cursor 密度三档——三个头部产品在 2026 年殊途同归走向"对话流内过程段 + 按需细节面"，且都在惩罚"模式碎片化"（A1 的问题现状）与"过程压倒对话"两类旧设计。
2. **最可抄的三个规格**：Claude Code 折叠摘要规格（markdown 渲染 + ≥3 秒可读 + 10 行截断）；Cursor 密度三档（可映射为"按编排模式给默认档 + 用户全局覆盖"）；Gemini"已学到 + 下一步"折叠态叙事。
3. **最大空白 = 本项目机会**：Claude Code 并行 subagent 至今"无进度条、无中间输出直到全部完成"——多智能体 / 思维树探索类编排（本产品高复杂度段）在现有产品中普遍缺乏过程呈现范式；Devin 的"聊天折叠条目 + 统一进度视图 + 嵌套子会话树"是目前最完整的参照。
4. **快问答无感的实现依据**：过程块呈现应由"是否实际发生编排"驱动（Claude 的模型自决 + ChatGPT 的模式限定）——单轮直答不生成编排段即可天然无感（对应 A1 / A3）。
5. **与 02-现状事实的交叉**：
   - TracePanel 已是"阶段级表格"雏形，但数据源是 Deep Mode 五阶段而非编排管线（02 §八）——缺的是管线级骨架事件，不是 UI 形态；
   - OrchestratorPanel 已是事件驱动的实时详图（02 §八）——与 Devin"专用 Tab 看全程"同构，A4 复用方向外部得证；
   - Windsurf 排队消息与 B11"v1 按请求串行"互补：串行 + 排队 = 不打断的连续指挥；
   - "计划批准对话式暂停点"（ChatGPT）与 D16 junction 判定的"可退避"天然衔接——计划节点可成为用户可否决的决策点（B0-8"哪些决策可被用户否决"的参照）。
