## 一、目标与范围

**一句话**：把 `EventBroadcaster`（`crates/agent-kernel/src/event.rs:736-761`）从"只读同步 fan-out"升级为带五种分发模式（`emit/bail/serial/parallel/waterfall`）、可逆注册、与现有会话隔离契约对齐的 `EventBus`，从而把审批、工具结果裁剪、超时、日志从调用点硬编码降级为监听器。

**不做什么**：
- 不搬 dsh 的插件容器（Context / Fiber / `inject` 依赖注入）——本项目无插件生命周期需求，只取其事件语义。
- 不做事件溯源与持久层改造（属 04 文档 A2，另一阶段）。
- 不动双路发射通道 `emit_dual`（05 §1.3：绕过它会让 HTTP bridge SSE 侧静默丢失）。
- 不在本阶段裁定 13 个死变体 / 2 条死通道的去留（05 §3.2 D6/D7）。

## 二、设计约束（四约束 → 设计响应）

| # | 约束（证据） | 设计响应 |
|---|---|---|
| C1 | **async/sync 两栖**：async 侧 `agent/mod.rs:526`、`orchestrator.rs:345`；sync 侧 `tools.rs:26-48`（`ToolStreamSink` + `try_read` 失败静默丢弃） | 总线骨架**零 await**：`emit/bail/waterfall` 为同步方法；需要 await 的模式只给 `serial_async/parallel_async` 两个 async fn（同步短路需求由 `bail` 覆盖）。调用方按自己语境选入口，互不污染 |
| C2 | **会话隔离去重契约**：`commands.rs:769` `EMITTER_REGISTRY`（每会话一个 emitter）+ `event.rs:750` `Arc::ptr_eq` 去重 | 总线**不引入 per-session key 过滤**，去重单位仍是"监听器实例"：`on()` 内部保留 `Arc::ptr_eq` 判重，重复注册返回**已存在句柄**而非新增条目；会话隔离继续由 registry 承担（总线不做第二套隔离，否则前端 delta 重复渲染复发） |
| C3 | **防重入**：`ForwardToAgentBroadcaster`（`agent-commands/src/lib.rs:194`）把编排事件转投 AgentLoop 广播器 → emit 中再 emit | 分发前对监听器表做 **copy-on-write 快照**（分发中注册/注销延后到本轮结束）；分发上下文携带 `depth`，同一 key 递归超上限（常量 `MAX_DISPATCH_DEPTH = 8`）即丢弃 + `warn!`——与现有 `try_read` 丢弃策略同风格 |
| C4 | **droppable 语义**：工具流式 sink 的丢弃式行为必须保留（`tools.rs:26-48`、`raw_context.rs:30-60`） | 总线提供 `try_emit(&self, ev) -> bool`：订阅表 `try_read` 失败返回 `false` 且不阻塞、不追补。sync sink 走 `try_emit`，async 侧走 `emit`（等价于现有 `broadcast`） |

## 三、接口设计草案

### 3.1 事件 Key 与模式声明

模式是**事件的公开约定**（dsh `cordis-primer.zh.md:29`），必须在可静态枚举处声明。本项目事件是**封闭 enum**（`event.rs:24` `AgentEvent` / `:80` `OrchestratorEvent`，非 dsh 的 declaration merging），故取"事件类型关联表"而非"注册时声明"：

```rust
pub type EventKey = &'static str;               // 由变体名产出，如 "orchestrator/plan_created"

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DispatchMode { Emit, Bail, Serial, Parallel, Waterfall }

/// 单一声明点：新增变体必须在此登记模式，表驱动 + 单测穷举校验
pub const fn mode_of(key: EventKey) -> DispatchMode { /* 表驱动 */ }

impl OrchestratorEvent { pub fn key(&self) -> EventKey { /* 变体 → key */ } }
```

**取舍**：注册时声明（`on(key, Mode::Waterfall, l)`）更灵活，但把模式交给监听方写、易不一致且需运行期校验；表驱动让"某事件是 waterfall"成为一处事实，代价是新增变体要改一处 `match`（变体数 67，封闭 enum，成本可控）。

### 3.2 监听器与 disposer

对齐 dsh "注册即 effect、注册可逆"（`cordis-primer.zh.md:13`）：

```rust
pub struct Disposer { bus: Weak<EventBus>, key: EventKey, id: ListenerId }
impl Drop for Disposer { fn drop(&mut self) { /* 注销 */ } }   // Drop 即注销

impl EventBus {
    /// 注册；同一实例（Arc::ptr_eq）重复注册返回既有 disposer（对齐 event.rs:750）
    pub fn on(&self, key: EventKey, l: Arc<dyn Listener>) -> Disposer;
    pub fn once(&self, key: EventKey, l: Arc<dyn Listener>) -> Disposer;   // 首次调用后自动注销
}
```

### 3.3 五模式分发

```rust
pub trait Listener: Send + Sync {
    /// 普通模式（emit/bail/serial/parallel）入口
    fn call(&self, ev: &OrchestratorEvent) -> ListenerOutcome;

    /// waterfall 专用入口：末参为 `next`（包围下游）
    fn call_waterfall(&self, _ev: &mut OrchestratorEvent, next: Next<'_>) -> Outcome { next.run() }
}

/// bail 语义：非 Null/非 false 视为否决（对齐 events.ts:13-15 `isBailed`）
pub enum ListenerOutcome { Continue, Bail(BailValue) }
pub enum Outcome { Ok(SlotValue), Vetoed }

pub struct Next<'a> { chain: &'a [Arc<dyn Listener>], idx: usize, key: EventKey, depth: u8 }
impl<'a> Next<'a> {
    /// 调下游；链尾为"内建默认行为"（dsh waterfall 的 innermost next）
    pub fn run(self, ev: &mut OrchestratorEvent) -> Outcome { /* 递归取下一个 */ }
}

impl EventBus {
    pub fn emit(&self, ev: &OrchestratorEvent);                    // 同步，忽略返回值，不 await
    pub fn try_emit(&self, ev: &OrchestratorEvent) -> bool;         // C4：不可用即丢
    pub fn bail(&self, ev: &OrchestratorEvent) -> Option<BailValue>;      // 同步串行，首个 bail 值停（= dsh bail）
    pub async fn serial_async(&self, ev: &OrchestratorEvent) -> Option<Outcome>;   // 顺序 await，首个 bail 停（= dsh serial）
    pub async fn parallel_async(&self, ev: &OrchestratorEvent) -> Vec<Result<Outcome, BusError>>;
    /// inner = 调用方提供的链尾内建兜底（对应 dsh 的 innermost next）
    pub fn waterfall(&self, ev: &mut OrchestratorEvent, inner: Next<'_>) -> Outcome;
}
```

**"末参 next"在 Rust 的落地**：用 `Next<'a>` 包装 `&[Arc<dyn Listener>] + 游标`，避免 `Box<dyn FnOnce>` 的堆分配与生命周期纠缠；"不调 `next` 即否决、返回值经 `next()` 向外传"由 `Next::run` 的返回值逐层上抛实现（对应 `events.ts:234-243`）。**`&mut OrchestratorEvent` 即"可改写负载"位点**——这正是 05 §2.4 指出的缺失契约（`EventListener` 只读，`tool_hook.rs:41-48` 的 `on_post_use` 也早于裁剪），裁剪迁移前须先按 §2.4 红线补"广播前同步预处理"契约。

> **兑现记录（2026-09-17）**：可改写负载位点已两次真实消费——① A3 输入准入 `InputAdmission`（改写/丢弃/否决）；② **第二段迁移 `ToolResultPreBroadcast`**（工具结果裁剪：链尾内建 = 现行裁剪，监听器可改写 `result`，否决走调用方兜底裁剪；三条红线：同步 / 单副本 / 广播前）。实施见 [04-§七](04-施工准备.md)。

### 3.4 async/sync 两栖三案取舍

| 方案 | 描述 | 结论 |
|---|---|---|
| **A 骨架同步 + async 变体** | `emit/bail/waterfall` 同步；仅 `serial_async/parallel_async` 为 async | **采用**：sync 调用点（`tools.rs:26-48`、`loop_control.rs:365`）零改动语义；async 侧（`mod.rs:526`）改调 `emit`（本来就不 await）或 `serial_async` |
| B 单一 `Pin<Box<dyn Future>>` | 全部 async | 否决：sync sink 被迫 `block_on` 或引入 runtime 假设，破坏 C4 |
| C 仅 async + 同步路径留旧接口 | 新总线只给 async，sync 继续用旧 `broadcast` | 仅作 §4 第一步的**过渡形态**，不作终态（否则两套语义长期并存） |

## 四、兼容路径（两步走）

05 §3.1 已裁定"先等价、后换签名"，本页落实为可验收的两步。

**第一步：旧 API 内嵌新总线（零行为变更）**
`EventBroadcaster` 结构与公开方法签名不变，内部 `listeners: Vec<Arc<dyn EventListener>>` 替换为 `EventBus` 的单一 slot（全部以 `Emit` 模式注册）；`broadcast()` 实现为 `bus.emit()`。
验收点：① `cargo test -p agent-kernel -p agent-commands` 全绿；② `subscribe` 的 `Arc::ptr_eq` 去重语义不变（`event.rs:750`）；③ `ForwardToAgentBroadcaster` 的 `try_read` 丢弃行为不变（`agent-commands/src/lib.rs:196-198`）；④ 新增单测：注册顺序 = 分发顺序、0 监听器静默、分发中注册不作用于本轮、递归 depth 超限丢弃。

**第二步：统一换签名（13 个 impl 一次性改）**
`EventListener::on_event(&self, &OrchestratorEvent)` → `Listener`（按 key 注册 + 模式化返回值）。涉及 4 个生产 impl（`agent-commands/src/lib.rs:194`、`agent-kernel/src/agent/backend_bridge.rs:16`、`apps/tauri/src-tauri/src/commands.rs:252` 与 `:1830`）+ 9 个测试 impl（`agent/tests.rs:1089/1243/1709/1905`、`agent-commands/src/lib_tests.rs:1060`、`subagent_tests.rs:244`、`loop_control_tests.rs:47`、`agent-commands/tests/e2e_llm.rs:1789`、`orchestrator.rs:1267`）。
验收点：① 13 impl 全编译；② 前端快照 `turnModel.spec.ts:989-1047` 不变；③ 13 条带监听的 Tauri 通道 payload 逐字段比对（05 §1.3）。

> **实施状态（2026-09-17）：已完成（实迁 16 个 impl）。** 实施要点与偏离记录：
> - **trait 换代**：`Listener`（`call` → `ListenerOutcome { Continue, Bail }`；`call_waterfall` → `Outcome { Ok, Vetoed }`，默认实现透传）+ 同步 `Next`（箱装 `FnOnce` 链尾）。
> - **key 机制**：`EventKey`（`&'static str`）+ `event::keys` 常量模块（66 项）+ `AgentEvent::key()` / `OrchestratorEvent::key()` 穷尽 match（无 default——新增变体编译期强制登记）+ `mode_of()` 单点声明（U1 表驱动的最简形态：当前全 `Emit`，非 Emit 事件迁移时在此登记）。
> - **注册**：`EventBus::on`（精确）/ `on_any`（全量），全局注册顺序 = 分发顺序，判重按 `(key, 实例)`；**命名偏离（对 §3.2 草案）**：对外壳 `EventBroadcaster` 保留 `subscribe` / `broadcast` 旧名（仅换参数类型），新增 `subscribe_key`——理由：三层封装（AgentLoop / Orchestrator / LoopControlEntry）订阅调用面 ~20 处、广播调用面 ~50 处，改名无行为收益；机制层（`EventBus`）沿用 `on` / `on_any` / `emit` 新名。`EventBroadcaster` 同步暴露 `bail` / `waterfall` 透传。
> - **分发实现**：`emit`（等价原 broadcast）/ `bail`（同步串行、首个否决短路、返回 bool）/ `waterfall`（同步环绕；`&mut OrchestratorEvent` 即 05 §2.4 的"可改写负载"位点）。**serial / parallel 分发方法缓做**（无场景，U2 减法精神；`DispatchMode` 声明层保留五模式，`mode_of` 中登记后即补——见 §七 U6）。
> - **深度防护细化**：仅分发入口（emit / bail / waterfall）计深度；waterfall 链行进（`Next::run`）**不计**——否则长链（>8 监听器）会误触上限（新增契约测试锁定）。
> - **impl 数修正**：草案估 13 个，实迁 **16 个**（首迁新增的 `PlanEventEmitter` 与骨架测试 2 个在内）——生产 5（`commands.rs` 主 emitter / PlanEventEmitter / LoopControlTauriEventListener、`agent-commands/lib.rs` ForwardToAgentBroadcaster、`backend_bridge.rs`）+ 测试 11。
> - **验收**：① 16 impl 全编译（kernel / commands / src-tauri `cargo check` 全链）；② 前端快照 turnModel **73/73** 通过；③ payload 逐字段核对——本次迁移对 payload 构造代码逐字未动（仅签名与返回值），代码审查确认。
> - **测试**：新增 10 项契约测试（key 过滤 / on_any 全收 / bail 短路 / bail 无人否决 / waterfall 环绕序 / waterfall 否决跳链尾 / **waterfall 可改写载荷** / 链含 on_any / 判重按 key / 长链不触深度上限）。基线：kernel **239/239** · commands **169/169** · patterns **117/117**。
> - **锁纪律（2026-09-17 风险点处置）**：监听器表**内部化**（`std::sync::RwLock` 只护表，注册改 `&self`）；`emit` / `bail` / `waterfall` **先取快照、再于不持表锁的前提下运行链**——C3「分发中注册不作用于本轮」由此从"不可能发生"变为**可实现语义**（注册即时完成、延后下一轮）；`EventBroadcaster` 改持 `Arc<EventBus>` + `handle()`，调度方（`AgentLoop` / `GenaiBackend` / `ConfirmationBroker` / `BackendEventBridge`）**先释放壳锁再分发** → 长链 / 链内 I/O 不再阻滞写者、`try_read` 型转发监听器不再因写者排队静默丢事件。契约测试：链内注册即时完成 + 不作用于本轮 + 下一轮生效（kernel **280/280**）。

## 五、首迁落地草图：Plan 事件族

> **实施状态（2026-09-16 首迁；2026-09-17 升级为精确订阅）：已完成。** 消费者侧迁至独立监听器 `PlanEventEmitter`（`apps/tauri/src-tauri/src/commands.rs`：新增结构 + 删主 emitter 三分支 + `ensure_emitter_registered` 一并订阅、每会话一个实例）；**第二步后升级为 3 key 精确订阅**（`subscribe_key` × PLAN_CREATED / PLAN_STEP_UPDATE / PLAN_REPLANNED，从"全量订阅 + match 自过滤"收敛为"按 key 精确接收"——首迁示范的完整形态）。发射点无需改（`broadcast` 已即 `bus.emit`）；`trace_summary`（同文件 `:172-179`，另一职责）保留于主 emitter 不受影响。验证：src-tauri `cargo check` 全链 + agent-kernel **229/229**（首迁时；第二步后 **239/239**）+ 前端 turnModel 快照 **73/73**。

**改什么**
- 发射点：`agent/tools.rs:174/193/252`（全在同一函数 `apply_plan_result`）→ `self.broadcast(..)` 改 `self.bus.emit(&ev)`；保留既有次序（先写 `state.plan`（`:173`/`:250`）后 emit，`PlanStepUpdate` 的 `drop(state)` 位置不动）。
- 模式声明：`PlanCreated | PlanStepUpdate | PlanReplanned` → `DispatchMode::Emit`（05 §1.5：不需要 waterfall/bail 表达能力）。
- 消费者：`commands.rs:588/597/615` 三个 match 分支改按 key 注册的三个监听器，函数体（`emit_dual` 调用）原样搬移，双路发射不得绕过。

**测什么（契约测试要点）**
1. **emit 等价**：迁移前后同一事件序列在监听器侧观察到的条数/顺序一致，且 `PlanStepUpdate` 观察到时 `state.plan` 已更新。
2. **订阅去重**：同一 emitter 实例二次 `on()` 不产生重复投递；两个不同实例（模拟每会话）各自收到一份，与 `commands.rs:769` registry 策略对齐（历史踩点：前端 delta 重复渲染）。
3. **async/sync 共存**：在 `apply_plan_result`（async 语境）与一个 sync sink 语境同时注册监听器，emit 不 panic、不丢事件。
4. **回滚成本**：三处调用点 + 一个函数 + 一组 emitter 分支，单 commit 可 revert。

## 六、未决问题（需上级裁定）

- **U1 模式声明方式**：表驱动（本页建议，编译期严、单点事实）vs 注册时声明（灵活、需运行期校验）。建议表驱动——封闭 enum 下成本低于收益。
- **U2 同步 waterfall 是否需要**：现有 waterfall 目标场景（审批拦截 `confirmation.rs:458-481`、结果裁剪 `tools.rs:579/725`）都处 async 语境。若确认无同步 waterfall 需求，则**只做同步 `Next`、不做 `NextAsync`**，省一层复杂度。
- **U3 模式不一致的处理强度**：监听器注册的 key 与 `mode_of` 冲突时 `panic!`（fail loud）还是 `warn!` + 以静态表为准？建议 warn：前端 emitter 在另一个 crate，panic 会波及 UI 线程。
- **U4 死变体/死通道（05 §3.2 D6/D7）**：清理则静态表少 13 项 key；不清理则表内以 `Emit` 兜底保留。需与 D6/D7 合并拍板。
- **U5 分发深度上限**：`MAX_DISPATCH_DEPTH` 取常量 8 + warn（安全不变量，按项目约束不做成配置项），确认即可。

## 七、评审结论（2026-09-16，执行方裁定）

> §六 未决问题的裁定——均属设计细节层，按此进入实现；如需推翻请提出。

| # | 裁定 | 依据 |
|---|---|---|
| U1 | **表驱动**（`mode_of` 单点声明） | 事件是封闭 enum（67 变体），表驱动让"模式"成为一处事实；注册时声明会把模式交给监听方写、易不一致 |
| U2 | **只做同步 `Next`，不做 `NextAsync`** | 目标场景（审批 `confirmation.rs:458-481`、结果裁剪 `tools.rs:579/725`）均在 async 语境中调用同步 waterfall——可直接调用，无需 async 版本，省一层复杂度 |
| U3 | **`warn!` + 以静态表为准** | 前端 emitter 在另一个 crate，跨 crate `panic!` 会波及 UI 线程；fail loud 的收益不及稳定性 |
| U4 | 与 05-§3.2 D6/D7 联动（用户已拍板"首迁时顺带逐个裁定"）：**静态表先以 `Emit` 兜底保留 13 项 key**，首迁时逐个裁定去留 → **2026-09-17 裁定落地：清 15（含实施期新发现的 MultiAgent 4）、留 A2UI 2**（见 [04-§七](04-施工准备.md)） | 避免清理与实现互相阻塞 |
| U5 | **`MAX_DISPATCH_DEPTH = 8` + `warn!`**，常量不做配置项 | 安全不变量按项目约束不做成 tunable |
| U6 | **serial / parallel 分发方法、Disposer / once 可逆注销缓做**（2026-09-17 第二步实施记录补裁） | 无场景（施工纪律"每项须有立项理由"+ U2 减法精神）；`DispatchMode` 声明层保留五模式；U3 模式冲突校验随首个非 Emit 事件迁移落地 |
