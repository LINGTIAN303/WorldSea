# 提取融合方向探究

> status: 已完成
> 方向定义（用户原话）：**「提取融合」——确认该项目的架构、链路、包、语言、机制等方面是否可以提取并替换本项目的一些实现。**
> 前置事实：[本项目 Agent 现状盘点](01-本项目Agent现状盘点.md)（可替换面 / 硬边界清单）。
> 参照项目：deepseek-harness（`dsh`，TypeScript / Node、MIT、开发者预览期），本地路径 `.独立项/【参考项】deepseek-harness/`。
> 取证方式：四路只读探索；关键论断附 dsh 文件路径。未改任何代码。

## 零、结论

**可以提取——但"提取"的形态是「设计/契约移植」，不是「代码搬运」。**

三句话概括：

1. **语言鸿沟是硬边界**：dsh 是 TypeScript/Node，本项目是 Rust；两边没有任何可直接复用的运行时制品。一切的"提取"都是把 dsh 的**协议、边界、语义**用 Rust 重新表达。
2. **好消息**：dsh 的核心资产恰好集中在"设计层"——它全仓的骨架（注册即 effect 的所有权模型、事件五模式、日志唯一事实源、能力缝隙三角色、fail-closed 审批）都是**跨语言的**，与 TS 语法糖无关。
3. **替换对象明确**：提取后能替换的本项目实现，正是[现状盘点 §3.1](01-本项目Agent现状盘点.md#31-可替换--可丢弃引擎层外部引擎能覆盖的)列出的引擎层；领域层（实体/芽/A2UI/规则/场景/记忆/群聊）不受影响，也不需要"提取"。

**分级结论**：

| 级别 | 内容 | 建议 |
|---|---|---|
| A 级（应提取） | 事件契约与工具执行管线、会话日志纪律、输入模型与取消语义、系统提示组装契约 | 逐条移植为 Rust 设计，替换现有对应实现 |
| B 级（值得借鉴） | 作用域注册、审批/sandbox 契约、LLM 错误分类、运行时不变式、扩展性归属表 | 结合本项目体量择机吸收，不做全量对位 |
| C 级（不适用） | HMR/热重载、PTC 运行时、声明合并/Proxy 类型技巧、vendored Cordis 本体、Electron 私有层 | 明确排除，避免盲目对位 |

## 一、语言与运行时鸿沟的定性

### 1.1 能跨的（设计层）

判断一条机制能否跨语言，问它是否依赖：**运行时可替换模块 / 动态类型 / 原型链 / 模块缓存**。答案是否定，则它是"设计层"，Rust 可比一重实现。

dsh 中最有价值的几条全部通过这个测试：

| 机制族 | 核心智慧（与语言无关） |
|---|---|
| 注册即 effect | 每次注册返回 disposer、归属某个 owner、owner 卸载即批量撤销（Rust 用守卫对象 + 注册表 owner 字段表达） |
| 事件五模式 | emit / waterfall（末参 next、不调即否决）/ bail / serial / parallel 的**语义差别**——特别是 waterfall 的"环绕中间件"与 serial 的 bail 判定 |
| 三层事件域 | 会话事件（持久事实）/ agent 事件（活体拦截）/ 能力事件（策略挂钩，不 import 循环）——这是纯架构决策 |
| 日志唯一事实源 | "模型可见 ⟺ 已记录"不变量 + 派生历史（deriveMessages 而非可变历史） |
| 能力缝隙三角色 | Service Definition / Provider / Consumer 必须三合一才算一条缝隙 |
| fail-closed 契约 | 审批四值结果中三个视为拒绝；单调 guard 不可被后续 listener 翻案；错误按 code 路由不解析 message |
| 数据驱动收敛 | turn 关闭由 steer 数据决定，不受 listener 顺序影响 |

### 1.2 不能跨的（实现层）

| TS/Node 特性 | dsh 中的用法 | Rust 的替代品（或放弃） |
|---|---|---|
| 声明合并（declare module） | 类型级扩展 SessionEventMap、工具契约推导 | Rust 无直接对应；用枚举 + 版本化 schema 表达 |
| Proxy / prototype 链 | 上下文对象、作用域影子映射 | 显式结构 + 注册表 |
| AsyncLocalStorage | 发起方作用域 | tokio `task_local!` 或显式传参 |
| ESM/CJS 模块缓存 + HMR | 插件热重载 | 放弃（本项目为编译期装配，天然无此需求） |
| 生成器 yield disposer | effect 的清理项收集 | 显式 Vec<Box<dyn FnOnce>> |
| PTC 运行时（run_code + TS/Python 类型剥离执行） | 模型写代码执行 | 不适用（Node/Python 生态绑定） |

**结论**：本项目的 Rust 侧不存在"拿来即用"的可能；但不存在"设计不可达"的机制。提取的产物是**设计文档 + Rust 重实现的工程量**，而非依赖引入。

## 二、机制清单与逐条评估（核心）

> 落点判断依据：[现状盘点](01-本项目Agent现状盘点.md) 的模块清单；成本为主观直觉（改动面量级），非时间估计。

### 2.1 A 级：应提取（替换现有引擎层实现）

| # | 机制 | dsh 设计要点 | 本项目落点 | 替换/融合方式 | 成本直觉 |
|---|---|---|---|---|---|
| A1 | **事件五模式 + 工具执行三瀑布** | `emit/waterfall/bail/serial/parallel` 五模式；工具固定流水线 `tools/pre-execute`（可重排 allow/deny/ask）→ 单调 guard（deny 不可翻案）→ `tools/execute`（环绕：超时/重试/指标）→ `tools/post-execute`（替换结果/阻止/附加上下文）→ 只观测的 `tools/result`；任何抛出规范化为 isError，**失败不结束 turn** | `crates/agent-kernel/src/event.rs`（现为 60+ 变体指令式广播）+ `agent/tools.rs`（现为串并行分流 + 硬编码确认逻辑） | 新建 Rust 动态事件总线（`EventKey → Vec<Listener>`，模式枚举 + `next` 环绕签名）；把审批、超时、结果裁剪、日志改造成**监听器**而非硬编码 | 基础设施约数百行；难点在异步 waterfall 的 Rust 表达（`Pin<Box<dyn Future>>`）与模式纪律（模式写进事件声明） |

| A3 | **inbox 三通道 + pre-step 准入 + 协作式取消** | `followup`（唤醒）/ `steer`（唤醒，最近 step 消费）/ `inject`（**不唤醒**）三语义正交；`agent/pre-step` waterfall 决定"这条输入是否进模型"（拒绝或空首条 → 关闭无 step 的 turn）；`cancel(keepInbox)` 保留已交付文本并记录中断锚点 | `crates/agent-kernel/src/agent/mod.rs` 的 RunPhase 五站位（现为硬编码阶段位） | 把"输入准入"从阶段位升级为可插拔决策点；把"插话/注入"语义显式化（压缩触发、指令注入、时间上下文都挂在 pre-step） | 中等；改动集中在内核循环，但语义收益大（可解释性） |
| A4 | **系统提示组装契约** | 段（section）= `{name, order, text, interpolate?}` 按 order 排序拼接；`{{var}}` 未知引用**抛错**（宁失败不给畸形提示词）；toolOrder 含唯一 `<unlisted-tools>` 占位；AGENTS.md 指令链注入有字节预算与"先省宽泛、最后截断具体"规则 | `crates/agent-kernel/src/agent/memory.rs:92` `build_prompt_options`（四段拼接）+ TS 侧 `useAgentRust.ts` 的规则/技能拼装（**职责分散双端**） | 统一为段式组装器，落一项契约：**未知变量引用即报错**；把双端拼装收敛到单一组装点 | 低—中；纯数据结构与排序逻辑，几乎无语言依赖，可快速收口技术债 #7 |
| A5 | **LLM 适配 seam 的契约细节** | provider 无关词汇（Message/ContentBlock/StreamChunk）；每个流**恰好一个终止 finish 分片**；失败用稳定 code（`NO_ADAPTER/MISSING_CREDENTIAL/AUTH/RATE_LIMIT/CONTEXT_WINDOW_EXCEEDED/QUOTA/EMPTY_RESPONSE/INVALID_CREDENTIAL/IMAGE_OFFLOAD_REQUIRED`），**按 code 路由不解析 message**；重试不属于本层 | `crates/agent-kernel/src/llm/genai_backend.rs`（含多 Key 降级；错误处理散落） | 补错误分类枚举 + 按 code 的策略路由（重试/降级/压缩触发/用户提示四路分流） | 低；主要是枚举定义与调用点改造 |

## 三、替换面映射（逐块对照）

> 口径：**替换 = 用移植的机制改写现有实现**；**融合 = 提取机制后与现有资产共存**；**不动 = 领域层资产**。

| 本项目现有实现 | dsh 对应机制 | 方式 | 备注 |
|---|---|---|---|
| ReAct 循环 + RunPhase（`agent/mod.rs`） | turn/step 循环 + pre-step 准入 + inbox | 替换 | 保留 RunPhase 作为可选钩子位，不保留硬编码语义 |
| 事件广播（`event.rs` 60+ 变体） | 事件五模式 + 三层事件域 | 替换 | 前端 `turnModel.ts` 需配套转换层（见[现状盘点 §3.3](01-本项目Agent现状盘点.md#33-需桥接面引擎更换时不可省略的接线)） |
| 工具执行（`tools.rs` 串并行 + 硬编码确认） | 工具三瀑布 + 单调 guard | 替换 | 审批/裁剪/超时/日志外置为监听器 |
| 上下文压缩（`enforce_context_budget` + 折叠锚点） | compaction（已在 [misc 调研](../../../misc/deepseek-harness-调研与借鉴方案.md) 专章） | 融合/裁定 | 与本项目"折叠 + 锚点回填"机制重叠，需先裁定取舍 |
| 会话存储（`session_log/live`） | Session 事件溯源 + surfaceOp | 融合 | 方向已正确，补"请求可重建"与崩溃修复 |
| Prompt 组装（Rust 四段 + TS 双端拼装） | 段式组装契约 + 指令链预算 | 替换 | 重点收口双端分散（技术债 #7） |
| 编排骨架（`agent-patterns` 13 模式） | 无直接对应（dsh 无 orchestrator 概念，`workflow` 是模型写脚本） | 保留待评估 | dsh 不提供替代品；编排线去留取决于产品需求，不由本方向决定 |
| MCP 实现（rmcp 3.1.4） | `mcp` 包（工具面） | 不动 | 两边都是标准协议客户端；本项目实现已闭环 |
| Skills 协议栈 | `skill` 包（SKILL.md 同源标准） | 融合 | 可对齐目录契约与渐进披露细节 |
| 长期记忆（agent-memory + agent-index） | **无对应物**（dsh 无记忆系统） | 不动 | 这是本项目独有资产（dsh 最近的替代物是 goal + session-query，不等价） |
| 实体/芽/A2UI/规则/场景/群聊 | 无对应物 | 不动 | 硬边界，见[现状盘点 §3.2](01-本项目Agent现状盘点.md#32-硬边界不可替代外部引擎不认识必须自留) |

## 四、成本与风险

### 4.1 成本形态（改动面量级）

| 项 | 改动面 |
|---|---|
| Rust 动态事件总线（基础设施） | 新增模块；`event.rs`、`tools.rs`、`confirmation.rs`、`loop_control` 等改造为事件消费方 |
| 内核循环语义升级（A3） | 集中在 `agent/mod.rs`（1282 行）；会牵动 118 个服务层方法与部分命令 |
| Prompt 组装收口（A4） | Rust + TS 双端（`memory.rs` + `useAgentRust.ts:2543-2650`）各改一处 |
| 会话日志纪律（A2） | `session_store.rs`（2126 行）+ 前端回源归约器 |
| 测试重建 | 事件契约变更会使现有事件相关断言失效；需补"按模式分发"的契约测试 |

### 4.2 风险清单（不自动处理，供决策）

| # | 风险 | 影响 | 缓解建议 |
|---|---|---|---|
| R1 | **"越抄越像"陷阱**：逐条移植可能演变成"用 Rust 重写一个 dsh" | 工程量失控，且失去本项目领域优势 | 严格限定 A 级清单；每项机制必须有"本项目为什么需要"的一行理由 |
| R2 | ~~机制重叠冲突：A2（replace 遮蔽）与"折叠 + 锚点回填"二选一~~ **已澄清（2026-09-16 现场调查）：两者语义同构、非冲突**——`session_log`（不可变原文）+ `session_live`（游标可重写）+ 折叠/锚点/外置，与 dsh 的"日志 + surfaceOp + replace"等价；改为补齐三项（触发时机 / 事务 / 事件化），见 [04-§一 A2](04-施工准备.md) | 无需裁定 | 已处置 |

| R4 | **上游漂移**：dsh 处于开发者预览期，机制细节可能变化 | 已移植设计可能过时 | 锁定调研快照（本地已下载版本）；机制移植后以本项目文档为准，不再跟随 |

| R6 | **领域面优先级被挤压**：引擎重构吸引全部注意力，实体/芽/A2UI 的产品演进停摆 | 产品方向受损 | 明确"引擎是手段"，重构排期不得挤占领域线 |

## 五、结论与建议（待拍板）
