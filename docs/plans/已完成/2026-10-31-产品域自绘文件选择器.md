# 产品域自绘文件选择器（File Picker）批计划

> 目标：产品域全部「选本地文件 / 选目录」入口由系统原生对话框改为自绘选择器，视觉跟随三套风格（mist / 磨砂巧克 / neu）与深浅色；保留系统对话框作边界场景兜底。
> 注释说明见 [FilePickerHost.md](../../details/注释/tauri/components/FilePickerHost.md) 与 [FilePickerApi.md](../../details/注释/packages/entity-core/core/FilePickerApi.md)。

## 一、背景

Tauri 的 `plugin-dialog` 封装的是 **OS 原生选择器**，官方无任何主题/样式定制项——不存在「保留原生行为、只改外观」的中间态。产品域在磨砂巧克、新拟态下点「上传/导入/导出」会突然弹出白色系统窗口，视觉断层明显。

## 二、已定口径（用户拍板 2026-10-31）

| 项 | 裁定 |
|---|---|
| 覆盖范围 | **全入口收编**（2 处 `plugin-dialog` + 13 处 `<input type="file">`） |
| 原生兜底 | **保留**——面板内提供「用系统对话框」按钮 |
| 新增命令 | **批准** `cmd_fs_drives`（只读盘符枚举 + ACL 条目） |
| 架构门禁 | **不动基线，保证不新增**（存量 18 项红另立批处理） |
| 交付节奏 | **分阶段**，批 0 后先真机走查 |

## 三、入口底账（施工前核实）

**2 处 `plugin-dialog`**
- `packages/entity-core/src/core/assetImport.ts` — 选资产文件（带扩展名过滤器 + 分级大小上限）
- `packages/entity-core/src/core/ProjectFS.ts` — 选项目导出/导入目录

**13 处 `<input type="file">`（11 文件）**
`FileTreeBrowser.vue`×2 · `MindmapView.vue`×2 · `NotebookEditorToolbar.vue` · `EditorToolbar.vue` · `BookInfoDialog.vue` · `HomePanel.vue` · `IconAssetsCard.vue` · `IconPicker.vue` · `plugin-sdk/ImageField.vue` · `ui-kit/ImportExportModal.vue` · `ui-kit/AppearancePanel.vue`

`save()` 零调用——项目导出是「选目录后写入」，不需要「另存为文件名」模式。

## 四、架构

```mermaid
flowchart TD
  A["调用点 15 处<br/>entity-core / plugin-sdk / ui-kit / apps"] -->|getFilePickerApi().pick| B["entity-core<br/>FilePickerApi.ts<br/>接口 + 注入槽 + noop 兜底"]
  C["apps/tauri<br/>composables/filePickerApi.ts<br/>队列实现"] -.注册.-> B
  C --> D["FilePickerHost.vue<br/>Shell 挂载一次"]
  D -->|cmd_fs_list / cmd_fs_drives| E["Rust 壳"]
  D -->|「用系统对话框」| F["plugin-dialog 原生兜底"]
```

三条约束决定此形状：
1. `entity-core` 不能依赖 `ui-kit`（架构白名单只有 core-api-types / perf-kit）→ 接口必须下沉。
2. 3 个调用点在 packages 内，不能依赖 apps → 注入是唯一通路。
3. **返回绝对路径而非 File**：资产与文件树直接走路径直传；其余链路用 `pathToFile()` 适配，下游业务逻辑不动。

## 七、风险点（需用户决定，不自动处理）

1. **`arch:check` 存量 18 项仍红**（含 `fs_commands.rs` 543>515、`FileTreeBrowser.vue` 998>966、`ImportExportModal.vue` 696>516）。本批按裁定只保证不新增；批 2/3 会碰到这些超限文件，需等量替换而非增行。**代价**：门禁本批结束后仍红，需另立批处理存量债。
2. **边界场景无法追平**：UNC/网络盘、OneDrive 云端占位文件、长路径 >260、junction 循环、权限拒绝目录、可移除盘热拔。靠「用系统对话框」逃生，自绘侧做降级提示而非硬扛。
3. **`pathToFile` 的 30MB 上限**：字体与视频已解决——新增 `pathToArrayBuffer`（asset 协议 `fetch` 直读，无 IPC 编码开销），字体导入已切过去，视频本就走 `importAssetByPath`。**无需改 `font-kit` API**。
4. **`cmd_fs_list` 无条目上限**：巨目录一次性返回全量，虚拟滚动只兜住渲染。取数上限留作后续优化。
5. **既有测试红灯（与本批无关）**：`packages/ui-kit/src/components/settings/panels/__tests__/appearancePreviewCard.spec.ts` 因 `vitest.config.ts` 缺 `@worldsea/style-kit` 别名而失败（`apps/tauri/vite.config.ts` 里有该别名）。`AppearancePanel.vue` 本批未改（`git diff` 为空），属 HEAD 既有配置缺口，**未修**。
6. **安全面**：`fs_commands.rs` 头注已写明路径来自可信前端、不做 workdir 边界。本批只新增只读 `cmd_fs_drives`，不扩大读写权限；`tauri.conf.json` 的 `csp: null` 是既有风险，不在本批范围。
