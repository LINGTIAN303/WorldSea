# 信息密度增强 · 批计划（五视图配置化）

> 立项（2026-10-19）：大纲白板五视图（表格式 / 树式 / 线索式 / 进度式 / 关联实体）的功能线已收盘，
> 用户拍板下一项为**信息密度增强**。本批**只做「显示多少」可配置**，不改五视图的聚合语义与写入路径。

## 一、目标与边界

- **目标**：把「显示多少信息」从硬编码或固定值变成配置项，让同一形式在小卡片与大容器上都能用。
- **边界**：只改 `apps/tauri/src/world/plugins/outline/board/forms` 与配置面板；
  不改实体 schema、不改布局协议、不新增表现形式、不改任何写入入口。
- **默认值原则**：一律保持现状——旧板子升级后观感不变，用户主动调才变。

## 三、技术决策

1. **`multi-select` 是通用配置类型，不是表格专用**：
   - 值为 `string[]`；面板渲染为 checkbox 组，按 `options` 声明顺序输出（避免勾选顺序影响列序）。
   - 增加可选 `minSelected`：表格列设 1，保证不会选空。
   - `resolveFormConfig` 对数组值做浅拷贝，避免多个组件共享同一个默认数组。
2. **表格新增两列**（用户拍板）：`nodeType`（英文四值→中文标签）与 `storylines`（原样显示，空值占位）。
   旧配置的 `columns` 保持原顺序，新选择的列按固定顺序排列。
3. **树式的展开层数只影响「初始展开」**：手动展开/折叠仍是会话态；配置变更时重置到新的初始层数。
4. **`initializeForms.ts` 已 374 行**，再加五视图配置会突破 400 行硬上限 → 按「内容型 / 聚合型」拆为
   `initializeForms.ts`（内容型 6 种）+ `initializeAggregateForms.ts`（五视图 5 种），共享选项常量抽到
   `formOptions.ts`。拆分为硬上限所迫，不改变注册表契约。
5. **`BoardInspector.vue` 当前 406 行，基线冻结 521 行**，多选渲染直接在原地增加（预计 +35 行），不新增子组件。

## 六、有意不做

- **跨形式统一「紧凑 / 标准 / 宽松」档位**：各形式的密度轴不同，统一档会牵动全部布局，风险大于收益。
- **表格列拖拽排序**：本批固定顺序 + 勾选；顺序自定义留待确有需求时立项。
- **表格虚拟滚动 / 树式懒加载**：属独立性能项（施工分解 §十三 B 类），不在本批。
- **新增数据字段**：`columns` 只从已注册字段（`name` / `order` / `status` / `wordCount` / `nodeType` / `storylines`）中选。

## 七、风险

1. **配置面板回归**：`BoardInspector` 是五视图共用入口，多选分支必须放在 `select` 之后、`text` 兜底之前，
   否则会把 `select` 落进文本输入。
2. **默认数组共享**：`resolveFormConfig` 的浅拷贝会让默认 `columns` 被多个容器共享；必须在解析时克隆。
3. **拆分注册文件**：迁移五视图定义时容易漏 `defaultConfig` 键或改错 `form` 标识；靠 `formsRegistration.spec` 守卫。
4. **空列选择**：`normalizeColumns([])` 会回退默认三列（既有语义），面板用 `minSelected: 1` 从入口挡住。
