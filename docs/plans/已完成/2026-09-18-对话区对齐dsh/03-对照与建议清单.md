## 三、建议清单

### 对话区（C）

#### C1 对话区性能门禁（基准 + 预算）【新增·质量基建】

- 现状：无对话区基准与预算（§1.2 末行）；dsh 以 5 个 benchmark 目录 + 源码常量预算（环境变量不可覆盖）+ 校准公式 `ceil(期望×2×1.25)` 压 CI，并用「流式中输入重叠必须为真、DONE 后必须为假」这类**语义断言**锁行为。
- 建议：建本侧等价物（脚本 + 预算常量，先本地 gate 后接 CI）——三条路径起步：① 会话首开/重开（记录 markdown 渲染与归约两段耗时）② 长会话滚动/窗口化 ③ 流式 delta 消费（输入响应不及时长）。预算取「本机基线 × 系数」固化。
- 验收：脚本可重复跑、预算写死、回归即红；附一份基线报告。

#### C2 流式 Markdown 块级增量渲染【增强·性能】（本轮重点）

- 现状：每次 rAF **整段** `marked.parse` + DOMPurify + mention 注入（`useMarkdownRender.ts:276-283`）；ThinkRow 亦整段插值；Prism 高亮同步（阻塞渲染线程）。
- dsh 参照：流式路径不重解析已完成前缀；高亮由单一 IntersectionObserver 按视口触发；未闭合围栏走降级（本侧已有该降级）。
- 建议：① **分块器纯函数化**——按 Markdown 块边界（段落 / 围栏 / 列表 / 表格）切分，已完成块缓存解析结果，仅重渲「活动尾块」；② 高亮移出同步热路径（视口触发或 idle——perf-kit 的 `createIdleRaf` 零消费方正好可接线）；③ mention 注入按块局部化。
- 验收：契约测试（**增量结果 ≡ 全量结果**不变量：任意切分下拼接一致）+ 量测（长回答流式 CPU 时间与掉帧对比）+ 真机走查（长代码回答流式流畅、无闪烁）。

#### C3 「虚拟滚动断线」裁定【决策项·登记】

- 现状：`useVirtualList` 零消费方、`KanbanView.vue` 空占位 = perf-kit 遗留断线。
- dsh 参照：**Chat 也不做虚拟滚动**——keyed memo seat + 只渲染已加载窗口 + 过程行折叠；虚拟化仅用于 Trajectory（初始 50 节点 + overscan）。

#### C4 渲染订阅粒度优化【增强·可选·挂账】

#### C5 会话数据层分页评估【评估·可选·挂账】

- 建议：登记；待 C2 落地后评估是否收敛（避免过度设计）。

#### C7 代码高亮移出流式热路径【增强·性能】（2026-09-20 立项，同日完成）

- 现状（取证）：`Prism.highlight` 代价与源码长度成正比（实测 60 行 TS ≈ 1.6ms）；渲染管线在**内容未变**时重复请求同一份代码。调用计数取证出两条热路径：① **闭合代码围栏停留在活动尾块** → 每帧 1 次全块高亮；② **整段回退路径**（文档含 def/html）→ 每帧重高亮**全部**代码块。对照：打字机未闭合围栏期本就 0 次（降级纯文本）、增量渲染器稳定段每块 1 次（token 缓存已生效）——即缺口不是「打字机期间」，而是**内容未变却重复高亮**。
- dsh 参照：代码高亮由**单一 document-wide IntersectionObserver 按视口触发**（首交即 `unobserve`），流式围栏另有按 32 行分组复用已完成 DOM 的 `StreamingHighlightSession`。
- 建议落地（按价值排序，本轮取 ①）：① **内容键 memo**（`(语言, 源码)` → 高亮结果，FIFO 有界）——语义不可见，一次性干掉两条热路径；② 视口触发（dsh parity）——进一步省掉「不可见块的首次高亮」，属**初始渲染成本**优化而非流式热路径优化（见施工记录「② 的边际价值」）。
- 验收：契约测试（输出逐字节等价 + 别名归一 + 缓存有界 + 重复请求只跑一次 Prism）+ 门禁（预算 + 判别力自证）+ 真机走查（长代码回答流式不卡、高亮完整）。

### 定时唤醒工具（S，用户追加需求）

#### S1 定时唤醒工具（`set_timer` / `list_timers` / `cancel_timer`）【新增·用户需求】

- **需求**：Agent 需要等待时设置倒计时，到点自动唤醒；附带两能力——① 倒计时期间捕获指定后台任务结果、到点一并送达；② 设置时挂事项内容，作到点提醒。
- **本侧地基（原语齐备）**：① 唤醒 = `AgentLoop::submit_input(FollowUp)` 既有「空闲即启动一轮运行 / 运行中入队待准入」语义（`crates/agent-kernel/src/agent/input.rs:136-162`）；② 会话实例 = `AgentCommandService.sessions` 常驻表（含重启恢复，`crates/agent-commands/src/lib.rs:903,3085+`）；③ 捕获 = PTY 输出缓冲**游标式增量读**（`SessionOutputBuf::read_from/end`，`crates/agent-commands/src/terminal.rs:355-467`）。
- **工具集（三件套，照 dsh schedule 族形态）**：
  - `set_timer`：`after_seconds`（10 ≤ n ≤ 86400）+ `note?`（提醒事项）+ `watch?`（PTY 会话 id 列表）→ 返回 `{ timer_id, fire_at }`；**工具立即返回、不阻塞**。
  - `list_timers`：列本会话未到期定时器（id / 剩余秒数 / watch 概要）。
  - `cancel_timer`：按 id 取消（到点前可撤销）。
- **唤醒语义**：到点 → `submit_input(FollowUp, payload)`——空闲即新开一轮；运行中入队、下一轮请求准入点注入（不打断当前 LLM 调用）。载荷 = 定时信息（设置时间 / 倒计时 / `note`）+ 捕获段 + 继续指引；消息带 `meta.input_kind = "timer"`（前端专门行呈现，非普通用户气泡）。
- **捕获（字节级精准）**：`set` 时记录每个 watch 会话的 `buf.end()` 游标 → 到点 `read_from(cursor)` 取「倒计时期间新增输出」（clean_ansi + 尾部截断，如 ≤2000 字符/会话；缓冲裁剪时如实标注「输出超限仅保最近部分」；会话已销毁逐条标注不静默丢）。**显式 watch 列表**（PTY 注册表全局共享、会话无归属标记——auto 会跨会话泄漏，不做）。
- **持久化与续跑**：新表 `session_timers`（随会话存储：`id / session_id / fire_at / note / watch_json / cursors_json / status(pending|fired|cancelled) / created_at`）；装配层 `TimerService`（对标既有巡检调度先例 `ensure_memory_gc_task`：懒启动 + 幂等 + 到点触发）；**到期补投**——启动恢复后扫描 `pending && fire_at ≤ now` 立即触发，载荷标注「补投（应用重启后到期）」；会话删除级联清理。
- **护栏**：最小 10s / 最大 24h；每会话未到期数量上限（实现定，建议 8）；一次性（不做周期，dsh `every_seconds` 留二期）；工具描述提示「每次唤醒消耗一次 LLM 轮次，仅在确实需要等待时使用」；子代理不可用（无独立 session 实例；以可见性或 execute 校验落地，施工时定）。
- **验收**：服务测试（状态机 pending→fired/cancelled / 游标增量捕获 / 重启补投 / 级联清理 / 护栏边界）+ 前端 timer 行呈现 + 真机走查（设 30s 定时等待 → 自动唤醒；PTY 后台输出随唤醒送达；关应用重开补投）。

#### 走查后修复：流式渲染帧率（2026-09-20，用户反馈「推理过程打字机帧率偏低」）

**② DotNav 全量扫描 → 用户行元素缓存 + 脏标记惰性重建**（`useMessageWindowing.ts`）：

- 原实现：每个滚动帧 `querySelectorAll('[data-msg-id]')` 全 DOM 遍历，且**先读 `offsetParent`（强制布局）再按 id 过滤** —— 非用户行也各付一次布局读；流式自动贴底期间即帧级频率。
