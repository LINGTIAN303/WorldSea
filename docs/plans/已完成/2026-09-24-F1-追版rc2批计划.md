## 六、回归中逮到的真缺陷（本轮修复；是我方 C2 补丁旧疾，rc.2 更并行的启动把它放大成必现）

**管道帧配对竞态**：

- **现象**：页面 `reload` 后 `[DSH-HOST] pipe-transport: protocol violation (binary frame mismatch for id 24); closing the connection` → 宿主**整条断链** → 之后所有 `/api/*` 全 `502`，页面 `[connection] connection lost, retry #…` 无限重试。
- **根因**：壳侧代理**每请求一线程**并发发 POST；`PipeClient::request()` 把「控帧（`req`，含 `bodyLen`）」与「体帧（`u32be id + body`）」**分两次写**，两线程可交错成 `J1 J2 B1 B2`；宿主按**单槽配对**读（`heldRequest`/`pendingBody` 各一个）→ B 帧 id ≠ 当前 pending id → fail-closed 断链。
- **修复**（`apps/tauri/src-tauri/src/dsh_pipe.rs`）：新增 `Inner.write_lock` + `write_frames(&[(kind, payload)])`——**成对帧在同一临界区内写完**；`request`（控+体）与 `stream_open` / `stream_send` / `stream_end` / `stream_cancel` 五个写帧点全走它。
- **反证**：新增 `dsh_pipe::tests::concurrent_requests_with_bodies_stay_paired`（16 线程并发带体请求；**测试宿主本身即配对校验器**）。**变异注入**（把配对窗口降级为逐帧各自加锁）→ 该用例**报红** ✅；修复版 → 绿 ✅。
- **真机复验**：连做 5 次 `location.reload()` → 日志 `protocol violation` **0**、真 502 **0**，页面 transport 与窗口栏仍在 ✅。

**新拖拽监视器（rc.2 `client/web/src/boot.ts` +9 行）判决**：源码取证 —— `window-drag/recall.ts` 开头即 `if (doc.documentElement.dataset.platform !== 'darwin') return () => {}`，**非 macOS 平台不安装任何东西**（注释亦点名 Electron 的 drag-rect 陷阱 electron#32341）→ **对我们是 no-op**（Windows + Tauri 壳），R1 由源码证据关闭；拖拽手感仍列入用户走查。

**确认未变的两条壳-宿主契约**：就绪行（`dsh web: http://127.0.0.1:<port>/?token=…`）与 `--patch` / `--no-open` / `--port` / 我方 `--ipc-pipe` 旗标族 —— 真机链路日志逐条印证（`spawn … --ipc-pipe …` → `ready:` → `bridge ready: mode=pipe`）。
