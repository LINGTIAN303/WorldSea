# 视口容器结构简化：S5 轮次级窗口化 + S4 单一滚动调度器

`status: 已完成（2026-09-05 施工完毕；本文件保留为设计稿原文，实施落点见 docs/index/README.md「状态勘误」）`

> 源自 2026-09-05 视口容器整体走查报告：体系稳定性靠 21 个抖动修复补丁 + 魔法数 + 七套 scrollTop 写入者互相制衡维持，根源是「补偿竞争无仲裁」与「测量粒度（行）≠ 渲染结构（嵌套折叠树）」。

## 一、实施顺序：S5 先行（关键判断）

原报告将 S4/S5 并列，走查后明确：**S5 先做，S4 跟进**。

理由：S5（轮次级窗口化）会把 scrollTop 写入点从 7 个自然收敛到约 4 个——行级测量收敛的锚定重建、v-show 隐藏行置 0、结构签名扩窗等整类机制随粒度改变而消失或简化。在简化后的体系上做 S4（调度器），仲裁面小一半以上；反过来先做 S4，调度器要覆盖将被 S5 淘汰的写入点，返工。

## 二、S5：轮次级窗口化（结构性手术）

### 目标与收益

测量/占位/切片的单元从「行」（几百条）改为「轮次」（几十个）：

- 合成折叠头不在行账本的问题**连根消失**（整个轮次是一个测量单元，块头高度变化被轮次级 RO 捕获）
- v-show 隐藏行置 0、结构签名扩窗、组合条/区头的锚定过滤等**整类补丁退役**
- 前缀和重建 O(轮次数)，切窗频率大降，layout thrashing 风险同步缓解

### 核心改动：渲染结构加轮次包裹层（前提条件）

当前 DOM 结构是平铺的：`messages-scroll > [占位, user行, process段, result行, ...]`——**没有轮次级包裹元素**，轮次高度无法整体测量。必须加：

```
messages-scroll
└── [topPlaceholder]
└── .turn-root（data-turn-root={turnId}）← 每轮一个包裹 div，RO 挂这里
│   ├── user 行 / 过程层 / 结果层 / 尾部行
└── ...（更多 turn-root）
└── [bottomPlaceholder]
```

AgentStreamList 已按 TurnGroup 分组渲染，包裹层在组容器上加即可，行渲染逻辑不动。

### 窗口化改造

- 前缀和：按 turn-root 实测高度（RO 挂轮次根，行级 RO 退役）累计
- 切片：可见轮次集合（首尾轮次索引）内的轮次**全量渲染**，窗口外轮次以占位替代
- 锚定：切窗锚定锚 `data-turn-root`（元素少且稳定）；折叠补偿仍走宿主 withProcessAnchor（锚 process 头行，语义不变）
- 流式兼容：流式轮次（末轮）强制在窗口内（对齐现行 `end=total` 语义）

### 超长轮次对策（S5 的核心 trade-off）

单轮次可达上万 px（长任务几百行段），轮次级窗口化对其失去裁剪能力。**首版决策：超长轮次直接全渲染，不预优化**——理由：单轮次全渲染的开销（几十行 DOM）远小于现行几百行的全量级管理复杂度；若实测出现性能问题，再在轮次内启用行级二级窗口（预留接口，不实现）。

### 分阶段实施（每阶段独立可回退、可走查）

1. **阶段 A（纯结构）**：AgentStreamList 加 turn-root 包裹 div + 行级 RO 迁移到轮次根；窗口化逻辑不变（仍按行切片，前缀和仍行级）——验证：现有全部滚动/折叠行为无回归
2. **阶段 B（粒度切换）**：前缀和/切片/占位改轮次级；流式轮次强制在窗；清理因此失效的行级补丁（隐藏行置 0、⑰扩窗、RO 隐藏检测⑲ 等）
3. **阶段 C（S4 落地）**：见下节

### 风险与回归点

- turn-root 包裹 div 引入新的嵌套层 → 需核查 CSS（flex 布局 gap、动画选择器、`data-msg-id` 遍历逻辑兼容）
- 入场动画治理（seenIds）与窗口 key 需按轮次调整
- 回归基准：本轮全部已修复的抖动场景（区级折叠、总折叠头、底部展开、边界滚动）逐一复测

## 三、S4：单一滚动调度器（在 S5 之后的干净地基上做）

### 优先级模型

```
requestScroll(target, source)
source 优先级：user(0 不可拦截) > fold-compensate(1 折叠补偿)
            > bottom-follow(2 贴底跟随) > measure-anchor(3 测量收敛锚定)
```

- 同帧多请求：低优先级让位于高优先级；同优先级合并（取最后一次）
- 写前校验：目标 ∈ [0, scrollHeight - clientHeight]，非法丢弃
- 写后统一记账 observedTop（收拢 syncObservedTop 的分散调用）
- S5 后的写入点清单（预期 4 个）：withProcessAnchor、切窗锚定、贴底跟随×2、用户滚动（信号源，不写入）

### 收益

补偿竞争从「时序约定 + 抑制窗口制衡」变为「优先级仲裁」——新交互接入只需声明来源优先级，不再需要调和既有补偿。

## 四、验证方案

- 每阶段全量单测 + typecheck
- 真机回归清单（本日已修复场景）：区级折叠跳顶/抖动、总折叠头展开丢行、底部展开闪烁、边界滚动、导航点高亮连贯、回底按钮
- 新增对照：长会话（>100 行段）Performance 录制对比（阶段 B 前后）
