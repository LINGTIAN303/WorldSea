# 多关键帧时间轴 · 批计划

> **E 批走查通过（2026-10-26）；本文件已归档。**

> 用户拍板立项（2026-10-26，D4 走查后）。前置：D3 单段轨迹 + D4 画布编辑器已交付。

## 一、目标

区域运动轨迹从「单段参数（起 0 → 终值）」升级为**多关键帧时间轴**：一条轨迹内编排多段运动
（先上移→再旋转→再缩放回位），每帧独立设 dx/dy/rotate/scale 与时间点。

## 二、数据模型（向后兼容）

```ts
interface MotionKeyframe {
  t: number          // 相对轨迹起点（秒）
  dx?: number; dy?: number; rotate?: number; scale?: number
}
interface MotionTrack {
  // 现有单段字段保留（无 keyframes 时即单段，D3/D4 数据不动）
  keyframes?: MotionKeyframe[]
}
```

渲染：`keyframes` 存在 → WAAPI 多关键帧（`offset = t / duration`，首帧自动补 t=0 恒等变换）；
`trigger='mouse'` 的轨迹不参与关键帧（内容追踪是连续跟随，非时间轴）。

## 三、UI（挂 D4 画布编辑器侧栏）

- 轨迹卡片展开「时间轴」区：横条=时长刻度，关键帧为可拖圆点（拖=改 t；双击空白=加帧；Delete=删选中帧）
- 选中帧的数值编辑（dx/dy/rotate/scale）即时入草稿；实时预览同步
- 时间轴组件独立文件（MotionTimeline.vue，估 ~250 行），MotionEditorSide 引用

## 四、批次与验收

单批（E）：类型扩展 + MotionStage 多关键帧渲染 + MotionTimeline UI + 编辑器集成 + 测试
（关键帧→WAAPI 参数换算纯函数、时间轴交互、兼容旧单段数据）。验收：一条轨迹三帧（上移→旋转→回位）
在预览/悬停/追踪浮层按序播放；旧单段数据行为不变。

## 五、风险点

1. 时间轴拖拽交互的指针捕获与前述 model-viewer 事件乱序同类坑（时间轴在弹层内无 web component，风险低）
2. 帧过密（<0.05s 间隔）渲染抖动——添加时钳最小间隔

## 六、施工记录（2026-10-26，待走查）

- **类型**：`MotionKeyframe { t; dx?; dy?; rotate?; scale? }` + `MotionTrack.keyframes?`（存在时优先生效，单段字段忽略；向后兼容）。
- **`trackToKeyframes`**（motionMath，纯函数可测）：单段=两帧等价路径（0 恒等→1 终值）；多帧按 t 升序 + 自动补 t=0 恒等 + offset=t/duration 钳 0-1；scale=1 恒等省略。MotionStage 的 keyframesOf 统一走此函数（单段/多帧同路）。
- **`MotionTimeline.vue`**：横轨时间轴——秒刻度、帧点拖动改 t（指针捕获+钳制+最小间隔 0.05s 防抖）、双击空白加帧、点击选中后数值编辑（t/dx/dy/rotate/scale）与删帧；**首次触碰把单段转多帧**（单段终值保留为末帧），未触碰的旧数据保持单段不动。
- **集成**：MotionEditorSide 的非 mouse 轨卡片下内嵌时间轴（mouse 轨=连续跟随无时间轴）。
