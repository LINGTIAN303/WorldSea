## 一、取证结论：F2 登记的 G1 前提有误，真缺口在别处

**① 上游 `data-fullscreen` 与「最大化」无关。** 真源是 Electron 的 `enter-full-screen` / `leave-full-screen`（`dsh/apps/desktop/src/main.ts:246-247`，并在每次加载后补发当前态见 `main.ts:244`），`preload-platform.ts:20` 的注释写明用途是「drops the clearance for **hidden native window controls**」。上游最大化时同样保留 `calc(32px + 20px)` 的浮层内缩。

**② 我方窗口栏最大化时照旧在位** → 52px 内缩在最大化下**本来就是正确的**，F2 §三「最大化时内缩不回落 = 缺陷」的判断不成立（本批已更正 F2 文档表述）。

**③ 真缺口 = 壳已有全屏模式但从未回传页面。** `menu.rs` 的「视图 → 全屏」（accelerator `F11`）已在调 `set_fullscreen`，但状态没有过桥：全屏时窗口栏仍在（栏上的最小化/最大化在全屏下语义已失效），dsh 也仍按 52px / 32px 内缩。

**④ 无中间态（二难）。** 上游全屏分支（`dsh/packages/client/ui-layout/src/client/AppFrame.module.css:109-113`）只重置 `--dsh-frame-overlay-top`(→20px) 与 `--dsh-frame-chrome-top`(→0)，**不**重置 `--dsh-windows-titlebar-height` → `.frame` 仍留 32px padding、`.frame::before` 仍画那条 32px 带。而我方栏是页内 `position:fixed`、z-index `2147483000`，**高于 dsh 浮层** → 「保留栏 + 置属性」会让浮层顶部 12px 被栏盖住（回归）。故只能二选一：隐藏栏 + 置属性，或保留栏 + 不置属性。用户选前者。

**⑤ F11 通路已去风险（同仓先例）。** `lib.rs:312` 已调 `SetAreBrowserAcceleratorKeysEnabled(false)`（否则 WebView2 壳层吞掉 F11），且 `apps/tauri/src/ui/layout/TitleBar.vue:124-148` 就是 F11 → `setFullscreen` 的现成实现（工作台窗在用，注释原文「绝对全屏（无边框真全屏，区别于最大化）」）。注意 `menu.rs:33-34` 写明菜单是 **popup 资源、未 `set_menu`** → 菜单项上那条 `F11` accelerator 是否生效**未实测**；本批不依赖它，退出通路由注入脚本的页面侧监听承接。

## 二、设计（改动面 4 文件，无新增依赖、ACL 面不增长）

| 文件 | 改动 |
|---|---|
| `apps/tauri/src-tauri/src/shell_bridge.rs` | `WindowActionOutcome` 加 `fullscreen` 字段（每次窗口动作一并回传）；`cmd_shell_window_action` 加 `"toggle-fullscreen"` 臂。**走应用命令而非 Tauri 窗口插件 → 不碰 ACL**（守 C3 的 202→7 纪律） |
| `apps/tauri/src-tauri/src/dsh_titlebar.js` | `applyFullscreen(on)` 独占全部 DOM 效果；F11 捕获相位监听；`worldsea:fullscreen` CustomEvent 监听；`relocateSidebarToggle` 加全屏守卫 |
| `apps/tauri/src-tauri/src/menu.rs` | `ID_FULLSCREEN` 在 `set_fullscreen` **成功后**派发 `worldsea:fullscreen`（新 `sync_fullscreen_js`），菜单路径回传页面 |
| `apps/tauri/src-tauri/src/dsh_proxy_tests.rs` | 注入契约加两条断言：脚本必须含 `toggle-fullscreen` 与 `data-fullscreen` |

**三条触发路径汇聚到一个 `applyFullscreen`**：① 页面 F11 → 壳命令返回值 ② 菜单（Rust 发起）→ CustomEvent ③ 挂载 / resize 查询 → 返回值。第 ③ 条使**全屏中重载页面能直接落全屏形态**（对齐上游 `main.ts:244` 的加载后补发）。

**`applyFullscreen` 的三件效果**：置 / 删 `html[data-fullscreen]`（照上游 `dataset.fullscreen = 'true'` / `delete`，不是置 `'false'`）· 隐 / 显 `#worldsea-titlebar`（必须走内联 `display:none`——`hidden` 属性会被本栏 author 级 `display:flex` 压掉）· 解除 / 重钉 E9 侧栏开关键的内联样式（全屏时槽位 rect 归零，钉住会把键扔到 `(0,0)`；解除后由 dsh 自己的 `left:12px / top:calc((H-28px)/2) / z-index:30` 接管，键落回 dsh 那条 32px 带内 = 上游 Windows 全屏观感）。

**一处刻意的规范偏离（已自主裁定并在此登记）**：F11 用**捕获相位**（`capture: true`），偏离 `TitleBar.vue` 的冒泡相位。理由：全屏时本栏已隐藏，F11 是唯一退出通路，不能被 dsh 内部某个 `stopPropagation` 掐断；F11 非文本键，捕获相位不干扰输入。`docs/details/架构/快捷键系统.md` §3 的「禁止 capture 抢跑」条目只点名 Escape，本处不属其列，但已在该文档就地写明例外与理由。
