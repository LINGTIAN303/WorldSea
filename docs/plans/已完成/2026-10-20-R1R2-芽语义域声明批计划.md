# R1/R2 · 芽语义域声明批计划

> 依据：[芽生态研究 · 02 语义域重划](../../details/架构/芽生态/02-语义域重划.md) §2.4 / §2.5 / §2.8，[05 用户信息架构与建议](../../details/架构/芽生态/05-用户信息架构与建议.md) §5.5。
> 范围：**只做 R1 声明层 + R2 语义域落地**。不做 R3 侧栏两级、R4 设置分组、R5 依赖/状态可见、R6 孤岛治理；本轮不改任何 UI 行为。
>
> **执行状态（2026-10-20）**：全部 Task 完成；专项/全量/类型/架构/文档/工作台构建门禁全绿；无 UI 改动，不走真机走查。

## 一、目标

让「芽属于哪个语义域」从研究结论变成代码事实：

1. `WorldPluginManifest` 新增 `domain` / `secondaryDomains`；
2. 27 个内置芽各声明一次主域与副域；
3. 8 个语义域成为单一真源（id / 中文名 / 核心问题）；
4. 旧 6 类 `category` 保留为过渡筛选标签，明确标记待退役；
5. 外部插件缺省域记为 `unclassified`，不默认塞进 `tool`。

## 二、已拍板决策（2026-10-20）

| 决策点 | 裁定 |
|---|---|
| 副域字段名 | **`secondaryDomains`**（不用 `subdomains`，避免被误解为子域名/层级域） |
| 副域填充范围 | 按 02 §2.5 为 16 个芽填副域；其余芽只写主域 |
| 外部插件缺 domain | 记为 **`unclassified`**，管理面显式提示“未声明主域”；不默认归 `tool` |
| 最小运行时消费者 | **数据 API**：`availablePlugins()` 暴露 manifest 域；`ExternalPluginState` 带出域。本轮不改 UI，R4/R5 再接 |
| 旧 category | 保留现有筛选行为；加 `@deprecated` 标注，R4 再退役 |

## 三、数据模型

### 3.1 域注册表

新增 `packages/entity-core/src/core/sproutDomains.ts`：

```ts
export interface SproutDomain {
  id: string
  label: string
  /** 域的核心问题（设置/侧栏解释文案用） */
  question: string
}

export const SPROUT_DOMAINS = [
  { id: 'geo', label: '地理与场所', question: '世界在哪里、由哪些地点构成' },
  { id: 'life', label: '生命与族群', question: '谁生活在这个世界、有哪些生命形态' },
  { id: 'society', label: '社会与文明', question: '他们如何组织、交流、冲突' },
  { id: 'knowledge', label: '知识与规则', question: '世界运行依赖哪些设定、规则与力量体系' },
  { id: 'goods', label: '物产与造物', question: '世界里有哪些物品、装备与造物' },
  { id: 'time', label: '时间与事件', question: '世界发生了什么、按什么顺序发生' },
  { id: 'narrative', label: '叙事与文本', question: '如何把世界组织成可写的文本' },
  { id: 'tool', label: '推演与工具', question: '用什么工具观察、推演、编排' },
] as const
```

- 域表是**开放集合**：新增域 = 在本表登记 id / label / question，再在芽 manifest 声明。
- 本表是**域层**单一真源；芽归域仍由各芽 manifest 声明，不在本表重复。

### 3.2 Manifest 字段

`apps/tauri/src/world/manifest.ts`：

```ts
/** 主语义域；内置芽必填（测试守卫），外部插件可缺省（缺省记 unclassified） */
domain?: string
/** 副语义域；不得与主域重复；内置芽取值由测试守卫 */
secondaryDomains?: string[]
```

`validateManifest` 只校验形状（非空字符串 / 字符串数组），不校验注册表成员：
外部插件允许使用未登记域名，避免把扩展面锁死。

## 五、验收判据

- 27 个内置 sprout manifest 均能回答“主域是什么、副域是什么”。
- `SPROUT_DOMAINS` 是 8 域的唯一域层真源；新增域必须登记四项信息。
- 外部插件缺 domain 时为 `unclassified`，不静默归 `tool`。
- 旧 6 类 `category` 筛选行为完全不变，仅增加退役标注。
- 不改侧栏、设置分组、字段矩阵 UI；R3/R4/R5/R6 不被本批顺带推进。

## 六、风险

1. **静态解析测试**依赖 manifest 对象形状；若未来把 manifest 移出 `index.ts`，测试需同步扩展文件发现规则。
2. **开放域集合**没有编译期枚举约束；未登记的域由测试/管理面提示，不在 `validateManifest` 拒绝（保护外部插件）。
3. **副域归属**来自研究建议，R4/R5 若发现不合适可调整 manifest，不影响主域导航。
4. **27 个插件 manifest 改动面广**，但每处仅 1–2 行；逐路径提交，避免 `git add -A`。
5. 本轮不改 UI，因此“侧栏/设置按域分组”仍然不可见；这是 R3/R4 的范围，不应把本轮当成用户可见交付。
