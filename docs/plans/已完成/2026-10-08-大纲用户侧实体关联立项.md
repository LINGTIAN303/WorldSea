## 一、背景与缺口定义

大纲节点（`outline_node`）与芽实体之间存在**三条语义化关联类型**（2026-09-18 注册）：提及（`outline_mentions`）、发生于（`outline_located_in`）、承载（`outline_covers`）。它们是「关联实体徽章」的数据来源。

**缺口**：这三条关联**用户侧没有任何建/删入口**——徽章刻意为只读派生（`OutlineRefsForm.vue` 注释：「本组件不写任何数据」），Inspector 节点属性区只有「关联章节」有呈现+解除先例，实体关联一行都没有。

**登记口径校正（2026-10-08 取证）**：登记句「现仅 Agent `link_entity` 可建」已过期——`link_entity` 工具**已不存在**（全仓只剩注释残留，随旧 Agent 面 E7 退场）。现 Agent 侧建法 = dsh 产品域 `world_relation_put`（`world_*` 12 工具之一，可建任意关系含三条 curated 型）。即：**数据机制早已就绪且 Agent 可写，唯用户侧零入口**。

**★ 重大发现：内置关系注册断链（本批修复的阻塞项，2026-10-08 考古确认）**

`relationshipRegistry`（V2 关系注册表）在运行时**长期为空表**——`relations/index.ts`
（全部内置定义，600+ 行 `defineRelation`）**没有任何生产加载点**：

1. 原载入点 = 旧 Web 端 `src/App.vue` 的动态 `import('.../entity-core/relations')` +
   `syncToLegacyRegistry()`（「不阻塞首屏」语义，见 `8c42a7e2`）；
2. `af93e3f1`（governor 系统接管启动流程）把它收进 governor 启动模块的「关系初始化」；
3. `980385c5`（端分离迁移，旧结构迁入三端）删 `src/`——**载入点随之下线，新端
   （apps/tauri）启动装配从未接过**；此后所有相关开发（含 09-18 徽章批）都在断链环境下。
4. 全仓 alias `@worldsea/entity-core/relations`（vite × 5 + vitest）齐备但**零消费者**；
   `git log -S` 全历史确认无 import 使用处。

**影响面（注册表驱动、静默失效的面）**：徽章 `pickRefRelationTypes` 恒空（徽章从不产出）；
类型中文标签回落英文；`useConsistencyChecker` 的关系类型已知集为空；`customRelationType` 防重失效；
`relationSchemaRegistry`（旧版，canvas-engine 图数据标签的消费者）同样为空。

**修复（本批）**：包入口 `entity-core/src/index.ts` 顶部 side-effect `import './relations'`
（一处接齐 app / 各包 / 测试）；定义文件末尾自带 `syncToLegacyRegistry()`（复刻老载入点两步）。
不再用「首屏不阻塞」的异步语义——纯内存注册（微秒级），同步即一致。

**「定制映射」的干净解法**：三条关系的合法目标类型已在注册表写死 ⇒「目标类型 → 可用关系类型」**反查注册表**即可（区域→发生于；事件/冲突→承载；建筑→发生于/提及 二义；其余 11 类→提及），不硬编码映射表（「注册表即扩展点」惯例）。

**耦合发现**：徽章「点击跳转」目前是坏的——`ws-navigate` 接缝使多数调用者只选中、不切视图（详见 §三）。

## 三、ws-navigate 接缝：现状与修复设计

### 现状（四路口径）

消费方 `Shell.vue:111-126` 的读法：`const { view: entityType, entityId } = detail`——把 `detail.view` 当**实体类型**用（查 schema → pluginId → 找该插件视图 → `setView`），再 `selectEntity` + 派发 `ws-select-entity`。

| 口径 | 调用者 | handler 能否切视图 |
|---|---|---|
| A. `{ view: <实体类型>, entityId }` | `GlobalSearch.vue:131` / `VersionHistory.vue:88` / `EntityRefControl.vue:126`（三字段冗余） | ✅ |
| B. `{ view: <视图 id>, entityId }` | `GlobalGraph.vue:518`（viewMap 把类型映成视图 id） | ❌ |
| C. `{ type:'entity', entityId, entityType }` | **9 个自绘子视图（17 处）+ 大纲徽章 + 打开正文** | ❌（handler 不读 `entityType`） |

另：`uiStore.selectEntity()` 写入的 `selectedEntityId` 全仓无消费者（死状态）；`ws-select-entity` 仅 `CharacterList` 一处监听。**「选中」的真实落点是各视图自己的详情态**（GEV `selectedEntity` / Timeline `selectedEvent`）。

### 修复设计（用户裁定：全链统一）

1. **契约单一口径 = `{ entityType, entityId }`**：
   - 派发侧：15 文件 21 处全部改为该形状（A 类删 `view`、B 类删 viewMap 直接传实体类型、C 类换字段名）；`type:'entity'` 等未消费字段一并去除。
   - 消费侧：Shell handler 改读 `detail.entityType`，删除 `view` 旧读法。
2. **选中双通道**（治「新视图尚未挂载、事件丢失」）：
   - 通道一（即时）：handler 保留 `dispatch ws-select-entity`；已挂载视图即时响应。
   - 通道二（挂载兜底）：handler 同时写 `uiStore.selectEntity(entityId)`（**死字段复活为『导航选中挂起位』**）；视图挂载时读取——类型匹配才选中（GEV 自带 `props.entityType` 判定），`setView` 已内置清空、无残留。
3. **消费接线**：
   - `GenericEntityView`：新增 `ws-select-entity` 监听（→ `selectEntityById` 既有实现）+ 挂载读挂起位。**一处收敛 16 芽**（含 characters——`CharacterList` 壳的转发保留，幂等重叠无害）。
   - `TimelineView`：新增监听 + 挂载读挂起位（`entity.type === 'event'` 时 `selectedEvent = entity`）。
   - `CharacterList`：onMounted 复用现有 handle（补 `loadEntityTabData`），保证跨视图跳转后 tab 数据齐。
4. **守卫**：源码形状守卫（扫描全仓 `ws-navigate` 派发点，断言只含 `entityType`、不含 `view:`/`type:'entity'` 旧形状；断言 Shell handler 读 `entityType`）。
5. **边界登记**：「打开正文」= 切到正文写作视图（旧行为等价），**精确打开对应书/章节不做**（ManuscriptView 导航模型另议）；自绘视图（graph/drawing/notebook/mindmap 等）作为跳转目标时的「选中」不在本批（无调用者指向它们）。

## 四、关联实体编辑行：设计定稿

### 落点与组件

- 新件 `outline/board/components/NodeRefsSection.vue`（自包含：读 relationStore、调 outlineLinks、弹 picker）。
- 挂载：`BoardInspector`「节点属性」区尾部加一行 `<NodeRefsSection :node="node" />`。
  **行数约束**：BoardInspector 基线 521 / 当前 520（余 1）——挂载+import 共 +2，施工时须在本文件净减 1 行（压缩可读性无损处）。

### 交互（四裁定）

| 动作 | 形态 |
|---|---|
| 查看 | 行列表：`实体名（截断） · 关系类型标签 · 解除`；点击名字 = 跳转实体（走修复后的 ws-navigate） |
| 建立 | 「＋ 添加」→ FloatingPanel：搜索框 + 类型筛选（合法 15 类）+ 候选列表（名字 zh 排序、已关联者排除）；**点击即建** |
| 类型 | 唯一合法 → 直建；建筑二义 → **默认「发生于」**；行内对二义联动显示 `改『提及』`（unlink 旧 + link 新，原子替换） |
| 解除 | 行内「解除」（与「关联章节」并列模式；经 relationStore.remove，**进撤销栈**） |

### 纯函数（进 `outlineRefs.ts`，带测试）

- `refTargetTypes(schemas)`：合法目标类型并集（15 类）。
- `refRelationTypesForTarget(schemas, targetType)`：目标类型的合法关系列表（**有序**，首位=默认；building 两条）。

### 写作纪律

- 写入唯一经 `linkOutlineEntity`（幂等、单向 node→entity、不静默回退），**不再有第二条写路径**；`relationStore` 作为 store 直接传入（接口兼容）。
- 空态文案：`暂无关联实体`；孤儿关系（实体已删）不入列表（复用 `refRelationsOf`/分组语义）。
- 本地写后刷新：relationStore 响应式更新（add push / remove removeById）→ Inspector 列表与徽章同步即时刷新，无手工刷新。

## 六、验收与走查清单（已走查通过 2026-10-08）

1. 大纲白板：选中容器 → Inspector「关联实体」行出现；「＋ 添加」搜「王城」类实体 → 点击即建 → 行列表与容器徽章即时出现该联动。
2. 建筑二义：添加建筑 → 默认「发生于」；行内「改『提及』」→ 徽章内关系标签随之切换。
3. 解除：行内「解除」→ 联动与徽章即时消失；Ctrl+Z 可撤销复原。
4. 跳转：点击联动名 → 切到目标实体所在芽视图**并打开其详情**（重点验证跨视图：从大纲跳到角色/区域/事件）。
5. 其他跳转回归：全局搜索跳转、图谱点节点跳转、时间线事件跳转、九子视图双击跳转——均应「切视图 + 选中」。
6. **注册面回归（断链修复）**：关联的中文关系标签显示为「提及 / 发生于 / 承载」（而非英文类型名）；存量关系（如 Agent 写入的）在徽章中可见。
7. 结构守卫：`ws-navigate` 派发点不再出现 `view:` / `type:'entity'` 旧形状；`BoardInspector` 保持挂载 `NodeRefsSection`（门禁自动）。
