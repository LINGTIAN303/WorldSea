# 时间线芽 · 时间体系与双态交互重构批计划

> 目标：把时间线从「硬编码纪元/年 + 两套视图硬拼 + 一批死交互」改造为「可定义时间单位体系 + 双态完整视图 + 全量交互」。
>
> 拍板记录（2026-10-23）：
> - 时间体系**内置时间线**（项目级配置，不新增芽）。
> - 单位模型做**完整历法**（任意层级单位 + 命名值 + 换算 + 闰规则 + 周 + 日以下时间）。
> - 日期录入 = **结构化选择器 + 文本解析**双通道。
> - 附加能力全取：**期段/纪元区间、模糊日期、多套历法、周期与节庆**。
> - 视图形态 = **双态保留**（编年史 / 时间画布），控件按态显隐。
> - 交互 = **全量新交互**（拖拽创建/移动/拉伸、缩放适配、选中聚焦、冲突跳转、两态批量、键盘）。
>
> 非目标：跨历法同轴换算（不同历法的事件不共享一条标量轴）；脚本化闰表；日以下单位自定义进制（时/分/秒固定 60 进制）。

## 一、现状与问题

时间线的单位语义被硬编码在五处，不是补一个解析器能解决的：

| 层 | 现状 | 位置 |
|---|---|---|
| 日期结构 | `era / year / month / day` 四字段 | `apps/tauri/src/world/plugins/timeline/composables/useDateParser.ts` |
| 文本解析 | 只认「第N纪元」「N年」，中文/阿拉伯数字不归一 | 同上 |
| 坐标换算 | `era * 10000 + year` | `apps/tauri/src/world/plugins/timeline/composables/useTimelineScale.ts` |
| 分组/色带 | 竖向读 `properties.era`，横向读日期解析纪元，字符串精确匹配 | `composables/eraGroups.ts`、`composables/useTimelineFilters.ts`、`composables/useSwimlaneLayout.ts` |
| 拖拽改时间 | 正则只替换 `\d+年`；实现从未接线，设置开关是死设置 | `composables/useTimelineDrag.ts` |

视图与交互的存量问题（详见 2026-10-23 探查结论）：

- 横向画布忽略「时序/大纲」开关；「分组」只在横向生效；批量选择只在竖向可用。
- 每条泳道头渲染两次（左侧栏一次 + 泳道内一次）；标尺按整块宽度计算但左侧 160px 泳道栏未扣除。
- 滚轮被无条件劫持成横向平移，泳道无法用滚轮纵向滚动。
- 缩放只有 `Ctrl + 滚轮`，`fitAll / zoomTo / panTo` 是死代码；时间轴显示 `grab` 但不可拖。
- 跨视图跳转只设置选中，不平移画布；冲突面板只读不可跳转；事件条 tooltip 用 `fixed` + 容器坐标，整体偏移。

## 三、核心设计

### 3.1 时间体系（Calendar）

项目级数据，一份或多份。结构：

```ts
interface Calendar {
  id: string
  name: string
  /** 从大到小排列的单位链，至少 1 个；最后一个是标量基 */
  units: CalendarUnit[]
  /** 周循环（可选）：每周几天、星期名、日单位与锚点 */
  week?: { length: number; names: string[]; dayUnit?: string; anchorScalar?: number; anchorIndex?: number }
  /** 日以下时间（可选）：时/分/秒的进制，固定 60 进制 */
  timeOfDay?: { hoursPerDay: number }
  /** 全日期显示模板（可覆盖单位片段拼接），`{0}`/`{1}`… 引用单位 */
  format?: string
}

interface CalendarUnit {
  id: string                 // 稳定 id，如 'era' / 'year' / 'month' / 'day'
  name: string               // 显示名，如 '纪元' / '年'
  kind: 'numeric' | 'named'
  /** 1 个本级单位 = factor 个下一级单位；最小单位省略 */
  factor?: number
  /** 数值单位起始值（默认 1；时/分/秒建议 0） */
  start?: number
  /** 数值单位数字样式（默认阿拉伯数字） */
  numeral?: 'arabic' | 'chinese'
  /** 显示片段，`{value}` 为取值占位（如 "第{value}纪元"） */
  format?: string
  /** named 单位的取值表（有序）；值可覆盖自身长度与专属闰规则（如二月闰日） */
  values?: { id: string; name: string; length?: number; leap?: LeapRule }[]
  /** 周期闰：每 every 个父级实例，在本级单位上加 add 个本级子单位 */
  leap?: LeapRule
}
```

规则：

- **任意层级**：单位链长度不限，可表达「纪元 → 年 → 月 → 日」，也可表达「劫 → 会 → 元 → 运 → 世 → 年」或「星历 → 周期 → 日」。
- **命名单位**：顶层通常是命名单位「纪元」；月份、星期也可是命名单位。命名值有序，顺序即时间顺序。
- **标量基**：单位链最后一项为标量基（通常是日或秒）。所有排序、缩放、冲突检测、拖拽都用 `toScalar()` 的结果。
- **闰规则**：支持「每 N 个父级实例在本级单位上加 M」+ 例外周期（每 N 跳过 / 每 M 补回），可挂在单位上（所有实例）或命名值上（如二月）。脚本化闰表不在本期。
- **周**：平行于单位链的循环，只影响显示（星期名）与「每周第几天」查询，不影响标量。
- **日以下**：若定义 `timeOfDay`，单位链末端可含「时/分/秒」，固定 60 进制；时间线最高缩放级别可显示到小时。
- **期段**：独立于单位链的命名区间（王朝、战争、时代），含 `start/end/parentId/color`，可嵌套；用于色带、分组与筛选。纪元区间由顶层命名单位天然表达，期段补充任意区间。

### 3.2 日期值

持久化采用**规范文本为真源**，避免给实体字段系统增加对象类型：

- `date` / `dateEnd`：按所属历法的单位片段（`calendar.format` 可覆盖）生成的规范文本。
- `calendarId`：事件所属历法；空 = 项目默认历法。
- `dateCertainty`：精确 / 约 / 早于 / 晚于 / 传说。
- `recurrence`：周期规则 JSON（工具内部结构，显式标注，不参与字段矩阵解读），如 `{ unit: 'year', every: 1, until: '...', exceptions: ['...'] }`。

运行时结构：

```ts
interface TimePoint {
  calendarId: string
  values: (number | string)[]   // 单位链取值，长度可小于单位数（低精度）
  scalar: number                // 派生，不持久化
  certainty: 'exact' | 'approx' | 'before' | 'after' | 'legend'
}
```

- **解析**：`parseDate(text, calendar)` 按单位名/取值名/分隔符解析；中文数字与阿拉伯数字归一；解析失败不丢原文，归入「未定时间」桶。
- **格式化**：`formatDate(point, calendar)` 按 `format` 模板生成规范文本。
- **排序/比较**：只比 `scalar`；模糊日期按估计值排序，显示保留限定词。
- **精度**：允许只填到年/月；低精度日期在缩放到更细单位时不伪造下级值。
- **周期事件**：按可见范围展开虚拟 occurrence，不落库；选中 occurrence 打开基础事件并标出现次；例外用跳过列表。
- **多历法**：同一视图一次只激活一套历法；其他历法事件不参与当前轴，列表中以「其他历法」分组/徽标呈现。跨历法对齐需要显式锚点，本期不做。

### 3.3 坐标与缩放

- `toScalar(point)` / `fromScalar(scalar)` 由 `calendar/math.ts` 提供；闰规则、变长月份、命名纪元都在此处理。
- 缩放级别 = 单位链下标：顶层单位（纪元/劫）→ 下一级（年/元）→ … → 最小单位。
- 标尺主刻度 = 下一级单位的边界；标签用命名值或数值；色带 = 期段/顶层命名区间。
- 缩略图、拖拽、冲突检测全部使用标量，不再出现 `era * 10000 + year`。

### 3.4 持久化

沿用项目库 `project_settings` KV + localStorage 回退（与思维导图文档同模式）：

| 键 | 内容 |
|---|---|
| `timeline_calendar_index` | 历法元数据数组（id/name/updatedAt） |
| `timeline_calendar_<id>` | 单套历法完整 JSON（单位/周/期段/格式） |
| `timeline_active_calendar` | 当前激活历法 id |
| `timeline_migrated_v1` | 旧日期迁移标记（幂等） |

- 项目切换时重读；项目导出/导入需补 `settings/timeline.json`（ProjectFS 与打包导出两条链都要接）。
- 单套历法 JSON 过大时按历法 id 分条，索引单条保持轻量。

### 3.5 旧数据迁移

首次加载（无历法且无迁移标记）时：

1. 建默认「简式历法」：单位链 = 纪元（命名）+ 年（数值）；格式 `{0}第{1}年`。
2. 逐事件解析 `properties.date` / `dateEnd`：提取纪元名与年份，写入规范文本；`properties.era` 的值作为纪元命名值来源（按首次出现排序）。
3. 解析失败的事件保留原文，标记「未定时间」，不丢失。
4. 迁移后 `era` 字段从时间线 schema 退场（历史属性保留只读，不再参与任何计算）。
5. 迁移幂等：标记写入后不再执行；重复导入不重复迁移。

## 四、UI 与交互

### 4.1 时间体系编辑面板

入口：时间线工具栏「时间体系」按钮 → 侧栏/弹层面板。

- **历法**：新建/复制/重命名/删除/设为默认；内置模板（简式、公历式、三纪元式）可一键创建。
- **单位链**：增删/拖拽排序；每项编辑名称、类型（数值/命名）、换算、命名值列表、闰规则；实时校验（factor > 0、命名值非空、最小单位存在）。
- **周与日以下**：每周天数、星期名、锚点；每天小时数。
- **期段**：树形列表（可嵌套）、名称、起止日期、颜色；从时间线选区快速建期段。
- **预览**：格式模板实时预览 + 示例日期解析结果。

### 4.2 日期录入控件

- **结构化选择器**：按单位链逐级选择（命名单位出下拉，数值单位出数字输入）；可停在任意精度；「约/早于/晚于/传说」开关。
- **文本输入**：同一控件内可切换文本模式，按当前历法解析；实时显示解析结果或错误原因；解析失败保留原文。
- **历法选择**：事件级 `calendarId`；非默认历法在卡片上带徽标。
- **周期编辑**：单位 + 间隔 + 结束日期 + 例外日期列表；预览最近若干次发生。
- **详情/表单复用**：主表单、详情行内编辑、Agent 建事件共用同一控件。

### 4.3 双态视图

| 形态 | 内容 | 控件（仅本态显示） |
|---|---|---|
| 编年史（竖向） | 按选定单位/期段分组；时序/大纲树；精度徽标；周期 occurrence | 分组、排序、紧凑、展开/折叠、分页、批量 |
| 时间画布（横向） | 单位层级缩放、泳道、期段色带、缩略图、轴 | 缩放/适配、分组、批量、拖拽提示 |

- 去掉无效组合：排序只在编年史、缩放只在画布、批量两态都可用。
- 泳道头只保留一处；标尺/缩略图宽度扣除泳道栏；滚轮纵向滚动泳道，`Ctrl + 滚轮` 缩放，拖拽画布平移。
- 期段色带与顶层命名区间共用绘制层；嵌套期段以深浅/描边区分。

### 4.4 全量交互清单

- **创建**：画布空白处拖拽出区间 → 新建事件并预填起止；单击空白 → 单点事件。
- **移动/拉伸**：拖事件条移动、拖两端拉伸；按当前缩放单位吸附；确认后写规范文本；支持撤销。
- **缩放/平移**：`+ / - / 适配全部` 按钮 + `Ctrl + 滚轮` + 轴拖拽 + 画布拖拽 + 缩略图点击/拖拽。
- **选中聚焦**：点击、跨视图跳转、冲突跳转都平移画布到事件；树模式自动展开祖先。
- **冲突**：冲突项可点击 → 选中并聚焦相关事件；模糊日期单独标注，不混入精确冲突。
- **批量**：横向/竖向都可进入批量态；框选（画布）与逐项切换并存。
- **键盘**：方向键在可见事件间移动焦点，Enter 打开，`+/-` 缩放，`Home` 适配，Esc 关闭详情/退出批量。
- **提示**：tooltip 改为容器内绝对定位；事件条显示历法徽标、精度、周期标记。

## 七、风险点

1. **历法数学复杂度**：变长月份 + 闰规则 + 命名纪元，`toScalar` 可能需要逐级累加；需缓存并按事件量评估性能。
2. **任意单位链的非法输入**：factor 为 0/负数、命名值为空、最小单位缺失、纪元长度不单调；面板需强校验，内核需 fail loud。
3. **迁移不可逆**：旧自由文本可能大量解析失败；必须保留原文桶并可手工修正。
4. **多历法边界**：用户可能期待跨历法同轴；本期明确不支持，需在 UI 中说明。
5. **周期展开量**：高频周期 + 大可见范围可能产生大量虚拟 occurrence；需按可见窗口展开并设上限。
6. **文件规模**：TimelineView / TimelineChart 已在冻结基线；新逻辑必须外移，新文件 ≤ 400 行。
7. **交互与无障碍**：画布拖拽、框选、键盘导航需同时支持鼠标与键盘，避免只做鼠标。

## 八、测试与门禁
