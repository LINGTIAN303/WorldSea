# dsh 账号登录放开批计划（壳回调口 + 一处 fork + 隐私 R3）

> 动机：dsh 的 DeepSeek 账号栈（Host 提供方 / 控制器 / 账号设置页 / 账号模型路由）在本仓 web profile 里**全部装载在位**，唯一断开的是 OAuth 浏览器回调的那一跳——于是用户看到的不是「没有登录」，而是「有登录按钮、点了必然失败」。本批把这一跳补齐，并同期落实长期挂账的隐私默认值 R3。

## 三、批次划分

### A · 壳侧回调口（新增 `dsh_oauth.rs`）

- **监听**：`TcpListener::bind("127.0.0.1:0")`，取实得端口；范式照 `dsh_relay.rs`（`Drop` 置停止位、逐连接派生线程、头部上限 16 KiB）。
- **路由面**：仅 `GET /oauth/callback`（含 query）；其余路径一律 404 并落档。**不接受方法外请求**（405）。
- **转发**：经 `DshBridge` 的当前装配转发（每请求现取，宿主重启后自然跟随新装配）——
  - 管道态：`PipeClient::request("GET", path_and_query, headers, None)`；
  - legacy 态：`Upstream::Tcp` 的 reqwest 客户端（同一 `ProxyCfg` 已有）。
  - 请求头：只补 `host: 127.0.0.1`（管道侧由客户端合成）与 `accept-encoding: identity`；**不带 cookie**——该路由按上游语义不要求 RPC 鉴权。
- **回包**：把宿主响应的 `status` + `location` 原样转给浏览器（302 透传）；204 时回一个「已处理，可关闭此页」的极简本地页。
- **超时**：本路由单独放宽（取 `min(120s, attemptTimeout)` 量级）。现状 `REQUEST_TIMEOUT` 60s 是写死常量，需增一个带超时的请求入口；超时后回本地降级页（「请回到应用查看登录结果」），**不能白屏**。
- **注入**：`TransportInject::OpenStream` 由单元变体改为携带回调 origin；注入脚本里补 `oauthCallbackOrigin`（`Object.assign` 只合并不覆盖，与现有口径一致）。

### B · dsh 侧一处（fork 台账 +1 文件）

- `dsh/packages/client/ui-settings-account/src/client/index.ts:252-254`：回调基址改为
  `transport?.oauthCallbackOrigin ?? (desktop && transport?.streamBaseUrl ? new URL(transport.streamBaseUrl).origin : window.location.origin)`。
- **不动 `loginOrigin` 白名单**（我们的监听是真 loopback + 显式端口，天然过校验）；**不动 `loginSource`**（保持 `desktop ? 'desktop' : 'web'`，我们走 web 语义）。
- 读取用局部类型断言，**不改 `ClientTransportHooks` 接口**——把 fork 面压到 1 个文件。

### C · 授权页自动打开（壳桥最小桩）

- `dsh_shell_bridge.js` 的 `window.open`：识别 `about:blank` 的**预开窗**语义，返回一个桩窗口对象（`{closed:false, opener:null, location:{replace:openExternal}, close(){}}`）。
- 效果：dsh 的 `BrowserLogin` 拿到桩后，`popup.location.replace(authorizeUrl)` 自动把授权页交给系统浏览器；成功/失败时 `close()` 为无操作。**dsh 侧零改动**。
- 非 `about:blank` 的 `window.open`（含 `_blank` 外链）**行为不变**（仍恒外开并返回 null），避免把逃逸面放大。

### D · 隐私默认值 R3（overlay 两行）

- `session-log-deepseek`：`config: { enabled: false }`（**config 整体替换**，须抄回 `maxBytes` 默认 8 MiB）。
- `session-telemetry-otel`：`disabled: true`。
- 依据：[现状与冻结面 §六 P1](../../details/架构/现状与冻结面.md)「隐私默认值 R3 未见落实记录」。

### E · 收口

- 文档：本计划状态流转 + 索引同步 + 运行手册补「账号登录」段 + fork 台账登记 + [现状与冻结面 §六 P3](../../details/架构/现状与冻结面.md) 摘掉「账号登录浏览器回调已知限制」。
- 门禁：`arch:check` / `fork:check` / 断链 / cargo `--lib` / 仓库根 vitest / dsh 自带 typecheck+lint+受影响包测试。

## 九、施工结果（2026-11-05，代码完成，**待真机走查**）

### A · 壳侧回调口（新增 `dsh_oauth.rs`，365 行）

- `OauthCallback`（listener 句柄，`Drop` 停监听）+ `install()`（起监听并交出转发目标槽）+ `point_at()`（传输面就绪后填目标）+ `forward_via()`（生产转发：管道 / legacy 两条同构）。

### 12.2 退出登录链路：发现并修复一个真实 BUG

排查结论三层：

1. **正常路径没问题**：`attempt` 为空 / `initializing` / `waiting-browser` 三态下 `signOut` 均 25–138ms 成功，本地凭证删除与状态转 `signed-out` 都正确。
2. **异常路径确实存在**：`attempt.phase === 'succeeded'`（刚在同一进程内登录完）时 `signOut` **30 秒无响应**——已实测复现。
3. **根因（诊断日志取证）**：
   ```
   [diag-done] running done, callback= true   ← 登录收尾链走到这里
   （缺 "finished() returned"）                ← 卡在 streamPromises.finished(attempt.callback)
   [diag-signout] enter phase= succeeded      ← 退出进来
   （此后无输出）                              ← 挂在 await cancelSignIn → await attempt.done
   ```
   壳的回调经**管道合成响应**送达（非真 socket），Node `eos` 对非 Stream 参数既不报完成也不报错（`cleanup: true` 吞掉）→ `attempt.done` 永不结算 → `signOut` 里 `await cancelSignIn` 永久等待。

**修法**：`attempt.done` 收尾改为**有界等待**（5s 上限，定时器随 race 结束即 abort）。原意只是「拆路由前让浏览器收完响应」，加上限后「载体不报完成」退化为多等 5s 而非卡死，真 socket 载体零影响。

**验证**：修复后同一场景 **94ms 成功**；账号包 **168/168** 全绿。

**放弃的方案**（留档以免重走）：壳侧把合成响应做成真 Writable 以根本满足 `eos`——实测打挂 C2 的 20 条 pipe 用例（10 失败），且属命脉接缝，风险大于收益，已还原。

### 14.1 风险点 1：「凭据环境剥离」从写死名单改为按库动态发现

**先纠正初判**：那个明文 Key 不是泄漏——

**真正查出的隐患**：`dsh_credentials.rs` 的剥离名单是硬编码常量 `["DEEPSEEK_API_KEY"]`，而模型页可配置**任意** provider（实机环境已有 `OPENCSG_API_KEY`、库里有 `ANTDIGITAL_API_KEY`）。一旦某 provider 的 Key 同时存在于继承环境与库中，环境变量就会永久盖住界面配置——正是 C5 批修掉的症状换了个 provider 重现。

**修法**：新增 `credential_ref_names(home)`，从库的 `refs:` 段动态读出全部凭据名并逐个剥离同名环境变量。三条正确性约束（均有测试锁定）：
- 只收 `refs:` 段的**直接子级**（`nested:` 下的 `inner: x` 不是凭据名）；
- 只收**自带同行标量值**的行（结构键 / 块标量排除）；
- 键名限 `[A-Za-z0-9_]`（环境变量形态），并去重。

**测试**：`dsh_credentials` **9/9**（原 5 例未改 + 新 4 例）。其中「只收环境变量形态」一例在实现中**两次报红**，实际抓出了上述两条候选缺陷——不是补测试凑数。
