## 一、背景与口径

F3 追版登记项（`2026-09-29-F3-追版0.2.0-rc.2批计划.md` §六 G3）：**「若将来要『可回滚的工作区修复』，按 rc.2 形态引入（探测 `pwsh` + 保留 `icacls` 兜底）」**。动机：C4 的一键修复（`icacls /grant <用户>:(OI)(CI)F`）是**单向且粘滞**的（授权后 dsh 沙箱还会在该目录常驻能力 ACE、删除拒绝与 Low 完整性标签），一旦需要撤销没有任何路径。

**用户 2026-10-01 三项拍板（均按推荐）**：
1. **主路径** = pwsh + 上游 rc.2 脚本（`diagnose-windows-sandbox-acl`；祖先链 WRITE_DAC/WRITE_OWNER 一并修、显式 AppContainer 包 ACE 清理、每处改动先备份后复核）；pwsh 或脚本缺失时降级兜底。
2. **回滚入口** = 仅产物 + 打印命令（不做壳内一键回滚——对齐上游技能立场：恢复由用户执行）。
3. **恢复产物** = 工作区根 `.acl-recovery\`（持久、用户可寻、与失败现场同位）。

## 二、勘察（G3-0 实验，全部真机）

**上游脚本面**（`dsh/packages/sandbox/sandbox-windows-acl/assets/diagnose-windows-sandbox-acl/scripts/diagnose-windows-sandbox-acl.ps1`）：
- 入参：`-Path`（必填）/ `-AllowRoot`（必填，改动边界）/ `-Out`（修复必需，产恢复件）/ `-Restore`（回滚模式，单路径）。
- stdout 尾部：`RECAP {json}`（verdicts/changes/verifications/refusals/scans）· `REPORT_FILE <path>` · `SUMMARY FIXED=.. GRANTED=.. REFUSED=.. RESTORED=..`；每处改动逐条打印 `ROLLBACK <cmd>` 并落 `<Out>/acl-backup-<id>.json` + `.ps1`（独立恢复脚本）。
- 本机实测（`D:\ws-g3-test`，D: 盘天然缺 WRITE_OWNER）：`PRECONDITION` 判定 → 备份 → 授权 → 复核（`writeOwner: false→true`）→ `nextAction=verify_original_confined_operation`；按其 `ROLLBACK` 命令回滚 → `RESTORED=1`、ACL 复原继承态。**上游恢复链完整可用**。

**★ icacls `/save`→`/restore` 本机失效（登记）**：受控实验中四种变体——同 CWD 相对名 / 盘根 CWD / 把存档首行改写为绝对路径 / 无扩展名文件——`/restore` 一律「已成功处理 0 个文件」不生效（存档首行被 `/save` 记录为去盘符相对名，疑为其解析路径的机制，未深究）；**同场实测 `/remove:g` 可用**（移除 1 项 → 计数 0）。→ 兜底回滚改用 `/remove:g`，`/save` 存档降级为「修复前 DACL 记录（SDDL 原文，供人工核对/资产管理工具恢复）」。

## 三、施工

**新模块 `apps/tauri/src-tauri/src/acl_fix.rs`**（原 `dsh_workspace::fix_workspace_permissions` 迁入升级；调用点 `shell_bridge::cmd_fix_workspace_acl`（返回值改 `FixOutcome`）与 `menu.rs` 同步；横幅脚本 `dsh_workspace_notice.js` 回执改用 `{label, note}`）：

- **主路径**：`resolve_dsh_root()`（提为 crate 可见）拼出脚本路径（`is_file` 守卫）→ `pwsh -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <脚本> -Path <工作区> -AllowRoot <工作区> -Out <.acl-recovery>`（stdout/stderr 读线程 + 120s 超时轮询 + kill）→ 解析 `SUMMARY`/`REPORT_FILE`/`ROLLBACK`（`parse_script_stdout`，纯函数）→ 恢复命令写 `restore-command.txt`；失败路径附 `RECAP.refusals` 首条 + 报告路径 + stderr 尾（`parse_recap_refusals`）；**脚本真跑了就以其结论为准（失败不回退 icacls——拒绝是它的安全判定）**。
- **兜底**：`icacls /save <pre-state 存档>` → 前检 `has_explicit_user_ace`（判据：`<用户>:` 后第一标志非 `(I`）→ `/grant` → 回滚命令 `icacls /remove:g <用户>` 落 `restore-command.txt`；前检为真时附注释警示（`/remove:g` 会连带移除既存显式项，原状见存档）。
- **回执文案**：横幅/菜单透出 `mode`/计数/「恢复命令见 …」；日志 `[DSH-SHELL] acl-fix: mode=… recovery=… probe=…` + 每条 `rollback: …`。

## 五、登记与不做

- **登记**：① icacls `/save`→`/restore` 本机失效（四变体实测；兜底以 `/remove:g` 为准）；② 兜底回滚对「既存显式项」有连带性（前检 + 警示已兜）；③ 上游脚本路径在 dsh 树内的相对位置有单测守卫（追版挪位即红，须同步 `UPSTREAM_SCRIPT_REL`）。
- **不做**：壳内一键回滚（用户裁定）；把上游脚本 vendored 进壳（零复制、随 dsh 升级受益）；不改 dsh 树；`workspace_probe` 的横幅 CLI 提示文案（`fix_command` 的裸 icacls 行）保持为「命令行兜底」语义不变。
- **风险点**：pwsh 缺失时能力降级（祖先链/包 ACE 清理不可用，仅根目录授权）——已在日志显式降级并保留 icacls 兜底（F3 G3 登记的原始口径）。
