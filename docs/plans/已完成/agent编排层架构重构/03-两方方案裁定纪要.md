## 一、总裁定

**以乙方 [orchestration-matrix.md](../../../details/架构/orchestration-matrix.md) 为唯一架构权威与施工基准**（roadmap 头部 2026-08-25 声明有效）。甲方 01 的依赖明细与耦合清单是有价值的事实补充；甲方 02（Harness/SessionRuntime 方案）列为**未采纳的备选方案**。

净效果 = **乙方框架 + 甲方四项事实修正**（见 §四）。

## 二、根源：两个「13」不是同一个 13

- 甲方「13」= NodeType 枚举的 13 个变体（含 React/SubAgent/Memory/Custom 四个无节点变体）
- 乙方「13」= 产品语义编号（roadmap §二定义），归属为「底座能力 5 + 扩展模式 8」

事实层面两方无矛盾：均为 9 个 OrchestratorNode 实现 + 其余由底座能力表达。分歧只是口径——**功能没有缺失，缺失的是 NodeType 枚举的诚实性**。

## 三、六项裁定

| # | 分歧点 | 裁定 | 核心依据 |
|---|--------|------|---------|
| 1 | 「13」口径 | 乙方产品语义编号为准；NodeType 枚举清理 4 个无节点变体 | 枚举与现实错位是命名问题，非架构问题 |
| 2 | ReAct 与底座 | **不抽离**，AgentLoop 留底座（乙方） | 子 Agent 三处创建 AgentLoop 为原子单元，抽离后语义悬空；织入能力改 Hook = 重写 933 行主链路，回归风险倒挂；「底座独立运行」无真实场景 |
| 3 | 扩展机制 | 不上 ExtensionRegistry；必要时走 `#[non_exhaustive]` + Custom(id)（甲方选项 C） | Rust 扩展通道本就是 trait，枚举仅是元数据标签；动态注册需求尚不存在 |
| 4 | SubAgent 重叠 | 采纳甲方问题，修正解法：**Spec 与实例池下沉为一份共享底层，保留节点/工具双触发** | 节点化会消灭「LLM 自主委派」语义；两者互补非冗余 |
| 5 | 目录与迁移 | 乙方 kernel/patterns 两层 + 样板先行顺序（ToT/Multi-Agent → 单文件升目录 → plan/reflection 拆） | 甲方 infra 层拆分 trait/实现无收益；6 阶段把三类最高风险混排在阶段 5 |
| 6 | 跨模式耦合 | 采纳甲方发现：GoT/ToT 类型解耦 + JSON 工具提取 | 乙方判定线「扩展只依赖底座」与 §3.1 GoT 行「核心依赖：ToT」自相矛盾，不补会卡住施工 |
