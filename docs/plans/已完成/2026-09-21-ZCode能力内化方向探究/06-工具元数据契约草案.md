## 一、立项理由

新内核的工具面需要**单一事实源**：现状是「Rust 原生 ~29 工具 + 前端桥 29 可执行工具 + TS 侧约 209 个工具定义（其中绝大多数不可达）」的三层漂移结构；审批 / 超时 / 输出裁剪 / 大结果外置散落在调用点。ZCode 用一份 `ToolMetadata` 声明（身份 + schema + 安全 + 限制 + 控制）驱动权限、调度与呈现——正是本项目要的词汇表。

## 二、字段契约（对齐 ZCode，Rust 类型为单源）

| 组 | 字段 | 说明 |
|---|---|---|
| 身份 | `name` / `aliases` / `category` / `description` | description 由运行时 schema render（延续「零漂移」哲学，worldview 三级披露不变） |
| Schema | `input_schema` / `output_schema` / `strict` | 跨进程/LLM 边界用可运行时校验 schema（不只用 TS/Rust 类型） |
| 安全 | `read_only` / `destructive` / `concurrent_safe` / `requires_user_interaction` / `always_ask` / `needs_approval` / `risk_level` / `side_effect_scope`(none\|workspace\|git\|network\|system\|session) | 权限系统**读声明**，不依赖调用点猜测（与 [05 草案](05-权限模式机草案.md) 联动） |
| 限制 | `timeout_ms` / `max_output_bytes` | 超时与输出上限元数据驱动（现为调用点硬编码） |
| 控制 | `stop_turn_on_success` / `provider_visible` | provider_visible=false = 仅系统用（不喂模型） |
| 执行 | `executor`：`local` \| `client` | **双执行栈正式化**（见 §三） |

## 三、双执行栈正式化（客户端工具一等身份）

```
ToolDescriptor（Rust 单源）
  ├─ executor=local  → 内核内执行（文件 / 终端 / 记忆 / MCP …）
  └─ executor=client → 前端执行（经既有桥通道 agent:tool_call → ALL_TOOLS_MAP → 结果回传）
```

- 现状的 29 个桥工具即 `executor=client` 的正式成员（`frontend_tool_bridge.rs` + 重生成 `bridge_tool_specs.json`）；`worldview`（114 动作薄壳转发）不变。
- **注册面保持铁律**：派发 action 名必须等于桥注册键 `pluginId:action`（09-17 修过的 `export_outline` 假成功不再复发）。
- 客户端工具与本地工具**同享**元数据契约（审批/超时/输出上限/大结果外置走同一条链）。
- 生成物单源不变：TS 侧声明 → `node scripts/gen-bridge-spec.mjs` → `src-tauri/src/bridge_tool_specs.json`（方向不变，只把「声明」升级为全字段）。
