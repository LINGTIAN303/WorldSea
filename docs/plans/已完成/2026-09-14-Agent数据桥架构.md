# 2026-09-14 Agent 数据桥架构（bridge 未挂载假成功治理）

> status: 已完成

## 一、根因（三层）

1. **数据操作的真相源放在视图组件**——Agent 动作的写操作由视图 handler 执行（`useAgentPluginBridge` 在 onMounted 注册 window listener），视图未挂载 = 无人消费；而工具层 `emitPluginEvent` 返回 `{ ok: true, dispatched: true }`（plugin-backend-tools.ts:5-15）——**「派发了」≠「消费了」**，假成功。
2. **emitPluginQuery 彻底单向**——广播 `worldsea:agent:plugin-query` 后返回「需要通过UI状态读取查询结果」，无等待/回传机制；Agent 拿不到任何数据。
3. **影响面全芽级**：timeline / graph / mindmap / tactical-board / magic / module-builder 同模式（60+ emit 点），不止写作三芽。
   > **后续（2026-09-25）**：`module-builder` 已随「自定义模块」整体剪除（见 [剪自定义模块批计划](2026-09-25-剪自定义模块批计划.md)），本条所列待迁芽清单中不再包含它。

## 二、拍板（AskUserQuestion 三问）

| 决策点 | 拍板 |
|---|---|
| 迁移范围 | **三芽先行**（notebook/manuscript/outline），其余芽同模式挂账分批迁；**迁移目的地澄清：前端 app 级全局模块（非 Rust、非 HTTP 桥）**——数据真相源在 pinia store（undo/关系联动/索引都在 store 层），绕过 store 直奔 Rust 会破坏一致性；HTTP 桥是外部客户端→Rust 的另一条链路，本方案零触碰 |
| 返回值诚实化 | **query 真回传**档：查询带 requestId 等待回传（3s 超时报「桥未就绪」）；写动作保持 fire-and-forget，store 层异常记入 `window.__worldsea_agent_bridge_errors__` 错误桶 |
| 连带语义 | **显式指定**：`create_chapter` 的 bookId 改 payload 显式（不传=未归书，工具参数表同步加字段）；notebook `create_note` 的 folderId 不再兜底第一个文件夹 |

## 三、方案与落地

### 架构：数据/UI 动作分路由

- **新建 `apps/tauri/src/agent/agentDataBridges.ts`**：`installAgentDataBridges()`（幂等）挂 **App.vue onMounted**（`useSystemBridge`「启动时 setup」同款惯例；须在 `bootstrapSprouts()` 之后）。注册两个全局 listener：
  - `worldsea:agent:plugin-action` → 数据动作路由表（`'pluginId:action'` 键）→ 直接操作 pinia store——**与视图挂载无关，必达**
  - `worldsea:agent:plugin-query` → 同步读 store → dispatch `worldsea:agent:plugin-query-result`（requestId 配对）回传
- **视图内 `useAgentPluginBridge` 只剩 UI 动作**：manuscript=export_document（开导出对话框）、outline=navigate；notebook 全数据 → **视图 bridge 整段删除**。每个 (pluginId, action) 只在一处消费，两集合不相交，无双写。
- **handler 串行队列**：Agent 连发动作按序应用（`dispatchChain.then(...)`）——并发执行会让 sortOrder 等派生值读到旧计数（测试实测抓到）。

### 各芽迁移明细

| 芽 | 上移到全局桥 | 留视图 | 留挂账 |
|---|---|---|---|
| notebook | create_note / update_note / delete_note / list_notes / search_notes / execute_code / create_backlink / export_note（8 全部） | 无 | — |
| manuscript | create_chapter / update_chapter / list_chapters / get_chapter_content / reorder_chapters | export_document | insert_mention / split_chapter |
| outline | create_node / update_node / delete_node / move_node / batch_create / export_outline | navigate | link_entity（get_structure 已随 query 真回传在全局桥实现） |

- outline 树逻辑复用 `useOutlineTree()`（install 时实例化：flatNodes/deleteNode/moveNode/syncParentChildRelation——该函数本轮补导出）；useBidirectional 无生命周期钩子可直接全局用。
- `useCodeSandbox` 生命周期钩子改 `getCurrentInstance()` 条件注册（全局桥实例无组件上下文，不再触发 Vue 警告；全局实例与 app 同生命周期）。
- `emitPluginQuery` async 化 + `waitQueryResult`（3s 超时）；`emitPluginEvent` 返回值加 note 说明数据/UI 动作语义；manuscript 工具参数表加 `bookId`。

### 测试（首个 bridge 级测试）

`apps/tauri/src/agent/__tests__/agentDataBridges.spec.ts` 9 用例：数据动作无视图必达（manuscript/notebook/outline 实体真落 store + parent_child 关系同步）、query requestId 回传协议（配对/未命中 found:false/未注册不回传）、install 幂等不双消费。

**测试基建教训**：
- entity store 持久化走 **Dexie/IndexedDB**（WebStorageBackend 兜底路径）——jsdom 无 IndexedDB → `fake-indexeddb/auto`（根 devDeps 已有 v6.2.5，`pnpm add` 时即入）polyfill。
- **共享 store 的断言必须用精确名单/唯一标题**：单次 install + 共享 pinia 下各用例数据累积，「前缀计数 === N」会被别的用例同名前缀数据污染（实测「桥测」前缀同时命中上一用例的「桥测第一幕/第一场」→ 计数永 5 → 谓词永假，一度误判为慢）。
- 串行队列下 handler 排队晚于「fire 后立即断言」→ 全部断言走 **waitFor 轮询**（条件用精确名单，不用总数——总数在中间态提前/滞后放行）。

## 四、挂账

- **其余芽迁移**（timeline/graph/mindmap/tactical-board/magic/module-builder）：同模式上移，各芽 handler 现状未盘点（部分可能从未实现），分批做。
- **UI 动作的跨视图投递**（如 Agent 导航到未挂载视图）：当前忽略语义合理；若要「Agent 导航自动切视图」需视图路由联动，另议。
- **写动作真回执**（requestId 贯穿写路径）：本轮拍板停在 query 真回传档；错误桶已提供排查痕迹，真回执待需求出现再上。
- **生产语义提示**：`create_chapter` 无 bookId 落未归书——Agent 侧若想建进某书需先查书 id（`book` 实体列表）再显式传。
