## 二、已拍板决策（2026-10-25 用户确认）

1. **追踪范围＝应用内跟随**：形象图浮层在应用窗口内置顶跟随鼠标，不做系统级桌宠。
2. **建模渲染＝`@google/model-viewer`**（web component，声明式 GLB/GLTF，自带 `availableAnimations`/`playAnimation()`）；格式限定 GLB/GLTF，不支持 FBX/OBJ。
3. **动态类＝原生动图（GIF/APNG/动态WebP）+ Lottie JSON**（新增 `lottie-web` 依赖）。
4. **静态编辑器＝焦点编辑 + 区域运动编排**（切区域配动效，服务追踪时的静态图动态化，简化版 Live2D 思路）。
5. **视频播放配置（2026-10-25 二次确认）**：网格内多视频同时自动播放**保持现状**（全局开启即全部播放），用户走查时验证性能，不行届时再关闭网格内多播；提前做两项配置：① 自动播放可**指定多个实体**（仅这些实体的视频封面自动播放）② **悬停实体卡片时自动播放**（独立交互项）。

技术前置结论（调研）：WebView2 支持 WebGL2 与 WebM alpha；model-viewer 官方支持动画播放与透明背景；大文件不宜走 base64 IPC——**选择文件走 plugin-dialog 拿磁盘路径 → Rust `cmd_fs_copy` 直拷**，拖拽/粘贴仍走 File 链路但受 base64 上限约束（超限提示改用选择按钮）。

## 三、数据模型

Entity 顶层新增（`packages/entity-core/src/types/entity.ts` + `fieldAccessor.ts` 同步映射）：

```ts
portrait?: string            // 形象图引用（asset URL，磁盘链路）
portraitKind?: 'static' | 'animated' | 'lottie' | 'model'   // 形象类别（上传时判定写入）
portraitMeta?: {             // 形象元数据（各批次渐进填充）
  focus?: { position?: string; zoom?: number }              // 焦点（B：预览/封面用）
  model?: { actions?: ModelActionConfig[] }                 // D2：动作配置分布
  motion?: MotionConfig                                     // D3/D4：区域运动编排
}
videoAsset?: string          // 视频 Tab 资产引用（C）
coverSource?: 'image' | 'portrait' | 'video'   // 封面源（互斥枚举，默认 image）
```

- 封面勾选 UI 呈现为两个独立勾选框（形象作封面 / 视频作封面），底层同 `coverSource` 枚举互斥联动；同时满足时后者优先级：勾「视频」>「形象」> 默认封面图。**与原始需求一致：默认封面图，勾选后形象图/视频替代。**
- MotionConfig（D3 定义、D4 编辑器产出，静态/动态共用）：

```ts
interface MotionConfig {
  regions: { id: string; x: number; y: number; w: number; h: number }[]      // 百分比区域
  tracks: {
    regionId: string
    trigger: 'loop' | 'hover' | 'click'          // 什么时候动
    delay?: number; duration: number; loop?: boolean
    keyframes: { t: number; dx?: number; dy?: number; rotate?: number; scale?: number }[]  // 向哪动/动多少
  }[]
}
```

- 渲染执行：同图源叠 N 层，每层 `clip-path` 切区域 + `transform` 关键帧动画（CSS/WAAPI），无需切图。

#### 遗留观察结案：GIF 丢失（2026-10-26，防御性修复落地）

- **用户线索**：只在重构建（更新程序）时丢失。主动复现（配 GIF→构建 dist→强杀→重启）未复现——磁盘与 UI 全程完好。
- **高嫌疑机制（节奏耦合）**：开发期每次重编需 `taskkill /F` 强杀进程——若恰逢实体写盘，`fs::write` 非原子会留截断 JSON → 前端 loadIndex 解析失败**静默跳过**（实体/形象"丢失"观感）；而「配 GIF 测试→通知开发→构建强杀」的节奏使 GIF 实体高概率撞上写盘窗口。
- **修复（fs_commands.rs）**：`atomic_write`（同目录 `.tmp` 后缀临时文件 + rename 覆盖，Windows 带 REPLACE_EXISTING）应用于 `cmd_fs_write` 与 `cmd_fs_copy_progress`（资产复制同防护）——强杀只留无害 .tmp 残留，目标文件要么旧要么新；loadIndex 解析失败改为 console.warn 留痕（可诊断）。
- **验证**：cargo release 重编 + 全量 1734 绿 + 落盘/JSON 完整性/tmp 残留检查通过。**日常观察**：若更新/重启后仍现丢失，console 将有「实体文件解析失败」告警（此前静默）——届时凭告警定位。生产更新流程（安装器优雅退出）属部署线范畴，不在本批。
