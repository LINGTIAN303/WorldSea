## 一、模块与文件落点

### 1.1 视图注册形态（**本轮第一个技术判断**）

**取证**：项目 27 个官方芽 **全部只注册 1 个视图**（`api.registerView` 每芽调用 1 次）；`ViewToolbarMode = 'bar' | 'none' | 'overlay'`，默认 `'bar'`（占 44px，`packages/entity-core/src/types/plugin.ts:39`）。

**决策**：白板自身用**一个视图内两层导航**（列表层 → 编辑器层），照 `manuscript` 芽的 `selectedBookId` 三态先例；**不把白板再拆成「列表视图 + 编辑器视图」两个视图**（否则要跨视图传「当前白板 id」）。

> **批次 1 落地勘误（2026-09-16）**：原文「**不注册第二个视图**」表述有误。实际落地是——白板作为**第二个视图** `outline-board` 注册（与既有树视图 `outline` **并存**），因为「树 = 结构保真视图 / 白板 = 表现自由视图」本就是两个视图（09-15 文档 §8.10.5-F）。**同芽多视图技术上可行**：`registerView` 是数组 push + 按 id 去重（`packages/entity-core/src/stores/pluginStore.ts:10-14`、`packages/entity-core/src/core/PluginAPI.ts:133-138`）。

**由此修正编辑器规格 §0.1 的布局描述**（原写「悬浮工具条 overlay」）：

| 区域 | 内容 |
| --- | --- |
| 视图工具条（`toolbar: 'bar'`，44px，宿主提供） | **列表层**：新建白板 / 排序；**编辑器层**：返回列表 · 白板名（可就地改） · 保存状态三态 · 折叠右栏 |
| 画布区（视图内容区 `inset:0`） | 画布本体；内含**画布级悬浮条**（画区 / 吸附开关 / 缩放控件 / 适配全部），是画布区内的绝对定位元素，**不依赖视图 toolbar 机制** |
| 右栏（240px，可折叠） | 节点侧栏（层级树 + 搜索 + 拖拽/双击入口 + 「已在板上」标记） |

> 编辑器层的「全屏」= 铺满**视图内容区**（视图工具条 44px 保留且正好承载返回/保存状态），不是 `overlay`。

## 三、分批施工顺序（5 批，逐批可验证）

### 批次 1 · 最小闭环（**先跑通链路**）

- **范围**：实体注册 + 列表层（新建/重命名/删除/进入）+ 画布（缩放平移）+ 右栏（树/搜索/拖拽/双击）+ 容器（创建/移动/选中/删除）+ **标题式**组件 + 保存链（布局防抖 + 退出落盘 + 状态提示）+ 白板撤销栈。
- **验收点**：建两块白板 → 拖 3 个节点入板 → 各有标题式组件 → 拖动排布 → 刷新/重启后**位置与内容都还在** → 删除容器后节点仍在树视图里。
- **不做**：区、吸附、句子式/表格式、缩略图、配置面板、快捷键全集、导出。

### 批次 2 · 布局能力补全

- **范围**：区（画/命名/移动/删除二选一）+ 辅助线吸附（`snap` 三态）+ 容器折叠 + 悬空容器占位与清理 + 撤销重做全覆盖（布局 + 内容单步归并）。
- **验收点**：拖区带内容器整体移动；吸附出现在 6px 内；删除节点后容器显示占位并可清理；`Ctrl+Z` 能回退移动/删除/改名。

### 批次 3 · 表现形式补齐

- **范围**：句子式 + 表格式（复用 `DataTable.vue`）+ `FormConfigPanel`（按 `configSchema` 自动渲染配置）+ 注册表完善。
- **验收点**：一个容器内放「标题式 + 句子式 + 表格式」三种，各自配置独立可改；表格式随子节点增删自动更新；同种形式重复时出现提示。

### 批次 4 · 体验补全

- **范围**：缩略图（退出时生成）+ 视口持久化恢复 + 四种空态与引导 + 快捷键全集（`useShortcuts` 注册）+ 右栏「已在板上」标记与定位行为。
- **验收点**：退出生成缩略图并在卡片显示；再次进入恢复视口；已在板上的节点再拖入 → **定位并选中已有容器**（不新建）。

### 批次 5 · 导出与收尾

- **范围**：导出按「表现形式渲染」接入（docx / markdown；表格式真表格 + 管道表；标题式按 depth 映射 H1–H6）+ 文档收口（三份规格状态流转）+ 挂账清单登记。
- **验收点**：同一份大纲，导出结果符合各形式的导出规格；导出不依赖白板布局。

### 8.2 技术要点

- **视图 id 复用 `outline`**：侧栏顺序持久化的是**视图 id 列表**（`uiStore.sidebarOrder` → localStorage，`uiStore.ts:17-21, 40-43`），复用 id 可无缝接管原入口位置与实体 type→view 映射，不留未知 id 残渣。
- **同一拖拽按落点分流**：右栏节点项的拖拽既可能落在画布（入板）、也可能落在节点项（重排）——由 drop 目标决定语义，两侧各自 `prevent` + `stop`，互不误吞。
- **撤销语义统一**：白板成为唯一入口后，撤销栈由「纯布局快照」升级为「**布局 + 层级**通用快照」（`useBoardUndo` 的 `BoardSnapshot`），层级重排可被 `Ctrl+Z` 撤销；实体侧写入一律带 `{ skipUndo }`，不污染实体全局撤销栈。

### 11.2 关键决策与偏差（如实记录）

1. **缩略图是「结构示意图」，不是内容截图**。白板渲染技术选型是 **DOM 绝对定位**（编辑器规格 §0.2），拿不到 drawing 芽那种 `drawImage(canvas)` 的画布对象；真实渲染截图需要 `html2canvas` 一类**新增依赖**（按项目规则需另行确认）。改为按布局体绘制：**区虚线框 + 容器实心块**——缩略图的用途是「一眼认出是哪块板」，展示区的划分与容器分布已经足够，且不依赖真实 DOM 渲染（退出时也能生成），零新增依赖。
2. **「首次进入适配」用「viewport 是否为空」判定**，而非「内容是否在视野内」。理由：后者会让用户手动缩到某处后重新进入又被强行适配。新建白板把 viewport 置空串即是这一判定的锚点；用户一旦保存过视口（任何拖动/缩放都会触发保存），后续严格恢复。
3. **适配要等画布拿到真实尺寸**：`openBoard` 后编辑器层刚挂载，首帧 `clientWidth` 可能为 0，直接算会得到错误的 zoom/pan（`fitViewport` 内部把可用区钳到 1px → zoom 落到下限）。故 `fitAllWhenReady` 用 `nextTick` + `requestAnimationFrame` 重试（上限 6 帧）。
4. **快捷键注册时机＝仅编辑器层**（`watch(inEditor)` 控制注册/注销）。列表层没有画布语义，不应响应 `Delete` / `Ctrl+Z`。已取证视图切换是**卸载重建**（`ViewContainer.vue:20` 的 `<component :is>` 带 `:key="currentView + ':' + viewRefreshKey"`），故切走视图时注册链自然注销。
5. **`Shift+1` 注册为 `['!']`**：`normalizeKeys` 对非字母可打印字符**不叠加 shift 修饰**（`useShortcuts.ts:79-85`），传 `['shift','1']` 永远匹配不上。这是一个不看实现就会写错的坑，已写入代码注释。
6. **`Space` 平移不进注册表**：它是「按住期间改变拖拽语义」的持续态，不是一次按键动作——注册表的 model 是「按键 → 执行一次 handler」，装不下按住态。
7. **顺延项**：规格 §九 的四种空态在批次 1–3 已全部具备（无白板 / 空白板 / 空容器 / 悬空容器 / 搜索无结果），本轮只做复核未改文案；「缩略图显示在卡片」原属批次 4，已随本轮落地。

### 12.2 关键决策与偏差（如实记录）

1. **「导出不依赖白板布局」的落地口径**：导出**全部大纲节点**，未入板（无容器）的节点按**默认标题式**渲染——判据是「不传 layout 时产物依然完整」。布局只提供**形式偏好**（哪一节点用哪种形式、编号样式等），**不提供结构**；位置 / 尺寸 / 区一概不参与（测试断言：移动容器、加入区后 IR 完全相等）。
2. **树式在导出中等价于「本节点子树」**：树式的 `scope='all'`（覆盖全部节点）在导出中会与逐节点递归**重复输出**同一批节点，故导出按子树处理并**停止对子树递归**。这是导出与画布呈现的**有意不一致**，若将来需要「树式覆盖全树」的语义，应改为在导出入口单独选择。
3. **docx 经 HTML 中转，而非另写 IR→IR 映射**：既有链路是「HTML → `DocxBlock[]` → docx」，已覆盖 heading/paragraph/table/ul 全部所需结构。直接喂 HTML 可少一份映射（那是最易悄悄写错的一环），并保证「HTML 所见 = docx 所得」。代价是一次序列化往返（导出为低频操作，可忽略）。
4. **跨芽引用收敛在一处**：`exportRunner.ts` 是唯一 import manuscript 模块的文件（`htmlToDocxBlocks` / `blocksToDocx` + 字体 store）。**未做文件搬迁**（那会牵动另一条活跃工作线）；挂账见 §12.5-1。
5. **由测试发现的实现缺陷（已修）**：`listItemsToHtml` 原把嵌套列表渲染为**兄弟 `<ul>`**（`<li>父</li><ul><li>子</li></ul>`）。而 docx 侧靠 `<ul>` 的**嵌套层级**推导 `listItem.level` —— 那种结构会让子项在 docx 里退化成同一层。改为先归树再递归渲染，产出真正嵌套的 `<ul><li>父<ul><li>子</li></ul></li></ul>`。
6. **顺带修复的独立问题（提交 `e3fcf39`）**：白板快捷键未出现在「设置 → 快捷键」——根因是设置面板的展示清单来自**静态目录** `SHORTCUT_CATALOG`，与注册表无关；批次 4 只写进了注册处。同时清掉目录里旧大纲视图的死条目 `outline.close-detail`，并把白板快捷键元数据收敛为单一来源 + 一致性守卫测试（`boardShortcuts.spec.ts`）。

## 十六、框架级发现：宿主拖放劫持（2026-09-17）

> **来源**：真机反馈「右栏拖节点时起手光标就是 🚫、画布收不到 dragover、松手无反应」。
> §十五 那轮补的 drop 侧三要件（`preventDefault` / `dropEffect` / 载荷判定 / 落点反馈）**没能解决问题**——因为真因在窗口配置，与页面代码无关。那些改动仍然必要（见下），只是不是根因。

### 16.1 根因

Tauri v2 的 `app.windows[].dragDropEnabled` **默认 `true`**。开启时宿主会在 **Windows** 上安装原生 OLE 拖放处理器，**在 webview 看到之前吃掉落放事件**。官方配置文档原文：

> *"Whether drag and drop is enabled or not on the webview. By default it is enabled. **Disabling it is required to use HTML5 drag and drop on the frontend on Windows.**"*

平台差异（取证自官方文档与社区issue）：macOS(WebKit) 与 Linux(GTK) **允许共存**，仅 Windows 是排他的（OLE 独占 drop target）——所以这个问题**只在 Windows 上暴露**。

**症状指纹**（本次据此在两个回合内定位）：起手光标即 🚫 · `dragstart` 会触发 · 但 **`dragover` / `drop` / `dragleave` 一律不触发**。

### 16.2 影响面（**不止大纲芽**）

| 受影响功能 | 位置 |
| --- | --- |
| 白板右栏节点 → 画布入板 | `outline/board/**`（本次主诉） |
| 白板层级重排（拖到节点项上） | `NodeSidebar.vue` |

### 16.3 处置

1. **配置**：`apps/tauri/src-tauri/tauri.conf.json` 窗口加 `"dragDropEnabled": false`。

2. **代价与兜底**：关掉宿主拦截后，把文件拖到窗口的**非落点区域**会让 webview **导航到该文件**（Chromium 默认行为，表现为整个界面被替换）。新增 `apps/tauri/src/composables/dragDropGuard.ts`（`main.ts` 安装）：只对**携带 `Files` 的拖拽**在 window 层 `preventDefault`（`dragover` 必须 prevent 才会触发 `drop`，否则默认导航照样发生）；页面内的节点拖拽（自定义 MIME）不受影响。配 3 条单测。
3. **代价的边界（需长期记住）**：关闭宿主通道后**拿不到文件系统路径**，只能读 `dataTransfer.files`（内容可读、**不可写**）。

### 19.3 为什么是「换 trait」而不是「删字段」

取证发现 `content` / `wordCount` / `sortOrder` **不是自由写入的野字段**，而是 `narrative` trait 声明的：

```ts
// packages/entity-core/src/traits/index.ts:193-202
export const Narrative = defineTrait({
  id: 'narrative', label: '叙事', description: '创作内容与字数统计',
  fields: [
    { key: 'content',   label: '内容', fieldType: 'textarea' },
    { key: 'wordCount', label: '字数', fieldType: 'text' },
    { key: 'sortOrder', label: '排序', fieldType: 'text' },
  ],
})
```

而该 trait 被 **3 个芽共用**：`manuscript`（章节正文 HTML）+ `notebook`（笔记正文）**确实需要 `content`**，`outline` 是**唯一**不需要的那个。

⇒ 所以「删字段」不能直接动 trait（会伤及另外两芽）。**正确解法是让 `outline_node` 不再复用它**：

### 20.5 三条工程判断

1. **方向不敏感读取**。关系只落一条（**节点 → 实体**），但读取时两端任一匹配即算（`refRelationsOf`）—— 因为注册表自动注册的 inverse（`mentioned_by_outline`）**不落库**，若读取只认一个方向，将来按 inverse 写的关系就会隐身。
2. **哪几条关系类型纳入徽章由注册表决定**，不写死常量。判据＝「源为 `outline_node` 且目标全是 outline 以外实体」，于是 `parent_child` 自动排除、新增一条「节点 → 芽实体」类型**自动纳入**。用 `relationshipRegistry.getBySourceType('outline_node')` —— 该注册表**不会返回自动注册的 inverse**（inverse 的 sourceTypes 是芽实体）✓
