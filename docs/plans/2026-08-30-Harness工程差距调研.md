## 一、流式区呈现差距分析（2026-08-30 首轮，已完成）

**结论**：数据模型层（`rowKind` 六类、折叠三条件、三分终止）与竞品对齐，真正缺的是归约层与渲染层之间的「呈现管线」。这是投入方向问题，不是工程能力问题。

**对照结论表**（4 竞品 vs 本项目，2026-08-30 截图）：

| 能力 | 竞品表现 | 我们现状 | 定性 |
|---|---|---|---|
| 结果投影 | stdout→终端块；搜索结果→可点击路径列表；编辑→diff 高亮块 | `ToolRow.vue` 的 `formatResult` 一刀切 JSON 全量 dump（含 `__meta`、`\n` 转义符直出） | 真缺口 ① |
| 活动聚合 | 「已读取 1 个文件，搜索 2 次文件」「显示更早的 11 条」同类聚合计数 + 二级展开 + 分页 | 只有 `ProcessSummaryRow` 全轮次折叠，无同类动作聚合 | 真缺口 ② |
| 事件闭环 | 过程区干净 | 路由 JSON `{\n}` 泄漏为正文段 | 已知待续（R6-4） |
| 步骤时长 | 每步「持续了几秒」「(4s)」 | 仅命令行有 `exit 0 · 0.9s` | 缺口 ② 子项 |
| 语义图标 | 眼睛/放大镜/终端/铅笔 | 单字角标「执/读/搜」（与「禁 emoji 用 Naive UI/SVG 图标」约束相悖） | 实现细节 |
| 标签去重 | 动词+对象名 | 「执 执行命令 (执行命令)」verb 与 toolLabel 重复 | 小 BUG |
| Markdown/代码 | 全渲染 + inline chips | bubbles 已有 `useMarkdownRender` + `codeHighlight` | 基本具备 |
| 压缩分隔符 | 「历史对话已被压缩」 | message-list 有 `ArchivedSection`，流式区接入待确认 | 待验证 |

**三缺口定性**：
1. **结果投影层**（最关键）：按 `rowKind` 分化的结果渲染（command→剥离 `__meta` 走终端块；search/file→结构化路径列表；编辑→diff 块）。分类字段已就绪，是坐着就能摘的果子。
2. **活动聚合层**：turnModel 归约层加「相邻同类动作合并」，渲染层加聚合行。解决「过程比正文还长」。
3. **事件闭环**：R6-2/3/4 已在 [R6 立项](./2026-08-30-R6动作段持久化计划.md) 计划内，不重复立项。

**优先序**：P0 正确性（JSON 泄漏 + `__meta` 剥离 + 标签重复）→ P1 结果投影层 → P1.5 R6-2/3 落地 + 桌面实例重启复验 → P2 动作聚合 + 时长 + SVG 图标 → P3 diff 渲染 + 时间线视觉。

### 2026-08-30 · 首轮现状盘点（H1-H7 四路并行调研）

#### 各域断点明细

**H1 上下文工程 — 可用，3 硬伤**
- 统一契约存在：`crates/agent-kernel/src/agent/memory.rs` 的 `build_prompt_options` 四段拼接（场景 prompt + 静态 system_prompt + memory_context + pipeline_context）；`crates/agent-memory/src/lib.rs` 记忆注入带 token 预算（2000）与阈值归档。
- 硬伤 ①：归档不回接压缩——`agent/mod.rs` 忽略 `archive()` 返回的 `new_boundary_index`（`let _ =`），消息历史只进不出，长会话终将顶爆窗口。
- 硬伤 ②：全链路无 token 计量的自动裁剪；唯一按条数截断函数 `truncateMessages`（`packages/agent-runtime/src/context/summary.ts`）是死代码。
- 硬伤 ③：工具结果无统一裁剪层——`crates/agent-kernel/src/agent/tools.rs` 全量序列化入历史，截断只靠各工具源头自律，terminal 输出/大文件读取无兜底。
- 附注：四层记忆 `LayeredMemoryStore`（agent-patterns）是模式内参照实现，主聊天链路未接；TS 上下文层（injector/builder）仅群聊在用 `buildSharedBaseLayer`，其余闲置。

**H2 MCP — 骨架（带完整设置界面的空壳）**
- TS 协议栈质量不低：`packages/agent-runtime/src/mcp/mcp-manager.ts`（streamable-http + SSE 解析 + 会话 ID；stdio 半成品，自注"JSON-RPC forwarding not yet implemented"）；`mcp-adapter.ts` 工具包装；ToolBus 有完整 `registerMcpTools` 接口。
- 断点 ①：全仓 `new MCPManager` 零匹配——管理器从未实例化，注册链路缺「点火」。
- 断点 ②：Rust 端整段缺失——`crates/agent-kernel/src/mcp.rs` 仅 trait + Mock（自注"阶段 1.5+ 在 Tauri 集成时注入"，1.5 未发生）；`apps/tauri/src-tauri` 无任何 cmd_mcp_*，stdio-bridge 的 invoke 必然失败；`useAgentRust.ts` 注释自认"Rust 端暂无 MCP 后端"，enabled 直接映射 connected（伪状态）。
- 能力面仅 tools（resources/prompts/sampling 无）；鉴权仅自定义 headers；持久化 localStorage（与数据进 SQLite 的走向不一致）。
- UI 完整：`apps/tauri/src/agent/panels/McpPanel.vue`（增删启停 + 10 官方预设）。

**H3 Skills — 骨架偏可用（断线）**
- 机制层完整且先进：`packages/agent-runtime/src/skills/` 五件套 + 内置 52 技能 + 三种格式兼容（WorldSea skill.yaml / Claude SKILL.md / 裸 instructions.md）+ `meta-tools.ts` 三元工具实现 progressive disclosure（≤2 references 且 ≤3000 token 自动预载）——设计层面对标 Claude Skills 甚至更细。
- 断点 ①（最大硬断点）：商城 Rust 命令层被删——`cmd_skills_*` 六命令在 `apps/tauri/src-tauri` 全部不存在（skills_store.rs 已删，invoke_handler 无注册），安装/卸载/导入/扫描全部必然报 command not found；独立 crate `worldsea-skills-store` 成孤儿；**ROADMAP 仍标记"已完成"，索引中 skills-store-spec 的"已完成"实为 UI 层视角**。
- 断点 ②：注入零调用——`buildSkillIndexPrompt`（registry.ts:186）与 agent-core 的 `buildIndexPrompt` 全仓无调用点；LLM 实际看不到技能列表，load_skill 工具描述里的"Available Skills section"是空头支票。
- 断点 ③：Rust 主链路无技能维度——`crates/agent-kernel/src/scenario.rs` 的 `builtin_skills()` 自注"仅登记意图，实际技能加载在 TS 侧"。
- 断点 ④：autoActivate 字段存在但全仓无消费点；与 13 编排模式零联动。
- 竞品差距定性：差距不在设计在接线——Claude 的索引注入是活跃路径，我们的索引生成函数是死代码。另 Claude Skills 支持可执行脚本，我们技能无脚本概念，工具扩权是会话级静态白名单。

**H4 插件 — 内置闭环 / 第三方生态未建**
- 27 个官方插件（`apps/tauri/src/plugins/plugin-manifest.ts`）端到端真实跑通：Agent 调 `plugin-backend-tools` → 直接写 entity store + 向量索引 + CustomEvent → 前端插件视图刷新；`PluginSandbox.ts` 权限沙箱（12 项权限 → API 白名单 + 原型链污染黑名单）完整。

**H5 规则工程 — 不存在（零骨架）**
- 全库无规则文件模型/存储/加载器/设置 UI；代码中规则全部是开发者硬编码（如 injector.ts 的工具使用策略）。

- 落地条件已备：Rust 注入位现成（`build_prompt_options` 四段加一段 rules）；缺规则文件格式定义、存储、加载时机、设置 UI 四件事。

**H6 IDE 工具面 — 可用（偏闭环）**
- 约 227 个工具（grep `name:` 实数，±3），注册链路三处（tool-meta-registry → 全局 ToolRegistry → ALIAS_MAP 兜底）；注释文档 22 篇与代码一一对应。
- 对照 TRAE 级 IDE 工具面：读/写/**精确编辑（edit_file：old_string/new_string 精确替换）**/Glob/Grep/终端（一次性 + shell 会话五件套）/Git/子代理委派/网络抓取 全部**有**。
- 三缺项：① 语义代码搜索——embedding 设施存在（`packages/agent-runtime/src/embedding/`，IndexedDB 向量库）但只索引实体/KB/记忆，**代码文件无语义索引**，search_files 是纯文本；② LSP/诊断集成——无；③ 浏览器自动化——只有 web_fetch/web_crawl 静态抓取，无浏览器驱动。
- 次要差距：Grep 无 ripgrep 级性能；edit_file 无行号定位/diff 预览。
- 权限体系三层齐全：A7 三分级 + HITL 确认（`crates/agent-kernel/src/confirmation.rs`，ConfirmationBroker 事件→前端弹窗→60s 超时按拒绝）+ A6 生命周期钩子（`tool_hook.rs`：PreToolUse 可改参/Deny）+ 子代理白名单（WhitelistToolBus）+ 写边界（workspace-boundary.ts）。
- **产品定位取舍提示**：H6 三缺项中，语义代码搜索/LSP 是编程 IDE 向能力，世界观构建产品的优先级需按领域需求重估（实体/KB 语义搜索已有）；浏览器自动化对"资料考据"场景有价值。

**H7 事件供给侧 — 可用（投影缺口大）**
- 已有：ToolCallStart/End 配对 + toolCallId 关联 + args/result 全量透传 + R6-1 六类动作段转发（subagent 含 durationMs）。
- 缺口 ①：事件层无 started_at/ended_at/duration（唯一每步耗时来源是 shell 专属的 `__meta.duration_ms`——这就是"竞品每步显示几秒、我们只有命令行 0.9s"的根因）。
- 缺口 ②：ToolCallEnd 无统一 envelope（status/error/stdout/stderr/exit_code/items 无契约），前端 `parseToolResult` 靠 `error` 键 + `__meta.exit_code` 猜测。
- 缺口 ③：search/fs 类结果无命中列表统一投影契约；trace 通道仅文本摘要无法回源重建行卡；confirm 事件 requested 不带 args。
- H7 是流式区 §一 P1（结果投影）/P2（步骤时长）的**直接上游依赖**——先补事件字段，前端投影才有米下锅。

#### 贯穿模式（跨域共性发现）

1. **「断线空壳」模式**：机制层与 UI 层完整、点火环节缺失——MCP（MCPManager 零实例化）、Skills 注入（索引生成函数零调用）、人格预设（有 UI 无消费）、TS 上下文层（死代码）。**我们缺的不是设计是接线**。
2. **「TS↔Rust 双轨脱节」模式**：单聊主链路已迁 Rust（agent-kernel AgentLoop），但 TS 侧资产（技能注册表、MCP 管理器、上下文层）未随迁，Rust 链路感知不到——端分离重构的遗留债。凡"前端可用、Rust 无感知"的域都属此类。
3. **「文档过期」模式**：ROADMAP 标 Skills 商城已完成（实际命令层被删）；`mcp.md` 注释指向 crate 拆分前旧路径；skills-store-spec"已完成"实为 UI 层视角。索引与实况漂移，印证了"文档变更必须同步索引"约束的必要性。

#### 首轮结论：Harness 侧优先序建议（与流式区 §一 P 级合并）

### 2026-08-30 · P1 真机冒烟（第四轮）——技能内容加载根因修复（Vite8 glob 坑）

**第四轮结果**：① 已安装区块出现 ✅ ② 卸载生效 ✅ ③ 时长可见 ✅（load_skill 行卡 0.0s 即 durationMs 字段）④ **发现真问题**：`load_skill('worldbuilding')` 返回 "has no instructions"——技能注册了但内容全空。

**根因（四轮诊断实验定位）**：**Vite 8（Rolldown）的 `import.meta.glob` 对模块相对模式（`../`、`./`）静默 0 命中**——只有项目根相对模式（`/packages/...`）能命中（对照实验：根相对 37 命中 / 模块相对全 0，连必然存在的 `*.ts` 都 0）。loader 的三个 glob 全部失配 → 动态 import 抛 TypeError → loader 的 try-catch 吞成 null → "空壳技能"。**这解释了为什么 52 个内置技能全部是空壳**（不止 worldbuilding）。

**修复**：弃用 glob，改为**生成式静态映射** `content-map.ts`（67 条内容文件：SKILL.md/instructions.md/references/*.md/assets/*，每条一个显式动态 `import('./xxx?raw')`，保留懒加载；PowerShell 生成器按目录扫描生成，技能文件变更时重新生成）。`loader.ts` 三函数（prompt/reference/asset）全部接映射。新增 `loader-smoke.spec.ts` 回归测试（worldbuilding prompt + references 加载断言）。

**验证**：loader-smoke 2/2 + typecheck + vitest 15 文件全绿。**重要教训入库**：① Vite8/Rolldown 的 `import.meta.glob` 模块相对模式静默失配（不报错、返回空）——全项目排查其他 glob 用法待办；② 桌面调试 alert 被 WebView 权限拦截，用 console.log；③ 管道写文件在中文路径下可能丢内容，用 `[IO.File]::WriteAllLines`。

**第五轮复验**（前端改动，刷新 WebView）：① 新会话 `用 load_skill 激活 worldbuild 技能并简述工作流` → 应返回技能真实内容（目标/工作流章节）→ ② 随便再试一个其他技能（如 content-craft）确认非个例 → ③ 完成后 Skills 链路闭环，开工 P1.5
