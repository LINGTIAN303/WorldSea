## 三、现状事实基线

### 3.1 dsh 侧（`D:\WorldSea\.独立项\deepseek-harness`，2026-09-23 快照）

- 体量：**312 个 workspace 包**；`packages/*/src` **2,304 文件 / 393,043 行**（client 60 包 936 文件 123,575 行，其中 `.tsx` 278 文件 47,608 行；core 45/14,646；session 98/17,845；host 25/4,077）。apps：cli（src 8/909，bin=`lib/bin.js`）、web（src 4/66 + vite 产物）、desktop（Electron，src 58/6,332）、desktop-host（纯 Node，8/628）。测试 1,802 个 `.spec`；外部运行时依赖 67 名；lock 1,678 条 resolution。
- 仓库 138 MB（packages 61 MB）；**未安装、未构建**（无 `node_modules`、无 `lib/`、无 `dist/`）。
- 许可 MIT；版本 `0.1.7-alpha.2`（developer preview，官方声明将有破坏性变更）。
- 运行要求：Node `^22.19 || >=24`（本机 v24.10.0 ✓）；pnpm 钉 `11.7.0`（本机 11.5.1，调用时需按版本）。
- 构建链：`pnpm install` → `pnpm run build`（`build:lib:host` = tsc -b + tsdown；`build:lib:client` = tsdown client face；`build:web` = vite → `apps/web/dist`）。
- 启动链：`dsh <profile>` → CLI → `runProfile` → `$DSH_HOME/profiles/<name>/` → webserver 监听 `127.0.0.1:3080` → `frontend-static` 伺服 `apps/web/dist`，并在 index 注入 `window.__DSH_BOOT__` 与 `/plugins/??…` 客户端包图 → 打印 `?token=` URL，浏览器换取签名 Cookie。
- 插件组合：`vendor/` 内置 Cordis（9 包，含本地修改）；组合序 = bundle → profile patch → home patch → `--patch` overlay。

### 3.2 dsh 与「壳」的耦合（换 Tauri 的全部工作面）

Electron 只出现在 `apps/desktop`（27 文件 import electron；引用计数 BrowserWindow 43 / webContents 92 / Menu 38 / ipcMain 35 / autoUpdater 3 / showOpenDialog 1；**无 Tray**）。`packages/client`、`packages/host`、`apps/desktop-host` 内 **零 electron 导入**。接缝共 6 处：

| # | 接缝 | dsh 侧现状 | Tauri 侧做法 |
|---|---|---|---|
| 1 | 子进程启动 | Electron RunAsNode + `--expose-internals` + 内置 pnpm | Rust 侧 spawn `node <dsh>/apps/cli/lib/bin.js --profile <p> --no-open --port <p>` |
| 2 | 传输 | 特权协议 `dsh-app://app/` + `protocol.handle` 伺服 dist + `/api` 转发 + WS 凭据注入 | **A（推荐）**：WebView 直指 `http://127.0.0.1:<port>/?token=…`，零协议重写；**B**：Tauri 自定义协议复刻 Electron 姿态 |
| 3 | 壳桥（preload 全局） | 8 个全局；client 真正读取只有 3 处且**全部可选**（`!('dshDesktop' in globalThis)` 时整页 return；`dshPlatform` 缺失即省略；`__DSH_HOST_PATHS__` 走 `?.`） | 按需注入（Tauri initialization script）；不注入也不坏主界面 |
| 4 | 宿主能力 | 原生目录选择 / 更新准入 / 平台凭据 / Office 运行时 / `load_workspace_dependencies` | 目录选择：dsh 在 Windows 走 koffi（非 Electron），**可能零改动**；其余按需 |
| 5 | 壳功能 | 原生菜单 / 强制更新 / 崩溃报告 / 单实例锁 / 麦克风权限 / DevTools 快捷键 | Tauri 侧按需（首期最小集：单实例 + DevTools + 退出清理） |
| 6 | 打包 | Electron 安装包 + electron-updater | 后置裁定（§十 R1） |

## 五、迁入方案（dsh 落点与形态）

**已拍板（D5/D6）**：仓根新建 `dsh/`，整仓原样迁入（`packages/`、`apps/`、`vendor/`、`scripts/`、`snapshots/`、`docs/`、`website/`、`python/`、`benchmarks/`），保留 dsh 自身 pnpm workspace 与 lockfile，**不并入本仓根 workspace**（`pnpm-workspace.yaml` 不收录 `dsh/`）。重构完成后再议是否调整形态。

理由：① dsh 的构建链、bundle purity 门、client 构建预设都假设其仓根结构，混入会破坏可更新性与可复现性；② 「直接迁文件」的最小改动路径；③ 上游以 `git pull` 更新，更新引发的问题一律在体外解决。

**基线来源（D9）**：迁入内容取上游 tag `dsh-v0.1.7-alpha.2` 的干净克隆（本地已验证副本 `D:\dsh-up`）；不使用 `.独立项/deepseek-harness`（理由见 §九 B0 结果）。

配套：
- 迁入后 `dsh/` 内不改源码；本仓需要的新行为一律经 dsh 扩展点（profile / `cordis.patch.yml` / 插件）实现。
- 依赖安装：dsh 无 `.npmrc`，而本机 npm 官方源不可达（既往实测）→ 以**命令行/环境变量**覆盖 registry（`npm_config_registry=https://registry.npmmirror.com`），不改 dsh 内任何文件；口径写进运行手册。
- 入库策略：`dsh/node_modules`、构建产物（`lib/`、`apps/web/dist`）、`~/.dsh` 均不入库；其余原样入库（§十 R7 / 待拍板 ②）。

## 六、壳替换方案（Tauri 替 Electron）

首期链路：Tauri 启动 → Rust 侧 spawn dsh CLI（`--no-open --port <空闲端口>`）→ 解析 stdout 的 `?token=` → WebView 指向 `http://127.0.0.1:<port>/?token=…` → Cookie 建立会话 → 退出时 kill 子进程（含异常路径）。壳桥按 3 处读取点按需注入。

- 窗口：现 `tauri.conf.json` 为无边框 + `dragDropEnabled:false`；dsh 界面自带布局，窗口形态（原生边框 / 无边框 + 自绘标题栏）属 UX 决策 → 首期取**原生边框**，后续按需。
- dev：`beforeDevCommand` 改指向 dsh 构建产物 + 起服务；`frontendDist` 让位（不再加载本仓 Vue 前端）。
- 本仓 Vue 前端在壳内不再加载——产品域部分（sprouts 等）落位另行立项（待拍板 ④）。

## 九、批次计划

> 反证式验收沿用既往口径：注入一次它声称会拦的错误 → 必须报红 → 还原 → 转绿，两次输出留档。

### B0 · 起跑线（不动本仓）

- 任务：在 dsh 副本上 `pnpm install`（registry 覆盖）→ `pnpm run build` → 起 `--profile web --no-open --port <p>` → 记录协议面（`/api`、`remote.mux`、cookie、`__DSH_BOOT__`）。
- 验收：真机走查——浏览器里跑通一次真实会话（含工具调用），界面与官方一致。
- 反证：registry 覆盖失效 / 端口占用 / token 缺失 三类失败留档（表现与判别）。
- 前置风险：Node 原生件（node-pty ConPTY、koffi）在本机 Windows 的构建结果必须在此批确认。

**结果（2026-09-23，通过）**

- **快照取舍**：`.独立项/deepseek-harness` 实测**不自洽**——相对上游 `master`（= tag `dsh-v0.1.7-alpha.2`，`00102833`，09-22 23:25）为 **+197 项新增 / 0 项缺失 / 仅 `pnpm-lock.yaml` 内容不同**，属「新源文件已加、清单与类型未同步」的中间状态（如 `boot/app-boot/src/watch-config.ts` 引 `chokidar` 而该包未声明）→ `pnpm run build`（`tsc -b tsconfig.host.json`）报 **487 个类型错误**，`pnpm run clean` 后重建仍 487。故改取上游 tag 干净克隆（D9）。
- **一次过链路**（干净克隆）：`pnpm install`（registry 覆盖 npmmirror；1679 解析 / 1386 包 / node_modules ≈2.1G）→ `pnpm run build`（`build:native-system` + `build:lib` + `build:web`；产出 263 客户端产物 / 69 个 `lib/client.js` / 307 个 `lib/index.js` + `apps/web/dist`）→ `node apps/cli/lib/bin.js web --no-open --port 3088`（隔离 `DSH_HOME`）。**Node 原生件（node-pty 等）在 Windows 下无阻塞**。
- **界面与协议面（B2 壳用）**：界面完整渲染（中文；左栏会话/工作区、主区输入区、设置），**控制台零 error/warn**；`GET /?token=…` → **303 + `Set-Cookie: dsh-auth-*`**（HttpOnly / SameSite=Strict / Max-Age 30 天）→ 换 Cookie 后 index 正常（32.9 KB，含 `__DSH_BOOT__`）；`/api` 无 Cookie → **401**（鉴权围栏在位）；监听 `127.0.0.1:3088`。
- **环境约束（B1 前置，实测）**：① **依赖安装须在工作区外**——在 `.独立项` 内安装连败四次，7 个补丁依赖（`patchedDependencies`）在「临时目录→正式名」改名时报 `ERR_PNPM_EPERM`；放工作区外全新安装即过（本机 Defender 实时保护已关，非杀软；换 import 方式无效）。② `DSH_HOME` 须隔离（`~/.dsh/profiles/web` 已被第三方插件改过、且有存量会话）。③ 构建需 git 提交（`repositoryCommitHash`；无 `.git` 时可用空基线提交或 `CLIENT_COMMIT_HASH_VARIABLE`）。④ registry 用 npmmirror 单次覆盖、pnpm 在 dsh 目录自动切其钉住的 11.7.0、Node v24.10.0 满足要求、环境已设 `DEEPSEEK_API_KEY`。
- **证据**：`.workbuddy/b0-evidence/`（安装 / 构建 / 启动日志 + 用户副本 487 错日志 + 快照差异清单；`.workbuddy/` 为本地目录不入库）。
- **真机走查（2026-09-23 用户确认通过）**：按 5 项清单执行（界面一致 / 流式回复 / 工具调用与审批 / 设置页 / 终端与文件能力），结论=**通过**。**B0 结案**。

| R4 | Web 安全姿态：cookie 无 `Secure`、无 logout、webserver 不含 TLS/认证 | 本地 loopback 可接受，暴露即危险 | 维持 loopback-only；不开 `--host 0.0.0.0` |
| R5 | 供应链：`dsh plugin add` 会执行第三方包 `prepare` 脚本 | 执行未审查代码 | 只装审查过的包；本仓不自动安装第三方插件 |
| R6 | Windows 原生件：node-pty（ConPTY）、koffi、ripgrep sidecar | B0 构建可能失败 | **B0 实测无阻塞**（Windows 下 install+build 一次过） |
| R12 | **安装环境**：dsh 依赖安装在工作区路径下会因补丁依赖改名报 `ERR_NPM_EPERM`（本机实测四次） | B1 在仓内 `dsh/` 安装可能复现 | B1 前置先做「`dsh/` 内安装」验证；复现则先补 `.qoderignore`（排除 `dsh/`、`node_modules/`）并清干净半成品；仍不行则把安装放仓外并登记为交付约束 |
| R13 | **快照完整性**：外部来源的 dsh 副本可能是不自洽的工作树拷贝 | 误用则构建不可用（实测 487 类型错误） | 已裁 D9 改用上游 tag；迁入前做一次「与上游 tag 的差异核对」（`diff -rq` 排除 node_modules/lib） |
| R7 | 仓库体积 +138 MB（未裁剪） | 克隆与 diff 成本 | 见待拍板 ② |
| R8 | 产品域（27 芽 UI / 产品 Rust 命令面）在壳内悬空 | 产品功能暂时不可达 | 本期不动、不删；「产品域落位」单独立项 |
| R9 | 门禁误伤：arch:check 的未登记/行数/baseline 增长会拦住 dsh 子树 | 提交被挡 | B1 即登记豁免；冻结面标「冻结」 |
| R10 | 端口/多实例/生命周期：dev 期与已装实例并存 | 冲突与残留进程 | 单实例锁 + 端口探测 + 退出清理（B2） |
| R11 | 凭证来源：dsh 需模型 Key（`DEEPSEEK_API_KEY` 等），与本仓既有 Key 配置（SecureStore / `.env`）并存 | 用户可能需两处配置 | 见待拍板 ③ |
