# 方向 3 · 权限分级与沙箱耦合设计（P2-2 拍板定稿）

> 背景：`docs/plans/2026-09-01-系统触达面补齐调研.md` 方向 3 的 P2-2 曾挂起——
> 现有三档选择器链路完整，但「完全通过（off）」放开边界涉及 L1 HITL / L2 敏感目录 /
> L3 项目数据三层守卫取舍，属产品安全底线。本设计完成拍板，供立项施工。

## 一、现有链路盘点（代码级事实，2026-09-03）

### 1.1 三档安全级别（已存在，运行时切换）

| 档位 | 语义 | 现状 |
|------|------|------|
| `off` | 完全通过（放开全部确认） | `set_security_level` 写入；前端 ChatInput 权限分级图标下拉 |
| `dangerous_only`（默认） | 仅危险操作确认 | ConfirmationPolicy::dangerous_only() |
| `moderate_and_dangerous` | 写操作/命令执行一律确认 | ConfirmationPolicy::moderate_and_dangerous() |

对应 Rust：`A7 tool_permission`（Safe/Moderate/Dangerous 三分级静态映射）+ `ConfirmationPolicy`（confirm_tools / dangerous_command_patterns / confirm_moderate / allow_sensitive_with_confirm）。

### 1.2 三层守卫（独立维度，与档位正交）

- **L1 HITL 确认**：`needs_confirmation`（confirmation.rs）——Dangerous 无条件确认；Moderate 按档位（confirm_moderate）+ 危险命令模式（rm -rf 等）动态升级
- **L2 敏感目录**：`guard_fs_path` + `is_sensitive_path`（~/.ssh、~/.gnupg、/etc、/usr、/bin、/sbin）——默认 `PathGuard::Deny`；隐藏开关 `allow_sensitive_with_confirm` 可改为 Confirm（**未接 UI，2026-09-03 决策删除**）
- **L3 项目数据**：E1 写保护（agent-commands fs_tools `ensure_not_protected`）——entities/、.worldsmith/ 一级目录 Agent 裸写拒绝（写工具与 shell 词法双通道）

另：agent-tmp 全权免确认（`should_bypass_confirmation`，2026-09-03 拍板）只作用于 L1，不削弱 L2/L3。

### 1.3 挂起症结（本设计要解决的）

`off` 档只放开 L1（L2/L3 仍硬拒）——「完全通过」名不副实；若真全放，无沙箱时 Agent 裸奔。三层守卫的取舍归属不清晰。

## 二、外部对标（2026 年，Claude Code 为主）

### 2.1 Permission Mode 光谱（6 档，非孤立开关）

| Mode | 自主度 | 行为 |
|------|--------|------|
| `plan` | ★☆☆☆☆ | 只读研究，只研究不动手 |
| `default` | ★★☆☆☆ | 读文件免问，其他操作逐条确认 |
| `acceptEdits` | ★★★☆☆ | 读写文件免问，执行命令要确认 |
| `auto` | ★★★★☆ | 背景分类器自动审批，危险操作拦截 |
| `dontAsk` | ★★★★☆ | 只执行预批准的工具，其他全部拒绝 |
| `bypassPermissions` | ★★★★★ | 全部免问（**仅限沙盒**） |

### 2.2 关键洞察（直接指导本项目）

1. **免审批的先进解法 = auto 分类器**（Anthropic 实测用户批准率 93%）：两层防御——输入层 prompt 注入探针（扫描工具输出）+ 输出层转录分类器（快速单 token 过滤 → 命中才链式推理）。威胁模型四类：过度主动 / 诚实错误（误判影响面）/ prompt 注入 / 模型失准。
2. **bypassPermissions 仅限沙盒**——「无护栏」强行绑定「隔离」。Windows 无官方沙箱，本项目现实形态 = 受限目录 + 受限进程。
3. 分级拦截至少覆盖前两类威胁（过度主动 + 诚实错误），prompt 注入靠 auto 层探针（远期）。

## 三、五档全光谱模型（2026-09-03 拍板）

把现有三档演进为光谱式五档，旧档位语义保留兼容：

| 档位 | 语义 | 与现状映射 |
|------|------|-----------|
| `plan` | 只读研究（无写/无命令，产计划文本） | 新增 |
| `default` | 读免问，写+命令确认 | = moderate_and_dangerous |
| `acceptEdits` | 读写文件免问，命令确认 | = dangerous_only + 文件 Safe 放行（新增档） |
| `auto` | 分类器审核，危险拦截 | 远期（轻量 judge 模型），本期占位 |
| `bypass` | 全免问 | = off 改名，**仅限受限执行启用时可用** |

### 3.1 守卫矩阵（三层永不为档位内可舍项）

| 档位 | L1 HITL | L2 敏感目录 | L3 项目数据 |
|------|---------|------------|------------|
| plan | 全禁写/命令 | 硬 Deny | 硬 Deny |
| default | 全确认 | 硬 Deny | 硬 Deny |
| acceptEdits | 仅命令确认 | 硬 Deny | 硬 Deny |
| auto | 分类器裁决 | 硬 Deny | 硬 Deny |
| bypass | 免问 | 硬 Deny | 硬 Deny |

- **L2 敏感目录：五档统一硬 Deny**（2026-09-03 拍板）——删除隐藏开关 `allow_sensitive_with_confirm`（未接 UI，防远期误开）
- **L3 项目数据：五档统一硬 Deny**（E1 不变，防数据损坏且不可确认放行）

## 四、与沙箱耦合

- **bypass 前置条件**：受限执行启用（Bash/命令落 `agent-tmp` 限定域 + Job object 受限进程 + 环境清理）；未启用受限执行时选 bypass → 拒绝并提示改用 default/acceptEdits
- **Windows 落地形态**（方向 3 主文）：受限目录 + 受限进程（Job object + cwd 限定 + 环境清理 + 禁危险内建），非完整容器；网络/文件系统强制隔离留远期
- **L1 中的危险命令三键确认（通过/取消/拒绝）保留**；沙箱内命令自动放行、沙箱外命令仍走确认——分级审批
