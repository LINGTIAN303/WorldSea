# 方向 3 · 权限分级与沙箱耦合设计（P2-2 拍板定稿 v2）

> 背景：方向 3 的 P2-2 曾挂起——现有三档选择器链路完整，但「完全通过（off）」放开边界
> 涉及 L1 HITL / L2 敏感目录 / L3 项目数据三层守卫取舍。经两轮设计（v1 五档光谱 →
> v2 三档 + 规则引擎）完成拍板。v2 引入用户两种规则机制（可学习白名单 / 上锁名单），
> 用规则覆盖档位粒度，从而精简档位数。

## 一、现有链路盘点（代码级事实，2026-09-03）

### 1.1 现行三档安全级别（运行时切换）

| 档位                       | 语义           |
| ------------------------ | ------------ |
| `off`                    | 完全通过（放开全部确认） |
| `dangerous_only`（默认）     | 仅危险操作确认      |
| `moderate_and_dangerous` | 写操作/命令执行一律确认 |

对应 Rust：`A7 tool_permission`（Safe/Moderate/Dangerous 静态映射）+ `ConfirmationPolicy`（confirm\_tools / dangerous\_command\_patterns / confirm\_moderate / allow\_sensitive\_with\_confirm）。

### 1.2 三层守卫（独立维度）

- **L1 HITL**：`needs_confirmation`（Dangerous 无条件确认；Moderate 按档 + 危险命令模式动态升级；危险命令三键确认：通过/取消/拒绝）

- **L2 敏感目录**：`guard_fs_path` + `is_sensitive_path`（~~/.ssh、~~/.gnupg、/etc、/usr、/bin、/sbin）→ 默认 Deny；隐藏开关 `allow_sensitive_with_confirm`（未接 UI）

- **L3 项目数据**：E1 写保护（entities/、.worldsmith/ 裸写拒绝，写工具 + shell 词法双通道）

另：agent-tmp 全权免确认（`should_bypass_confirmation`）只作用于 L1，不削弱 L2/L3。

## 二、v2 核心：规则引擎（用户补充想法，2026-09-03 拍板）

档位只表达「默认策略」，粒度控制交给两条用户规则表：

### 2.1 可学习白名单（Allow Rules）

- **触发**：L1 拦截弹窗内新增「添加白名单并放行」按钮 → 命令/目录加入白名单 → 放行；后续再遇自动放行

- **粒度**：命令白名单（前缀/精确命令模式）、路径白名单（目录或文件，可 glob）

- **意义**：确定性、零模型成本的降疲劳方案（对齐 Claude Code *always allow*）；消解 `default` 档重复询问 → 吸收原 acceptEdits 档价值

- **约束**：白名单可被锁覆盖（命中锁时白名单不生效）

### 2.2 上锁名单（Lock Rules）

- **触发**：用户显式指定目录/文件上锁；UI 名单表（三维度勾选）

- **三个维度**：`read` 可读取/不可读取、`command` 命令可用/不可用、`write` 可写/不可写

- **默认策略（拍板）**：锁默认 `command`/`write` 禁 + `read` 可；敏感目录预置为全维锁（含 read 禁），用户可在 UI 调整

- **语义**：锁是硬约束，任何档位与白名单均不可突破（安全底线）

### 2.3 优先级链（关键设计点）

```
Lock（上锁规则，最高·硬约束） > Allow（白名单，放行例外） > 档位默认策略
```

- 命中锁 → 按锁维度拦截（不符维度即拒绝/禁命令；读锁禁读）

- 未命中锁、命中白名单 → 自动放行

- 均未命中 → 按档位默认

### 2.4 与 L2/L3 的关系（统一为预置锁）

- **敏感目录** → 内置预置锁（`~/.ssh` 等全维锁，用户可见可编辑）——取代现硬编码 `is_sensitive_path` + 删除隐藏开关 `allow_sensitive_with_confirm`（v1 已拍板）

- **项目数据 E1** → 内置预置锁（entities/、.worldsmith/ 建议 `command`/`write` 锁且 UI 默认不可解除或需高阶确认——数据正确性红线）

## 三、三档光谱（v2 拍板）

| 档位             | 语义                                                       | 吸收的原五档                                 |
| -------------- | -------------------------------------------------------- | -------------------------------------- |
| `plan`         | 只读研究（写/命令禁，锁仍生效）                                         | plan                                   |
| `interact`（默认） | 交互确认：读免问，写/命令按确认策略问（含危险三键），拦截时可一键加入白名单                   | default + acceptEdits（白名单学习覆盖）+ 可学习白名单 |
| `autopilot`    | 免逐条确认：白名单自动放行 + 锁自动拦截 + **未覆盖操作由 Agent 自动判断**（名单外不强行问用户） | bypass + auto 的融合                      |

- **autopilot 内嵌 Agent 自动判断**（用户拍板保留 auto 概念）：名单（白+锁）内直接裁决不模型判断；名单外由 Agent 自动判断（远期 P2，依赖 judge 模型 + prompt 注入探针）

- **agent-tmp 免确认**（`should_bypass_confirmation`）语义保留：视为隐式白名单（interact 档也放行）

### 3.1 守卫矩阵（三档 × 三守卫）

| 档位        | L1 HITL         | L2 敏感目录（预置锁） | L3 项目数据（预置锁）    |
| --------- | --------------- | ------------ | --------------- |
| plan      | 全禁写/命令          | 全维锁          | command/write 锁 |
| interact  | 按确认策略问 + 白名单可学  | 全维锁          | command/write 锁 |
| autopilot | Agent 自动判断（名单外） | 全维锁          | command/write 锁 |

## 四、与沙箱耦合

- 原「bypass 前置受限执行」被 autopilot 吸收：autopilot 因有锁+白名单兜底，安全性高于原裸 off；**仍建议配合受限执行**（Bash 落 agent-tmp 限定域 + Job object 受限进程 + 环境清理）作为更硬边界，是否硬前置由沙箱施工时定

- 危险命令三键确认在 interact 档保留；沙箱内命令自动放行、沙箱外走确认（分级审批，随方向 3 主业）
