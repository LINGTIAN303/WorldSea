## 一、目标与非目标

**目标**：跑起来之后，`dsh` 宿主进程**不监听任何 TCP 端口**；页面的全部通信（静态/`/api`/流）经「壳协议 → 壳内 Rust → **命名管道/UDS** → 宿主」到达。UI 与功能 100% 不变（与 C1 走查项等强）。

**非目标**：
- 不改页面可感知的协议语义（openStream 之外的客户端面不动：unary RPC 仍走文档基址）；
- 不做账号登录的浏览器回调通道（见裁定 ③）；
- 不做打包/分发形态与更新通道（C1 §七 遗留，仍挂账）。

## 三、形态与做法（帧隧道）

**通道**：命名管道（Windows `\\.\pipe\worldsea-dsh-<pid>-<rand>`）/ Unix 域套接字（POSIX）。**路径由壳生成**，经 CLI `--ipc-pipe <path>` 传入；宿主 `net.createServer().listen(path)`；壳解析 ready 行（取 token/authority）后拨号（带重试）。单连接、帧内 id 多路复用。

**帧格式（两端自定，长前缀 + 类型）**：`u32be(len) + u8(kind) + payload`
- `J`：JSON 控制帧——复用 dsh 隧道帧 shapes（`req`/`res`/`res-head`/`res-chunk`/`res-end`/`res-err`/`stream-open`/`stream-item`/`stream-end`/`stream-error`/`stream-uplink-*`/`abort`），二进制体字段以 `bodyLen` 声明；
- `B`：二进制体帧 `[u32be(id)][bytes]`——严格跟随同 id 的 `J` 帧（顺序即关联）。

**宿主侧（dsh fork）**：
1. **webServer**：加「外部载体」模式——不 bind TCP（`port` 返回声明值），暴露请求派发接缝（供合成请求 feed）；
2. **web-app bundle**：新增 `pipe-transport` 模块——管道 server + 帧编解码 + 把合成请求/流喂给 `TunnelServer`（自 experimental 抽取/迁移复用，评审时定「迁移 or 复制」）；seams 用事实 4 的公共服务组装；`startup.ts` 增 `--ipc-pipe`；`cordis.patch.yml` 接线；
3. ready 行不变；`/__boot__` 不需要（index 仍由宿主渲染，C1 形态保留）。

**壳侧（Rust）**：
1. `dsh_pipe.rs`（新）：拨号 + 帧编解码 + 请求多路复用（id → oneshot）+ 流通道 API；
2. `dsh_proxy.rs`：转发后端从 reqwest↔TCP 换为 pipe client（闸门/缓存/注入/降级逻辑不变）；
3. `dsh_bridge.rs`：303 换 cookie 改走管道帧（`Host: 127.0.0.1`，与合成请求同 authority）；`dsh_relay.rs` 与 `streamBaseUrl` 注入转 legacy（仅保留作反证/回退，文档标冻结）；
4. `dsh_stream.rs`（新）：页面流桥——Tauri 命令（open/send/end/cancel）+ 下行通道，映射管道 stream 帧。

**页面侧（注入脚本）**：`__DSH_TRANSPORT__` 只合并不覆盖地补 `{ ownsHost: true, openStream }`（**不再注入 `streamBaseUrl`**）；`openStream` 经 Tauri IPC 实现逻辑流生命周期，失败语义按 worker 先例给 `remote`/`carrier` 两类 marker（供域层重试）；注入顺序契约不变（`<head>` 后、宿主 head 行前）。

**鉴权口径（裁定 ②）**：保持 route lane + cookie——帧头携带 303 换来的 cookie、合成请求 `Host: 127.0.0.1` 与交换时一致；围栏三查与认证逐字保留（与 C1 行为等强）。

## 五、批次划分（每批含实现 / 验收 / 反证 / 台账 / 文档）

### C2-a · 宿主侧管道载体（fork 首批）——**进行中**
- **任务**：webServer 外部载体模式 + 请求派发接缝；web-app 的 `pipe-transport` 模块（管道 server + 帧编解码 + TunnelServer 复用 + seams 组装）；`--ipc-pipe` CLI；ready/声明端口语义。
- **验收**：手动起宿主 `--ipc-pipe <path>` → 测试客户端拨号：index 200（含宿主注入行）· 静态资源 200 · `/api` POST 200（route lane + cookie）· stream-open 收到 item/end；**零 TCP 监听断言**（进程 TCP 监听数 0）。
- **反证**：帧编解码变异（长度前缀/顺序关联摘除）→ 单测红；`--ipc-pipe` 缺席 → 旧 TCP 行为不变（回归）。
- **台账**：逐文件登记 fork 改动；`pnpm fork:check` 绿；dsh 自带门禁（typecheck/lint/目标包测试）过。

### C2-b · 壳侧帧桥与页面钩子
- **任务**：`dsh_pipe.rs` + `dsh_proxy` 后端换管道 + 303 走管道 + `dsh_stream.rs` + 页面 `openStream` 注入；relay/`streamBaseUrl` 转 legacy。
- **验收**：C1 全走查项等强复跑（会话/流/工具/静态/重载/菜单/外链/壳桥/降级页）+ 零端口断言 + 真实会话跑通。
- **反证**：摘 `openStream` 注入 → 流面显式降级；管道断开 → 页面降级不白屏；`WORLDSEA_TCP_HOST=1`（legacy）对照：netstat 有监听 vs 管道模式零监听。

### C2-c · 收口
- 文档回写（运行手册载体形态/开关/排障；准备方案 §六/§九 C2 条目；索引 + WORKSTREAMS + 变更记录）；台账核对；走查清单交付。

## 六、风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 合成派发接口面（route handler 读 `req.socket` 等）缺项 | worker 先例已覆盖主要路由（含 gzip 无 socket 分支）；错误驱动补齐；失败显式降级不白屏 |
| R2 | 大载荷（上传/附件/静态包）经 Tauri IPC 与帧管道的性能 | 先做对再做快；必要时分块/背压；验收含一次真实上传路径走查 |
| R3 | 无端口后浏览器回调类流程失去落点 | **已拍板登记**（裁定 ③）；运行手册写明 |
| R4 | fork 面扩大（webserver + web-app + 新模块） | 逐文件台账 + dsh 自带门禁作回归网；接缝尽量收敛 |
| R5 | 双模式（管道 / legacy TCP）并存的语义漂移 | legacy 仅作反证与回退并标冻结；默认管道 |

## 七、本批不做

- 打包/分发形态、更新通道（仍挂账）；
- 账号登录的浏览器回调通道（裁定 ③ 后置立项）；
- HMR 的页面级流式（Tauri 协议应答缓冲限制仍在；mux 流已解决，HMR 维持关闭）。
