## 一、A 级清单 × 现状对照（施工前事实基线）

> 口径：每项含「dsh 机制要点 / 本项目现状 / 改造内容 / 关键证据」。

### A1 事件契约（五模式分发 + 工具执行三瀑布）

| 维度 | 内容 |
|---|---|
| dsh 要点 | `emit/waterfall/bail/serial/parallel` 五模式；工具固定流水线 `tools/pre-execute` → 单调 guard → `tools/execute` → `tools/post-execute` → 只观测 `tools/result`；失败不结束 turn；deny 不可被后续 listener 翻案 |
| 本项目现状 | 事件为**指令式广播**：`AgentEvent` 11 变体（`event.rs:24`）+ `OrchestratorEvent` 60+ 变体（`event.rs:80`）经 `EventBroadcaster` 直推 Tauri 通道；工具执行在 `agent/tools.rs` 串并行分流，审批/裁剪/超时**硬编码**在调用点 |
| 改造内容 | 新建 Rust 动态事件总线（`EventKey → Vec<Listener>` + 模式枚举 + `next` 环绕签名）；把审批、结果裁剪、超时、日志、度量改造为**监听器**；补契约测试（按模式分发的行为断言） |
| 关键证据 | `crates/agent-kernel/src/event.rs`（广播式）、`agent/tools.rs:370-424`（硬编码分流）、`confirmation.rs`（判断散落） |

> 进展注记（2026-09-17）：首段迁移 = Plan 事件族（已完成）；**第二段迁移 = 工具结果裁剪（已完成，见 §七）**；审批属 B 级不夹带（§五）；超时 / 日志 / 度量未入阶段计划（如需再做须单独立项）。

### A2 Session 事件溯源纪律（**重大修正：与现状同构，非二选一**）

| 维度 | 内容 |
|---|---|
| dsh 要点 | append-only `SessionEvent`；surface 事件带 `surfaceOp: 'append' \| {op:'replace', start, end}`；`deriveMessages()` 派生；`request/header` 使每个请求是日志的纯函数；`compaction/*` 括号事务（start → summary → end）+ 孤儿锁检测 |
| 本项目现状 | **基础设施已同构**：`session_log` = 不可变日志（原文追加）；`session_live` = 活跃视图（`position → log_offset` 游标，可重写，`session_store.rs:433-452`）；裁剪已从"直接删除"升级为**折叠**（原文先外置 → 锚点对 + 空容器位占位 → 压缩文本填回，`mod.rs:915-970`）；手动压缩 `/compact` 与自动裁剪共用计量（`measure_context`，`mod.rs:1007`） |
| **修正结论** | 02 文档 §4.2 风险 R2 提出的"replace 遮蔽 vs 折叠锚点二选一"**不成立**——两者语义同构（不可变日志 + 活跃视图变更 + 原文可取回），只是表达与工程化程度不同。**不需要二选一，只需要补齐三项**： |
| 补齐 ① 触发时机 | dsh 在**请求派生前**（pre-step）压缩；本项目在**轮次结束后**（AfterRun，`mod.rs:826-836`）——"先超后压"顺序问题 |
| 补齐 ② 事务性 | dsh 括号事务 + 孤儿锁（崩溃可检测）；本项目折叠为内存态 `fold_context` + 写穿，无事务保护 |
| 补齐 ③ 事件化 | dsh 压缩过程有 `compaction/*` 事件族（可回放/可 UI 呈现）；本项目折叠只有 `info!/warn!` 日志（`mod.rs:934-967`），前端不可见、不可审计 |
| 补齐 ④ | `request/header`（请求可重建）——**已裁定纳入**（D1 四项全补）；桌面产品诊断性价值最高、改动面也最大，须单独设计评审 |

### A3 输入模型（inbox 三通道 + pre-step 准入 + 协作式取消）

| 维度 | 内容 |
|---|---|
| dsh 要点 | `followup`（唤醒）/ `steer`（唤醒，最近 step 消费）/ `inject`（**不唤醒**）三语义正交；`agent/pre-step` waterfall 决定输入准入；`cancel(keepInbox)` 保留已交付文本并记录中断锚点 |

| 改造内容 | 把"输入准入"从阶段位升级为可插拔决策点；显式化三种输入语义（用户插话 / Agent 自驱 / 上下文注入）；取消语义补"已交付文本终结 + 中断锚点" |
| 关键证据 | `crates/agent-kernel/src/agent/hooks.rs`、`mod.rs:1162`（run_react_loop） |

### A4 提示段组装契约

## 六、施工纪律（防"越抄越像"）

1. **限范围**：A 级清单是白名单；B 级（作用域/不变式/审批审计等）不夹带，出现时必须单独立项。
2. **每项必须有立项理由**：格式 = "本项目为什么需要此机制"一行；写不出理由的不做。
3. **渐进与可停**：每项机制完成即独立可验证；任一阶段停止不产生烂尾。
4. **双轨防护**：新机制与旧实现切换时设截止点（禁止长期并存——现存 TS↔Rust 双执行栈即是教训）。
5. **测试配套**：每项机制配契约测试（不是覆盖率指标，是行为断言）。
6. **上游冻结**：机制以本项目文档为准（`dsh` 参考快照已锁定本地版本）；不再跟随其细节漂移。
