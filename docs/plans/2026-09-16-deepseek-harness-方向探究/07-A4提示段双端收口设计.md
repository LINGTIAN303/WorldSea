## 一、目标与范围

**一句话**：把"TS 拼装完整文本 → Rust 只做追加"的双端拼装（技术债 #7），收口为——**TS 只提供结构化段清单，Rust `assemble_sections` 成为唯一组装点**。

**不做什么**：
- 不引入 dsh 的 `{{var}}` 插值 / 未知引用报错契约（本项目无模板化 prompt 承载面；`prompt_sections.rs` 模块注释已裁定"未来若引入模板化 prompt 再补校验"）。
- 不动群聊 participant prompt（`create_group_session_participant`）与子 Agent `SubAgentSpec.system_prompt`——两条独立机制，继续走 legacy 单段路径。
- 不改 `run()` 首条 System 消息推入语义（仍为"静态段合集文本"，会话创建/刷新时代快照）。
- 不做段的条件/循环等高级表达能力——段 = `{name, order, text}` 三元组不变。

## 二、现状（施工前事实基线）

**三处拼装点**（双端拼装实际是"三拼装"）：

```
① TS 拼装（useAgentRust.ts:2543 buildSessionSystemPrompt）
   6 块 join('\n\n')：WORLDSEA.md → 全局组(4件) → MEMORY.md → 项目组(4件) → 工作区分区 → 技能索引
        │  产出：单一字符串
        ▼
② agent-commands 追加（lib.rs:1806-1810）
   system_prompt = format!("{p}{mcp_note}")   ← MCP 环境注记（动态，尾部字符串拼接）
        │
        ▼
③ kernel 组装（memory.rs:135-157，已段式）
   assemble_sections([scenario(100), static(200), memory(300), pipeline(400)])
        │
        ▼
   PromptCallOptions.system_prompt_override → LLM
```

**持久化与恢复**：
- 写穿：`sessions.system_prompt TEXT NOT NULL`（存 ①+② 的文本快照，`lib.rs:2130`）；
- 恢复：`restore_sessions` 读 `record.system_prompt` → `new_agent(Some(文本))`（`lib.rs:2979`）→ 回到 ③ 的单段 static；
- 动态刷新（H5 风险点③）：规则/技能变更 → TS 重建完整文本 → `cmd_agent_update_system_prompt` → `agent.set_system_prompt` + 写穿（`lib.rs:3283-3296`、`useAgentRust.ts:2667/2692`）。

**问题清单**：
| # | 问题 | 证据 |
|---|---|---|
| P1 | **组装点三处**，拼接规则各写各的（TS join / Rust format! 追加 / kernel 排序拼接） | 上述 ①②③ |
| P2 | **TS 段序无结构**：6 块顺序是 TS 硬编码的隐式事实，Rust 视野里只是一个 `static` 段（200），无法与其他段细粒度混排（如未来"记忆"要插在"项目规则"与"技能索引"之间时无处表达） | `memory.rs:141-143` |
| P3 | **刷新路径同病**：动态刷新走完整文本重建，段结构在传输中被压扁为字符串 | `useAgentRust.ts:2683-2695` |
| P4 | **恢复失真**：重启恢复只有文本，段结构丢失（退化为单段）；若未来 TS 段序调整，老会话无法感知 | `session_store.rs:33`、`lib.rs:2979` |
| P5 | **mcp_note 为尾部字符串拼接**（`\n\n` 前缀硬编码），与段式体系并存两套表达 | `lib.rs:1776-1778` |

## 三、目标形态与接口设计

### 3.1 契约：`PromptSection` 跨端复用

`crates/agent-kernel/src/agent/prompt_sections.rs` 的 `PromptSection { name, order, text }` 增加 `serde::{Serialize, Deserialize}` 派生，作为**唯一段契约**跨端直传（不再定义 DTO 副本）：

```rust
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct PromptSection { pub name: String, pub order: i32, pub text: String }
```

TS 侧对应类型（仅类型声明，不复制逻辑）：

```ts
export interface PromptSectionDto { name: string; order: number; text: string }
```

### 3.2 段带与段序（分段带：Rust 管带间，TS 管带内）

| 带 | 取值范围 | 归属 | 段 |
|---|---|---|---|
| 场景身份 | 100 | kernel 动态 | `scenario` |
| **静态注入带** | **200-299** | TS 快照 + 会话构造快照 | 见下表（TS 12 段 + `mcp_note`） |
| 运行期记忆 | 300 | kernel 动态 | `memory` |
| 管线指引 | 400 | kernel 动态 | `pipeline` |

**静态注入带内段序**（TS 侧集中常量分配，值留空隙便于插入）：

| 段名 | 来源 | order | 对应旧 6 块 |
|---|---|---|---|
| `worldsea` | TS | 200 | ① WORLDSEA.md |
| `global_rules` / `global_writing` / `global_design` / `global_tools` | TS | 210/215/220/225 | ② 全局组 4 件 |
| `memory_md` | TS | 230 | ②.5 MEMORY.md |
| `project_agents` / `project_writing` / `project_design` / `project_tools` | TS | 240/245/250/255 | ③ 项目组 4 件 |
| `workspace_partition` | TS | 260 | ③.5 工作区分区 |
| `skill_index` | TS | 270 | ④ 技能索引 |
| `mcp_note` | agent-commands | 290 | ② 的尾部注记（段化，去掉 `\n\n` 前缀） |
| （legacy `static`） | 老路径 | 200 | 群聊/老会话的整段文本 |

**校验（warn 不 panic，对齐 U3 精神）**：TS 段 order 落在 `[200, 299]` 之外时 `warn!` 并照常参与排序（内部契约，不做夹取改写）。

### 3.3 通道接口（Tauri 命令）

**新建**（`new_session` 增参，而非替换——文本参数保留供 legacy/群聊）：

```rust
system_prompt: Option<String>,              // 保留：legacy 单段（群聊/兼容）
prompt_sections: Option<Vec<PromptSection>>, // 新增：结构化段（TS 主路径）
```

**刷新**（改造现有命令，旧名删除——防双轨并存）：
- `cmd_agent_update_system_prompt` → **`cmd_agent_update_prompt_sections`**（参数 `promptSections: PromptSection[]`）；
- `AgentCommandService::update_session_system_prompt` → `update_session_prompt_sections`；
- kernel `AgentLoop::set_system_prompt` → `set_prompt_sections(Vec<PromptSection>)`（内部：更新 `config.prompt_sections` + 同步 `config.system_prompt = assemble_sections(..)` 缓存）。

### 3.4 kernel 组装（唯一组装点）

`AgentLoopConfig` 新增字段：

```rust
pub prompt_sections: Vec<PromptSection>,   // 默认空
```

`build_prompt_options`（`memory.rs`）组装逻辑：

```
prompt_sections 非空 → 展开为各段（order 各自）   ← 新主路径
prompt_sections 为空 → system_prompt 作为单段 static(200)   ← legacy 回退（群聊/老会话）
```

其余（scenario/memory/pipeline）不变；`assemble_sections` 仍是唯一拼接器。

**`system_prompt` 字段语义保持**：仍为"静态段合集文本"（`assemble_sections(prompt_sections)` 的产物缓存），供两处 legacy 消费——`run()` 首条 System 推入（`mod.rs:656`）、群聊路径。截止点见 §四。

### 3.5 持久化与恢复

- `sessions` 表**新增列** `prompt_sections TEXT`（JSON，可空；按既有迁移模式幂等 ALTER，旧数据 NULL）；
- 写穿（`lib.rs:2127-2145`）：`system_prompt` 照旧存文本（兼容读取方），`prompt_sections` 存段 JSON（精确）；
- 恢复（`lib.rs:2979`）：`record.prompt_sections` 可解析 → 结构化传给 `new_agent`（精确恢复）；否则回退 `system_prompt` 文本单段（legacy 老会话零迁移）。

### 3.6 TS 侧改造（`useAgentRust.ts`）

1. `buildSessionSystemPrompt()` → **`buildSessionPromptSections(): Promise<PromptSection[]>`**——6 块改产出 12 段（标题头文案逐字保留），段序常量集中定义（`SECTION_ORDER` 表，见 §3.2）；
2. `newSession(systemPrompt, ..)` → `newSession(sections, ..)`（`invoke('new_session', { promptSections, .. })`，`useAgentRust.ts:2660` 唯一调用点）；
3. 动态刷新两处（`2667` / `2692`）改调 `cmd_agent_update_prompt_sections`；
4. 类型定义 + 相关注释同步（`2534` 的"注入契约"注释更新为段式契约定版）。

## 四、迁移与兼容

| 对象 | 处置 |
|---|---|
| 老会话（DB 无 `prompt_sections` 列值） | 恢复走 legacy 文本单段——**零迁移**，行为不变 |
| 群聊 / 子 Agent | 继续 `system_prompt` 文本路径（legacy 回退分支覆盖） |
| 前端刷新路径 | 与新建同批切换（同步提交，不留双轨） |
| `system_prompt` 字段（config + DB 列） | **保留期为长期**（群聊仍依赖）；本期内它从"事实源"降级为"派生缓存" |

**换出魔数说明**：TS 段序常量（`SECTION_ORDER`）与 Rust 带间常量（`order` 模块）分居两端、各自集中——这是"分段带"契约的两半，不是散落魔数。
