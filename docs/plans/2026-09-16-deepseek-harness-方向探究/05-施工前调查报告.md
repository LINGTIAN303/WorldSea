### 1.2 消费方矩阵（迁移批次划分）

**两个 Rust 漏斗**：`TauriAgentEventEmitter::on_event`（`commands.rs:252-762`，主漏斗）+ `LoopControlTauriEventListener`（`:1830`）。

| 批次 | 内容 | 理由 |
|---|---|---|
| 批次 1（低风险） | Plan 三件、Reflection、Trace 四件、SubAgent 三件、Router、StepBudgetWarning、ToT/GoT | 纯数据变换、消费方稳定、可逐一验证 |
| 批次 2（中风险） | ToolCallDelta、FileChange | 高频 + 走同步丢弃式 sink（"droppable"语义须保留） |
| 批次 3（高风险） | 流式四件、ToolCallStart/End、Confirmation 两件、LoopEng 族 | 直接决定用户所见；审批是"先广播后 await oneshot"的阻塞交互——瀑布/拦截模式的目标场景，须在总线语义验证通过后再迁 |

**测试影响面**：9 个测试 `impl EventListener`（`agent/tests.rs` 4 个 + `agent-commands` 5 处）+ 前端 `turnModel.spec.ts:989-1047`。

### 1.3 前端通道清单（14 条）

13 条带监听（`agent:event:stream/trace/orchestration_trace/orch/orch_supervisor/a2ui/subagent`、`agent:confirm`、`plan_created/update/replanned`、`loop_control:event`）+ **2 条死通道已废弃（2026-09-17：`orch_multi`、`reflection` 专用通道——均无前端监听，发射代码已删；`ReflectionResult` 事件本身保留，仍经 R6 动作段通道下发）**；另有 `deep_phase_changed` 只剩注释。
**注意**：双路发射 `emit_dual`（Tauri IPC + HTTP bridge SSE）——任何绕过它的新发点会静默丢失 SSE 侧。

### 1.4 广播实现细节与改造断点

```text
EventBroadcaster（event.rs:736-761）
  listeners: Vec<Arc<dyn EventListener>>    ← 无 topic 过滤，全量 fan-out
  subscribe(&mut self)                      ← Arc::ptr_eq 去重（配合 commands.rs:769 的 EMITTER_REGISTRY 每会话一个 emitter）
  broadcast(&self, &OrchestratorEvent)      ← 同步、无返回值、0 监听器静默
trait EventListener { fn on_event(&self, event: &OrchestratorEvent); }   ← 只读借用 = 核心断点
```

**调用语境两栖**：async（`agent/mod.rs:526`、`orchestrator.rs:345`、`confirmation.rs:468`）+ sync（`tools.rs:26-48` 的 `ToolStreamSink`，`try_read` 失败静默丢弃）→ **新总线 API 必须同时支持两种语境**。

**重入风险**：`ForwardToAgentBroadcaster`（`agent-commands/lib.rs:194`）把编排器事件转投 AgentLoop 广播器 → 新总线 emit 中再 emit 需防环。

### 1.5 首段迁移建议：Plan 事件族（修正）

- **发射点唯一**：`agent/tools.rs:174/193/252`，全在同一函数 `apply_plan_result` 内
- **消费者唯一**：`commands.rs:588/597/615` 三个分支（无第二生产监听器消费）
- **纯 emit 语义**：不需要 waterfall/bail 表达能力 → 可在不动签名难题的前提下验证：emit 等价、订阅者管理（含会话隔离与去重契约）、async/sync 两栖共存
- **回滚成本低**：三处调用点、一个函数

## 二、压缩与审批域调查（为 A2 四项补齐与首段迁移）

### 2.1 写穿路径与触发链

```text
[内存态] state.messages（循环内写入）＋ backend.set_messages（每轮同步）
   │
   ├─ 自动：run_react_loop 返回 → AfterReact → run_memory_archive → enforce_context_budget（mod.rs:875）
   │        → 有外置器：fold_context（interaction.rs:175-279）+ backfill_folds（:289-333）
   │        → 无外置器：trim_context_dropping（:101-144）
   │
   ├─ 手动：/compact（useAgentRust.ts:2721）→ cmd compact_context → AgentCommandService（lib.rs:1244）
   │        → AgentLoop::compact_now（mod.rs:1085，trigger=0 全选，is_streaming 拒绝）
   │
   ─ [持久化] send_message 收尾 → persist_messages（lib.rs:3748）→ replace_messages（session_store.rs:753-930，单事务）
        事务内三步：session_log 追加原文 → session_live 游标重写（DELETE+INSERT）→ session_events 追加（kind ∈ initial/append/revise/trim/noop）
        另有 register_fold_refs（lib.rs:3770，只增不删）
```

### 2.2 「时机挪到请求派生前」的影响面

- 现调用点唯一（`mod.rs:836`，AfterRun 内）→ 语义后果：**裁剪收益滞后一整轮**（本轮请求都已用旧窗口发完）
- 候选前置位：`run_react_loop` 每轮 `:1232`（build_prompt_options）之前、`:1234`（set_messages）之前——与"请求派生前"语义最贴合
- **两个必须处理的耦合**：
  1. `compact_now` 的 `is_streaming` 守卫（`:1088`）会拒绝循环内调用（run 内 `is_streaming=true`）→ 需抽出无守卫内部方法
  2. 每轮前置 = 每轮 `measure_context`（O(n) token 估算 + 分类 + 持 state 锁）→ 需轻量短路（如消息数/步数变化才计量）
- **✅ 已落地（2026-09-17，[04-§七](04-施工准备.md)）**：两耦合的解法——① 压缩执行体归一为无守卫的 `run_compaction`（自动路径直接调用，不经 `compact_now` 守卫；手动 `/compact` 保留守卫）；② 新增 `CompactCheckMarker` 短路基线（上次占用 + 新增体量保守 token 下界 < 触发线即跳过完整计量；触发线变化强制重计量）。调用点已前移至 `run_react_loop` 每轮 `build_prompt_options` / `set_messages` 之前；AfterRun 不再执行压缩
