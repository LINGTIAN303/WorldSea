# C6 · 窗口栏形态恢复批计划（小批）

> 承接：C1-c「壳件最小集」在**无边框**形态下的整体重落位。
> 用户口述（2026-09-24）：「在此之前可先恢复窗口栏」——指认**旧 `TitleBar.vue` 的 space 变体**（`apps/tauri/src/ui/layout/TitleBar.vue`，含「Agent 空间 ⇄ 工作台」切换控件）；该窗口栏随旧 Vue 前端于 B3 退役，现需以**壳侧注入**方式在 dsh 界面之上恢复。

## 〇、本批前置实测（2026-09-24，`WORLDSEA_FRAMELESS=1` 无边框态）

| 观测 | 结果 |
|---|---|
| 窗口 | 无边框生效；页面整窗铺满（dsh 界面未留顶部空间） |
| **Win32 菜单栏** | **视觉消失**（截图取证）；**无障碍树仍有「菜单栏 应用程序」残留节点**——UIA 取证在无边框下会**误报**菜单仍在，此坑记入运行手册 |
| 拖拽 | 无任何拖拽机制（页面无 drag region）→ 无边框下窗口不可移动 |
| 窗口控制 | 无（无边框即无系统控制按钮） |
| 调整大小 | 可用（无障碍树见 `TAURI_DRAG_RESIZE_WINDOW` 窗格） |
| dsh 侧能力 | 官方 Electron 桌面端即此形态：`titleBarStyle:'hidden'` + 40px 标题栏；dsh 界面内置 `data-windows-titlebar` 适配（`padding-top` / 圆角 / 侧栏连色 / `.frame::before` 拖拽带，高度由 `--dsh-windows-titlebar-height` 驱动）；官方 Windows 菜单是**自绘按钮 + 原生 popup**（`apps/desktop/src/preload-menu.ts`） |

## 二、形态规格

```
┌──────────────────────────────────────────────────────────────────────┐
│ [▣ Agent 空间]  ······拖拽区······  WorldSea — Agent 空间  ···  ▣ ⋯ ⛶ ✕ │ 32px
├──────────────────────────────────────────────────────────────────────┤
│  dsh 界面（padding-top 32px；centerCol 圆角、侧栏连色 —— dsh 内置适配）  │
```

- **左侧**：壳切换控件（胶囊按钮：`chat`/`monitor` 图标 + 当前壳名；填充样式照旧 TitleBar：默认填充激活、悬停扩散成空心）；`Ctrl+Tab` 对应键位由壳桥处理（或保留浏览器默认不劫持——见 §五）。
- **中间**：居中标题 —— Agent 空间态「WorldSea — Agent 空间」/ 工作台态「WorldSea — 工作台」。
- **右侧**：「···」图标按钮（popup 菜单）+ 三控制按钮（最小化 / 最大化⇄还原（图标随状态）/ 关闭）。
- **交互**：整条空白区按下拖动窗口（双击 = 最大化⇄还原）；按钮区不参与拖拽。
- **工作台占位页**：覆盖内容区（保留窗口栏可见）；内容 = 「WorldSea」+「工作台 · 产品域即将落位」+「返回 Agent 空间」按钮；dsh 页面在被覆盖时**保持运行**（不改导航、不断流）。
- **主题**：全部配色取 dsh 运行时 token（`--dsw-specific-sidebar-fill` / `--dsw-alias-*`），随亮暗主题自动适配；无 emoji 图标（内联 SVG，遵循仓内图标规范）。

## 四、验收与反证

**验收（真机 + 探针）**：
1. 启动即以无边框 + 32px 窗口栏呈现；dsh 界面留白 32px、内容不破版（对比截图）。
2. 拖拽空白区可移动窗口；双击最大化/还原；三按钮各自生效；最大化后按钮图标切换为「还原」。
3. 点切换控件 → 占位页；再点（或点「返回 Agent 空间」）→ 回 dsh 界面且**流与状态不丢**（日志佐证：占位期间流未断）。
4. 点「···」→ 菜单在按钮下方弹出；四项子菜单可用；「打开设置」「修复工作区权限」功能不变。
5. 主题：亮/暗切换后窗口栏配色跟随（走查项）。

**反证**：
- `WORLDSEA_NO_TITLEBAR=1` → 不注入窗口栏（页面顶格、无拖拽——显式缺省，不静默）。
- `WORLDSEA_FRAMED=1` → 回原生边框 + 不注入窗口栏（对照口，旧形态零回归）。
- 单测变异：jsdom 用例对「拖拽区域判定」「切换状态机」「幂等」逐一注入变异 → 报红 → 复原复绿。

## 五、风险与边界

| # | 风险 / 边界 | 处理 |
|---|---|---|
| R1 | 无边框下 UIA 老取证手段（看菜单栏）失效 | 本批起验收改「截图 + 探针日志」；坑记入运行手册 |
| R2 | 拖拽走 JS（非系统非客户区）：拖到屏幕边缘**不会**触发系统 snap | 登记为已知差异；后续需要时评估 WebView2 non-client（`-webkit-app-region` + `IsNonClientRegionSupportEnabled`） |
| R3 | popup 菜单定位依赖屏幕坐标换算（缩放比例） | 换算失败时兜底弹在窗口左上；实测覆盖 100% 与 125% 缩放 |
| R4 | `Ctrl+Tab` 切换键位 | **不进本批**：浏览器/WebView 语义下劫持风险高，本批只做点击切换（登记为候选） |
| R5 | 兜底页（shell-loading）期间无窗口栏 | 瞬态页，不做（登记）；无边框下该页不可拖动为已知边角 |
| R6 | 关闭按钮语义 | 与系统按钮一致（托盘激活时隐藏到托盘，否则退出）——复用 `CloseRequested` 现成行为，不改 |
