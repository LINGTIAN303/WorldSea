## 〇、通用约定（所有表现形式共用，定一次）

### 0.1 规格模板（每种形式必须回答的六问）

| # | 项目 | 必须回答的内容 |
| --- | --- | --- |
| ① | 内容映射 | 读节点的哪些字段 / 关系；缺值时如何退回 |
| ② | 结构 | 生成什么结构（一行标题 / 一句话 / 子节点表 / 关系图） |
| ③ | 编辑能力 | 能否就地改；改的是哪个字段；写回策略 |
| ④ | 配置项 | 该形式可配什么（含默认值与取值范围） |
| ⑤ | 导出形态 | 导出 docx / markdown 时呈现成什么 |
| ⑥ | 边界与风险 | 空值、超长、超深、与其他形式叠加时的行为 |

### 0.2 三层结构下的组件契约

- 组件**不存内容**：一切内容由 `nodeId` 指向的 `outline_node` 派生（§8.10.2 的核心原则）。
- 组件**不存位置**：位置属于容器（`Container.pos`）。
- 组件只持有三样：`form`（表现形式类型）、`order`（容器内次序）、`config`（该形式的配置）。
- 一个容器内可放**多个**组件（同一节点的多种呈现并列）；同 `form` 是否允许重复要逐形式定（默认允许，但同类重复时给出提示）。
- **禁止 emoji**（项目约定）：所有形式的状态/图标一律用 `WsIcon`（SVG）表达。**原欠账已清（2026-09-18，Q6-③）**：此前 `nodeIcon` 返回 `✅/📝/📋`，它**已无任何调用方**（随旧视图遗留），已随 Q6 处置删除。

### 0.3 编辑写入的工程约定

| 场景 | 约定 | 依据 |
| --- | --- | --- |
| 就地编辑（改名/改字段） | 防抖 **400ms** 写回，携带 `{ skipUndo }`，不携带 emit 时刻的全量快照 | 笔记本芽写入治理先例（8b180ce） |
| 实体更新语义 | 提交前**自行合并 properties**（实体更新 = 顶层浅合并 + properties 整体替换） | `crates/**/entity_commands.rs:338` |
| 组件级撤销 | 白板编辑器自持 undo 栈（布局操作：移动/缩放/增删容器）；**内容写入并入同一栈**（`asSingleUndoStep`） | 笔记本芽撤销归并先例（c7eefda） |
| 高频拖拽保存 | 布局体保存防抖（建议 ≥500ms，与 `drawing` 的 `AUTOSAVE_DELAY` 对齐，具体值待性能预算） | `drawing/composables/useDrawingPersistence.ts:85-101` |
| 只读/可写两档 | 每个形式必须声明是**派生型**（只呈现，编辑须回实体侧）还是**就地型**（可直接改并写回） | 本规格新增约定 |

### 0.4 自研注册表形态（草案）

```ts
/** 表现形式注册表（自研；不复用 module-builder 模型，见 09-15 文档 §8.8.1-2） */
interface FormDefinition {
  form: string                    // 'title' | 'sentence' | 'table' | …
  label: string                   // 中文名（编辑器内显示）
  icon: string                    // WsIcon id（禁 emoji）
  kind: 'derived' | 'inline'      // 派生型 / 就地型
  minSize?: { w: number; h: number }
  defaultConfig: Record<string, unknown>
  configSchema: Array<{
    key: string
    label: string
    type: 'text' | 'number' | 'select' | 'boolean'
    options?: Array<{ value: string; label: string }>
    default: unknown
  }>
  component: Component             // Vue 组件（给定 node + config 渲染）
  exportMap: (nodeId: string, config: Record<string, unknown>) => ExportBlock
}
```

### 0.5 派生数据工具（施工前需新增）

| 工具 | 用途 | 现状 |
| --- | --- | --- |
| `resolveNodeDepth(nodeId)` | 由 `parentId` 链算出层级深度（深度 0 = 根） | **无**——现有树视图靠递归渲染隐式携带 depth，白板需要显式函数 |
| `resolveSiblingIndex(nodeId)` | 由同级 `order` 算出序号（用于编号呈现） | **无**——`order` 存在但 UI 未显示序号 |
| `resolveChildNodes(nodeId)` | 取子节点（按 `order` 排序） | 有（`useOutlineTree.getChildren` 同构逻辑，需抽为纯函数便于复用） |

## 一、标题式（Title Form）· 样板规格

### 1.1 形态描述（前端）

容器内一行文本，可按配置附加**层级前缀**与**状态标记**。它是「主干省略」的最短表达——只保留"这条是什么"，不承载内容。

```
[缩进] 1.2  第三章 · 夜访旧宅            ● 
 ↑       ↑        ↑                      ↑
深度缩进 编号     节点 name              状态色点（可关）
```

### 1.2 规格六问

| # | 项目 | 规格 |
| --- | --- | --- |
| ① | **内容映射** | `node.name`（主文本）；`resolveNodeDepth`（缩进层级）；`resolveSiblingIndex`（编号）；`node.properties.status`（状态色点）。**全部缺值可降级**：无 name 显示「未命名节点」占位；无 status 不显示色点 |
| ② | **结构** | 单行文本，`text-overflow: ellipsis` 单行截断；层级以**左缩进**表达（每层 16px，上限 6 层后不再累加）；可选前缀 = 编号 + 分隔符 |
| ③ | **编辑能力** | **就地型**：双击进入行内编辑（与原位文本宽度自适应），Enter / 失焦提交、Esc 取消。**只写 `node.name`**，写入策略见 §0.3（400ms 防抖 + skipUndo）。**不允许**在组件内改层级或顺序——那属于实体侧（树视图的移动/重排、白板的容器拖动都不改变语义层级） |
| ④ | **配置项** | `showDepth`（缩进，默认 true）· `numbering`（`none` \| `numeric`（1.2.3）\| `chinese`（一、（一））\| `roman`，默认 `numeric`）· `showStatus`（状态色点，默认 true）· `fontScale`（0.8–1.5，默认 1.0）· `align`（`left` \| `center`，默认 `left`）· `showBranch`（是否在末尾显示子节点数，默认 false） |
| ⑤ | **导出形态** | 映射为**标题层级**：depth 0→`H1`、1→`H2`、…、5+→`H6`；当 `numbering = none` 时降级为无序列表项（保持层级缩进）。docx 与 markdown 同规则。**已实现（09-17 批次 5）**：`board/export/outlineExport.ts`；超层（`MAX_INDENT_DEPTH`）亦降级为列表项 |
| ⑥ | **边界与风险** | 见 §1.4 |

### 1.3 交互清单（前端行为）

| 操作 | 行为 |
| --- | --- |
| 单击 | 选中**容器**（组件不单独选中——选中粒度是容器） |
| 双击 | 进入行内编辑（就地型能力的唯一入口） |
| Enter | 提交并退出编辑；**不新建兄弟节点**（白板内新建节点须走显式动作，避免误建） |
| Esc | 取消编辑（回滚到进入编辑前的值） |
| 拖拽 | 拖动**容器**（组件不参与拖拽） |
| 悬停 | 显示容器操作条（添加组件 / 删除容器 / 折叠），组件本身不加悬浮按钮 |

### 1.4 边界与风险（需负责人裁定或施工时验证）

| # | 情形 | 拟定行为 | 待定？ |
| --- | --- | --- | --- |
| 1 | 节点无 name | 显示占位「未命名节点」（斜体弱化），仍可双击编辑 | 已定 |
| 2 | 层级超 6 层 | 缩进停止累加（第 6 层起同缩进），避免窄容器溢出 | 已定 |
| 3 | 导出超 6 层 | 沿用缩进停止策略，markdown 用列表缩进替代 heading | 已定 |
| 4 | 同一容器内放两个「标题式」组件 | **允许 + 提示**（裁定项 09-16：同种形式重复不禁止，但给出「该容器已有同种表现形式」提示） | 已裁定 |
| 5 | 容器宽度不足以显示完整标题 | 单行省略号；**不做横向滚动**；悬停显示 title 提示 | 已定 |
| 6 | `status` 与项目色点体系冲突 | 复用 ChapterList 既有色点规格（6px 圆点 + 文字语义），不新造颜色 | 已定 |
| 7 | 节点被删（容器悬空） | 组件渲染为占位「节点已删除」，容器提供清理入口（§8.10.3 策略） | 已定 |

## 二、句子式（Sentence Form）

### 2.1 形态描述（前端）

容器内一段短文本（1–3 行），字号略小于标题式、配色次级。语义是「这条讲的是什么」的一句话概括——比标题式多一层信息，但**仍不承载正文**。

```
第三章 · 夜访旧宅                      ← 标题式（主干）
主角夜访旧宅，在密室中发现一把铜钥匙。    ← 句子式（一句话概括）
```

### 2.2 规格六问

| # | 项目 | 规格 |
| --- | --- | --- |
| ① | **内容映射** | `node.description`（**复用现有字段，不新增 `summary`**）；空值显示占位「（暂无摘要）」（斜体弱化）。**不从 `content` 派生**——那会绕过 Q1 的边界 |
| ② | **结构** | 单段文本，默认最多 3 行（超出省略）；**纯文本渲染**（不解析 markdown / HTML，转义后显示，避免注入与视图不一致）；字号默认 0.9× 基准，配色次级 |
| ③ | **编辑能力** | **就地型**：双击进入编辑，`textarea` 自适应高度；`Enter` 提交、`Shift+Enter` 换行、`Esc` 回滚；只写 `node.description`（400ms 防抖 + `skipUndo`，见 §0.3）。软上限 120 字：超出仅在编辑态提示字数，**不硬截断、不阻止提交** |
| ④ | **配置项** | `maxLines`（默认 3，范围 1–10）· `fontScale`（默认 0.9）· `align`（`left`/`center`，默认 `left`）· `emphasis`（`normal`/`italic`/`muted`，默认 `muted`）· `charLimit`（软上限，默认 120）· `showQuoteMark`（引号装饰，默认 false） |
| ⑤ | **导出形态** | 容器内**同时**有标题式时 → 标题下的一行**斜体摘要**（md `*…*`；docx 斜体段落）；容器内**仅**有句子式时 → 该节点的普通正文段落（md 普通段落；docx 正文）。**已实现（09-17 批次 5）**；`description` 为空时不产出块 |
| ⑥ | **边界与风险** | 见 §2.4 |

### 2.3 交互清单

| 操作 | 行为 |
| --- | --- |
| 单击 | 选中**容器**（组件不单独选中，与标题式一致） |
| 双击 | 进入编辑；容器内有多个组件时**各组件独立响应**（点哪个编辑哪个） |
| Enter / Shift+Enter | 提交 / 换行 |
| Esc | 回滚到进入编辑前的值 |

### 2.4 边界与风险

| # | 情形 | 拟定行为 | 待定？ |
| --- | --- | --- | --- |
| 1 | `description` 为空 | 占位「（暂无摘要）」；仍可双击进入编辑 | 已定 |
| 2 | 内容超 `maxLines` | 行钳制省略，不滚动；悬停显示全文 | 已定 |
| 3 | 内容含换行 | 保留换行，最多 `maxLines` 行 | 已定 |
| 4 | 内容含 markdown 语法（如 `**粗体**`） | **按纯文本显示**（不解析）——首版不做富文本，如需另立议题 | 已定 |
| 5 | 容器内放两个句子式 | **允许 + 提示**；与 §1.4-4 统一为同一条规则（裁定的完整记录见编辑器规格 §十一-1） | 已裁定 |

### 2.5 原待定点收敛

| 原待定点 | 收敛结果 |
| --- | --- |
| 1 映射到 `description` 还是新增 `summary` | 复用 `description`；**不新增**（若日后确需「一句式摘要」与「描述」分离，再议） |
| 2 是否可编辑 | 就地型 |
| 3 是否限长 | 软上限 120 字 + 编辑态提示 |
| 4 与标题式的排版关系 | 建议顺序＝标题式在上、句子式在下（由容器内 `order` 决定，**不强制自动排序**） |
| 5 导出形态 | 见 §2.2-⑤ |

## 三、表格式（Table Form）

### 3.1 形态描述（前端）

容器内一张小表：**行 = 该节点的子节点**，列 = 子节点字段。它是容器内唯一的**跨节点**呈现，用途是「一眼看清这一支的结构与进度」。

```
第二章 · 入城                          ← 标题式（可选）
┌──────────┬────────┬───────┐
│ 标题      │ 状态    │ 字数   │
├──────────┼────────┼───────┤
│ 城门口    │ 草稿    │ 1200  │
│ 客栈相遇  │ 未写    │   0   │
└──────────┴────────┴───────┘
```

### 3.2 规格六问

| # | 项目 | 规格 |
| --- | --- | --- |
| ① | **内容映射** | `resolveChildNodes(container.nodeId)`（**直接子节点**，按 `order` 排序）；列取子节点字段：`name` / `status` / `wordCount` / `order`。单元格缺值显示「—」；无子节点显示空态「暂无子节点」 |
| ② | **结构** | 表格，**必须复用** `packages/ui-kit/.../data/DataTable.vue`（表格单一来源，不另造）；**仅渲染直接子节点、不递归**（递归留作未来「树表格」形式）；行顺序恒按 `order`，**不提供交互排序**（排序属视图态，且易与语义 `order` 混淆） |
| ③ | **编辑能力** | **派生型（只读）**。理由：表内编辑属于**跨层级写入**（改的是子节点），与「容器 : 节点 = 1:1」模型冲突，且绕过实体侧编辑路径。点击行**首版不触发动作** |
| ④ | **配置项** | `columns`（默认 `['title','status','wordCount']`，可选加 `order`）· `includeSelf`（本节点自身作首行，默认 false）· `showHeader`（默认 true）· `density`（`compact`/`standard`，默认 `compact`）· `maxHeight`（超出滚动，默认 240px） |
| ⑤ | **导出形态** | **docx 真表格**（**表头恒含**，不受 `showHeader` 影响——否则 markdown 表无表头语义不成立）；**markdown 管道表**。**已实现（09-17 批次 5）**：md 侧单元格 `\|` 转义、换行折空格；无子节点时不产出空表 |
| ⑥ | **边界与风险** | 见 §3.4 |

### 3.3 交互清单

| 操作 | 行为 |
| --- | --- |
| 单击行 | 首版**无动作**（只读；「点击定位该子节点的容器」留作后续） |
| 悬停行 | 高亮该子节点在白板上的容器（**可选实现**，成本高则不做） |
| 滚动 | 仅在 `maxHeight` 内垂直滚动；列数固定，不做横向滚动 |

### 3.4 边界与风险

| # | 情形 | 拟定行为 | 待定？ |
| --- | --- | --- | --- |
| 1 | 子节点 50+ | 高度上限 + 垂直滚动；**导出不受限**（全量导出） | 已定 |
| 2 | 单元格文本过长 | 省略号 + 悬停提示 | 已定 |
| 3 | 子节点被删 | 行自动消失（派生型天然免疫，**无需清理逻辑**） | 已定 |
| 4 | 子节点在白板上没有容器 | 正常显示——**表的数据源是实体，不是白板上的容器** | 已定（重要澄清） |
| 5 | 与 `DataTable.vue` 的契约 | 只读用法：传 `columns` / `rows` / `resolveCell`，**不接 `edit`** | 已定 |
| 6 | 状态列着色 | 复用既有色点/语义色约定（同 ChapterList），**不新造颜色** | 已定 |
| 7 | 想看整棵子树的诉求 | 由未来「树表格」形式承接，**不在本形式内加深度配置** | 已定 |

### 3.5 原待定点收敛

| 原待定点 | 收敛结果 |
| --- | --- |
| 1 数据源（子节点 / 同级 / 按线索过滤） | 默认**直接子节点**；首版不做切换 |
| 2 列定义（固定 / 动态） | 固定 3 列起步，`columns` 作为配置项（后置扩展） |
| 3 表内可否就地编辑 | **派生型只读**（避免跨层级写入） |
| 4 与 `DataTable.vue` 的关系 | 必须复用，不另造表格 |
| 5 导出形态 | docx 真表格 + markdown 管道表 |

## 四、树式（Tree Form）

### 4.1 形态描述（前端）

容器内一棵缩进树，可展开折叠、可就地改名。**它承载原独立「大纲树视图」的浏览形态**——2026-09-16 入口整合后旧视图下线，树不再是一个独立视图，而是白板里的一种容器内容（负责人裁定方案 C）。

```
▾ 第一章 · 夜访旧宅            ●
   ▸ 场景A · 密室发现
   ▾ 场景B · 铜钥匙
      · 镜头1
```

### 4.2 规格六问

| # | 项目 | 规格 |
| --- | --- | --- |
| ① | **内容映射** | 由 `resolveChildNodes` 递归取子树；显示节点 `name` + `status`（可选）+ 编号（可选，由 `resolveNodeNumbering` 派生）。`scope='all'` 从全部根开始，`scope='this'` 从容器节点之下开始 |
| ② | **结构** | 每行 = 折叠箭头 + 状态点 + 名称；按 `depth × indent` 缩进；高度上限内垂直滚动（大树不撑爆容器）；**展开态是会话态，不入库** |
| ③ | **编辑能力** | **就地型（受限）**：双击行内改名，只写 `node.name`（400ms 防抖 + `skipUndo`）。**不支持**在组件内改层级/顺序——层级重排的唯一入口是**右栏树**（见编辑器交互规格 §0.1） |
| ④ | **配置项** | `scope`（`all` 全部节点 / `this` 本节点子树，默认 `all`）· `showStatus`（默认 true）· `numbering`（`none`/`numeric`/`chinese`/`roman`，默认 `none`）· `indent`（默认 14px）· `maxHeight`（默认 240px） |
| ⑤ | **导出形态** | 按深度输出**嵌套列表**（md 缩进列表 / docx 多级列表）；`numbering≠none` 时输出编号前缀 —— **已实现（09-17 批次 5）**。**实现约定**：导出时按**本节点子树**展开并**停止对子树递归**（否则与逐节点导出重复；`scope='all'` 在导出中等价于子树，见施工分解 §12.2-2） |
| ⑥ | **边界与风险** | 见 §4.4 |

### 4.3 交互清单

| 操作 | 行为 |
| --- | --- |
| 单击折叠箭头 | 展开 / 折叠该节点（仅影响本组件的会话态） |
| 双击名称 | 进入行内编辑（Enter 提交 / Esc 回滚 / 失焦提交） |
| 点击其它区域 | 交给容器（选中容器） |

| # | 情形 | 拟定行为 | 待定？ |
| --- | --- | --- | --- |

## 五、线索式（Storyline Form）· 迁移形态

> **来源**：原独立大纲视图的「情节线索」页签（`OutlineView.vue:91-104` + `useOutlineStorylines.ts:5-15`）。
> 旧视图 09-17 下线时，其数据层与渲染被迁成**派生型表现形式**（旧文件已删除，见施工分解 §十五）。

### 5.1 形态描述（前端）

容器内按**线索**分行：每行左侧是线索名（加粗、超长省略），右侧是「N 节点」与「M 字」两个计量，行下是**节点标签组**（换行折行、标签内省略、悬停显全文）。没有任何线索时显示一行空态提示。

### 5.2 规格六问

| # | 问题 | 规格 |
| --- | --- | --- |
| ① | **内容映射** | 节点 `properties.storylines`——**逗号分隔字符串**（同时接受中文逗号 `，`）。**不新增字段**；一个节点可属于多条线索（标签即多值） |
| ② | **结构** | 线索行（按线索名分组）→ 行内节点标签；线索名按**拼音序**排列（`localeCompare('zh-Hans-CN')`），保证同一份数据每次渲染顺序一致 |
| ③ | **编辑能力** | **派生型只读**：本形式不写任何数据。填线索的入口在**属性面板的「节点属性」区**（状态 / 所属线索 / 字数 / 关联章节） |
| ④ | **配置项** | `scope`（全部节点 / 本节点及子树）· `showCount`（节点数）· `showWordCount`（字数）· `showNodes`（节点标签）· `maxHeight` |
| ⑤ | **导出形态** | **不参与导出**——导出按节点语义顺序逐节点渲染（规格 §0 通用约定），线索是**横向视图**，导出会打乱层级 |
| ⑥ | **边界风险** | ① 无线索的节点**不产生任何行**（旧实现同）② 线索名大小写与空格敏感（`trim` 后比较）③ 只读，故无并发写入问题 |

### 5.3 与原实现的两处有意改进（输入容错，不改语义）

| # | 项 | 原实现 | 现实现 |
| --- | --- | --- | --- |
| 1 | 分隔符 | 只认英文逗号 `,` → 中文输入法下整串被当成**一个**线索名 | 英文与中文逗号都作分隔符 |
| 2 | 线索名排序 | 默认 `sort()`（**按码点**，中文会得到「丙 < 乙 < 甲」这类反直觉结果） | `localeCompare('zh-Hans-CN')` = **拼音序** |

### 5.4 边界与风险

| # | 情形 | 行为 |
| --- | --- | --- |
| 1 | 无线索 | 显示「暂无线索（在属性面板的「节点属性」里填「所属线索」）」 |
| 2 | 节点无名字 | 标签回退「未命名节点」 |
| 3 | `scope='this'` 但本节点不在集合内 | 退化为「全部节点」（不显示空） |
| 4 | 数据成环 / 父链断裂 | 范围解析有环与断链防御（不重复入列、断链视为根） |

## 六、进度式（Progress Form）· 迁移形态

> **来源**：原独立大纲视图的「进度总览」页签（`OutlineView.vue:106-117` + `:314-324`）。

### 6.1 形态描述（前端）

容器内自上而下：**三张统计卡**（节点数 / 字数 / 完成度）→ **完成度进度条** → **状态分布**（未写 / 草稿 / 完成 三态色点 + 计数）→ **线索分布**（每行「线索名 + N 节点 / M 字」，复用线索式的聚合，不重复实现）。节点数为 0 时进度条宽度为 0、完成度显示 0%。

### 6.2 规格六问

| # | 问题 | 规格 |
| --- | --- | --- |
| ① | **内容映射** | 节点 `properties.status`（三态）+ `properties.wordCount` + `properties.storylines`。**不新增字段** |
| ② | **结构** | 统计卡 → 进度条 → 状态分布 → 线索分布（四段可各自关闭） |
| ③ | **编辑能力** | **派生型只读**。状态与字数的写入入口同在属性面板的「节点属性」区 |
| ④ | **配置项** | `scope` · `showBar` · `showStatus` · `showStoryline` · `maxHeight` |
| ⑤ | **导出形态** | **不参与导出**（同线索式：导出按语义顺序逐节点渲染） |
| ⑥ | **边界风险** | ① 未知/缺失状态一律计入「未写」（**不新增状态值**——三态由节点注册的 `deteriorable` trait 锁定）② `wordCount` 非法值（负数 / 非数字）按 0 累加 ③ 大板下为纯计算（无虚拟滚动） |

### 6.3 口径（与原实现一致处 + 一处更实用处）

- **完成度 = round(完成节点数 / 总节点数 × 100)**，空集为 0（原实现 `Math.round`，同）。
- **字数 = `properties.wordCount` 求和**（原实现同）。
- **`scope='this'` 挂在「卷」容器上 = 每卷一张进度卡** —— 这是原实现（单一全局总览）没有的用法，也是白板形态带来的增量。

## 七、段落式（Paragraph Form）· **已取消（2026-09-18，随 Q1 裁定）**

**取消决定**：Q1 经 09-18 裁定为 **A 纯结构层**（详见 [理论基线与现状](2026-09-15-大纲芽重构-理论基线与现状.md) §九 Q1），且 `content` 字段已**删除**（取证发现它是无入口、无消费方的野字段）。故段落式**不再是待做项**——节点内不留长文，需要正文时走 manuscript（节点 ↔ 章节关联已打通，见 [施工分解](2026-09-16-大纲白板-施工分解.md) §十八）。

**「一段话」的表达能力仍然存在，但不是段落式**：`description`（实体顶层）+ **句子式**已覆盖（软上限 120 字，多行截断）。若将来确实需要「不截断的长备注」，那是**新增需求**，应重新立项而非复活本节。

**保留原文以存历史**（当时为暂缓，理由是与 Q1 耦合）：

> 暂缓原因：它映射 `content`（长文本），等价于 Q1 的「B 双模」选项。**与 Q1 一起拍板**，否则会绕过「大纲不是仓库」这条约束。
>
> **方向提示（09-17，未拍板）**：如果定「大纲节点不承载正文」（即 `content` 退场），段落式可以改为映射 `description` 的**长文本版**（句子式是多行截断，段落式是不截断）；若定「双模」，则段落式就是 `content`。

> **09-18 附注**：上面那条 09-17 方向提示的**前半句已经兑现**（Q1 定为不影响正文承载），但结论是**取消**而不是改映射 `description` —— 因为「一句话/一段话备忘」这个能力句子式已经有了，再加一个只差「截断与否」的第二形态，属零收益的形态膨胀。

## 九、关联实体（Refs Form）· 已实现（2026-09-18）

> 重建旧树视图的「关联实体徽章组」（`useOutlineEntityLinks.ts`，09-17 随旧视图删除）。按项目惯例「先实现后补规格」（同 §五/§六 的迁移），故本节按实现反写。

**① 内容映射**：**不映射任何节点字段** —— 数据源是**关系表**（`outline_mentions` / `outline_located_in` / `outline_covers` 三条，2026-09-18 新增）。这是它与此前六种形式的**根本区别**：其它形式读 `properties.*`，它读 `relationStore.relations`。

**② 结构**：按**目标实体类型**分组的徽章组（如「角色 3」+ 成员名 chip）。组间按成员数降序；组内按名字拼音序。

**③ 编辑能力**：**派生只读**（`kind: 'derived'`）。属性面板里**没有、也不该有**对应输入框 —— **关系不是字段**。建立/解除关联的入口在 Agent（`outline(action='link_entity')`）。

**④ 配置项**：
| key | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `maxPerGroup` | number | 4 | 每组最多显示几个成员，超出显示「+N」 |
| `emptyText` | text | 「暂无关联实体（可由 Agent 建立关联）」 | 空态文案 |

**⑤ 导出形态**：**不参与导出**（与线索式/进度式同属**横向视图** —— 导出按节点语义顺序，横切视图无法映射成线性文档）。**遗留**：若将来需要「导出时列出每个节点的关联实体」，应作为导出配置项单独设计，不在本形式内。

**⑥ 边界与风险**：
1. **孤儿关系**（另一端实体已删）→ **丢弃不显示**（不显示幽灵徽章）；关系记录本身不自动清理（与「白板不自动删悬空容器」同一纪律）
2. **同一实体经多条关系关联**（如某建筑既被「提及」又「发生于」）→ 徽章**只出现一次**，`relationTypes` 累积用于 hover 提示
3. **方向不敏感**：关系只落「节点 → 实体」一条，读取时两端任一匹配即算（inverse 不落库）
4. **纳入哪几条关系类型由注册表决定**（`pickRefRelationTypes`）—— 新增「节点 → 芽实体」类型会自动出现在徽章里，**无需改本形式**
5. 成员名过长 → chip 省略号截断（`max-width: 100%`）
6. 关联数量很多时**暂无分组内滚动**（`maxPerGroup` + 「+N」是当前的降噪手段）
