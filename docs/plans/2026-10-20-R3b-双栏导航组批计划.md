# R3-b · 双栏导航组批计划（形态 5/6 收敛）

> 依据：[R3-a 已完成](./已完成/2026-10-20-R3a-芽导航形态批计划.md)｜用户 2026-10-20 裁定：5/6 收敛为**一个双栏模式**，域栏 + 芽栏作为导航组，整体随现有「芽侧边栏位置」移动。
> 范围：只加双栏形态；收藏/最近、工具域折叠、管理入口、域内拖拽留给 R3-c。
>
> **执行状态（2026-10-20）**：双栏模式已实现；浏览器预览通过（左侧/右侧、1100px 窄窗）；待用户真机走查。

## 一、形态定义

- **双栏导航组**：在同一侧边栏区域内并排两列——左列语义域，右列当前域内的芽。
- `sidebarPosition=left` → 组在左侧；`right` → 组整体移到右侧。**不是第三个独立面板**，避免与详情面板抢同一侧。
- 不新增独立位置设置；沿用 `settingsStore.sidebarPosition`。
- 形态 5 与 6 的差异由该设置直接覆盖，不再单独实现第六个模式。

## 二、架构

```text
Shell.vue
 └─ SidebarHost.vue
     ├─ SidebarV2.vue        // flat，零改动
     └─ SproutNav.vue
         └─ DomainDual.vue   // 新增：域列 + 芽列
             ├─ DomainList.vue（复用）
             └─ SproutList.vue（复用）
```

- `SproutNavMode` 增加 `'dual'`；`SPROUT_NAV_MODES` 同步。
- `SproutNav` 的 prop union 增加 `'dual'`；`DomainDual` 作为 `v-else-if` 分支。
- `Shell.vue` 在 `.shell-body` 上按 `sproutNavMode === 'dual'` 加 `sprout-nav-dual` 类；CSS 把 `--layout-sidebar-width` 覆盖为 `--layout-sidebar-dual-width`（默认 330px）。
  - `ViewContainer` 已有的 margin 占位使用同一变量，无需改冻结文件。
  - 收起态仍用 `--layout-sidebar-collapsed-width`（36px），由现有 `.sidebar-collapsed` 规则覆盖。
- 双栏宽度：域列约 140px + 芽列剩余；总宽 330px。走查后可调，R3-c 再精修。

## 三、行为

- 域列：`全部` + 有可见芽的域；标签 + 计数；当前域高亮。
- 芽列：当前域内的可见芽；当前芽高亮；空态复用 `SproutList`。
- 点域只切过滤，不自动打开芽；点芽切视图。
- 记住上次域、`unclassified` 只在「全部」、快捷键切域跟随——复用 R3-a 的 `buildSproutNavigation` / watcher。
- 双栏不做域内拖拽重排（R3-c）。
- 左右侧栏、收起/展开、底部 AppMenu 与 R3-a 同口径。

## 六、真机走查（交付时）

1. 设置切「双栏导航」：左侧（或右侧）出现域列 + 芽列；总宽约 330px；主区正确让位。
2. 点「生命与族群」：芽列只显示角色；点角色打开；当前域/当前芽高亮。
3. 点「全部」：芽列显示全部可见芽。
4. 设置「芽侧边栏位置」切右：整个双栏组移到右侧；主区左右让位正确。
5. 收起/展开：双栏收回 36px 窄条；展开恢复；底部菜单可用。
6. 刷新/重启：形态与上次域保留。
7. 窄窗：观察主区与详情面板是否被挤压；记录给 R3-c。

## 七、风险

1. **双栏总宽 330px** 会压缩主区；窄窗需 R3-c 降级。
2. **域列 140px** 对长域名可能截断；用 title/ellipsis，走查后调宽度。
3. **不改 ViewContainer** 依赖 CSS 变量在 `.shell-body` 的继承；需确认左右侧栏与收起态都生效。
4. **双栏与详情面板同侧**：双栏是侧栏组，不是第三面板；若详情面板也在同侧，仍按现有布局共存，需走查确认。
