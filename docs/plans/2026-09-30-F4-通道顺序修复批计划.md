## 一、现象与根因（真机取证）

**现象（用户报告）**：dsh 侧流式输出在前端「渲染停住」（非卡死：后台照常运行、页面可交互）；**切到其它会话再切回、或刷新界面，渲染才「接上」**。

**根因**：Tauri `Channel` 对 JSON 载荷有**两条投递路径**（`tauri/src/ipc/channel.rs`）：

- **< 8192B** → 同步 `webview.eval(…runCallback…)` —— **有序**；
- **≥ 8192B** → 异步 `plugin:__TAURI_CHANNEL__|fetch`（`invoke(...).then(runCallback)`）—— **会被后续小消息超车**。

两者混用时**不保序**。而 dsh 客户端流协议要求**全序**（assistant 帧 `revision` 连续、持久事件 `seq` 连续）：

1. 乱序 → 客户端判定 carrier 故障 → **拆流重启**（其设计内修复路径）；
2. 重启若发生在**回合进行中**，新开的 follow 会把**开局快照**（长会话实测 428–628KB）走异步路径，而紧随的流式小帧（≈240B）走同步路径 → **快照被整体超车** → 客户端 `expected=1, got=11000+` → 报 **`session assistant stream skipped revision 1`**；
3. 重试一次（attempt 2）再撞同一竞态 → 终局失败：`failEventStream`（`session.ts:875`）把会话置 `openState='error'` 并 **dispose 流、不再重开** → **前端从此无实时更新 = 「卡住」**（后台照常跑完；切会话/刷新重取才接上）。

**证据链**（`.workbuddy/_stream-stall-probe.log` / `_shell-timestamps.log`，全部真机抓取；探针见 §四）：

| 证据 | 内容 |
|---|---|
| 线级乱序实录（14:57:33） | `chunk rev=10648/10649` 先到、`rev=10647` 后到（探针 GAP 标记）→ `RemoteStream.restart` abort（栈+reason 已抓） |
| 确定性复现（15:04:34） | 帧 `rev=11100..11109`（240B）先行；`snap size=428233` 迟到 27ms；重试快照同序；壳 `open→cancel→open→cancel` 后死寂；页面文案与用户所见逐字一致；服务器 `turns=5 / running=false`（后台正常完成） |
| 尺寸对撞 | 开局快照 428–628KB（异步路径）vs 帧 ≈240B（同步路径）——阈值两侧的典型载荷 |

## 二、修复

**A 方案（全序，`channel_order.rs`）**：壳装官方扩展点 `Builder::channel_interceptor`（tauri 2.11.5 `app.rs:1698`；`format_raw_js` 虽为 pub(crate)，按小载荷分支形状自行构造）——**所有 Json 体 Channel 消息统一走同步 eval 直投**（`window.__TAURI_INTERNALS__.runCallback(id, {message, index})`；U+2028/U+2029 转义），弃用异步 fetch 路径；Raw 交回默认。**反证开关 `WORLDSEA_NO_CHANNEL_ORDER_FIX=1`**（交回默认双路径）。

**泄漏流小修（`dsh_stream_bridge.js`）**：桥内登记本页未完成流，**`pagehide` 批量 `cmd_stream_cancel`**（终态/取消自动出集；窗口隐藏/最小化不触发 pagehide，不误伤流式）。

**代价口径（用户问询后实测）**：正常小帧（99.9%+）路径零改动 → **不影响 tok/s**；受影响仅 ≥8KB 大消息（快照级，每流一次）——实测 fetch 比 eval 迟 ~27ms，改 eval 端到端不再变慢；唯一代价是 UI 线程一次性解析执行大脚本（毫秒级、单次、不可感知）。
