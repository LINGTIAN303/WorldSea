# 液化玻璃研究（探针）

> 目标：评估在 WebView2 / Chromium 中实现接近 iOS 26 Liquid Glass 的**边缘折射与光学形变**的可行性，为 `liquid-glass` 槽位提供实现依据。

## 一、问题

- CSS `backdrop-filter` 只能模糊/调色，无法弯折背景；真正的「液态」来自边缘折射与镜面高光随形状变化。
- Chromium 支持 `backdrop-filter: url(#svgFilter)`，可用 `feDisplacementMap` 做位移折射，但位移图需按元素尺寸预生成，且多层浮层叠加时开销较高。
- 需要确认：WebView2 当前版本是否支持、性能是否可接受、边界伪影是否可控。

## 二、探针内容

1. 独立 HTML 探针：圆角矩形 + SVG 位移图（R/G 通道编码 X/Y），对比 4/8/12px 位移强度。
2. 叠加 `feBlend` 生成边缘高光；验证与 `saturate/brightness` 组合的效果。
3. 在 WebView2 与 Chromium 中分别截图对比；记录帧率与 CPU/GPU 占用。
4. 测试性能模式：位移滤镜关闭后是否仍保留玻璃染色与高光。
5. 记录限制：尺寸变化需重建位移图、圆角半径与位移强度的关系、与 `overflow: hidden` 的兼容。

## 三、产出

- 探针页面（`docs/misc/生成物/` 或临时目录，不提交生成物）。
- 结论：可行 / 有条件可行 / 不可行，附性能数据与降级方案。
- 若可行，另立实施批：为 `liquid-glass` 写 CSS + 可选 SVG 滤镜定义，接入 `style-kit`。

## 四、风险

- 位移图按像素生成，动态尺寸下需节流重建。
- 多层模糊 + 位移叠加可能显著掉帧，必须绑定性能模式。
- 不同 WebView2 版本行为可能不一致，需要真机实测。

## 五、探针结果（2026-10-30）

探针：`.workbuddy/liquid-probe.html`（临时件，未入库）——三张玻璃卡（仅模糊 / 折射+模糊 / 仅折射），背景为动态渐变 + 高密度文字网格。

- **兼容性**：`CSS.supports('backdrop-filter', 'url(#lens)') === true`，计算值正常返回 `url("#lens") blur(16px) saturate(1.8) brightness(1.06)`。
- **性能**：三张卡同时使用位移图 + blur，背景持续动画，实测 **61 FPS**。
- **视觉**：在高频背景（文字网格）下，圆角边缘可见明显文字弯折；纯渐变背景下折射不明显，需要高光边与颗粒配合才能读出「液态」。
- **实现要点**：位移图由 JS 按元素尺寸与半径生成（R/G 通道编码法线，128 为中性）；`feDisplacementMap` scale 18–26 可见；`feImage` 需随尺寸重建（防抖）。
- **WebView2**：未在真实 Tauri 窗口验证，需真机探针确认；若不支持 `url()`，回退到普通模糊。

## 六、结论与建议

**有条件可行**。建议另立实施批，为 `liquid-glass` 槽位落地：

1. App 根注入一个共享 SVG 滤镜（`sf-liquid-lens`），位移图由 `useLiquidGlass` 按元素尺寸生成。
2. 仅 tier A（浮层/模态/导航/窗口栏）启用；内容层继续普通玻璃。
3. 性能模式与不支持环境回退到 `blur()`；位移滤镜不参与内容层。
4. 叠加镜面高光、噪声与染色，避免「只有弯折没有材质」。
5. 真机走查重点：WebView2 支持性、动态尺寸重建、多层浮层叠加帧率。

## 八、WebGL 原型（2026-10-30）

- 文件：`.workbuddy/liquid-webgl.html`（临时件，未入库）。静态背景纹理 + 全屏 fragment shader。
- 实现：圆角矩形 SDF → 每像素法线；沿法线采样背景纹理做折射；RGB 通道不同偏移做色散；Fresnel 边缘反射；Blinn-Phong 镜面光；软阴影与烟灰染色。
- 观感：明显比 CSS/SVG 版更接近参考图——玻璃有厚度、边缘弯折、色散与镜面高光；可调折射/色散/模糊/镜面/圆角/染色/光位。
- **关键限制**：背景是静态纹理。真实产品必须拿到玻璃背后的内容纹理；DOM 无法直接被 WebGL 采样。
- 捕获候选：
  1. 引入截图库（如 modern-screenshot）在弹层打开时对背后区域截一次；背景静止时足够。
  2. 自研 foreignObject 光栅化；无新依赖但实现量大。
  3. 滚动类表面继续 CSS/SVG 近似，只有静态浮层用 WebGL。

## 九、结论更新

WebGL 是达到「真液态」的必要条件；CSS/SVG 只能做近似。建议先验证「弹层打开时截背景 → WebGL 渲染」这条链路的可行性与性能，再决定是否落地。

## 十、截图 → WebGL 链路验证（2026-10-30）

- 待解决：

  2. 背景变化（滚动/视频）需要低频重截或降级；

## 十二、物理折射升级（2026-10-30）

参考：Charles Grassi（squircle SDF / 斜面法线 / RGB 色散 / 圆柱焦散）、GPU Gems 2 Ch19（法线扰动折射 + Fresnel）、Imad Rahmoune（SDF / Snell IOR 1.52 / 色散）、Inigo Quilez（圆角 SDF）。

- 形状：`sdSquircle`（指数 4–6，圆角滑杆映射），替代圆角矩形。
- 法线：SDF 梯度 + 斜面 z 分量，边缘形成厚度。
- 折射：`refract()` + 三个 IOR（1.505/1.520/1.535），RGB 分别采样；不再用线性偏移。
- Fresnel：`F0=0.04` 标准公式；镜面光 Blinn-Phong；边缘焦散亮带。
- 参数：折射 24、色散 16、模糊 46、镜面 1.30、圆角 57（squircle n≈4.5）、染色 0.14。
- 注意：Snell 模型的偏移尺度与旧线性模型不同，旧的折射 87 会变成厚透镜；默认已重设。

## 十三、纯 CSS 分层方案对照（2026-10-31）

来源：用户提供的社区实现 `gitee.com/greyd097/yzrt` → `纯CSS液态玻璃`（已下载到 `.workbuddy/ref-css-liquid/`，临时件）。

**它的做法**（不是折射，是分层伪造）：

- 玻璃本体几乎不加效果：`rgba(255,255,255,.04)` + `backdrop-filter: blur(2px)` + `brightness(.9)`。
- 质感全靠四层：① 2px/6px 两级内阴影在四角拉出白边；② 内圈 1px 黑边 + `blur(8px)`，只在上缘露出，伪装厚度暗焦散；③ 45° 对角渐变 + `blur(3px)` 做角眩光；④ 外层容器 `contrast(3)` 提升整组对比。
- 结论：**玻璃感不来自模糊，而来自边缘的明暗层次**；本体越清晰越像玻璃，模糊越多越像磨砂。

**对照实验**：`.workbuddy/liquid-css-vs-webgl.html`（左 CSS / 右 WebGL，同一背景、同尺寸、同圆角）。

- CSS 版：背景完全清晰、几乎零成本，但深色背景下本体不可见，只剩发丝边，像“描边面板”而不是玻璃；浅色/有纹理背景才成立，且必须按主题换边色。
- WebGL 版：中心清晰、边缘弯折 + 色散 + 白边，深色背景仍有实体厚度，明显更接近 iOS。
- 定位：CSS 配方作为**降级层**（性能模式 / 截图不可用 / 低端设备）合格；主路径仍是 WebGL。

**对照过程中修掉的两个 shader 物理错误**：

1. 斜面法线 `nz` 上限只到 0.92，中心永远残留 8% 倾斜；SDF 在中心梯度为零、归一化后产生假方向 → 整块玻璃变成凸透镜，中心重影。改为 `nz` 到 1.0，中心 N=(0,0,1)，平直区零折射。
2. 额外 RGB 色散按单位法线全表面偏移，平直中心也被撕成三份 → 改为乘 `(1-nz)`，色散只发生在弯折带。

**参数更新**：折射 24、色散 12、边缘模糊 30、中心清晰 0.12（中心模糊系数）、内暗线 0.34、角眩光 0.30、镜面 1.30、染色 0.10。

## 十五、纯 CSS 路线研究（2026-10-31）

### 15.1 专业资料结论

- Josh Comeau《Next-level frosted glass with backdrop-filter》：`backdrop-filter` 只采样元素正后方，需把层向外扩展再用 `mask` 裁回；边缘再叠一层「更小半径 + `brightness`」的模糊，能做出玻璃厚度。
- CSS-Tricks《Getting Clarity on Apple's Liquid Glass》：CSS + SVG 位移折射可行，但 Safari 支持有限、性能代价明显。
- LogRocket《How to create Liquid Glass effects with CSS and SVG》：`backdrop-filter: url(#filter)` 仅 Chromium 支持，GPU 开销大，建议只用于小元素并准备静态降级。
- Apple HIG / WWDC25：Liquid Glass = 实时模糊 + 深度折射 + 镜面高光；分 regular / clear 两种材质。

结论：纯 CSS 无法真正弯折背景，但「扩展采样 + 边缘分层 + 遮罩高光」足以做出可信的玻璃质感，且成本远低于 SVG 位移。

### 15.2 实验室

| 变体 | 做法 | 定位 |

| B 弯折带 | A + 遮罩到 14px 环的重模糊层（外扩 24px 采样） | 厚度增强 |

### 15.3 实现坑

1. **`isolation: isolate` 会创建 backdrop root**：玻璃容器一旦加上，内部 body 层的 `backdrop-filter` 只采样到 edge 层，中心始终是重模糊。去掉后恢复正常。
2. **边缘层必须遮罩成环**：仅靠半透明 body 覆盖中心，边缘层的 18px 模糊会从 body 底下透上来，整块变成双重模糊。用 `mask-composite: exclude` 把 edge 层裁成边带后才干净。
3. **给 backdrop 层加 `transform: scale()` 不会产生折射位移**：Chrome 先做 backdrop 过滤再应用变换，观感无变化，已移除。
4. **祖先的 `filter` / `contrast()` 同样是 backdrop root 风险**：参考实现的 `contrast(3)` 包裹层不能直接照搬，会把子层采样隔离。
5. **参考配方只适合小元素 + 浅背景**：2px 模糊、4% 白填充在大面板/深色背景下会「隐形」或发灰；大面板需要按主题给本体染料与模糊，并依赖弹层遮罩提供可读性。

### 15.4 推荐配方（C）

| 项 | 深色 | 浅色 |
|---|---|---|
| 本体填充 | `rgba(8,12,20,.34)` | `rgba(255,255,255,.12)` |
| 本体模糊 | 6px + saturate 1.3 + brightness .98 | 3px + saturate 1.15 + brightness 1.0 |
| 本体渐变 | 顶白 .07 → 透明 34% → 底黑 .08 | 顶白 .14 → 透明 40% → 底黑 .04 |
| 边带 | 18px / saturate 1.9 / brightness 1.14 | 12px / saturate 1.5 / brightness 1.05 |
| 边框 | `rgba(255,255,255,.16)` | `rgba(20,30,50,.22)` |
| 白边 | 2px .92 + 6px .55 | 1.5px .95 + 6px .6 |
| 暗焦散 | `rgba(0,0,0,.6)`、透明度 .55 | `rgba(0,0,0,.45)`、透明度 .50 |
| 对角眩光 | .38 / .30，blur 3px | .5 / .4，blur 3px |
| 外阴影 | `0 20px 50px rgba(0,0,0,.42)` | `0 18px 42px rgba(30,44,70,.18)` |

性能模式：去掉 edge 层与眩光，body 模糊降到 2px；保住填充、白边、暗焦散即可维持玻璃识别。

### 15.5 未决

- WebView2 实机测量「body + edge」两层 `backdrop-filter` 的帧成本，决定大面板是否保留 edge 层。
- 浅色主题在真实应用背景上的存在感仍偏弱，需在设置弹层实机确认是否加深边框/底影。
- 文字对比度：玻璃本体染料需纳入 `contrast.spec` 的合成计算，确保 ≥ 4.5:1。
- 产品接入面：先做设置弹层样板，再决定表格/侧栏等高频面是否启用。
