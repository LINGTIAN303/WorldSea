# 编辑器内核集成可行性调研（编程场景 / CodeMirror 6 vs Monaco）

> 2026-09-03 调研完成（两轮外部检索：编辑器对比 + Tauri 集成专项）。
> 背景：Agent 空间场景滑块含「编程」场景（现占位），需要代码编辑器内核支撑文件查看/编辑。
> 界面形态（VSCode 式布局）与扩展发布两方向已明确排除；本文只评编辑器内核。
> **状态：方案已拍板（2026-09-06 启动一期），一期已落地并通过静态验证（vue-tsc 清零 + vitest 324 全过），待用户真机手测。**

## 一、结论先行

**推荐 CodeMirror 6 作为集成目标，Monaco 保留为远期选项。**

核心依据是项目第一要素——本地化与离线可用：CM6 是纯 ES 模块、天然随 Vite 打包进单二进制、零 CDN 依赖、零 Web Worker 要求；Monaco 的语言服务依赖 Web Worker，可行但多一层打包与协议配置，且体积/内存成本对「预览 + 轻编辑」场景是超配。

## 二、对比总览

| 维度        | CodeMirror 6                                                               | Monaco Editor                    |
| --------- | -------------------------------------------------------------------------- | -------------------------------- |
| 体积（gzip）  | 核心 \~50-150KB，全量 \~700KB                                                   | >2MB 起步（node\_modules 可达 29MB）   |
| Worker 依赖 | 无（纯主线程）                                                                    | 必须（语言服务 workers）                 |
| Vue 3 集成  | vue-codemirror（最流行）/ vue-codemirror6（v-model）                              | monaco-editor-vue3（含 DiffEditor） |
| 语言支持      | 官方 `@codemirror/lang-*` 按需装（js/ts/python/rust/java/go/sql/json/yaml/cpp 等） | 内置全语言 + TS 智能提示（LSP 级）           |
| 编辑能力      | 高亮/折叠/搜索/多光标/补全（扩展拼装）                                                      | 开箱即用、最全                          |
| 主题适配      | CSS 变量友好（EditorView\.theme 映射项目令牌）                                         | 自定义主题对象，成本略高                     |
| 维护/生态     | 活跃，模块化（Sourcegraph 迁移案例：JS 下载量降 43%）                                       | 活跃（微软维护），体积问题长期无解（issue #463）    |

## 三、项目第一要素逐条对照

- **本地化/离线**：CM6 无任何 CDN/远程资源，天然合规。Monaco 默认 AMD/CDN 加载方式必须改造为 npm 自托管（vite-plugin-monaco-editor 或 Vite `?worker` 导入），可行但属额外工程。

- **单二进制部署**：两者都随 Vite 产物进 Tauri 资源。Monaco 的 worker chunk 在 Tauri 下有已知坑：`file://` 协议禁止创建 worker，必须走 Tauri 自定义协议（`http://tauri.localhost`）——本项目 dev 走 `localhost:5175`、生产走 Tauri 协议，**worker 在生产协议下的加载需实测**。CM6 无此风险。

- **技术栈**：两者均有成熟 Vue 3 封装；Tauri WebView2（Chromium 内核）兼容性无虞。

## 四、与现有设施的关系

- 现有 Prism 只读高亮**不冲突**：编辑器是新增能力层。FilePreview 的轻量渲染（Markdown 富文本/HTML sandbox/图片）继续走现有管线（2026-09-03 已落地一期渲染预览）；编辑器用于「打开即编辑」形态。

- 保存链路已具备：后端 `cmd_fs_write`/`cmd_fs_read` 现成，编辑内容直接落盘，「人改 → Agent 可读」闭环零后端改动。

- 新增依赖（若采纳一期）：`codemirror` + `vue-codemirror` + 若干 `@codemirror/lang-*`——**需用户确认后安装**。

## 五、落地分期（一期已于 2026-09-06 落地）

1. **一期（低风险试点）——已落地**：文件面板「预览 / 编辑」切换；CM6 集成 + 语言包（python/typescript/rust/go/java 起步）；编辑态 Ctrl+S 走 `cmd_fs_write` 保存。
   - 实现落点：`CodeEditor.vue`（CM6 封装：v-model/语言映射/令牌主题/保存键位）+ `FilePreview.vue`（切换/脏态/保存链路），均在 `apps/tauri/src/components/files/`。
   - 保存键位收编注册表 `space.fileEditor.save`（同 §2-9 输入焦点内命令模式，可改键，目录已同步 SHORTCUT_CATALOG）。
   - 语法配色与 Prism 同语义映射 `--agent-*` 变量，明暗主题自适应；编辑上限 1MB（>1MB 只读预览）。
   - **包名修正**：调研原文写「typescript 语言包」，实际 npm 无 `@codemirror/lang-typescript`——TS 支持在 `@codemirror/lang-javascript` 内（`javascript({ typescript: true })`）。
   - **安装事故记录**：本机 pnpm `importPackage` rename 系统性 EPERM（瞬态文件锁，重跑无效）；应急以手动 junction（`mklink /J`，11 个：7 直接依赖 + 4 直接 import 的子包）+ package.json + lockfile 三方对齐收尾。后续 pnpm install 恢复正常时会自动接管重建。
2. **二期（2026-09-07 已落地）**：语言包扩展（json/yaml/markdown/html/css/sql + legacy-modes shell——md 源码与配置/前端族编辑高亮，html() 自带内嵌 css/js 支持）；两个小修补（编辑器外 Ctrl+S 兜底：注册表 handler 经事件总线 `ws-file-editor-save` 触达 FilePreview，先例 ws-open-settings；秒点竞态：enterEdit 等待 loadingPromise，仍失败不进编辑防空起点覆盖）。**搜索面板免做**：basicSetup 已内置 searchKeymap（Ctrl+F/Ctrl+H/高亮匹配），一期即有。diff 对比（@codemirror/merge）与主题色阶深化留待按需另立项。

3. **二期第二批（2026-09-07 同日追加，用户三项新需求）**：① 搜索面板 UI 令牌化（CodeEditor 内 ：deep 覆盖 .cm-panel.cm-search/输入框/按钮/匹配高亮，明暗自适应）；② 右侧滑动预览窗 minimap——`@replit/codemirror-minimap` 0.5.2（用户拍板社区包；**0.5.x API=showMinimap Facet**，create 仅提供容器 DOM，渲染/滚动联动/点击跳转包内处理，无旧版 minimap()/createLogo）；③ 多文件栏——FileTabBar.vue 顶置 tab 条 + ProjectFilesPanel tabs/activePath 多实例（v-show 切换，编辑缓冲互不干扰；tab× 经 FilePreview expose 的 tryClose 三键确认防丢稿；dirty-change 事件汇聚驱动 tab 脏点；browser/docked 两布局分支同构）。

4. **二期第三批（2026-09-07 同日再追加，用户四项）**：① 缩进参考线——自研 extension（零依赖）：行首空白宽度按 indentUnit 分级，视口内每行画级数-1 根竖线（WidgetDecoration 绝对定位 ch 列对齐，滚动/编辑自动重建）；② 一键结构化——**内核原生 `indentRange`**（@codemirror/language）语法树重排全文缩进，编辑态头部「缩进」按钮触发（无语法树语言安全降级不动内容；prettier 级深度格式化留待另议）；③ 文件类型图标映射——抽共享 `fileIcons.ts`（继承目录树原表 + 代码类扩充 + 身份色维度），目录树/tab/预览头三处同源消费；④ 多文件栏迁移至文件面板头部行——ProjectFilesPanel 经 **Teleport** 传送 FileTabBar 至 PreviewPanel 头部 `#fp-header-tabs` 容器（tabs 状态不搬家），「+ 打开文件」按钮钉住浮层目录树（dock/非 dock 均可弹，选中/再点/点外关闭），tab 区横向滚动无滚动条 + 滚轮纵转横。

5. **二期第四批（2026-09-07，用户拍板：diff + 更多语言；TS 提示/LSP 挂起）**：① diff 对比视图——`@codemirror/merge` 官方包，新 CodeDiff.vue（MergeView 只读双栏：左=磁盘基准、右=编辑缓冲；差异行令牌高亮 + 未变区折叠 collapseUnchanged + 两侧行号；语言/主题与编辑器同源 cmLangs/cmTheme）；FilePreview 三态（预览/编辑/对比），编辑态有脏改动时头部出现「对比」按钮，状态机：preview↔edit 脏态确认、diff 只读自由进出。② 语言扩展至 30+ 类——语言映射抽共享 `cmLangs.ts`（CodeEditor/CodeDiff 同源），新增官方 cpp/php/vue（Lezer 语法树）+ legacy-modes lua/ruby/toml/dockerfile/ini/cfg/conf（流式高亮，无语法树）。③ **挂起记录（用户拍板后续进行）**：TS 类型级智能提示（需 tsserver 引擎入包+协议桥，中等偏大）；LSP 通用语言服务（后端 server 进程 + WS 桥，每语言分发 server 二进制 pyright ~30MB/rust-analyzer ~50MB，与单二进制部署冲突最重——仅当编程场景成为产品主线再试点）。

6. **二期第五批（2026-09-07，用户五项手测反馈修复）**：① **tabs/编辑缓冲持久化**——右栏文件 Tab 是 v-else-if 条件挂载，切五 Tab 重挂即丢 tabs；新建 fileTabsStore 模块单例（tabs/activePath/dirtyPaths/编辑缓冲 buffers），ProjectFilesPanel 加 `owns-tabs` prop 隔离左栏实例（SessionSidebar 挂有第二个 ProjectFilesPanel）；外部联动 watch 改 path 字符串比较（对象引用浅比较被同引用点击静默跳过=「点击无反应」根因）。② CodeDiff 两侧加行号列。③ **预览态语法着色**——CodeEditor 加 `minimal` 只读模式（无保存键/缩进线/minimap），code 与 html 源码预览弃 Prism 改 CM 渲染（与编辑态同源配色；JSON 压缩重排移 previewCode computed；Prism 高亮链路退役）。④ 缩进线仅编辑态（minimal 不挂 guides 即满足）。⑤ **文件类型图标换 vscode-icons 集**（Great Icons 风格 per-type 多色 SVG）——构建期从 @iconify-json/vscode-icons 提取 37 图标 body 生成 file-icon-data.ts（**零运行时依赖**，勿手改），FileIcon.vue 渲染，目录树/tab/预览头三处同源。

## 六、风险点

- CM6 拼装式：补全/搜索等需显式装扩展，初期功能面比 Monaco 窄——匹配分期落地节奏（一期按 basicSetup 默认能力：行号/折叠/多光标/括号匹配）。

- Monaco worker 生产协议加载未实测（若远期切换 Monaco，此项列为首验）。
