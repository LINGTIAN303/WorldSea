## 二、设计定稿

### 2.1 工具契约

```ts
worldview({
  sprout?: string,  // 芽名（中文名或 id）。不传 → 返回全部芽名清单
  action?: string,  // 动作名。仅传 sprout → 返回该芽使用方法（含动作目录与参数）
  params?: object,  // 动作参数（按使用方法中该动作的参数说明传）
})
```

- 三级行为：无参 → 芽名清单；`sprout` → 使用方法；`sprout` + `action` → 执行动作。
- 错误契约（fail loud，不假成功）：未知芽名 → 报错 + 可用芽名清单；未知动作 → 报错 + 该芽动作目录；动作执行沿用既有「诚实化口径」（dispatched 只代表已派发；query 类真回传）。
- 参数形态取 `params` 单对象（JSON Schema 静态；60+ 动作无法平铺进单工具 schema）。

### 2.2 芽名动态机制（「随已有芽的注册」）

- 工具内注册表以**芽 id（official.xxx）为稳定键**；`name` / `description` 由芽注册侧在激活时登记（`bootstrap.ts` 批量登记 27 个 manifest 的 id/name/description）。
- 效果：**改芽名 / 增删芽 → 工具返回的清单自动跟随**（名字实时取登记值）。
- 清单含：芽名（+ id）与一句话定位；**不全量披露说明**（渐进披露）。
- 已登记但工具内无说明的芽 → 基本信息 + 明确「暂无详述」；未登记芽名 → fail loud。

### 2.3 注册表结构（单一事实源）

```
packages/agent-runtime/src/tools/worldview/
  index.ts          — 工具定义（ToolDefinition；进 BRIDGE_TOOL_NAMES → 生成 Rust 契约）
  registry.ts       — 芽登记表（运行时）：registerSprout(id, name, desc) / list() / resolve(name|id)
  sprout-guides.ts  — 27 条说明的「概述」数据（id 键控：定位 / 实体类型 / 数据模型约束 / 边界）
  sprout-actions.ts — 芽动作表（id → action → { description, params, run }）——自 10 域工具迁入
  render.ts         — 说明渲染纯函数：概述 + **动作目录自动生成**（动作描述/参数从 sprout-actions 出，杜绝双份漂移）
```

### 2.4 动作表以「可执行实况」为准

- 迁入范围 = 10 个域工具的现有 switch 分支（60+ 动作，含 timeline/entity_type 的直写 store 类与 emit/query 类，语义不变）。
- `entity_type` 的 10 类型 × 4 动作（list/create/update/get_detail）→ 归入对应 10 芽（characters/culture/languages/conflict/buildings/items/concepts/combat_stats/apparel/inspiration）。
- **「声明但未实现」的动作不迁**（plugin-bridge 表中的 `building_get_layout` 等——与「假成功治理」同口径）。
- 无专属动作的芽（如区域/组织/物种/植物/武器/画板/自定义；以逐芽盘点实况为准）：动作表为空，说明以中性事实写「实体通过通用工具读写」（不发明动作）。

## 三、说明内容规范（中性、无倾向性）

1. 只陈述事实：能力动作、参数、数据模型约束、边界（如「删除含子树的节点会连同子树一起删除」）。
2. 不出现：推荐/优先/建议/应该/避免等引导词；输出渠道偏好；方法论断言（如「因果链优先」）。
3. 不做价值判断（「强大」「重要」）。
4. 示例（改前 → 改后）：
   - 「整棵树一次成型时**优先** `batch_create`——比逐层创建少很多次调用」→「`batch_create`：从结构化数据一次创建多个节点（参数 `structure`）」
   - 「叙事建议 → 聊天文字」（输出偏好）→ 不写。
5. 芽名清单不暗示优先级（按登记顺序）。
