## 一、要解决的问题

白板里复制一个容器（卡片），让用户不必「新建容器 → 绑定节点 → 逐个重配表现形式」。
**核心矛盾**：容器与节点是 **1:1**（`outline_board.properties.layout` 的 container 带 `nodeId`），
所以「复制容器」必须先回答「节点是否一起复制」——否则会出现两个容器指向同一节点。

## 二、三种语义候选（待拍板 Q1）

| 方案 | 含义 | 后果 |
| --- | --- | --- |
| **A · 复制节点 + 容器**（倾向） | 新建一个 `outline_node`（属性照抄、命名加「副本」），再建容器指向它，组件配置全复制 | 守住 1:1；会新增节点（用户需知情）；可一次 Ctrl+Z 撤销 |
| B · 仅复制容器、复用同一节点 | 两个容器 → 同一节点 | **破坏 1:1**，与白板既有硬决策冲突 → 不推荐 |
| C · 仅复制容器配置 | 新建空容器（未绑节点）+ 复制表现形式配置 | 不产生节点、最轻；但用户仍要手动选节点，价值有限 |

**倾向 A**：复制是「复制一份内容」的直觉语义，且 1:1 是既有硬约束。

> **✅ 五项已拍板（2026-10-18）**：Q1 = **A（复制节点 + 容器）** · Q2 = 自动递增命名（`原名 副本` → `副本 2/3…`）· Q3 = **不复制关联章节** · Q4 = **不复制任何关系** · Q5 = 右下偏移 +24/+24。以下问句保留以便追溯。

## 三、待拍板问句

- **Q1**：采用 A / B / C？（建议 A）
- **Q2**：新节点命名策略——`原名 + " 副本"`，重名再递增（`副本 2`）？还是弹窗让用户直接输入？
- **Q3**：是否复制**关联章节**（`manuscriptId`）？
  - 章节与节点是「1 节点 ↔ 1 章节」语义（`chapterLink` 双侧同写），
    两个节点指向同一章节会打破该语义 → **建议默认不复制**，在计划里注明。
- **Q4**：是否复制**关系**（跨芽 `outline_mentions` 等 + 横向三型）？
  - 建议**不复制**：关系表达「这个节点指向哪些实体」，复制出来会产生成倍的重复边；
    用户可后续手动添加。
- **Q5**：复制位置——原容器右下偏移（如 `+24, +24`），重叠时继续递增？

## 四、施工步骤（按 Q1=A 展开）

1. `useBoardLayout` 新增**原子操作** `duplicateContainer(containerId)`：
   - 读容器 → 克隆 `components`（新 id、保留 form/order/config）
   - 计算新位置（Q5 规则）+ 新 `order`
   - 新建节点（Q2 命名、`properties` 照抄但 `parentId`/`order` 按同级末尾重算、不复制 Q3/Q4 的内容）
   - 建容器并指向新节点
   - **整批一次写入**（一个 `replaceLayout` + 一次实体 `add`），保证单步撤销
2. BoardView：容器右键菜单 / 选中态操作加「复制」入口（与既有删除/折叠同组）
3. 测试：
   - 属性与组件配置照抄、`id` 全为新值
   - 命名去重、位置递增、不复制章节与关系
   - 撤销一次即整体回退（节点 + 容器同时消失，不留孤儿节点）
4. 真机走查：复制 → 内容与配置一致 → Ctrl+Z 一次干净回退

### 4.1 施工记录（2026-10-18）

| 环节 | 落点 |
| --- | --- |
| 布局克隆（纯函数） | `board/duplicateContainer.ts` → `cloneContainerIntoLayout`：新容器 + 组件换新 id + config 浅拷贝 + 尺寸与归属区跟随 + 折叠态不复制 |
| 编排（组合函数） | `board/composables/useContainerDuplicate.ts`：`recordUndo` → 建节点（命名递增、不复制章节）→ 同步 `parent_child` → `replaceLayout` → 选中新容器 |
| 入口 | `BoardInspector`「复制容器」按钮（「恢复内容自适应」下方）→ `BoardView.onDuplicateContainer` |
| 测试 | `__tests__/duplicateContainer.spec.ts` **7 例**：新 id / config 深拷贝 / 尺寸复制 / 折叠不复制 / 拒绝同节点二次容器 / 源不存在 |

**与计划的偏差（已按实际落地修正）**：§四 原写「整批一次写入、撤销不留孤儿节点」——实际落地为**与「空白双击新建节点」同口径**：`recordUndo()` 记布局快照，撤销回滚**布局**，新建节点保留为「未入板」。原因：`useBoardUndo` 是布局快照式栈，没有「反向删除实体」钩子；为单项功能引入第二套撤销机制不划算。若日后要求「撤销连节点一起删」，需扩展 `useBoardUndo` 支持随快照附带的实体回滚。

**行数纪律**：`BoardView`（冻结 1230）与 `useBoardLayout`（冻结 444）均不得增长——新增全部落在两个新文件，BoardView 净增 0 行（模板属性合并 + 模板内 `.value` 抵消）。

## 五、门禁与风险

- **门禁**：`vue-tsc` 0 · `arch:check` 0 违规 · `vitest outline` 全绿 · `workspace-dist` 重建。
- **风险 1**：撤销只覆盖布局而漏了节点 → 留下孤儿 `outline_node`（必须在同一撤销步内合并，
  参考 `useBoardUndo` 的 `{skipUndo}` 与 `field` 两类记录）。
- **风险 2**：复制时若原容器在折叠状态，新容器是否也折叠？建议**展开**（新容器需可见）。
- **风险 3**：批量复制（多选）不在本批范围——只做单容器。
