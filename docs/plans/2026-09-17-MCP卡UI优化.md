## 二、已拍板决策（2026-09-17 讨论确认）

1. **范围**：A 硬伤修复 + B 视觉打磨 + C 状态与工具可见性 + D 编辑能力（B4），全做。
2. **行交互形态**：**行可展开**——收起行为紧凑摘要，点击展开详情区（连接明细、工具清单、错误原因、编辑/重试/删除操作），信息渐进披露。
3. **添加表单**：保持**卡内内联展开**（不做二级弹窗），表单顶部提供**「表单 / JSON」双模式切换**；JSON 模式编辑**单条**服务器配置，前端解析后走现有添加/保存命令，**不改 Rust**。

### 计划内的细化裁定（需随本计划一并确认）

- **C-1 分组改为三组 + 行级 pending 态**：「已连接 / 未连接 / 已禁用」，去掉永不出现的「连接中」分组；连接操作进行中时该行图标转 spinner（组件本地瞬时状态，不进数据源）。
- **C-2 启用失败语义变更（行为变化，重点确认）**：现逻辑 `toggleConnection` 启用失败时静默把配置回写为 `enabled=false`（useMcpConnections.ts L81-85），用户无感知。改为：**失败时保持 `enabled=true`** → 该行落「未连接」组，展开区显示错误原因 + 「重试连接」；错误只在前端本次运行期记忆（composable 内 errors Map，Rust 不持久化错误，重启后回到无原因的"未连接"）。
- **C-3 工具数用 `toolCount` 零成本展示，明细展开时按需拉取**：`MCPConnectionState` 加可选字段 `toolCount?: number`（TS 视图类型，不涉 Rust 契约）；McpPanel 展开时直接 `invokeRpc('cmd_mcp_list_tools', { id })` 懒加载（组件内已有直接 invokeRpc 取 configPath 的先例，L141-146），不新增穿层事件。
- **D-1 编辑保存语义**：编辑「已启用」服务器 → `cmd_mcp_connect`（幂等 upsert，保存并重连）；编辑「已禁用」服务器 → `cmd_mcp_save`（仅写文件，不意外启动连接）。`id` 不可编辑（仅 name/传输/地址/参数/Headers）。
- **删除确认**：编排层 `SpaceAgentSettingsPanel.onRemoveMcp` 调全局 `useConfirm()`（type=danger，明示"删除配置、断开连接并注销工具，不可撤销"），McpPanel 仍只 emit。
- **Headers 展示脱敏**：展开区只显示 Header **键名**（如 `Authorization: ••••••`），编辑回填时给原值。
- **手风琴**：多行可同时展开（展开态用 `Set<id>` 本地维护）；搜索平铺模式下默认全收起。
- **不做轮询/实时推送**：状态在加载、添加、切换、重试后刷新；「重试」即手动刷新手段。
- **不做 mcp.json 全文批量编辑**（已排除，本期只有单条 JSON 模式）；「打开配置文件」按钮挂账（无现成打开文件命令）。

## 三、UI 规格

### 3.1 收起态行（摘要行）

```
●  my-mcp-server                    HTTP   12 工具   [✓] [⌄]
   http://localhost:3000/mcp
```

```
●  filesystem-server                stdio  8 工具    [✓] [⌄]
   npx -y @modelcontextprotocol/server-filesystem /tmp
```

```
●  broken-server  (启用未连接)       HTTP   重试      [✓] [⌄]
   http://localhost:9999/mcp
```

```
○  disabled-server                  stdio             [✕] [⌄]
   npx some-server
```

- 行首：**8px 状态色点**（取代 check/X/grip 三图标）——已连接 `--success`、未连接 `--danger`、已禁用 `--text-muted`、pending 用 LoaderCircle 旋转（`--info`）。
- 名称：`--font-size-sm` + `font-weight: medium`；禁用行整体 `opacity: .55`（沿用现规格）。
- 第二行描述：`--font-size-2xs` + `--font-mono` + tertiary 色，单行省略；HTTP 显示 URL，stdio 显示 `command + args 拼接`（修复 #10 args 不可见）。
- 右侧 inline 元信息：传输类型小标签（HTTP / stdio，弱化 pill 样式）；已连接显示「N 工具」徽标；未连接显示「重试」文字按钮（快捷重试，等同展开区内按钮）。
- 右侧操作：启停图标按钮（沿用 `.skill-toggle` 同款 check/close 图标，与 Skills 行保持一致）+ chevron（`chevron-down`，展开旋转 180°）。
- 行规格对齐 Skills：`gap: 8px`、`padding: 6px 8px`、`border-radius: var(--radius-mid)`、`background: var(--bg-muted)`、hover `1px var(--border)` 描边。
- 整行点击（除按钮外）切换展开；按钮 `@click.stop`。

- 容器：行内下方折叠块，`border-top: 1px dashed var(--border)` 分隔，内边距 8px，背景透明（不套第二层卡片，避免双层底）。

- stdio：Command 一行；Args 以 tag 序列展示（每个 arg 一个小 pill，含空格参数也能完整呈现，弥补表单按空格拆分的表达缺陷）。
- 工具清单：首次展开懒加载（loading spinner + "工具加载中"）；成功列工具名（mono xs）+ description（tertiary，单行省略 + title）；失败显示「工具清单加载失败」+ 重试；右上角「刷新」重拉。`toolCount` 与拉取结果不一致时以拉取结果为准并更新徽标。
- 操作按钮置底右对齐：「编辑」（ghost）、「删除」（ghost danger 色）；未连接时前置「重试连接」（primary 弱样式 = set-btn hover 主色即可，不引入强按钮）。

### 3.3 分组头

保留现有「标签 + 计数」结构（`.mcp-group-head`），标签色与行首色点同色：已连接 success / 未连接 danger / 已禁用 muted；空组隐藏（沿用现逻辑）。

### 3.4 添加 / 编辑表单（卡内内联，表单/JSON 双模式）

```
──────────────────────────────────────────────────
添加 MCP 服务器            [表单] [JSON]           ← 分隔线 + 小标题 + 模式药丸
 名称      [ My MCP Server                       ]
 传输      [ HTTP/SSE                      ▾ ]
 URL       [ http://localhost:3000/mcp         ]
 Headers   [ Authorization: Bearer xxx         ]  ← textarea 多行，每行 Key: Value
           [ X-API-Key: abc                    ]
           （每行一个，如 Authorization: Bearer xxx）
                          [取消]  [确认添加]      ← 右对齐，主操作在右
```

- 表单区与列表间 `border-top` + 8px 间距 + 小标题（添加态「添加 MCP 服务器」/ 编辑态「编辑：{name}」）。
- 模式切换复用基座 `.set-cats` / `.set-cat` 药丸（遵守设置规范，不新造样式）。
- 字段：
  - 名称：必填。
  - 传输：TuiSelect，两项——`HTTP/SSE (streamable-http)`、`stdio`（legacy `sse` 不单列，与 2026-07-28 规范取向一致）。
  - HTTP/SSE：URL（必填）、Headers（**改 `<textarea>`**，mono，3 行高，每行 `Key: Value`；解析沿用 L148-157 现有逻辑）。
  - stdio：Command（必填）、Args（单行 input，空格分隔；hint 注明"含空格的参数请用 JSON 模式以数组形式填写"）。
- 校验（纯函数，可单测）：名称非空；HTTP 态 URL 非空且形似 http(s)://；stdio 态 Command 非空。不通过：确认按钮 disabled + 失焦字段下显示小字 danger 错误提示。
- 按钮：右对齐；「取消」ghost（TuiButton variant=ghost size=sm）、「确认添加 / 保存」主按钮；`Esc` 等同取消。
- 成功或取消后：**重置全部字段、模式回到「表单」、收起表单**（修复 #2 残留）。
- JSON 模式：
  - textarea（mono，6 行），placeholder 为单条配置示例（HTTP 与 stdio 各给一段注释说明，注释用 `//`？JSON 不支持注释——placeholder 是提示文本不是 JSON 本体，可写两行示例）。
  - 接受单服务器对象：`{ "name", "transport", "url"|"command"+"args", "headers"? , "enabled"? }`（`id` 可缺省，添加时生成 `mcp-${Date.now()}`；编辑态保留原 id）。
  - 检测到 `{"mcpServers": {...}}` 包裹格式 → **取其中第一个服务器**（键名作 id），多键时 toast 警告"仅取第一个，批量编辑请直接改 mcp.json"（2026-09-18 调整：由报错拒绝改为宽容取首 + 警告，降低从 Claude Code 文档粘贴的摩擦）。
  - JSON.parse 失败 → 显示"JSON 解析失败：{原始错误信息}"； schema 校验失败 → 指出缺哪个字段。错误均显示在 textarea 下方，不丢内容。
  - 模式互转：表单 → JSON 实时序列化当前字段；JSON → 表单尝试解析回填，解析失败保留表单原值并在 JSON 侧报错。
- 编辑态：点展开区「编辑」→ 表单区以编辑模式展开并预填（含 headers 回填原值，不脱敏）；保存后按 D-1 语义分派 connect/save，退出编辑态并刷新列表、保持该行展开。

## 六、风险与边界

1. **C-2 是唯一行为语义变更**（启用失败不再回写禁用），已在 §二 列出重点确认；其余均为呈现层与新增入口，不改用户既有操作路径的主干（编辑/展开属新增能力）。
2. `invokeRpc` 带参调用在 McpPanel 内属第二次使用（首次为无参的 data_dir），实施时先核对其参数传递约定（Tauri invoke 与 HTTP bridge 两路径都要能通；rpc.rs L585-592 已注册 `{ id }`）。
3. 工具清单无缓存失效推送：展开时拉取一次，「刷新」按钮手动重拉；不做轮询（本期边界）。
4. 错误原因由 M6 后端状态机在运行期提供（failed 携带 error，经 mcp:status 事件实时刷新）；前端不持久化错误，重启后未连接项是否显示原因取决于 Rust 自动重连状态机是否落 Failed entry（前端无额外记忆）。
5. 搜索（设置顶部搜索框）平铺模式下 MCP 卡关键词已在 `CARD_KEYWORDS`/`CATEGORY_KEYWORDS.agent` 覆盖，本期不新增卡内元素级搜索；展开区在 flat 模式默认收起。
6. 不引入新依赖、不改 Cargo、不改 mcp.json 格式、不做用户数据迁移（项目暂无在用用户）。
