## 一、已拍板结论（讨论滚动登记）

### 1.1 项目↔会话映射：项目 = dsh workspace（同源，非映射）——开场第一题，2026-09-27 拍板

用户模型（优于 Agent 提案 A「当前项目即真相」/ B「会话绑定项目」/ C「workspace 一一对应」——本模型是 C 的方向反转：产品跟随 dsh，非 dsh 配合产品）：

- **项目 = dsh workspace，单一真相源在 dsh 侧**——产品域**取消「新建项目」入口**（新建项目 = 去 dsh 界面添加工作区）；产品域项目列表 = 壳转发 dsh `workspace/list`（E2 已验证壳内 `DshBridge::call_api` 通道），瘦身为「展示 + 切换」。
- **实体数据落 `<工作区>/worlddata`**——Agent 会话 cwd = workspace → **FS 直写对全部项目天然可达**；对根工作区与现状完全一致。
- **双向解耦写死**：dsh 换会话 ↔ 产品切项目，互不影响、互不联动（禁止任何「切 X 时联动 Y」设计）。
- **FS 直写保留，dsh 工具面不动**——直写与能力调用并存；判定线：直写 = 文件级便捷（绕数据层校验，适合批量/原始操作）；能力调用 = 带校验、带感知、带审计（D2 主体建设方向）。
- **零迁移**：默认项目（dirPath=根）↔ 已有「WorldSea」workspace 天然对齐；`D:\WS` 自动成为第二个项目。
- 连带注意：dsh 工作区的**可供给性**（C4：外部目录需 WRITE_OWNER）由 dsh 侧机制 + 「修复工作区权限」命令兜底。
- 施工落点（设计收口后细化）：产品 `ProjectManager`/`useProjectSwitcher` 改造（列表来源切 dsh workspace、创建入口移除、`entityDirOf` 统一 `<workspace>/worlddata` 口径）、壳命令 +1（workspace 列表转发）、product.toml 授权。

## 二、讨论中

### 2.1 能力面扩容——能力形状（2026-09-27 拍板）

- **Z · schema 驱动的通用 CRUD**：`world.schema.get(entityType)`（字段/必填/枚举/关联，从运行时 `entitySchemaRegistry` 动态生成——worldview 收口轮已有零漂移机制，零手写）+ `world.entity.put/get/query` + `world.relation.*` 通用数据面打底。Agent 两步走：先拿 schema → 按 schema 组装调用。语义化动作表路线（Y）沿用世界观整合线结论淘汰；纯 CRUD（X）缺 schema 认知不采纳。
- **数据变更通知随第一梯队同期做**（能力桥边界 #6）：倾向形态 = **页面内闭环**——能力声明带 `mutates` 标志，工作台伺服（`shell/capabilities.ts`）执行 mutation 类能力后自派事件 → 各 store 刷新，零壳改动；壳级事件通道作为备选，施工时定。
- 第一梯队能力清单（核心闭环）：`world.project.list/current`（配合 1.1 模型）· `world.schema.get` · `world.entity.*` / `world.relation.*` CRUD · 变更通知。
- 第二梯队（操作便利，后置）：芽启停 / 视图切换刷新 / 文件预览推送。第三梯队（重设计）：orchestration 子 Agent 接 dsh / 长任务进度与取消 / schema 扩展。

### 2.2 认知面（2026-09-27 拍板）

- **能力描述自带领域词与最小示例**——worldview「发现路径轮」验证有效（可见 + 语义命中才会被用），立即生效。
- **workspace 根放产品域说明书**（能力地图 + 典型用法 + 判定线）；各能力 description 尾部带指向 → 模型首轮经 read_file 拉取，冷启动问题消解。零 dsh 树改动（纯用户数据文件）。**命名待核实**：若 dsh 支持自动加载 workspace 根 `AGENTS.md`（dsh 生态惯例，dsh 仓自身用 AGENTS.md 做开发规范）则直接自动注入优于「指向 + 拉取」；否则按原设计命名 `WORLDSEA.md`。★ 已核实：旧 Agent 面的 WORLDSEA.md 是代码树内置资源（`src/agent/rules/`），随 E7 物理删除、零残留、零活引用——与新说明书同名无冲突、机制不同（旧 = 规则链注入，新 = 用户文件 + Agent 拉取）。
- 说明书由施工批生成（能力清单自动汇编 + 人工校订），用户可编辑。

### 2.3 能力桥 7 项边界的补齐取舍（2026-09-27 拍板，第一梯队范围内）

| 边界 | 处置 |
