## 零、四契约总览

```
前端（Vue/TS）──①事件契约（下行）──▶ AgentLoop（新内核，Rust）
     ▲                ◀──②输入契约（上行：三语义 + 准入 + 取消）
用户 ──④审批契约（四值 + 三型交互）──▶ AgentLoop
工具 ◀──③工具契约（ToolDescriptor + 执行器二态）──▶ AgentLoop
```

四契约之外的编排族细节**不在本冻结范围**（D2：编排线停止演进，不为其做新内核承载设计）。

## 一、事件契约（冻结）

| 项 | 冻结内容 |
|---|---|
| 载体 | `EventKey(&'static str)` + `DispatchMode{ Emit \| Bail \| Serial \| Parallel \| Waterfall }`；`mode_of()` 单点表；新增变体**编译期强制登记** key + mode |
| 实装面 | 五模式声明保留；近景实装 `Emit` / `Bail` / `Waterfall`（现状裁定 U6：serial/parallel 无场景缓做，首个消费方出现时补） |
| 规模 | 现状 **59 个 key 常量**（`event.rs:722` `pub mod keys`），按域分：Agent 流（AGENT_*/STREAM_*/TOOL_CALL_*/ERROR/FILE_CHANGE）· Orchestrator/NODE/TRACE · Plan/Reflection/SubAgent/Router/Thought·ToT · LoopEng/Judge · ContextCompact（3）· RequestSnapshot · InputAdmission · ToolResultPreBroadcast · A2UI · Confirmation/Ask（各 2） |
| 不变量 | **模型可见 ⟺ 已记录**；分发**先快照后运行链**（不持外包锁）；递归深度上限 = 8（常量，不做 tunable）；`waterfall` 的「不调 next 即否决」不可被后续监听器翻案（单调 guard） |
| 新增约定位（本方向） | `checkpoint_created` · `conversation_forked` · `conversation_rewound`（沿既有 snake_case 单词式口径；落地时登记 `keys` 常量 + `mode_of`） |
| 前端面 | `turnModel` 归约器（`ActionKind` 8 类：tool / subagent / plan / a2ui / confirm / phase / router / reflection）**消费口径不变**；新事件若无归约规则 → 明确落「活动日志」通道（沿用 04-§二 D3 转换层策略，前端适配独立排期） |
| 冻结粒度 | 既有 59 key **零改名零删除**（除按 D2 随编排线处置的族，另行报告）；新 key 一律增补式 |

## 二、工具契约（冻结）

| 项 | 冻结内容 |
|---|---|
| 声明 | `ToolDescriptor` 全字段（[06-§二](06-工具元数据契约草案.md) 表：身份 / Schema / 安全 / 限制 / 控制 / 执行），Rust 侧为聚合单源 |
| 执行器 | 二态：`local`（内核内）/ `client`（前端经桥执行）——**客户端工具一等身份**；同享审批/超时/输出上限/大结果链路 |
| 注册面铁律 | 派发 action 名 **必须等于**桥注册键 `pluginId:action`；`worldview` 薄壳转发不变 |
| 生成物 | `bridge_tool_specs.json`（`{generatedBy, source, tools[]}`，现 **29 工具**；方向不变：TS 声明 → `gen-bridge-spec.mjs` → Rust 生成物，勿手改） |
| 大结果 | 阈值起步 32KB（ZD3-4）→ artifact（内容寻址），与「原文外置 + 锚点对」合并为同一存储 |
| 元数据消费方 | 权限判定（§四）读 `alwaysAsk/riskLevel/sideEffectScope` 等声明；调度读 `concurrentSafe`；不做调用点猜测 |
| 冻结粒度 | 字段集合一次到位（ZD3-1）；既有工具名零改名；209 尸体清算挂账后置（ZD3-3） |

## 三、输入契约（冻结）

| 项 | 冻结内容 |
|---|---|
| 三语义 | `InputKind{ FollowUp（唤醒）/ Steer（唤醒·最近一轮消费）/ Inject（不唤醒） }`（`input.rs:30`），提交序 = 消费序 |
| 准入 | `InputAdmission` waterfall：run 起始 + 每轮请求构建前分发；监听器可改写/丢弃/否决（否决 → 输入原序回退）；零监听器 = 现状行为 |
| 取消 | 协作式取消：已交付文本落终稿（`meta.interrupted*` = 中断锚点）+ `StreamEnd` + `AgentInterrupted` 双事件；收口幂等 |
| 不引入 | 第二套 inbox（ZD1-6：ZCode CommandInbox 仅作术语参考） |

## 四、审批契约（冻结）

| 项 | 冻结内容 |
|---|---|
| 结果四值 | `ConfirmationOutcome{ Approved / Denied / Skipped / Timeout }`（`confirmation.rs:46`；**Timeout 仅内核侧产生、不接受前端回传**）；fail-closed：非 Approved 一律不执行 |
| 判定顺序 | 单点纯函数（[05-§三](05-权限模式机草案.md) 顺序表 + 本项目强化项：内置锁硬判定、数据区保护优先）；`alwaysAsk` 为**结构化标记**（不靠 ruleId 文案比对），模式放行分支不得绕过 |
| 承载三型 | 交互请求三型（`permission` / `userInput` / `hookReview`）为外层统一模型（S5 落地）；审批 = 其中 permission 型，四值语义不变（B7 回归底线） |
| 会话级授权 | `allowOnce/allowAlways` 记录于会话，**只服务 alwaysAsk gate**（对齐 ZCode 语义）；full-access 持久化走现有 secure_store（仅会话内，ZD2-3） |
| 档位 | 保持三档 `Plan / Interact / Autopilot` ⟷ ZCode `plan / build / yolo` 映射（ZD2-1）；名单优先级 `Lock > Allow > 档位` 不降级（ZD2-5）；项目规则层新增为第三层（ZD2-4） |

## 五、逐条对照（现有实现 → 新内核需做）

| 契约 | 现有落点 | 差距（新内核动作） |
|---|---|---|
| 事件 | `event.rs`（59 keys + 穷尽 key()/mode_of）+ `event_bus.rs`（五模式声明/三实装/锁纪律） | **零基础风险**；仅增补新事件族（检查点/分叉）+ 前端归约规则 |
| 工具 | `bridge-spec.ts` → `gen-bridge-spec.mjs` → `bridge_tool_specs.json`（29）；桥 29 工具；TS 侧 209 定义大多不可达 | 升级为全字段 `ToolDescriptor`；尸体清算（挂账）；`executor` 二态显式化 |
| 输入 | `input.rs`（三语义 + waterfall 准入 + 取消收口，A3 已落地） | **无缺口**（只随新内核平移） |
| 审批 | `confirmation.rs`（四值 + 超时单列）+ `permission_rules.rs`（三档 + Lock/Allow） | 判定顺序单点化；`alwaysAsk` 名单化（元数据驱动）；三型交互新增（S5）；项目规则层新增 |
| 会话 | `session_log/session_live` + replace + 快照 + 压缩事务 | 分叉/回滚/检查点新增（S3）；崩溃冷修复扩面 |
