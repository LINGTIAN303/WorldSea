## 二、差异矩阵（C1-C10）

> 处置含义：**重写** = 内核本体按 ZCode 能力面重构；**升级** = 在既有实现上对齐语义；**新增** = 缺失能力；**保留** = 不动；**借鉴** = 只取设计不落机制。

| C | ZCode 做法 | WorldSea 现状（2026-09-21） | 差距 | 处置 |
|---|---|---|---|---|
| C1 主循环 | turn 机 + turn 四件 + **target-continuation（不硬停）** + 消息派生 | ReAct 循环 + RunPhase 五站位（input.rs 已有准入瀑布）；长任务有独立管理器 | 无显式 turn 状态机；无「目标续跑」语义（长任务 ≠ 续跑） | **重写** |
| C2 工具系统 | ToolMetadata 全字段契约 + 注册/执行/调度三层 + 大结果 artifact | 双执行栈（Rust 原生 ~29 + 前端桥 29 可执行；TS 侧 209 定义大多不可达）；元数据散落 | 无工具元数据契约（副作用/风险/审批/超时/输出上限/并发安全/幂等）；无「客户端工具」正式概念 | **重写**（双执行栈正式化） |
| C3 权限审批 | 五档模式 + 判定顺序契约 + 会话级授权 + 三型交互 + disallowedTools | 三档（Plan/Interact/Autopilot）+ Lock/Allow 名单（320 行）+ 四值审批 + 领域写保护 | 无「edit/build」档位细分；判定顺序未契约化（alwaysAsk 不可绕过未立）；无会话级 always-allow 持久化；交互仅 permission 单型 | **升级**（三档映射到五档语义，名单保留） |
| C4 会话 | 事件溯源 + **fork/rewind/checkpoint（conversation/workspace/both）** + 仓储（usage/todos/…） | session_log/live + replace 语义 + 请求快照 + 压缩事务；长任务检查点（心跳 5s / stale 30s） | **无会话分叉/回滚**；无工作区检查点（文件面）；无 usage/todos 仓储 | **新增**（分叉/回滚/工作区检查点） |
| C5 长程自动化 | Cron/OffPeak + 后台任务 + 工作流沙箱 | 定时器 3 工具？/长任务心跳；无后台任务（Bash 阻塞）；工作流 = 编排线待裁定 | 后台任务面、定时面 | 新增（按需分批） |
| C6 提示上下文 | 指令链字节预算 + 技能渐进 + 自动压缩 | 段式组装（12 段单点组装）+ 八文件规则 + WORLDSEA.md + 技能渐进（worldview 三级披露） | 指令链预算规则（先省宽泛后截断具体） | 借鉴 + 保留 |
| C7 扩展 | 插件 5 组件 + hooks（7+ 事件，含信任模型）+ MCP(http/sse/OAuth) + 工作流 | MCP（rmcp，已闭环）+ Skills（1 存）+ 芽插件 SDK + tool_hook（局部） | hooks 体系与**工作区 hook 信任**；插件清单标准化 | 新增（hooks/信任）；MCP 保留 |
| C8 模型 | 三协议分派 + 11+ 内置模板 + 推理档位 DSL | genai 0.7 + **16 错误码四路分流（已落地）** + registry 697 行 + 3 模式 + Keyring | 协议枚举广度（responses/chat-completions）；档位 DSL | 借鉴（genai 覆盖足够，不引新链路） |
| C9 协议呈现 | V4：投影 snapshot/delta/rows + 双客户端语义 + ACK | Tauri IPC + 事件流（turnModel 归约） | 投影与恢复语义（replayable）——**单壳场景低优先** | 借鉴（多端需求出现时再立项） |
| C10 工程机器 | 架构策略文件 + `--changed` 检查 + 阅读包 + knip + 新鲜度 | vitest 988（70 文件）+ cargo 三 crate + vue-tsc + doc-links + docs 体系 + 7 点清单 | 无「模块边界策略化 + 自动检查 + 阅读包」 | **新增**（首批 P 线） |

## 四、风险表

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | **越抄越像**（用 Rust 重写一个 ZCode 工作台） | 工程量失控、领域线停摆（09-16 R1/R6 同款） | 对标清单以 C1-C10 **Agent 能力面**为界（01-§三 负面清单钉死）；每族开工必须有「本项目为什么需要」一行；负面清单项一律不做 |
| R2 | **重写期前线断档**：事件协议变更使 `turnModel` 与行段失效 | 体验回退 | 转换层先行（04-§二 D3 策略沿用）；前端适配独立排期 |
| R3 | **回归丢失**：既有 311+180+117+119 用例覆盖的机制在新内核漏项 | 静默退化 | §三回归底线逐条对账；每族切换以底线用例通过为验收 |
| R4 | **双轨并存**（旧内核与新内核长期并行） | 债上加债（现存 TS↔Rust 双执行栈即教训） | 每族切换即删旧实现；切换截止点写入批次计划 |
| R5 | **上游漂移**：ZCode 0.16.x 高速迭代、协议未冻结 | 蓝图过时 | 本方向是「能力蓝本」而非跟随：以 2026-09-21 本地快照为准，机制以本项目文档为准 |
| R6 | **工程机器误伤存量**：400 行上限等阈值对存量文件大面积报红 | 门禁形同虚设或噪声淹没 | 先建存量基线（违规登记为豁免），门禁只对**新增/变更**生效（--changed 语义） |
| R7 | **产品面注意力牵引**：ZCode 的商店/多端/工作流等产品能力诱使扩大范围 | 首发失焦 | 首批钉死「工程机器 + 会话与权限」两族；其余按批次表排队 |
| R8 | **权限语义重排引发使用习惯断点**：三档 → 五档的映射若含混，用户（即作者本人）会踩到不确定的放行行为 | 安全语义不清 | S 线先出映射表并单独评审（三档 = 五档的哪几个；Autopilot 与 yolo 的边界）；真机走查覆盖 |
