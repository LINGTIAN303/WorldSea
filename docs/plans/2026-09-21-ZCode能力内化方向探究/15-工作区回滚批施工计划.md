## 二、设计（草案）

**写前快照（before-image，内容寻址）**
- 挂点 = `fs_tools.rs` 三处写入点（与 `sink.file_change` 同处，已有 path/kind）；
- 写入**成功前**：读目标文件现内容 → `raw_store.put`（零重复）→ 记 `workspace_file_ops` 行：
  `(session_id, request_seq, path, before_hash: Option<String>（None=当时不存在）, after_hash: Option<String>, op: 'write'|'edit'|'edit_diff', at_ms)`；
- **失败降级**：快照失败不阻断写入（记 warn）——但**并行 in-flight 标记**？不引入；`F-1` 语义见 §四 Q4。

**回滚执行链**：`rewind_workspace(session_id, request_seq)`（自由函数 + 事务括号，同 S3 家族）
- 取 `request_seq > target` 的 ops **倒序** → 逐条：`before_hash=Some` 写回内容；`None`（当时不存在）→ 删除文件；
- **只触碰 ops 记录过的文件**（不扫描、不臆测）；重复回滚同边界 → 无 op → no-op（幂等）；
- 结果明细报告：`{ restored: n, removed: n, failed: [{path, reason}] }`——失败**不静默**；
- 前置：运行中拒绝（同 `rewind_session` 守卫）。

**命令面**：`rewind_workspace(session_id, request_seq)` → 明细 DTO；`list_workspace_ops(session_id, limit?)`（面板可选：显示某边界的文件变更数）。

**前端**：回滚确认弹窗加「同时回滚文件」复选框（Q2）→ 勾选则先 `rewind_workspace` 再 `rewind_session`（顺序：先文件后会话——会话回滚成功后才切换视图；文件失败则以明细提示，会话不阻断）；历史抽屉边界行显示「N 处文件变更」徽标。

## 四、裁定表（待拍板）

| # | 裁定点 | 选项 | 建议 |
|---|---|---|---|
| Q1 | 快照范围与时机 | (a) 仅 Agent 写入工具触碰的文件、**写前** before-image（内容寻址）(b) 全工作区定时快照 (c) 写后 after-image | **(a)**——(b) 体积不可控且与本仓「按需」原则冲突；(c) 拿不到「改写前」状态、回滚第一步就缺源 |
| Q2 | 回滚入口 | (a) 现有回滚弹窗内加「同时回滚文件」复选框（默认勾选）(b) 独立操作按钮（历史抽屉里单列「回滚文件」） | **(a)**——回滚的心智是「回到那个点」，文件与会话应同一次操作；独立按钮易造成只回一边的分裂态 |
| Q3 | 新建文件回滚 | (a) **删除**该文件（b) 保留空文件 | **(a)**——回滚语义 = 恢复当时状态（当时不存在 ⇒ 删除）；保留空文件会留垃圾 |
| Q4 | 快照失败 / 回滚冲突 | (a) 快照失败仅 warn 不阻断写入（回滚时该条缺 before 则报告「不可回滚」）(b) 快照失败即拒绝写入 | **(a)**——与「外置失败退回截断」同哲学：增强项不得反噬主操作；明细报告兜底 |

**自主项（不拍板）**：agent-tmp 分区**纳入**回滚（临时区文件也是 Agent 写的，回滚应一并恢复；登记）；边界行徽标形态；明细提示文案。

## 六、风险

| # | 风险 | 缓解 |
|---|---|---|
| W1 | 快照遗漏（工具绕过 fs_tools 写文件，如 terminal 命令写文件） | 本批**只覆盖 Agent 文件工具**；terminal 写入不回滚（登记为已知边界，UI 提示语注明） |
| W2 | 大文件快照膨胀 | 内容寻址去重 + raw_store 总量闸门（超限拒外置 → 该条标「不可回滚」，写入不阻断） |
| W3 | 回滚目标文件已被外部修改（用户手改） | 回滚直接覆盖（以 Agent 视角恢复）；不做三方合并（登记） |
