### 2.3 为什么「效果很差」——六条根因

1. **分派靠名称猜，且三张表并行**：`TOOL_LABELS`（中文名）/ `TOOL_OP`（7 类动词）/ `classifyActionRowKind`（6 类行段容器）三套，口径不一、互不覆盖；对 20+ 现存工具 MISS（`bash`/`powershell`/`grep`/`find`/`edit_diff`/`list_directory`/`todo_write`/`memory_*`/`workspace_search`/`ask_user_question`/定时器/子代理/`shell_session_*` 全 MISS），对 MCP 动态工具**永远** MISS。
2. **详情形态一把梭**：参数与结果都是「JSON + Prism + 2000 字符截断」，不按语义分派——读文件看不出行号，搜索结果看不出命中列表，抓网页看不出正文。
3. **视觉身份缺失**：只有 7 个抽象操作图标（create/read/edit/delete/search/cmd/tool），没有文件类型图标、MCP 服务器、技能、子代理的身份标识。
4. **摘要对象不完整**：文件只显示 basename（无完整路径）；终端行不显示 shell 身份、exit code；`rowKind` 虽已透传但只挂 class、无视觉差异（`ToolRow.vue:29`）。
5. **专属身份缺失**：MCP / Skills / SubAgent 无行段；SubAgent 刷新即失（事件不回源）。
6. **同域多入口并行**：计划三处、交互两套——同一件事在流区有两种以上呈现，互相稀释。

## 三之二、dsh 流区与推理段取经（2026-09-23 源码级取证，三路并行）

> 来源：`D:\deepseek-harness`——`packages/client/ui-conversation|ui-chat|ui-trajectory|ui-tool`、`packages/llm/llm|llm-deepseek`、`packages/core/session|agent-loop`、`docs/subsystems/{conversation,session,session-projection,spill,llm-streaming}.zh.md`、`docs/web-styling.zh.md`。**设计取经，不搬代码。**

### 3.1 哲学三条（指导取舍）

1. **重写是一等公民的显式日志操作**：`{op:'replace', startSeq, endSeq}` 遮蔽区间并在原位插入新事件；红线 = 端点必须已存在 / 必须早于替换事件 / 必须**密集引用每个被遮蔽节点**（`core/session/src/surface.ts`）。流区不做 `push/splice` 式可变列表；**「发生重写」是单调计数器信号**（`replaceGeneration`），增量消费方能区分「纯尾部增长」与「整段被改写」。
2. **身份 / 位置 / 可见性三轴正交**：`kind+id`（它是谁）· `anchorSeq`（排哪）· `visibility`（看不看得见）。隐藏 ≠ 删除；移动 ≠ 重建；**折叠/隐藏绝不移除数据**；分页前插只改更早的锚点，已渲染节点的 key 与展开态必须保留；节点暂离场用 `hidden` 而不是返回 `null`。
3. **引擎通用、业务可插拔**：每类流内容 = **一个折叠单元（纯函数：事件 → 状态）+ 一个 keyed 渲染器**；**任何可入流事件必须有归属渲染器，未知走 fallback**（不许静默消失）；展示态（折叠 / 滚动 / 展开）**永不写回数据源**。

### 3.2 渲染三层分派（本批对齐的关键机制）

dsh 工具行 = ① 注册表（keyed slot，key = 工具名，命中即整体替换）→ ② 客户端静态枚举（工具名 → variant：bash/read/write/edit/search/web/…）→ ③ **结果形态纯函数**（terminal / diff / read / search / web / details card model，从 args + 结果 metadata 推导）。

- **类由客户端判、结构由服务端给**：`meta.path/lines/totalLines/lang`（读）、`meta.diffs`（改）、exit code/signal（终端）由**工具侧写进结果**，UI 只做校验与渲染——**不从文本里正则抠**。
- 原生 tool 命中 keyed 注册 → 整体替换组件；未命中 / 畸形数据 → 通用 IN/OUT 行（**稳定降级**，工具名进摘要槽）。
- **dsh 的空档**：MCP 无专属形态（落通用行）——恰是我们已知要对齐的点。
- 缺口对照：我们的 `TOOL_OP` / `classifyActionRowKind` 只做了 ② 的一半（且 20+ MISS），①③ 缺失 → R-0 补齐。

### 3.3 折叠行基础设施

- 所有单元共用**一个折叠行**（`DisclosureRow`，24px）+ **本地 disclosure 状态** + **纯函数摘要**；状态仅四态 `running/ok/error/stopped`，用颜色 + shimmer + 屏读隐藏文本**三通道**表达（不靠图标形状）。
- **默认全部折叠**；仅「滚动中的 turn 的过程组」常开，turn 完成即收起。
- 摘要全部组件内纯函数：工具行取 args 白名单键 + 结果首行；推理行取「**最新已完成段落**首行」（流式中避免抖动）。
- 折叠/展开只切 CSS（不卸载组件）。

### 3.4 推理段运行时（四条结论，逐条对我们）

1. **推理是 assistant 消息内的一个一等内容块**（与 text / tool-call 按 block index 交错，不是独立消息/事件流）；**落盘、可回放**；「是否回传模型」由适配器 replay 元数据决定（DeepSeek 回传原样、跨模型只丢签名不丢正文）。→ 我们已用 `meta["thinking"]` 持久化 + 回源重建，方向一致；**需明确「回传口径」**。
2. **中断语义与工具调用分离**：中断时保留 text/reasoning 前缀（落成 `interrupted:true` 的消息），**丢弃未派发的 tool-call**——否则出现「有 call 无 result」的脏历史。
3. **UI 折叠规则**：默认折叠一行；摘要用「最新已完成段落首行」；**绝不吞掉最终答案**——最后一步自带推理则随答案内联，否则归入过程折叠；展示模式分档控制「是否给折叠预览」。
4. **token 口径**：`reasoningTokens ⊆ outputTokens`（信息性字段，汇总不得重复相加）；「推理不计」只适用于「可见文本 / 首 token」类读数，**不是计费口径** → 我们不宣称「推理不计费」。

### 3.5 与本项目草案的差异登记

| 点 | dsh 做法 | 本批口径 |
|---|---|---|
| 交互（审批 / 提问） | **不占流内位置**，接管输入区（composer），避免与本轮等待态重复渲染 | 按 Q7 拍板：三类都弹窗 + 流内恒留行段（留痕 ≠ 决策通道），差异登记 |
| 类判定来源 | 客户端静态枚举（无 descriptor 下发） | Q1 裁定加一层 Rust 目录（补 MCP 归属等；静态表保留为 variant 层） |
| 流区虚拟化 | Chat 不做虚拟化（TurnNavigator + 分页）；Trajectory 用 react-virtual | 维持现有窗口化 |

## 四、能力面 × 目标行段（13 组）

> 以下各组「目标形态」为**拟定方案**，逐项可在拍板时调整；`▸` = 折叠态，`▼` = 展开态。

### A 终端与进程（`bash` / `powershell` / `shell_session_*` / `detect_shells`）

- 现状：两套分类表全 MISS → 通用「工具」图标 + 分词标签；仅增量输出区。
- 目标：**终端卡**——折叠态 `▸ ▮ 命令 · bash  $ npm run build …  ✓ 3.4s`；
  展开态 = 终端身份行（`bash(WSL)` / `PowerShell` / `PTY 会话 #id` + cwd + 超时）+ 命令块（等宽）+ 输出区（已有，补 stderr 与自动滚底标识）+ 尾部状态行（`exit 0 · 3.4s`；非 0 红、超时/被杀单独标识）+ 参数区（env 等）。
- 数据：args（`command`/`cwd`/`timeout_ms`）· `__meta`（`op`/`command`/`exit_code`/`duration_ms`/`timed_out`/`sandbox`）· `tool_delta` 增量。

### B 文件（`read_file` / `write_file` / `edit_file` / `edit_diff` / `list_directory`）

- 现状：`▸ 编辑 foo.ts (编辑文件)  +3 −1`——无文件类型图标、无完整路径、read 结果无行号视图。
- 目标：**文件行**——折叠态 `▸ [ts] 编辑 apps/tauri/src/main.ts  +12 −3  ✓`；
  展开态按操作分派：**读** = 带行号只读代码视图（语言高亮）；**写/改** = diff 区（现状保留 + 文件图标 + 完整路径 + 复制路径）；**批量改** = 逐块 diff + 块计数；**列目录** = 目录树。
- 数据：args（`path`/`content`/`edits`）· `__meta`（`op`/`path`/`lines`/`additions`/`deletions`/`truncated`）· `file_change` 事件（`hunks`）。
- 附带候选：路径「点击打开」（需接宿主打开能力，见 §八 挂账）。

### C 搜索与检索（`grep` / `find` / `search_files` / `workspace_search` / `content_search`）

- 现状：通用工具行；结果 2000 字符截断文本。
- 目标：折叠态 `▸ 🔍 搜索 "usePlanStore"  · 12 处 / 5 文件`；
  展开态 = 命中列表（文件分组 + 行号 + 片段高亮）；`find` 类 = 路径列表；`workspace_search` = 条目 + 相关度。

### D 网络（`web_search` / `web_fetch`）

- 现状：通用工具行。
- 目标：折叠态 `▸ 🌐 搜索「…」· 5 条` / `▸ 📄 抓取 example.com（200 · 12.4 KB）`；
  展开态 = 结果列表卡（标题 + 域名 + 摘要）/ 正文预览（截断处接 artifact 卡）。
- 数据：args（`query`/`url`）· `__meta`（当前两者**无 `__meta`** → 本批补，登记在建）。

### E MCP（`mcp__{server}__{tool}` + 3 枢纽工具）

- 现状：**零专属**——标签分词出错、落 `other` 段。
- 目标：折叠态 `▸ ⬡ filesystem · read_file   ✓ 0.3s`（服务器徽标 = 首字母色块 + 服务器名，`getToolLabel` 兜底不再乱分词）；
  展开态 = 参数 + 结果（结构化 JSON，同 §5.5）+ 原始工具名标注。
- 数据：Rust 侧 `McpTool` 已持 `server_id` 与原始 `tool_name`（`mcp.rs:180`）→ 随工具目录下发（Q1 方案 A）。

### F Skills（`load_skill` / `load_skill_reference` / `load_skill_asset`）

- 现状：只有中文标签，技能名 / 正文 / 引用只能靠展开 JSON。
- 目标：折叠态 `▸ ◈ 加载技能 · 大纲白板`；
  展开态 = 技能名 + 说明（Markdown）+ 可用工具清单 + 引用清单（≤2）。
- 数据：工具结果（`{skill,name,instructions,references}`）已有，无需跨栈改动。

### G SubAgent（`delegate_to_sub_agent` / `list_sub_agents` + 编排事件族）

- 现状：退化为普通工具行；刷新即失。
- 目标：折叠态 `▸ ◉ 子代理 · 代码审查员  「审查 src/auth」 ● 8.2s`（运行中实时计时）；
  展开态 = 任务全文 + 结果摘要 + 耗时；**回源补齐**（事件写入 `meta.action_events`，刷新后仍在）。
- 风险：回源需 Rust 侧持久化配合（R6 动作段机制已在），是本批最大跨栈项（§八）。

### 5.1 分派基座（Q1 已定 + dsh 三层对齐）

**三层分派**（对齐 dsh「类由客户端判、结构由服务端给」）：

| 层 | 职责 | 来源 |
|---|---|---|
| ① 工具目录 | 类归属的稳定依据（`category` / `mcpServer` / `readOnly` / `destructive` / `aliases`） | **Rust `list_tool_catalog`**（Q1 裁定；填 dsh 的 MCP 空档）；前端 `useToolCatalog`，装配后拉取 + 工具集变更刷新 |
| ② 前端静态表 | 精确形态 variant（终端 / 文件读 / 文件写 / 文件改 / 搜索 / 网络 / MCP / 技能 / 子代理 / 计划 / 记忆 / 交互 / 域内） | 新模块 `toolClassify.ts`（**纯函数，可单测**）；三张旧表降为文案兜底 |
| ③ 结果 metadata | 内容形态（读 = path/lines/total/lang、改 = diffs、终端 = exitCode/signal、搜索 = 分组 + total） | **服务端在结果 `__meta` 写**；不齐的补（web_* / todo_write / shell_session_* / subagent / MCP） |

- **fallback 必备**：任何工具必须有归属渲染（未知 → 通用行 + 工具名进摘要槽），**不允许静默消失**（dsh `fallback.ts` 口径）。

`[chevron] [类图标] [动词] [对象] (标签) [状态] [chips：沙箱/规模/耗时] [错误或摘要]` + 折叠详情区。
本批把**对象**与**详情区**做成按类分派（现状：对象 = basename / 首个优先键；详情 = 一把梭 JSON）。

### 5.5 结果渲染分派

统一骨架：`结果头（类型 + 规模 + 外置/截断标记）→ 结构化内容（按类分派）→ 原始兜底`。
分派初稿：读文件 → 带行号代码；编辑 → diff；搜索 → 命中列表；终端 → 输出区；网络 → 页面/结果卡；MCP / 其余 → 结构化 JSON + 键值摘要头。

**「结构由服务端给」原则（dsh 口径）**：行号/总数/语言、diff hunks、exit code/signal、命中分组与 total 一律由工具结果 `__meta` 携带，UI **不复从文本正则抠取**（现状 exit code 即来自 `__meta`，保留此路线并补齐缺口）。
artifact 外置（>32KiB）机制**不变**，作为最外层兜底。

### 5.7 渲染稳定性（采纳 dsh 三轴正交）

- **身份**：行 key = 业务稳定 id（段 id / tool_call id / 回源推导 id）——**禁止**从「最近一个未完成项」推断归属；
- **位置**：行序锚定持久证据（对应我们的 `request_seq` / 段序），隐藏与插入不改既有排序；
- **可见性**：折叠 / 隐藏只做渲染过滤，**不移除数据、不改 key**；分页前插后已渲染行的展开态保留（现状 `stepCollapsed` 等已是此精神，R-0 拆组件时保持）。
