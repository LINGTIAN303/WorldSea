> **本项目为什么需要**：现主循环以「工具调用次数」硬熔断（`total_steps=200` → `TotalStepsReached` 失败）——
> 长任务跑到一半被**打断为失败**，而 ZCode 的设计原则是「长程优先：不以工具次数硬停止」；这是 C1 与 ZCode 的最后一处核心语义差距。
> 本文只做设计与裁定点收敛，**未动任何代码**。

## 三、设计（草案）

### C1-a 目标续跑（不硬停）

**A1 次数软化**：次数类不再作**硬**边界——
- `total_steps`：达阈值（200）→ **注入「目标未达成可继续」提示 + 继续跑**（不再 `TotalStepsReached`）；`StepBudgetWarning` 事件保留（前端横幅已有）；
- `RateLimiter.tool_calls`：默认阈值同步放宽（200 → 1000，可配置）且**保持硬熔断**（作为防失控兜底；真实失控场景由 duration 6h / tokens 10 万兜底）；
- **硬边界保留**：token/context（压缩已有）、取消（abort/协作）、权限（确认拒绝）、软超时（告警）、duration 熔断、retry 上限。

**A2 续跑触发（目标未达成时自动续跑）**：模型**停止调用工具**（自然收敛点）时，若 `state.plan` 存在**未完成项**（pending/running）→ 自动注入一轮「计划未完成，请继续」推进提示并**继续循环**（不退出 run）；连续续跑上限 `max_continuations`（默认 3，可配置）→ 超限则正常收尾（返回当前文本，不报错）。
- 复用既有 plan 数据（无新概念）；无 plan 的任务完全不受影响（行为逐字不变）。

**续跑语义边界（登记）**：续跑不重置 `total_steps` 计数（防绕）；续跑轮同样计入速率限制。

### C1-b turn 状态机（若 Q3 选「本批」）

- 内核显式状态：`Idle / Streaming / ToolExecuting / AwaitingUser`（HITL 等待）/ `Interrupted`（终态）；
- 广播 `turn_state_changed`（增补式新 key，00-07 冻结按「增补」登记）；
- `get_state` 快照带 `turn_state`（前端可消费；**前端 turnModel 不改**——它继续用既有事件派生，状态机先建可观测面）。

## 四、裁定表——**拍板记录（2026-09-23）**

| # | 裁定点 | 拍板 |
|---|---|---|
| Q1 | 次数硬停处置 | **(a) 两次数均软化**；**追加修订（用户追加问「6h 哪来的？长任务不应由数值规定」）**：取证确认 `RateLimiter` 为**单调累计三边界**（tool_calls 200 / **tokens 累计 10 万** / duration 6h，均为 A5 批自定，非 ZCode）——其中 tokens 累计会让长任务**更早熔断**。**修订口径（全按建议）**：① `total_steps` + `tool_calls` 改**软**（达阈值提示「可继续」，不再失败）② **tokens 累计熔断移除**（上下文窗口由压缩管理，累计消耗 ≠ 失控）③ **6h 改由「无进展超时」承担**（升级既有 `Watchdog` idle 检测：有进展的正常长任务永不截断，真卡死才停）④ 硬边界 = 取消 / 权限 / 上下文压缩 / retry / 截断 / **无进展超时** |
| Q2 | 续跑触发 | **(a) plan 驱动**（模型停止工具调用时 `state.plan` 有未完成项 → 自动续跑，上限 3）；**追加意见（用户）：plan 需先优化**（对比主流产品有明显问题）→ **plan 优化批先行**（见 [17-plan优化批](17-plan优化批施工计划.md)），C1-a 的续跑触发建立在新 plan 面上 |
| Q3 | turn 状态机范围 | **(a) 另批（C1-b 独立）**——本批只做目标续跑；状态机紧随 |

**执行顺序（用户拍板）**：**17 plan 优化批 → 本批 C1-a**。

## 五、验收口径（反证式）

1. **反证**：≥3 处变异注入（预告）——① 熔断分支保留（软改硬）→ 「200 步后不失败」用例红；② 续跑触发摘除 → 「plan 未完成自动续跑」用例红；③ 续跑上限失效 → 「连续 N 次后正常收尾」用例红；留档 `证据/C1/`。
2. **回归底线 B1-B10 逐条对账**（本族动内核心脏）：事件五模式 / 准入 / 提示段 12 段 / 错误码 16 / 压缩四件套 / 快照 / 审批四值 / A2UI / 长任务心跳 / 记忆三件。
3. **行为变化登记**（预期两处）：① 越过 200 步不再失败（继续跑，仅提示）② 有 plan 且未完成时模型自然收敛点自动续跑（上限 3）。
4. **真机走查**：长任务跑过 200 步不失败；plan 未完成时自动续跑并最终完成；无 plan 任务行为不变。
5. **文档同步**：`docs/index/README.md` + 02-§1.4 + `.workbuddy/memory/`。

## 六、风险

| # | 风险 | 缓解 |
|---|---|---|
| C1-R1 | 次数软化后失控长跑（模型死循环调工具） | RateLimiter tokens/duration 硬熔断 + 协作取消 + 软超时告警；上限可配置 |
| C1-R2 | 续跑触发误伤（plan 长期 pending 导致反复续跑） | `max_continuations=3` 上限 + 超限正常收尾（不报错）；续跑轮计入限流与预算 |
| C1-R3 | 改停止语义影响既有守候用例 | 既有 `TotalStepsReached` 相关用例**逐条重审**（语义变化登记）；B1-B10 全量对账 |
| C1-R4 | 「软超时只告警」意味超时也不停——长跑无终止 | 现有语义不动（ZCode 同款：超时是资源边界之一，由 duration 6h 兜底）；如用户要更强可另批 |
