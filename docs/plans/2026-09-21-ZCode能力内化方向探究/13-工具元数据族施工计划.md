## 二、设计

### 2.1 契约层（`agent-engine::contracts::tool`，Rust 单源）

```rust
pub struct ToolDescriptor {                 // 字段一次到位（ZD3-1）；安全组无默认值 = 编译期强制显式
    // 身份
    pub name: String, pub aliases: Vec<String>, pub category: String, pub description: String,
    // Schema
    pub input_schema: serde_json::Value, pub output_schema: Option<serde_json::Value>, pub strict: bool,
    // 安全（权限系统**读声明**，不做调用点猜测）
    pub read_only: bool, pub destructive: bool, pub concurrent_safe: bool,
    pub requires_user_interaction: bool, pub always_ask: bool, pub needs_approval: bool,
    pub risk_level: RiskLevel, pub side_effect_scope: SideEffectScope,
    // 限制（元数据驱动，取代调用点硬编码）
    pub timeout_ms: Option<u64>, pub max_output_bytes: Option<usize>,
    // 控制
    pub stop_turn_on_success: bool, pub provider_visible: bool,
    // 执行（双执行栈正式化）
    pub executor: Executor,
}
pub enum RiskLevel { Safe, Moderate, Dangerous }              // 对齐现状三级 + TS PermissionLevel
pub enum SideEffectScope { None, Workspace, Git, Network, System, Session }
pub enum Executor { Local, Client }                            // local=内核内 / client=前端桥
```

**三字段的判定读法（映射既有位次，**语义不变**——B7）**：
| 字段 | 读作 | 落位次 |
|---|---|---|
| `always_ask` | 不可被模式绕过的确认（对齐 ZCode alwaysAsk） | 5（S4-b 名单的声明化来源） |
| `needs_approval` | 默认需确认（按档位策略可放宽；对齐现状「Moderate 按策略」） | 12（`tool_level`） |
| `requires_user_interaction` | 工具**自身**承载人工交互（提问类）→ 免执行前确认 | 豁免（对齐现状 ask 豁免） |
| `risk_level` | Dangerous → always_ask 语义（现状「破坏性」自本字段派生） | 5 / 12 |
| `side_effect_scope` | 审计与后续沙箱读；本族不驱动放行 | — |

### 2.2 声明载体（**Q1 待裁**）

原生工具经 `Tool` trait 声明 descriptor；桥工具经生成物声明（TS 单源，ZD3-2 方向不变）。

### 2.3 生成物升级（TS → Rust，方向不变）

`ToolDefinition.meta` 由可选升级为**桥工具必填**（类型层 + 生成器校验）→ 生成物携带安全 / 限制 / 控制字段 → Rust `BridgeToolSpec` 扩展并构造 `ToolDescriptor { executor: Client, .. }`。
**校验器三件**：① `bridge-spec.spec.ts`（生成器即校验器，vitest 全量跑测时比对）；② Rust 侧 `bridge_tools_spec_matches_bridge_contract` 扩展为全字段比对；③ 新增「桥工具清单 ↔ 前端 `ALL_TOOLS_MAP` 注册键」一致性守卫（注册面铁律：派发 action 名 = 桥注册键）。

### 2.4 消费方接线

1. **权限**：`permission_machine` 的 alwaysAsk 来源改为「工具声明 `always_ask` / `risk_level`」（S4-b 静态名单**删除**）；**例外保留**：MCP 动态工具（注册点构造 descriptor，`always_ask=true`）、数据区路径型（E1，仍是内置锁位次 1）。
2. **限制**：工具级 `timeout_ms` / `max_output_bytes` **优先**，回落后全局配置/常量（默认值不变 ⇒ 行为零变化）。
3. **调度**：读 `concurrent_safe`（**Q2**：只读登记 vs 行为变更）。
4. **artifact**（**Q4**：本族 or 另批）：>32KB 结果落 artifact（内容寻址），上下文只留摘要 + 引用；与 `raw_context` 合并为同一存储。

## 四之三、T-b 落地记录（2026-09-22）

- **落型（实施期细化，Q1 精神不变）**：`fn descriptor(&self) -> ToolDescriptor` **必填方法**（无默认——

  一致性由**注册面守卫强制**（见下）——比「工具持有描述符字段」改动面小一个量级且无漂移风险。
- **注册面守卫**（`SimpleToolBus::register`，fail loud）：① `descriptor().validate()` 失败即 panic
  （如 `dangerous` 但 `always_ask=false`）；② `descriptor().name` ≠ `name()` 即 panic。
  用例 `tool::tests::register_rejects_invalid_or_mismatched_descriptor`（三态：错名 / 无效声明 / 合法）。
- **原生工具声明补齐（~30 件）**：fs 8（读 5 只读工作区 / 写 3 写工作区）、memory 6
  （读 2 只读会话 / 写 3 写会话 / `memory_delete` 不可绕过确认）、terminal 7（shell 执行 5 件
  **进程执行→不可绕过确认**〔位次 5，S4-b 名单的声明化〕/ detect_shells 与 shell_session_list 只读）、
  timer 3（读写会话）、subagent 2（`delegate_to_sub_agent` 危险级不可绕过 / 列表只读）、
  `ask_user_question`（**interactive** 预置：工具自身承载人工交互 → 免执行前确认，对齐既有豁免）、
  `workspace_search`（只读）。
- **MCP 动态工具**：`McpTool` 与 tauri 侧 `McpResourceTool`（枢纽级资源/提示族）在**注册点**

  `mcp__*` 前缀静态规则）。
- **桥工具（29 件）**：`FrontendBridgeTool` 持生成物全字段描述符（T-a 已落），`descriptor()` 直接返回。

## 五、验收口径（反证式）
1. **缺字段报红**：新增 / 修改一个桥工具声明缺 `side_effect_scope` → 生成器校验红；原生工具 descriptor 缺字段 → **编译不过**（Q1-a）。
2. **注册面铁律**：派发 action 名 ≠ 桥注册键（如 `export_outline` 假成功旧例）→ 守卫报错。
3. **元数据-权限一致性**：构造 `always_ask=false` 但 `risk_level=Dangerous` 的工具 → 判定读取声明后行为与声明一致（反例注入：把 Dangerous 工具声明为 safe → 判定不得放行）。
4. **限制生效**：工具级 `max_output_bytes=1KB` → 该工具结果被裁剪到阈值；工具级 `timeout_ms` → 超时按该值（既有 `parallel_tool_timeout_is_enforced` 复跑）。
5. **B8 / B7 回归**：A2UI 通道与 R6 动作段全绿；权限判定结果集与迁移前**逐条等值**（alwaysAsk 四类名单声明的等价性用例）。
6. **桥契约**：工具数 29 不变；`bridge_tools_spec_matches_bridge_contract` 全字段比对通过。
