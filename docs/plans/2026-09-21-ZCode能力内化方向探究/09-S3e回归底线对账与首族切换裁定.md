## 二、首族切换的工程事实（取证结论）

> 08-§五 要求「切换 / 保留边界 / 删旧范围」三项裁定。先给事实，再给裁定项（§三）。

**事实 1｜本族已以「原位重排」形式完成，不存在并行第二实现。**
- 契约面**已迁**：事件键 / 模式 / 输入三语义 / 审批四值 → `agent-engine::contracts`（S3-a/b1；key 59→62）；旧 kernel 经 `pub use` 只读引用（单一定义处）。
- 能力面**已增**：`session_branch`（三表 + 收敛原语）· `session_fork` / `session_rewind` / `session_checkpoint`（执行链）· 装载期冷修复接线（S3-b2/c/d）。
- 存储/执行**仍是同一实现**：`session_store.rs`（`session_log`/`session_live`/`session_events`/快照/压缩事务）在 09-16 方向一（A1 丙2 阶段 B）已重构为现形态；本轮是**扩展**而非另写一份——故 **D4 的「切换即删旧」在本族落为「无旧可删」**（不存在双轨）。

**事实 2｜「旧接口」的仅存候选（三处，逐项给出处置口径）**：

| 候选 | 现状 | 是否双轨 | 处置口径（建议） |
|---|---|---|---|
| `messages` 表 + 旧快照→日志迁移块（session_store.rs） | 迁移**幂等**（`messages` 存在且日志为空才跑），仅在从未迁移过的库上生效；已迁移库完全静默 | 否（休眠路径） | **保留**（成本近零、防本机旧库断档）；如需彻底删旧另立小批（见 §三 Q3） |
| 长任务 `CheckpointProvider`（`long_task.rs`） vs 会话检查点（`session_checkpoints`） | 两者并存：前者 = 任务断点快照（`LongTaskCheckpoint`：AgentLoop messages + 任务元数据，用于续跑），后者 = 会话请求边界指针 | 否（**语义不同域**，但概念面重复） | **拍板：按 04-§2.5 原文合并为同一接口**（用户 2026-09-22 裁定，与工程建议不同——设计要求见 [10-检查点统一接口设计草案](10-检查点统一接口设计草案.md)） |
| 编排线 13 模式（agent-patterns） | D2 已裁「停止演进」 | 否 | 不在本族范围（随重写按割裂成本处置，涉退役另报） |

**事实 3｜未接线的面（能力已落地但尚不可用）**：
- 命令层：无 fork / rewind / checkpoint 的 Tauri 命令入口（手动打点、按边界回滚均无调用方）。
- 事件发射：`conversation_forked` / `conversation_rewound` / `checkpoint_created` 已登记（key + mode）但**无发射点**（发射需命令层持 broadcaster）。
- 内存态同步：分叉后子会话的 AgentLoop 未建立（存储已就绪）；回滚后运行中会话的内存消息未随视图同步。
- 前端：无交互入口（属 UX 设计范畴——按决策边界规则需单独确认；预计随前端适配排期）。

**事实 4｜本族验收已完成**：S3-a..d 四批各自的验收（含双变异反证）与本节 B1-B10 对账均全绿；`arch:check` 零违规；基线显式复核 5 处（lib.rs / lib_tests.rs / session_store.rs 两轮）。
