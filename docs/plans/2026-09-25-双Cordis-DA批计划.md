## 一、D · 视图生命周期收口

### 1.1 现状缺陷（已核实，含 file:line）

- **两份视图数组**：真源 = `pluginAPI._views`（`packages/entity-core/src/core/PluginAPI.ts:39`，芽经沙箱 `api.registerView` 写入）；
  显示 = `pluginStore.views`（`packages/entity-core/src/stores/pluginStore.ts:7`，侧栏/快捷键/设置/召唤面板都读它）。
- **只有单向、一次性的镜像**：`apps/tauri/src/plugins/bootstrap.ts:64` 给 `pluginManager.setViewHook` 装钩子，
  `apps/tauri/src/plugins/PluginManager.ts:127` 只在 **activate 时**对新注册视图推一次 → store 里有了；
  而 `PluginManager.ts:155` 的 `deactivate` 只调 `pluginAPI.unregisterView(viewId)`，**store 不动** → 侧栏留幽灵项。
  （当前无芽走 deactivate，属潜伏缺陷；Spike 是用 `store.views.filter` 绕过的。）
- **四处 ad-hoc 同步**（同一件事四种写法）：
  `apps/tauri/src/composables/useProjectSwitcher.ts:299+317`（清空 store 后全量重灌）、
  `apps/tauri/src/sprouts/official/module-builder/ModuleBuilder.vue:92-96,147-151`（自己 splice + 手动 registerView）、
  `bootstrap.ts:90-93`（默认选中首个）、Spike（过滤数组）。
- `uiStore.sidebarOrder` 是**用户排序偏好**（`SidebarV2.vue:151-163` 按 order 排序、缺失即不渲染）
  → 反注册**不应**删 order 项（删了会丢用户排序）；只需处理 `currentView` 悬空。

### 1.2 改法（一条真源 + 变更事件 + 一个装配点）

1. **`PluginAPI`（真源）**：新增 `onViewChange(listener): () => void` 与
   `ViewChange = { kind: 'registered' | 'unregistered'; view: PluginView }`；
   `registerView` / `unregisterView` / `clearViews` 在**真发生改变**时派发；单个监听器抛错不影响注册（逐个 try/catch）。
2. **`pluginStore`（显示侧）**：补 `unregisterView(id): boolean`（与 `registerView` 对称）。
3. **新装配模块 `apps/tauri/src/plugins/viewSync.ts`**：`installViewSynchronizer()`（幂等）——
   订阅事件 → store 增/删 + `uiStore.ensureViewInOrder`。两条刻意不做（施工中定）：
   **不删 `sidebarOrder` 项**（那是用户排序偏好，视图缺席本就不渲染，删了反丢排序）；
   **不夺当前选中**（`viewComponent` 是组件引用、面板不会崩；夺选中会破坏项目切换的选中保持，
   且属用户可见路径变更——要「删视图即切走」应由删除方显式 `uiStore.setView(...)`，B 批做拆装面板时一并处理）。
4. **收敛 ad-hoc**：删 `PluginManager.viewHook` / `setViewHook`（订阅已覆盖，含 module-builder 直调）；
   `useProjectSwitcher` 改「清**真源** `pluginAPI.clearViews()`（事件自会镜像）→ 重播种」；
   `ModuleBuilder` 只调 `pluginAPI`；Spike 清理改走 `pluginAPI.unregisterView(VIEW_ID)`。

## 二、A · 壳侧能力桥（最小双向）

### 2.1 角色与协议

- 三侧角色：**product**（工作台窗 = 世界语义提供方）/ **agent**（主窗 = Agent 面）/ **shell**（注册表 + ACL + 中转 + 审计）。
  v1 壳不做提供方（扩展位预留：`provider` 取值域含 `shell`，D2 写世界数据时启用）。
- 命令面（新增权限 `allow-capability-bridge`，**两窗共用**——它本身就是两窗的缝）：

| 命令 | 谁调 | 语义 |
|---|---|---|
| `cmd_capability_register(decls)` | 提供方 | 登记能力；**provider = 调用窗口 label**（不可冒名）；同 id 异提供方 → `CAPABILITY_CONFLICT`；同提供方重复 → 覆盖（开发期热重载友好） |
| `cmd_capability_list()` | 任一侧 | 内省：`[{id, summary, params, acl, provider}]`（供 Agent 发现面） |
| `cmd_capability_invoke(id, args)` | 调用方 | ACL 校验 → 中转 → 结果 / 结构化错误 |
| `cmd_capability_result(callId, ok, result, error)` | 提供方 | 回执；**只有该调用声明的提供方窗口**能回（`CAPABILITY_NO_PENDING` 兜底） |

- **中转走 `window.eval` 派发**（E2 已验证的模式）：壳在提供方窗口执行
  `__WORLDSEA_CAPABILITY_CALL__(callId, id, args)`；提供方 `Promise.resolve(handler(args))` → 回执。
  理由：不引事件监听面 / Channel，两端同一套派发协议，Rust 侧只有一条路径。
- **错误码**（`CODE: 说明` 字符串，结构化可判）：`CAPABILITY_UNKNOWN` / `CAPABILITY_FORBIDDEN` /
  `CAPABILITY_CONFLICT` / `CAPABILITY_UNAVAILABLE`（提供方窗口不在）/ `CAPABILITY_TIMEOUT`（10s）/
  `CAPABILITY_BAD_DECL` / `CAPABILITY_NO_PENDING`。
- **审计**：注册与每次调用打壳日志 `[WORLDSEA-CAP] caller → provider::id 结果 耗时`。
- **反证开关**：`WORLDSEA_NO_CAPABILITY_BRIDGE=1` → 不注入 agent 侧伺服脚本（agent 提供方缺席，product→agent 应报 UNKNOWN）。
- **依赖**：不新增 crate（`tokio` 现带 `sync` feature 供 oneshot；超时用 `std::thread::sleep` 兜底，不引 `tokio/time`）、不新增 npm 包。

## 三、边界（本批不做）

- **Node 侧接入载体**：本批调用方是「Agent 面窗口」；让 dsh 的工具（Node 侧）发起调用需一条 dsh→壳载体
  （MCP server 或 dsh 双半插件），属 B/C 决策，不在本批。
- **shell 作为提供方**（D2 写世界数据要用）：扩展位已留，实现随 D2。
- **E1 目录口径**（写盘落点）仍是 D2 前置，未动。

## 四、风险与口径

- **eval 派发跑在主线程**：提供方 handler 必须**快返回**（重工作先异步化再回执）；`invoke` 是 async 命令 + 10s 超时，不阻塞壳。
- **能力表是内存态**：窗口页面刷新/重建后由提供方脚本重跑重登记；产品窗是懒创建 → 未建窗时 main 调 product 能力报
  `CAPABILITY_UNKNOWN`（真机探针须先切到工作台建窗）。
- **ACL 只按窗口 label**：同窗内的不同插件不再细分（B 批做插件级信任时再细化）。

### 5.4 施工中改主意的一处（口径已同步 §一）

§1.2(3) 原写「反注册时把 `currentView` 回落到剩余首个视图」——**施工时判定不做**：`viewComponent` 是组件引用、面板不会崩，而项目切换的「先清后建」路径会因此把选中打空（回归）；且夺选中属用户可见路径变更。现口径 = 镜像**纯**同步；要「删视图即切走」由删除方显式 `uiStore.setView(...)`（B 批拆装面板一并处理）。

### 5.5 走查清单（用户亲测）

1. **基本形态**：打开应用（Agent 空间）→ 点窗口栏胶囊切到「工作台」→ 产品域应照常工作（侧栏、项目切换器、各视图都在）。

3. **顺序偏好**：在侧栏拖动调序 → 切到 Agent 空间 → 再切回工作台：顺序与当前视图保持。
4. **芽启停（顺序不丢）**：设置里关掉一个芽（如「思维导图」）→ 该视图从侧栏消失；重新打开 → 回来且**位置不变**。

### 5.6 遗留与后续（不阻塞本批）

- **能力桥是内存态**：工作台窗刷新/重建后由页面脚本重跑重登记（现由 `workspace/main.ts` 无条件登记）；页面加载失败时 Agent 侧调用报 `UNKNOWN`（可辨）。
- **ACL 粒度 = 窗口 label**；插件级信任留 B 批。
- **★ `pluginAPI.currentPluginId` 是全局单值**：任何 `pluginAPI.registerView` 都会把视图的 pluginId 覆写成「最后一次 activate 的芽」——第二棵树正式化（B）**必须**做按插件作用域的注册面，否则插件身份错乱（本批 Spike 用显示侧注册绕过、探针手动归零，均为临时口径）。
- **Node 侧接入载体**（让 dsh 工具发起调用）与 **E1 目录口径**仍是 D2 前置（见 §三）。
