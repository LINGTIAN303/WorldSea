# C2 批计划（批量迁芽：25 个官方芽按插件模型迁入第二棵树，三区分批）

> **来源**：用户 2026-09-25 走查 C 通过后「开始批量迁吧」。**四项裁定**：
> ① 启停 UI = **沿用芽面板**（树装载器按芽清单过滤，且升级为**真启停**：切换即装/卸插件，不再只是隐藏视图）
> ② 切分 = **三区分批提交**：①10 轻芽 ②11 实体系 ③4 布局/特殊
> ③ 插件注册面 = **树自持作用域化 API**（`apply(ctx, api)`，锁到插件 id）
> ④ 旧芽机器 = **全部迁完后当轮删**（PluginManager / PluginSandbox / plugin-manifest / bootstrap 装载段）。

## 一、现状（已核实）

- 剩 25 芽 / **302 文件 / 约 5.0 万行**（`apps/tauri/src/sprouts/official/**`）。入口注册面：**全部 `registerView`**；除 `apparel/weapons/graph/custom` 外**都注册实体类型**（`registerEntityV2`；`tactical-board`/`workflow` 用旧版 `registerEntityType`；`items` 多一枚 `registerFacet`）。
- **无任何剩余芽带 `agent-descriptor.ts`**（mindmap 是唯一一个，C 批已迁）→ 代理面只需保持 `worldview` 的 actions/guides 不动。
- 旧机器：`plugins/{bootstrap,PluginManager,PluginSandbox,plugin-manifest}.ts` + `PluginManager.preRegisterAllEntityTypes`（20 条硬编码实体系，保证「芽未激活也能查关系」）。

## 二、关键机制决定（本批新增基建）

1. **树自持插件 API**（`world/api.ts`）：`apply(ctx, api)`，`api` 全作用域化——
   `api.registerView(view)` · `api.registerEntityType({type,label,icon?,traits,ownFields,facets?})`（V2 口径）· `api.registerRelationType(schema)` · `api.registerFacet(facet)` · `api.capabilities.register(caps)`。
   实现 = 逐项包 `pluginAPI.withPluginScope(pluginId, …)`；**视图与能力自动登记反注册清理**（插件作者不必记）；**实体/关系类型不随卸插件注销**（沿用旧语义：类型元数据长期可查，避免关系查询断裂）。
2. **插件 id 沿用原芽 id（`official.*`）**：芽清单行、`isViewVisible`、世界观 actions/guides 的键、设置面板全部**零改动**；新插件（非芽来源）仍用 `ws.*`。（mindmap 已是 `ws.mindmap`，保持不动。）
3. **真启停**：`world/index.ts`（应用侧）读 `settingsStore.isActive(id)` 作为过滤 + 订阅芽清单变化 → 动态装/卸对应插件（卸载走 `runPluginCleanups` + fiber dispose + 能力撤登记；实体类型按 §二.1 保留）。树 `tree.ts` 增加 `loadPlugin(plugin)` / `unloadPlugin(id)`（幂等）。
4. **预注册面**（施工时**收缩**）：原计划「清单声明 `providesEntityTypes` + 起树预注册」——施工核实 `PluginManager.preRegisteredTypes` 是**内部死账本**（`isTypePreRegistered/isTypeActive` 全仓**零消费方**，其 `active` 标记也没人读）→ **不做**该机制；类型注册沿用「装载时注册、卸载不注销」，与旧行为**实际等价**（旧机制也没真正注册任何东西到 registry）。
5. **装载器**：`assemblePlugins(candidates, services, { isEnabled })` —— 未激活的插件**不装载**（但参与预注册）；清单非法/依赖缺失照样拒并留痕。

## 六、边界与遗留

- **代理面**：`worldview` 的 actions/guides（键为 `official.*`）不动；mindmap 的 5 条桥能力已是新面。
- **不做**：插件沙箱/权限运行时门禁（新 API 以**类型面**代替；信任模型留后续）；清单外部投放。
- **风险点**：① 302 文件搬迁要让 arch 基线逐条改径（机械但量大）② `PluginManager` 删除时须确认无其它消费者（`viewSync`/`useProjectSwitcher` 的接线已在 B/C 批收敛过）③ 实体预注册表从硬编码迁到清单声明时，**逐芽核对 20 条类型不漏**（有单测守）。
