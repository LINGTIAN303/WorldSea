# 表现形式写入交互规格

> 立项（2026-10-19）：用户核对发现——**7 种表现形式里 4 种纯只读、3 种可编辑但「写入」这件事从来没被系统定义过**；
> 计划文档只散落过一句「双击就地编辑」，没有回答「每种形式谁写、在哪写、写什么字段、空态怎么引导」。
> 本文补这个缺口：先定三档模型，再逐形式落定义，缺口收敛为 3 个待拍板问句。

## 一、问题陈述

| 事实 | 取证 |
| --- | --- |
| 7 种形式中 **3 种可写**、**4 种纯只读** | 右键菜单/注册表：标题式、树式、句子式标「可编辑」；表格式、线索式、进度式、关联实体标「只读」 |
| 可写的 3 种**只写 2 个字段** | 标题式 → `name`；句子式 → `description`；树式 → 该行节点 `name` |
| 只读的 4 种**没有任何写入入口** | 表格式/线索式/进度式的数据源是节点字段或统计；关联实体是关系表 |
| **写入交互形态无文档** | 表现形式规格只写了「双击就地编辑」，未覆盖只读形式的写入路径 |
| 空态只说明「没什么」，不说明「去哪写」 | 卡片空态：`暂无线索（在属性面板的「节点属性」里填「所属线索」）` 是唯一带引导的一条 |

## 二、三档模型（本文的核心约定）

| 档位 | 语义 | 触发方式 | 写入落点 |
| --- | --- | --- | --- |
| **就地编辑** | 形式本身就是编辑器 | 双击内容区 | 直接写节点字段（防抖 + `{skipUndo}` + 白板撤销栈一步） |
| **面板编辑** | 形式是「视图」，写入口在别处 | 形式内提供「管理」入口 → 打开编辑面板/节点详情 | 经各自的唯一写入入口（如 `chapterLink`、`outlineLinks`） |
| **纯派生只读** | 数据从别处派生，本形式无写语义 | 不提供写入 | 无（读侧只做聚合与跳转） |

**判定规则（新增形式必须回答）**：

1. 它承载的是**单个节点的字段**吗？→ 是 → 就地编辑（双击）。
2. 它聚合的是**多个节点/多条关系**吗？→ 是 → 面板编辑（形式内给「管理」入口，不当场改）。
3. 它的数据完全由**别处写入的结果**决定吗？→ 是 → 纯派生只读，但**必须给一句「去哪写」的引导**。

## 三、逐形式定义

| 形式 | 档位 | 写入字段 / 操作 | 当前实现 | 缺口 |
| --- | --- | --- | --- | --- |
| 标题式 `title` | 就地 | `name`（+ 层级/编号为只读派生） | ✅ 双击 → input，Enter 提交 / Esc 回滚，400ms 防抖 | 无 |
| 句子式 `sentence` | 就地 | `description`（软上限 120 字） | ✅ 双击 → input | 无 |
| 树式 `tree` | 就地 | 双击**某一行** → 该行节点 `name` | ✅ 行内 input | 行内只改名字；增删子节点仍走画布/右栏 |
| 表格式 `table` | **待定** | 行 = 节点；可写的是每行节点的字段 | ⚠️ 纯只读 | **Q1：要不要行内双击改名 / 面板增删行** |
| 线索式 `storyline` | 面板 | `storylines`（顿号分隔） | ⚠️ 只读；写入口在节点详情「所属线索」 | **Q2：形式内是否需要一个「管理线索」入口** |
| 进度式 `progress` | 纯只读 | `status` / `wordCount` | ✅ 只读（数据源在节点详情可改） | 空态缺「去哪写」引导 |
| 关联实体 `refs` | 纯只读 | 关系表（跨芽三条） | ✅ 只读；写入口在节点详情「关联实体」区 | 空态文案已改中性，缺「去哪写」引导 |

### 3.1 就地编辑的统一契约（已实现，作为后续形式的模板）

- **进入**：双击内容区（`@dblclick.stop`），自动聚焦并全选。
- **提交**：Enter / 失焦；**回滚**：Esc（显式写回会话起点值，防抖已落库的中间值也会被纠正）。
- **落库**：400ms 防抖 + `{ skipUndo: true }`（内容改动不进实体全局栈）。
- **撤销**：一次编辑会话 = 白板栈**一步**（`recordContentEdit`），中间防抖不占步。
- **切容器**：`watch(nodeId)` 退出编辑态，避免把 A 的草稿写到 B。

## 四、缺口清单

1. **表格式没有任何写入路径**——它是「多节点视图」，但用户看到表格的第一反应是「改这一格」。
2. **线索式的写入藏得太深**：用户要先去节点详情、找到「所属线索」、手动输入顿号分隔的字符串。
3. **空态只报「没有」，不报「去哪加」**：4 个只读形式中只有线索式有半句引导。
4. **"可编辑"标签与实际能力不一致**：树式标可编辑，但只能改行标题，不能增删行——标签应更精确（「可编辑（仅标题）」）。

> **✅ 三项已拍板（2026-10-19）**：**Q1-B**（表格式＝面板编辑）· **Q2-B**（线索式形式内加「管理线索」）· **Q3-A**（空态可点击直达写入位置）。以下问句保留以存历史。

## 五、待拍板

  - A 行内双击改名（与就地编辑一致，最小改动）
  - B 面板编辑（表格式只读，编辑面板里增删行 / 改字段）
