## 二、关键设计决策（调研结论）

### 2.1 派生解析器＝轻量语法感知扫描器（不构造编辑器实例）

- **正则同源**：复用 noteLinkExt tokenizer 的同一正则 `/\[\[([^\[\]\n]+)\]\]/`（导出共享常量），保证「扫描器认得的」与「编辑器认得的」是同一套；
- **语法感知**：逐行扫描 + **围栏状态机**（``` / ~~~ 区间跳过）+ **行内反引号对跳过**——与 contentNormalize 的围栏状态机同思路（先例：`repairTableBlankLines`）。目标：代码块内 `[[名]]` 不被误认为引用（编辑器重解析后代码块内就是裸文本）；
- **不构造无头编辑器**：保存后高频跑（每次落库）+ 进视图全量跑（N 篇），构造编辑器实例（~10-50ms/篇）不可接受；轻量扫描为 µs–ms 级/篇；
- **转义形态天然排除**：已转义的 `\[\[X\]\]`（字符间夹反斜杠）不满足连续 `[[` 序列，正则不命中——与「未命中不建关系」语义一致；
- **契约测试对冲**：扫描器 vs 编辑器解析的边界 case 矩阵（fence / 行内反引号 / 转义 / 嵌套 / 多行 / trim 语义）。

### 2.2 重算 ＝ diff（语义等价「全删重插」+ 无变化短路）

- 目标集合：`extractNoteRefs(md)` → 逐名 `resolveNoteRef`（唯一命中取 id；miss/ambig 跳过）→ id 集合；
- 现集合：`note_link && sourceId=该笔记`（forward）及其 pair（reverse）；
- 执行：diff 增删（新增 = createBidirectional 同形态两条；删除 = 成对删）；**无变化 → 零写入短路**；
- **幂等可重放**：同输入重复执行结果一致（崩溃残留、重复触发均自愈）；
- **串行队列**：模块级 `Map<noteId, Promise>` 链——同笔记重算按到达顺序排队，杜绝交错写（防止「保存 A → 重算中 → 二次保存 → 双跑交错」）。

### 2.3 派生写入＝无撤销通道（系统行为不进撤销栈）

- 派生是**系统行为**（非用户操作）：若进撤销栈，打字保存会瞬间冲掉全局撤销历史（与「逐键写库」同型缺陷，已有实证）；
- 方案：`relationStore` 的 `add/remove` 补 `opts?: { skipUndo?: boolean }`（对齐 entityStore.update 既有模式）——最小侵入；派生器全部走 skipUndo；
- 用户可感知的撤销仍成立：文本层 TipTap undo → 保存 → 重算 → 关系随内容收敛。

### 2.4 三时机接入（对协议「启动增量扫描」的强化替代）

| 时机 | 挂点 | 粒度 | 说明 |
|---|---|---|---|
| ① 保存后 | `useNoteEditor.flushSave` 尾（persistContent 成功后） | 单笔记 | 编辑即派生（300ms 防抖后）；失败不重算 |
| ② 装载时 | `useNoteEditor.loadNote` 装载分支后（fire-and-forget） | 单笔记 | 修正「装载前被外部改过」的陈旧关系（Agent 写入等） |
| ③ 进视图 | `NotebookView onMounted`（替代 migrateBacklinks 挂点） | **全量 + diff 短路** | 无状态自愈：所有漂移（外部改动 / 崩溃残留）进视图即修复 |

- **关于协议「启动增量扫描（扫 updatedAt > 上次扫描点）」**：本设计**不引入扫描点状态**，改用「进视图全量重算 + 无变化零写入」——更强（全量覆盖 vs 增量防遗漏；无状态 vs 需维护扫描点）；成本＝N 篇纯内存扫描（100 篇 ≈ 几十 ms 级），笔记量增长（>1000 篇）后再评估增量优化（留档项）。同理不挂 App 启动（消费方在笔记本视图内，进视图已覆盖）。
- **全量重算即首次迁移**：旧 picker 建的「无内容关系」在首轮全量重算中自然清除（符合裁决 G2 语义）；`migrateBacklinks` 函数退役（旧字段清理由全量重算覆盖，见 §2.6）。

### 2.5 引用重写器（裁决 D：全库重写 S-1）

- **触发检测**：`flushPendingWrites` 落库时对比 `changes.name` 与 `live.name`——有变化进入改名流程；
- **原子化（单条撤销）**：`asSingleUndoStep('重命名笔记「X → Y」+ 重写 N 处引用')` 包住「改名 update + 全部受影响的 content 重写」——一次 Ctrl+Z 整体回退；
- **替换规则**：扫描器定位各笔记的引用区间 → 对 `trim(raw) === 旧名` 的 `[[raw]]` **整体替换为 `[[新名]]`**（顺带规范化空格形态）；代码块/反引号区跳过；转义形态（`\[\[`）不匹配天然不动（「从来不是链接」的文本不重写）；
- **打开中笔记的边界**：本应用单笔记打开（改名时打开的就是被改名者）——受影响的其他笔记均未打开，直接写存储即可；被改名笔记**自引用**场景：重写触发 store update → 载荷回流，编辑器非持焦且内容不同 → `setContent` 重载（光标重置影响面：焦点此刻在标题框，可接受；回归锁定）；
- **重写后重算**：对所有被重写的笔记执行 §2.2 重算（内容变 → 关系重导）；被改名笔记自身无需重算（关系存 id 不存名）；
- mention 侧实体改名重写＝**非目标**（协议 §3.5「未来」），一期不做。

### 2.6 旧账清理（字段/入口退役）

- **picker 退役**：BacklinkPanel「创建链接」按钮 + link picker UI + `createLink` 删除（建联唯一入口＝正文 `[[`，弹层保留）——**已拍板：移除**；
- **弹层落库步骤退役**：`useNoteEditor.onNoteLinkInsert` 的 `linkCurrentTo` 删除（插入内容即可，建联交给保存派生）；
- **`resolveNoteByName` 升级**：抽为共享 `resolveNoteRef(name)` → `{ kind:'hit', id } | { kind:'miss' } | { kind:'ambiguous', ids }`（歧义信息显性化，供派生跳过 + 未来 UI）；noteLinkExt.parseMarkdown 复用（行为不变：非 hit 一律字面）；
- **schema 退役**：`notebook/index.ts` 移除 `backlinks`/`forwardLinks`/`linkedEntities` 三字段声明；`NotebookView` 创建初始化的 `linkedEntities: []` 与 `types.ts` 旧字段类型同步清理；现有实体 properties 里的旧字段值**不主动清理**（无 UI 露出即可，避免无谓写放大）——**已拍板：退役**；
- `migrateBacklinks` 函数退役（被全量重算替代）。

### 2.7 歧义态（裁决 E：提示消歧，不自动猜）

- **派生侧（必做）**：`ambiguous` → 不建关系（与 miss 同处置）——不自动猜测；
- **编辑器侧（已拍板：后置）**：现状＝歧义渲染为字面文本（引擎转义 `\[\[X\]\]`）；增强（歧义态高亮 + 候选提示）**后置单开**——一期只做派生正确性（不建关系），聚焦机制切换。
