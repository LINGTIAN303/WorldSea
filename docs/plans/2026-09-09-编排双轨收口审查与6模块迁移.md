### 构图原理（multi-agent 创作编排步骤）

```
┌─────────────────────────────────────────────────────────────────────┐
│  multi-agent 创作编排步骤（B 轨 DefaultOrchestrator）                  │
├─────────────────────────────────────────────────────────────────────┤
│  1. MultiAgentNode("ma"): 读 task.intent，用 decompose_prompt LLM 切分 →  │
│     写入 ma.tasks（车道列表） + ma.task.<id>（车道任务）                   │
│     输出 Spawn(SubgraphRequest::Lanes) 并发所有车道                  │
├─────────────────────────────────────────────────────────────────────┤
│  2. 每个车道：SubAgentWorkerNode（配置 task_key=ma.task.<id>）        │
│              result_key=ma.results.<id>，emit_assigned=false           │
│     读任务 → 委派真实子 Agent → 写结果 ma.results.<id> → Done          │
│     所有车道完成 → 全部 Done 经 return_map 回 MultiAgentNode 父图 →       │
│     沿 Out 边触发 AggregateNode 执行                              │
├─────────────────────────────────────────────────────────────────────┤
│  3. AggregateNode("agg"): 收集全部 ma.results.* → LLM 聚合 →         │
│     写入 result.draft → Done → 步骤结束                             │
└─────────────────────────────────────────────────────────────────────┘
```

**语义对齐设计**：
- **静态切分**：切分一次确定车道，后续每个车道独立并行不通信——区别于群聊会议轮次通信（动态协作）
- **子 Agent 桥接**：每个车道 `i % specs.len()` 轮转取子 Agent 规格 → `SubAgentWorkerNode` 桥接到真实子 Agent → 产出写入聚合键
- **LLM 聚合**：默认启用 `merge_with_llm = true`，输出经过 LLM 对齐融合 → 交付 `result.draft`。
- 转发瘦身：`agent-runtime/src/lib.rs` 删 `pub use supervisor::{...}`（含 `LlmAssignmentStrategy` 等 A 轨专属）；e2e 测试 `e2e_supervisor_orchestration_deepseek` + `StubAssignmentStrategy` 桩随删（A 轨引擎已无验证意义）
- 处置结论：supervisor 的 A 轨形态**彻底消失**（非休眠待删），B 轨 `SupervisorNode` 为唯一实现。m3_tests 的 `orchestrator::supervisor::SupervisorNode` 指向 B 轨，不受影响
