## 一、施工面（按盘点编号）

### 1. 托盘三项收口（#1 监听方懒建 + #2 错窗）

- **真因**：「新建项目 / 最近项目 / 打开设置」的事件监听方在工作台窗 `useSystemBridge`，而工作台窗**懒创建**——没开过工作台时点托盘 = 事件静默丢弃；「打开设置」还先 `show_main_window`（dsh 窗）再 emit，监听方却在隐藏的工作台窗。
- **方案（建议）**：托盘动作**壳内直执行**——先确保工作台窗存在（复用 D1 懒创建逻辑）→ show + focus → 再 emit 事件；错窗随「先建对窗」一并消解。托盘菜单项语义同步核对（「打开 Agent 对话」已随 E8 退役）。

### 2. 托盘「新建项目」语义（#5 语义漂移）

- 现状实为「打开文件夹选择器」。**拍板点 P1**：① 改标签「打开项目文件夹」（最小语义诚实）② 接产品域真「新建项目」（建目录 + 项目列表刷新，动产品域数据层）。

### 3. 菜单动作跟随焦点窗 + 缩放持久（#6 + #7）

- `menu.rs` 刷新/缩放/全屏从硬编码 `get_webview_window("main")` 改**焦点窗优先**（无焦点回落 main）。
- 缩放档位持久化到 `prefs.json`（复用 E2 `app_prefs` 真源模式），两窗各自档位。
- **拍板点 P2**：产品窗要不要补「⋯」入口（现仅 dsh 窗有注入式窗口栏菜单；产品窗有自带 TitleBar 但无刷新/缩放入口）。建议：不补（快捷键跟随焦点窗已可达），登记即可。

### 4. 自启 `--autostart` 分支（#11）

- `lib.rs` 传入的 `--autostart` 全仓无读取。**拍板点 P3**：自启时的启动形态——① 正常显示主窗 ② 启动到托盘（不自动 show，点击托盘再显）。建议 ②（开机自启场景的常规预期）。

### 5. 通知通道（#9 零生产者）

- 两窗 ACL 均放行 `cmd_notify` 但无生产者。**拍板点 P4**：① 本批只做**链路验证**（壳自发一条测试通知，证明端到端通），生产语义（Agent 长任务完成/空闲通知）留给 D2 的反向事件通道设计——**建议此项**（通知时机依赖 dsh 会话状态感知，属 D2 事件通道范畴；且 dsh 侧派发需动 fork，违背零改动口径）② 本批接壳侧最小版（管道空闲 N 分钟 → 通知）。

### 6. 设置面空分组显式登记（#8 + #10 尾项）

- 盘点产品 `SettingsDialog` 现存分组，无消费者的分组收掉或标注「到 Agent 面设置修改」（E4 已删 Agent Tab，剩余分组逐个核）。轻改。

### 7. 打包产物落位（D1 R1 尾项）

- dev 口径 = `<crate>/../workspace-dist`（运行时 `fs::read`，`WORLDSEA_WORKSPACE_DIST` 可覆盖）。**拍板点 P5**：打包形态产物从哪读——① **tauri bundle resources 嵌入**（`resource_dir()/workspace-dist`，单安装包分发省心——建议）② 安装到数据目录（支持产物热替换不重装壳）。连带：`pnpm build` 已能出 MSI/NSIS（E8 门禁），**是否将安装包作为常规交付物**一并确认。
