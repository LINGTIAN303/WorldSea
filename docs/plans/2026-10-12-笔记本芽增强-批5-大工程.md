## 三、I7：图片交互（宽度/对齐/alt）

**方案取舍**：自研 Vue NodeView（原计划）→ 官方 Image 3.2 已内置 `resize` 引擎（`ResizableNodeView`，源码实证：四角手柄、等比 `alwaysPreserveAspectRatio`、触摸、拖拽中实时预览、onCommit 写 width+height）→ **宽度拖拽零自研**，只补对齐与 alt。

| 层 | 实现 |
|---|---|
| 扩展 | `composables/notebookImage.ts`：`NotebookImage = Image.extend(...)`。新增 `align` 属性（parseHTML：`data-align` 优先、历史 `align` 属性兼容、非法值拒收）；`renderHTML` 合成对齐 style（display:block + margin auto）——**落库 HTML 自带样式**，预览端及其它 HTML 渲染端无需共享 CSS 即可正确显示 |
| 编辑端渲染 | NodeView 把 `data-align` setAttribute 到 img → prose.css `img[data-align=…]` 规则渲染（两端口径见 notebookImage.ts 头注释） |
| 工具栏 | NotebookTipTapEditor「图片上下文组」（`v-if="onImage"`）：对齐三钮（再点取消回原样）+ alt 输入（change/Enter 提交） |
| 手柄样式 | prose.css `[data-resize-handle]`：12px 圆点（主题色），中心落在图片角点（translate 半出），hover/选中/拖拽中显现 |
| 落库形态 | `<img src alt width="300" height="200" data-align="center" style="display: block; margin-left: auto; margin-right: auto;">`——width/height 数字属性（官方 resize 落库）+ data-align 语义属性 + style（合成）。**DOMPurify 全保留（实验实锤）**，sanitize 直渲染路径不受损 |
| 图标 | lucideMap 新增 `align-left/align-center/align-right`（lucide TextAlignStart/Center/End） |

**关键实现事实**：
- NodeView 的 HTMLAttributes 只跑**各属性自己的 renderHTML**（不含节点级 renderHTML 的 style 合成）→ 编辑端对齐必须走 data-align + CSS，不能靠 style（该结论由官方源码锁定，双端口径由此而来）。
- resize 后 `el.style.width` 内联 + prose.css `max-width:100%` 共同约束，窄容器不溢出。
- 官方 resize 的 NodeView 包裹后选中类 `ProseMirror-selectednode` 落在 container 上——选中高亮选择器已对应更新。

## 四、V4：块级拖拽手柄 + 快捷菜单

| 层 | 实现 |
|---|---|
| 逻辑层 | `composables/blockHandle.ts`：`findTopBlock`（任意位置 → 顶层块；嵌套列表/表格归其容器）、`moveBlockBy`（相邻交换，一次 `replaceWith` 重排两兄弟）、`duplicateBlock`、`deleteBlock`、`blockSlice`（开区间单节点 slice）——纯函数，可测 |
| 视图层 | `components/BlockHandleLayer.vue`：挂在 `.nb-tt-wrap`（定位锚层惯例，与 TOC 同层）；mousemove（rAF 节流）→ `posAtCoords` → 手柄定位于块左外侧；滚动捕获重算；隐藏延时 260ms（手柄/菜单 hover 保持） |
| 拖拽 | **PM 外部拖拽源模式**：手柄 `dragstart` 设 `view.dragging = { slice, move: true }` → drop 由 PM 内置处理（移动语义：先插后删源）；落点指示线 = StarterKit 自带 Dropcursor（其 dragover 无条件响应 + 读 `view.dragging.slice` 精确定位——**无需 dragstart 发生在编辑器内**，prosemirror-dropcursor@1.8.3 源码实证）；拖拽预览图 = 源块截图（`setDragImage`），源块淡化 `.nb-block-dragging` |
| 快捷菜单 | 点手柄展开：复制块 / 上移 / 下移 / 删除块（危险色）；点击层外/Esc/动作后关闭 |
| 守则 | 空文本块（含拖尾空段）不显示手柄；atom 块（hr/图片）照常；菜单/拖拽期间锁定 hover 更新；预览态不挂载 |

**交互边界**：仅顶层块（doc 直接子级）；列表项级手柄不做（Notion 有，一期从简）；与图片四角 resize 手柄共存（互不干扰）。

**可见性增强（走查反馈「手柄不太明显」→ 增强一轮）**：① 悬停块整块淡背景 `.nb-block-hover`（Notion 式块指示）——`setHoverBg` 随 hover 块迁移（place() 内随 nodeDOM 刷新，hideNow/unbind 清除），CSS 用 `color-mix(in srgb, var(--color-text-primary) 6%, transparent)` 按主题自适应（亮=6% 墨色/暗=6% 亮色），过渡声明在 `.ws-nb-prose > *` 基态（增删两侧都淡入淡出）；② 手柄图标 xs→sm（14→16px）、基色 tertiary→secondary、hover 到 primary；③ 兜底：类直接落 img 上时不裁圆角。

## 五、F5：大文档性能（量化 → 修复）

**基准**：`__tests__/notebookPerf.bench.ts`（vitest bench，五链路 × 10k/50k 双规模；跑法见文件头）。

**量化结果**（2026-10-12，jsdom）：

| 链路 | 10k 字符 | 50k 字符 |
|---|---|---|
| normalizeNoteContent（装载归一） | 0.32ms | 1.6ms |
| setContent（装载进编辑器） | 12.3ms | 50.9ms |
| 单键输入对（transaction + view 管线） | 1.31ms | 2.21ms |
| **getHTML（全量序列化）** | **7.1ms** | **37.6ms** |
| sanitize(getHTML)（预览刷新，已 250ms 防抖） | 18.3ms | 89.2ms |
| getText（字数统计） | ~0.4ms | ~1.5ms |

**头号瓶颈实锤**：`onUpdate` 每键 `ed.getHTML()`（下游仅是 NotebookEditor 的本地 ref 同步，无实时性依赖）——大文档打字延迟的主项。

**修复**：`useNoteEditor` 的 contentChange 从「每键」挪到 `flushSave`（300ms 防抖，与落库同帧）+ 卸载路径补发（防抖窗口内切走/切类型时下游仍拿最新）。

**端到端对照**（bench 同跑验证）：

| 每键成本 | 旧 onUpdate | 新 onUpdate | 提速 |
|---|---|---|---|
| 10k 文档 | 8.9ms | 1.21ms | **7.4x** |
| 50k 文档 | 36.6ms | 2.6ms | **30.3x** |

**已达标不再动**：预览刷新（250ms 防抖；50k 极端规模下单次 89ms 属可接受，若真机 50k+ 文档分栏打字仍有顿挫，候选优化 = 预览刷新间隔自适应）；装载（打开笔记一次性 12/51ms）；归一（亚毫秒级）。

**已知环境注记**：`vitest bench` 不带 `--run` 会进 watch 模式（挂住不退）；bench 模式不支持 `--reporter=basic`。

## 六、上下文响应基建（V4/I7 附带）

工具栏上下文组（表格/图片）此前依赖「输入触发 re-render」的顺风车（saveStatus/wordCount 变化）——**点选节点/光标移动不触发**（隐性失效）。现由 `toolbarTick`（transaction 驱动）显式响应；表格组 `v-if` 同步收敛为 `inTable` computed。打字路径本就有 wordCount 触发 re-render，此 tick 不增加实际渲染成本。

## 七、设计决策记录

1. **I7 用官方 resize 而非自研 NodeView**：官方引擎已覆盖宽度拖拽全部难点（等比/触摸/commit）；自研仅剩的增量（对齐/alt）用「工具栏上下文组」承接，比浮动工具栏少一套定位/跟随/层级问题（与表格组同模式，风格统一）。
2. **V4 自研而非引社区扩展**：TipTap 官方 drag handle 属付费 Pro；社区等价物需新增依赖（本机 pnpm 安装有既知限制），且 PM 外部拖拽源模式文档充分（view.dragging + Dropcursor 免费落点线），自研代码量可控（逻辑层 ~100 行 + 视图层 ~230 行）。
3. **落库双形态（属性 + style）**：width/height/data-align 语义属性 + 合成 style 并写——语义端可解析往返，样式端让任意 HTML 渲染端（预览/未来导出）无需共享 CSS。
