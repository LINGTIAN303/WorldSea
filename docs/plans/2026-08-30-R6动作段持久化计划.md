# R6 动作段持久化缺口立项

> 起源：[2026-08-29-stream-render-layer-plan.md](./已完成/2026-08-29-stream-render-layer-plan.md) §六 R6——
> 用户明确「整个会话都要持久化」，但 6 类动作段事件仅存前端内存、回源即失。
> 定性：**后端事件转发 + 持久化联动**改造，独立于渲染层计划。

## 一、缺口盘点（走查实证）

| 动作段 | 事件源 | 现状 | 回源 |
|---|---|---|---|
| `tool` | ToolCallStart/End（tools.rs） | ✅ 已转发已持久化（tool_calls + toolresult 消息） | ✅ |
| `plan` | PlanCreated/StepUpdate/Replanned | ✅ get_state 快照携带 | ✅ |
| `subagent` | SubAgentStarted/Completed/Error | ❌ 前端内存 `subAgents` | ✗ |
| `a2ui` | A2UIEvent | ❌ 前端内存 `a2uiSurfaces` | ✗ |
| `confirm` | ConfirmationRequested/Resolved | ⚠️ 交互态，历史无需完整还原 | 部分 |
| `phase` | TracePipeStarted/PhaseEntered/PhaseResult/PipeFinished | ❌ 前端内存 `useOrchestrationTrace` | ✗ |
| `router` | RouterDecisionMade | ❌ 未转发至前端 | ✗ |
| `reflection` | ReflectionResult | ❌ 前端未消费 | ✗ |
| **thinking** | PromptResponse.reasoning | ✅ M3 冒烟轮已补（meta.thinking） | ✅ |

- [ ] 第二部分：持久化载体（`meta.action_events` 数组并入 msg_json，推荐先行）
- [ ] 第三部分：前端回源翻译（rebuildFromMessages 增 action_event → TurnEvent；handleStreamEvent 增消费）

## 三、方案骨架（待细化）

1. **转发补齐**（apps/tauri/src-tauri/src/commands.rs）：`_ => return` 白名单扩展——
   SubAgent*/A2UI/Phase*/RouterDecisionMade/ReflectionResult 五组事件进 SSE/app.emit 通道；
   复用渲染层计划 T6 的「双发去重」经验（genai 侧与 tools.rs 侧只取权威一份）。
2. **持久化载体**：动作段事件不走 `messages` 表（非对话消息）——新表
   `action_events(session_id, seq, kind, payload_json, created_at)` 或并入
   msg_json 的 `meta.action_events` 数组（零迁移，推荐先行）。
   回源顺序严格对齐实时流（事件序 = 时间序）。
3. **前端回源**（turnModel.ts）：`rebuildFromMessages` 增补动作段事件翻译
   （对齐 `classifyActionRowKind` 六类：subagent/a2ui/phase→其他段，router→决策段）；
   实时路径 handleStreamEvent 增对应 TurnEvent。
4. **口径统一**（冒烟新发现）：深度思考模式下路由器 JSON 决策（`{"target_id":"query",…}`）
   泄漏为过程文本段——应在事件面将路由决策归 `router` 动作段而非 text_delta。

## 三、验收

- 发起含子代理/编排阶段/路由的会话 → 刷新 → 六类行段全部回源重建；
- 回源态与实时态 DOM 结构一致（复用渲染层计划「两套 DOM」验收方法）；
- 全量测试绿 + 浏览器/桌面双端冒烟截图。

## 四、规模预估

后端转发 1 天、持久化 1 天、前端回源 1-2 天、冒烟 0.5 天——建议独立会话执行，
不与编排链路工作混线。
