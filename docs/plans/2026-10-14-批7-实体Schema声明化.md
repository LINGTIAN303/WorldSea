# 批 7 · 实体 Schema 声明化（字段/traits 数据外置，Agent 运行时可编辑）

> **来源**：2026-10-14 插件细粒度讨论收口——用户拍板：A「inject 式服务依赖声明」**挂账**（无真实插件间服务协作需求，对齐批4「AppMenu 贡献位」挂账先例）；B「实体字段声明化」**立项**，口径 4 决策点当场确认。
> **盘点证据**（同日实读）：GenericEntityView（plugin-sdk）为 16/26 芽视图共享骨架、输入全声明式；SchemaRenderer 已打通「registry → 视图」全自动通路；缺口唯一 = schema 声明仍以 .ts 代码内联在插件里（构建期固化，Agent 运行时不可达）。

## 一、现状与缺口

**已立底座（不重建）**：

- **三段全自动通路**：`registerEntityV2` → `compileEntitySchema` → entitySchemaRegistryV2 + entitySchemaRegistry 双写（[PluginAPI.ts](../../packages/entity-core/src/core/PluginAPI.ts#L102-L125)）→ [SchemaRenderer](../../packages/plugin-sdk/src/components/SchemaRenderer.vue) 按 typeKey 读 registry 派生视图 props（含预留的 `schemaLoader` 异步加载口子）→ [GenericEntityView](../../packages/plugin-sdk/src/components/GenericEntityView.vue) 声明式渲染（列表/筛选/排序/详情全数据驱动）
- **热装载通道**：watcher `.worldsea/plugins/` 分类 + `onPluginDirChange` 回调面（批1）——schema 目录复制同构
- **重填语义现成**：TraitRuntime「项目切换清空；重激活经 registerEntityV2 重填」
- **覆盖面**：16/26 芽视图走 GEV；其余 10 个为非列表特殊形态（timeline/mindmap/graph/drawing/tactical-board/notebook/orchestration/manuscript/custom/weapons），本批不涉及

**缺口（本批两件半）**：

1. schema 声明外置（.ts 内联 → worlddata 声明式数据，Agent 运行时可改）；
2. 热生效通道（schemas 目录 watcher → 校验 → registry 重填）；
3. （半）双层声明漂移修复——实测 FieldSchema（实体层）与 FormFieldDef（视图层）双轨且已漂移（appearance/tags 仅在视图层声明，实体 schema 层没有）。

## 二、口径（定稿）

| 项 | 定稿 |
|---|---|
| 外置落点 | `worlddata/.worldsea/schemas/<type>.json`（与 plugins/ 同域「内部目录」语义，schema 快照同域） |
| 文件内容 | 单文件单类型：`{ type, label?, icon?, traits?, ownFields?, fieldOverrides?, detailLayout? }` |
| 合并策略 | 内置芽代码内默认 schema（不动）+ 项目级 schema **逐键深合并覆盖**——Agent 只写要改的键；ownFields 数组按 key 匹配（同 key 覆盖、新 key 追加），未知顶层键拒绝 |
| 校验 | 合法 JSON + `type` 与文件名一致 + 字段结构校验（对齐 FieldSchema）；非法 → rejected 记录（console.warn + 管理面可见），其余照常 |
| 生效通道 | watcher `.worldsea/schemas/` 新分类 → 防抖 → 重读 + 重合并 + registry 重填（复用批1 diff/防抖模式，~1s 热生效） |
| 试点 | species（薄芽）+ characters（富定制）各一，验证「纯覆盖」与「覆盖 + 定制共存」两条通路 |
| 归一 | FieldSchema/FormFieldDef 归一与 config 退役 → **第二批**（本批不动视图层声明，范围锁定） |

## 三、施工面（文件级）

1. **entity-core**：schema 合并器（内置默认 ∪ 项目覆盖：逐键深合并 + ownFields 按 key 对齐）+ 校验器（纯函数、注入可测）；[useFsWatcher](../../packages/entity-core/src/composables/useFsWatcher.ts) 新增 `.worldsea/schemas/` 分类 + `onSchemaDirChange` 回调面（对齐 `onPluginDirChange` 先例，entity-core 不反向依赖 world）
2. **world 侧**：`world/schemas.ts`（新）——`collectProjectSchemas`（注入式 IO，默认走 cmd_fs_*）+ diff 重对账（新增装载/变更重填/消失回落内置）+ `reloadProjectSchemas()`；[world/index.ts](../../apps/tauri/src/world/index.ts) watcher 订阅接线
3. **registry 重填**：合并后 schema 经既有 `registerEntityV2` 兼容层双写（pluginId 标记 project-scope，项目切换清空语义不变）
4. **dsh 工具**：`world_schema_*` 四件（list/read/write/delete；write 原子写 + 轻校验；对齐 world_plugin_* 先例与错误码三段式）——落 [apps/dsh-plugin-worldsea/lib/index.js](../../apps/dsh-plugin-worldsea/lib/index.js)
5. **试点接线**：species/characters **零代码改动**（合并发生在外层）；characters 附带修复漂移——appearance/tags 升入正式 ownFields（施工时定夺，属其正式字段则升、纯视图配置则显式标注）
6. **测试**：合并/校验单测（深合并口径锁死）、watcher 通道 spec（对齐 external.spec 模式）、dsh 工具 spec（对齐 plugin-tools.spec 模式）

## 四、验收门

- vue-tsc 0 · vitest 全量 · cargo 不动（零 Rust 改动——读写走既有 cmd_fs_*）· workspace-dist 重建（走查前必须）。
- **真机走查清单**：
  1. Agent 执行 `world_schema_write` 给 species 加一个字段 → ~1s 内视图热生效（表单/筛选出现新字段）；
  2. 修改 fieldOverrides 标签 → 生效；
  3. 写入非法 schema（坏 JSON / 字段结构错）→ rejected 可见，其他 schema 不受影响；
  4. 删除 schema 文件 → 回落到内置默认；
  5. 切换项目 → schema 覆盖跟随项目（另一项目无此覆盖）；
  6. 重启应用 → 项目 schema 自动重装载；
  7. characters 回归：家谱/装备等定制页签不受 schema 覆盖影响。

## 五、边界（本批不做）

- FieldSchema/FormFieldDef 归一与 config 退役（第二批）；GEV 覆盖面扩至其余 10 个特殊形态芽；schema 的 ACL/能力细分；跨项目 schema 导入导出；dsh 侧以外的 Agent 通道；非 GEV 视图（特殊形态）的字段消费改造。

## 六、风险

| 风险 | 处置 |
|---|---|
| 深合并语义争议（数组按 key 还是整体替换） | 施工首日定死口径并写单测锁死：ownFields 按 key 匹配、同 key 覆盖 / 新 key 追加 |
| 项目覆盖与内置默认类型冲突（如 select 改 text） | 校验器拒绝该键 + rejected 可见，回落内置默认 |
| SchemaRenderer 旧版契约（EntityTypeSchema）与 V2 类型漂移 | 合并输出经既有 registerEntityV2 兼容层双写（该兼容层已实证可用） |
| Agent 写一半文件被 watcher 捕获 | 原子写（临时文件 + 同卷 rename）+ 失败隔离；下次变更自愈（对齐批1 处置） |
