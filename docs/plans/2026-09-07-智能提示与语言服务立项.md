## 一、背景与约束

- 编辑器内核二期收官（CM6 + minimap 定版），原挂起两项（TS 提示 / LSP）转正；讨论中新增 **JSON Schema 字段提示**线（方案 D），用户确认三线全铺。
- **红线约束（方案取舍第一判据，2026-09-07 二轮校准口径）**：① 用户数据全程本地（世界观/会话/文件不上传）；② 除 LLM 推理 API（既定联网点）外，功能面不引入新的云端依赖；③ 分发形态 = 单二进制免安装。**注意口径不是"整机断网可用"**——Agent 联网调模型不受此约束；判断标准是"是否新增云端依赖 / 是否破坏单二进制"，不是"是否触网"。

## 二、三线分期总览

| 期 | 线 | 一句话 | 前端产物增量 | 工程量 | 部署冲突 |
|---|---|---|---|---|---|
| 一 | **D：JSON Schema 字段提示** | 世界观结构化 JSON 编辑获得字段补全/描述悬停/schema 诊断 | ~100KB 级 | 小 | 无 |
| 二 | **A：TS 类型级智能提示** | 浏览器内 TypeScript 引擎，.ts/.js 获得类型补全/悬停/诊断/跳转 | +8~9MB（gzip +2~3MB）+ lib.d.ts ~1MB | 中 | 无（Worker 随前端打包） |
| 三 | **B1：LSP 外挂检测** | 检测系统已装语言服务器，有则接入项目级智能，无则降级 | +几十KB（客户端包） | 中（大头在 Rust 桥） | 无（零分发） |

**B2（应用内分发 server 二进制）**：server 仍跑用户本机，「云」仅在下载那一刻（GitHub Releases/镜像渠道拉取一次），**不是云端计算服务**；不违反"离线"口径，违反的是单二进制（体积膨胀 + 版本管理复杂化）与开箱体验（无网装不上）。定性=**远期可选增强**（有网时按需下载、缺省无感），当前不做；编程场景主线化且用户出现"无工具链但需 LSP"诉求时重估。

## 三、第一期 D：JSON Schema 字段提示

> **施工完成（2026-09-07，待用户手测）**：`entitySchemaAssist.ts` 三源落地——schema 源复用运行时 `EntityTypeSchema`（`schemaListEntityTypes` 进程级缓存，失败静默回空），匹配键=文件顶层 `"type"` → typeKey；补全（override 独占源：顶层固定键 / properties 字段键 / 值位 options 枚举与 type 的类型列表）+ 悬停（键名显示 label/fieldType/required/placeholder）+ 诊断（linter：顶层未知键 warning、未知字段 warning、缺必填 info，全文 parse 失败静默）。接入 CodeEditor 编辑态 json 语言（minimal 预览态不挂）。依赖：`@codemirror/autocomplete@6.20.3` + `@codemirror/lint@6.9.7`（树内已有实体，junction 显式化，零新增下载）。待验：`codemirror-json-schema` 社区包路线经评估不需要（schema 源非标准 JSON Schema，转换层多余）。

- **范围**：结构化实体 JSON（编辑器内打开时）字段级补全、字段描述悬停、schema 校验诊断（非法字段/缺必填）。自由叙事型 JSON 不套 schema（价值低），按文件类别区分。
- **路线**：schema 源评估复用既有 EntityTypeSchema 统一事实（见大文件拆分计划）；CM6 侧 CompletionSource + lint 映射——社区 `codemirror-json-schema` 包先评估，不合适则自写轻量映射（schema → CM 补全源，工程量可控）。
- **验收**：编辑实体 JSON 时字段补全命中、悬停显示字段描述、非法字段出诊断；无 schema 类文件零回归。

## 五、第三期 B1：LSP 外挂检测

> **施工完成（2026-09-07，待用户手测；走查清单见 [任务/2026-09-07-智能提示B1期走查清单.md](./任务/2026-09-07-智能提示B1期走查清单.md)；含 Rust 桥改动，走查前需重启 cargo 壳）**：
> Rust 侧 `lsp_commands.rs`：`cmd_lsp_detect`（PATH 探测 where/which）+ `cmd_lsp_start`（spawn + stdout 读线程解 Content-Length 帧 emit `lsp-message`）+ `cmd_lsp_send`（封帧写 stdin）+ `cmd_lsp_stop` + `kill_all`（lib.rs `RunEvent::Exit` 退出钩子统一回收防孤儿）。内置映射：rust-analyzer / pyright-langserver / gopls / clangd / typescript-language-server。
> 前端 `lspAssist.ts`：`codemirror-languageserver@1.22.1`（tarball 五件套安装：+marked +vscode-languageserver-protocol/-jsonrpc/-types）自定义 Transport 字符串直通 IPC；server 按语言**常驻**（编辑器卸载不停进程；`autoClose: true` 仅前端摘除）；多文件同 lang 共享 server 多 client。
> **仲裁落地（立项 §六）**：CodeEditor watch 内 `lspAvailable(lang)` → 已装且编辑态有真实 filePath 则 LSP 优先，未装回落 tsAssist（ts/js）或无提示；json 不在候选集（D 期 entityAssist 专管）。
> FilePreview → CodeEditor 新增 `filePath` prop（LSP 按真实路径工作；A 期虚拟文件名路线不受影响）。

- **server 是什么（名词解释）**：LSP（Language Server Protocol，语言服务器协议）= 微软制定的「编辑器 ↔ 语言智能进程」标准协议。每种语言的智能不在编辑器里，而在独立进程：Python=pyright、Rust=rust-analyzer、Go=gopls、C/C++=clangd、TS/JS=typescript-language-server。VSCode 语言插件安装的正是这些 server。
- **外挂检测形态**：打开代码文件时检测系统 PATH（如 `where rust-analyzer`）→ 有则 Rust 侧 spawn 进程、stdio ↔ Tauri IPC 桥接前端 `codemirror-languageserver`（自定义 Transport，该包补全/悬停/诊断/跳转/重命名/格式化全支持、有生产案例）；无则维持现状（语法高亮 + CM6 内置能力），**用户无感**。
- **应用场景**：
  1. 开发者用户机器上本就装着工具链，在 WorldSea 里编辑真实代码工程（含 WorldSea 自身源码）获得项目级跳转/诊断/重命名；
  2. AI Agent 产出多文件代码工程后的审阅与修改场景；
  3. 无工具链的普通用户零影响——这是「零分发」的代价与含义。
- **验收**：已装 server 的机器上获得补全/诊断/跳转；未装机器零回归；进程生命周期（退出/崩溃/超时）不拖垮宿主。
