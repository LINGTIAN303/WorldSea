# R3-a · 芽导航形态批计划（1–4）

> 依据：[芽生态研究 · 05 用户信息架构与建议](../details/架构/芽生态/05-用户信息架构与建议.md) §5.4 / §5.5，用户 2026-10-20 六形态裁定。
> 范围：**先做单侧栏的 1–4 四种形态**；5/6 双栏留到 R3-b。不改收藏/最近、工具域折叠、管理/添加入口。
>
> **执行状态（2026-10-20）**：形态 1–4 已实现；浏览器预览走查通过（含右侧栏浮层翻转、设置即时切换）；待用户真机走查。

## 三、数据与状态

### 3.1 新增持久化状态（`uiStore`）

```ts
type SproutNavMode = 'flat' | 'popover' | 'rail' | 'tabs'
type SproutDomainFilter = 'all' | SproutDomainId

sproutNavMode: SproutNavMode        // 默认 'flat'
sproutDomainFilter: SproutDomainFilter // 默认 'all'
```

- localStorage 键：`worldsea_sprout_nav_mode` / `worldsea_sprout_domain_filter`。
- 加载时归一：未知形态 → `flat`；未知域名 → `all`。
- 形态 1 忽略域过滤，但保留上次选择；切回 2–4 时恢复。

### 3.2 域注册表补图标

`SPROUT_DOMAINS` 的 `SproutDomain` 增加 `icon: string`，8 域各给一个现有 `WsIcon` 图标：

| 域 | 图标 |
|---|---|
| geo | `region` |
| life | `species` |
| society | `organization` |
| knowledge | `concept` |
| goods | `item` |
| time | `timeline` |
| narrative | `manuscript` |
| tool | `tactical` |

「全部」用 `menu`（或 `layers`；视觉走查可改）。

### 3.3 域归视图

新增纯逻辑 `apps/tauri/src/ui/layout/sidebar/sproutNavigation.ts`：

- `domainOfPlugin(pluginId, manifests)`：从 `availablePlugins()` 的 manifest 取 `domain`；取不到 → `unclassified`。
- `buildSproutNavigation(views, domainOf, filter)`：
  - `views` = `visibleViewsInSidebarOrder()`；
  - `filter='all'` → 全部视图；
  - `filter=域名` → 该域视图；
  - 域列表只保留**有可见芽的域**（研究 5.4 规则 1），按 `SPROUT_DOMAINS` 顺序；
  - 「全部」永远第一项，计数 = 全部可见芽；
  - `unclassified` 只在「全部」出现，不进入 8 域列表（R5 再做显式提示）。
- `normalizeSproutDomainFilter(value, knownDomains)`：未知 → `all`。
- `domainOfView(view, domainOf)` / `nextFilterForView(view, currentFilter)`：当前视图变化时，若过滤不是 `all` 且新视图不在当前域，过滤跟随新视图的域（快捷键切换时不出现“主区变了、侧栏无高亮”）。

## 四、组件架构

```text
Shell.vue
 └─ SidebarHost.vue            // 按 sproutNavMode 选择
     ├─ SidebarV2.vue          // 形态 1：原样，不改
     └─ SproutNav.vue          // 形态 2–4 外壳：最小 chrome（收起/底栏/宽度/左右）
         ├─ DomainList.vue     // 域列表（popover / rail / tabs 共用）
         ├─ SproutList.vue     // 域内芽纵向列表（2–4 共用）
         ├─ DomainPopover.vue  // 形态 2：域按钮 + 浮层芽列表
         ├─ DomainRail.vue     // 形态 3：图标窄条 + 芽列表
         └─ DomainTabs.vue     // 形态 4：语义域 / 芽 两个 Tab
```

- `SidebarV2.vue` **零改动**（冻结）；`Shell.vue` 只换 import 与组件名。
- `SproutNav` 自己负责 `.sidebar` 根、收起按钮、底部 `AppMenu`；样式用现有 CSS 变量与最小私有样式，保证与平铺态观感一致。
- 每个新文件 ≤400 行；`sproutNavigation.ts` 纯函数，组件只负责渲染与事件。

## 五、四种形态行为

| 形态 | 域选择器 | 芽列表 | 轮盘 | 域过滤 |
|---|---|---|---|---|
| 1 平铺 | 无 | 现有轮盘 | 保留 | 忽略 |
| 2 弹出层 | 侧栏内纵向域列表；点击域在侧栏旁弹浮层 | 浮层内纵向列表 | 无 | 全部 / 域 |
| 3 图标栏 | 侧栏左侧窄条（约 34px）图标域 | 窄条右侧纵向列表 | 无 | 全部 / 域 |
| 4 Tab | 顶部两 Tab：「语义域」「芽」 | 「芽」Tab 内纵向列表 | 无 | 全部 / 域 |

共同规则：

- 「全部」第一项；8 域只显示有可见芽的域；有计数；当前域高亮；当前芽在可见时高亮。
- 点击域只切过滤，**不自动打开芽**（保持用户“选择域 → 选择芽”的两步模型）；主区保持当前视图，若不在当前域则侧栏无高亮。
- 形态 2 浮层：点击域打开；选芽后关闭；Esc / 点外部关闭；侧栏在右时浮层向左侧展开。复用 `FloatingPanel`（`Teleport to=body` + fixed）或等价浮层。
- 形态 4：默认停在「语义域」Tab；选域后自动切到「芽」Tab；Tab 块在侧栏头部下方，内容区滚动，不改变侧栏收起行为。
- 形态 3：窄条只放图标 + tooltip；芽列表保持侧栏总宽，标签可截断 + `title`。
- 形态 2–4 不做拖拽重排；`sidebarOrder` 域内相对顺序保留。
- 形态切换即时生效；不需要保存/应用按钮（与现有侧栏位置设置同口径）。

## 九、真机走查清单（交付时给用户）

1. 形态 1：与改动前完全一致；侧栏拖拽/滚轮/收起/快捷键不回归。
2. 设置切到形态 2：域列表出现；点击域弹浮层；选芽切视图；Esc/点外部关闭；侧栏在右时浮层向左。

4. 形态 4：默认语义域 Tab；选域自动切芽 Tab；Tab 块不破坏收起/展开。
5. 全部/记住上次域：选「全部」→ 全部芽；选某域 → 刷新/重启后仍在该域；切回形态 1 不受影响。
6. 当前视图不在所选域：主区不跳；侧栏无高亮；点该域内芽才切换。
7. 快捷键切换视图到其它域：若过滤不是「全部」，域过滤跟随新视图的域。
8. 窄窗/左右侧栏：272px/宽窗各看一次；无溢出、无遮挡、无横向滚动。

## 十、风险

1. **`SidebarV2` 冻结**：不能加行；形态 1 原样复用，新形态全部外置；若 `SidebarHost` 导致 Shell 行数增长，优先拆组件。
2. **样式 scoped**：新组件需要最小 chrome 样式；R3-b 做双栏时再抽共享 frame，避免现在动冻结文件。
3. **轮盘只在形态 1**：形态 2–4 用列表，用户可能觉得观感跳；这是本轮明确取舍，走查后可调整。
4. **域列表只显示有芽的域**：空域不可见；激活/管理仍走设置页（研究 5.4 规则 1）。
5. **浮层定位**：左/右侧栏、窄窗、滚动都要测；优先复用 `FloatingPanel`，避免自写定位。
6. **外部 unclassified**：只在「全部」出现；R5 再做显式提示，本轮不新增第九域。
7. **形态配置粒度**：本轮是一个 4 值枚举；若后续想“域选择器”和“芽列表形态”独立组合，再拆成正交设置。
