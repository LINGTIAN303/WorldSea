# C4 · 壳侧工作区取向与「可供给性」批计划（小批）

> 承接：C1/C2/C3 收口（壳载体、零端口传输、壳侧安全面）。本批解决 2026-09-24 插查暴露的**载体侧真问题**：
> 壳 spawn 宿主时 `current_dir` = 仓内 `dsh/` 树（`dsh_shell.rs`），使新会话的默认工作区落在 D: 的引擎树——
> 既非产品语义（工作区应是用户的项目目录），又必然踩 dsh 的 Windows ACL 沙箱前提（目录 ACL 只给 Modify、
> 无 `WRITE_OWNER` → 供给被拒 `Win32 5` → 该工作区里**任何命令都在沙箱初始化阶段失败**，前台后台一视同仁）。
> 事实基线见 §二；机制与证据见记忆 `worldsea-dsh-sandbox-acl-facts.md` 与 `.workbuddy/bg-repro-{1,2}.log`。

## 一、裁定记录（2026-09-24 拍板）

| # | 裁定点 | 结果 |
|---|---|---|
| ① | 壳的默认工作区改到哪 | **用户 profile 下专用工作区**（`%USERPROFILE%\WorldSea`；`WORLDSEA_WORKSPACE` 可覆盖）。用户在 UI 里仍可用「添加工作区」指向自己的项目目录 |
| ② | 可供给性怎么处理 | **检查 + 提示 + 一键修复**：启动时无副作用探针；不可供给 → 系统通知 + 壳日志 + 页面横幅（含修复命令）；另给「修复工作区权限…」菜单动作，**点击才执行** `icacls` 授用户完全控制 |
| ③ | 沙箱模式 | **不动**（维持 dsh 默认 `workspace-write` + 审批 ask）；本批只保证「默认工作区可供给」，不替用户改安全姿态 |

## 二、事实基线（本批开工时的可核查项）

| # | 事实 | 依据 |
|---|---|---|
| F1 | 宿主 `cwd` = 新会话默认工作区来源 | `apps/cli/src/profile-boot.ts:291` 把 `process.cwd()` 作为 profile 上下文传下去；headless 复现里 `grantWrite(D:\WorldSea\dsh)` 即该 cwd |
| F2 | 沙箱供给要求目录上有 `WRITE_OWNER` | dsh 上游 `packages/sandbox/sandbox-windows-acl/README.zh.md`「已验证边界」：*被授权目录必须由调用者拥有并授予 WRITE_OWNER … DACL 只授予 Modify 的目录现在会大声失败* |
| F3 | 本机 D: 盘继承 ACL 只给 `Authenticated Users:(M)` | `icacls D:\ / D:\A` 实测；`D:\WorldSea\dsh` 更甚（显式 ACE、无用户完全控制） |
| F4 | 可供给性可无副作用探测 | 以 `WRITE_OWNER (0x00080000)` + `FILE_FLAG_BACKUP_SEMANTICS` 打开目录句柄：开得成=有该权限，`ACCESS_DENIED (5)`=没有（只做访问检查，不改任何 ACL） |
| F5 | 一键修复的代价 | `icacls <dir> /grant "<用户>:(OI)(CI)F"` 之后 dsh 会在该目录常驻「能力 SID ACE + world 删除拒绝 + Low 完整性标签」（上游文档明示、粘滞），故必须用户点击确认 |

## 三、批次划分（每批含实现 / 验收 / 反证）

### C4-a · 工作区取向 + 可供给探针 + 提示（日志/通知）

- **实现**：
  - `dsh_shell.rs`：新增 `resolve_workspace()`（`WORLDSEA_WORKSPACE` > `%USERPROFILE%\WorldSea`，缺失则创建）；宿主 spawn 的 `current_dir` 改为该工作区（**dsh 树根仍用于定位 `apps/cli/lib/bin.js`**，两者分开）；日志同时打印 dsh 根与工作区。
  - 新文件 `workspace_probe.rs`：Windows 上手写 FFI（`CreateFileW`/`CloseHandle`，与 `dsh_pipe_io.rs` 的 `PeekNamedPipe` 同一模式、**不新增依赖**）实现 `check(dir) -> WorkspaceProbe`；策略判定为纯函数（`Ok` / `NoWriteOwner` / `Missing` / `Other`）。
  - 装配：启动即探测默认工作区；不可供给 → `println!`/`eprintln!` 可读行 + 系统通知（复用 `tauri_plugin_notification`，C1-c 先例）。
- **验收**：真机起壳 → ① 应用数据目录旁/用户 profile 下出现 `WorldSea` 工作区目录；② 壳日志打印工作区路径与探测结果 `可供给`；③ 新会话里 agent 跑命令**直接可用**（不再 `grantWrite` 报错）。
- **反证**：`WORLDSEA_WORKSPACE=D:\A`（或 `D:\WorldSea\dsh`）起壳 → 探针报 `不可供给` + 通知弹出 + 日志含修复命令；同一会话里命令复现 `SetNamedSecurityInfoW failed (Win32 5)`（证明探测与实际行为一致）。

### C4-b · 横幅提示 + 一键修复

- **实现**：
  - `dsh_workspace_notice.js`（新注入件）：不可供给时在页面顶部出可关闭横幅（文案含修复命令与后果说明），按钮「修复工作区权限」→ 调新命令。
  - `cmd_fix_workspace_acl`（新 Tauri 命令）：执行 `icacls "<工作区>" /grant "<用户>:(OI)(CI)F"` 并回读探测结果；**同步登记进 `permissions/worldsea-shell.toml` + capability**（C3-a 口径：新增页面可调命令必须逐条白名单）。
  - `menu.rs`：「设置」菜单加「修复工作区权限…」项（与横幅同一命令；点击前由命令自身返回文案提示后果，hmm——菜单路径无二次确认，改为菜单触发**页面横幅的展开态**最简）。
  - `ProxyCfg` 增 `workspace_warning: Option<String>`（装配侧由桥状态提供）→ `inject_shell_scripts` 带出横幅脚本。
- **验收**：反证环境下起壳 → 横幅可见（文案含修复命令）；点「修复工作区权限」→ 命令行返回成功、横幅切换为「已修复（重载后生效）」；重启壳 → 无横幅、命令可用。
- **反证**：`WORLDSEA_NO_WORKSPACE_NOTICE=1`（新开关）→ 不注入横幅，其余不变（证明横幅由壳常量/状态控制）。

## 四、风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 一键修复给目录打上 dsh 常驻 ACE + Low 标签（粘滞） | 只对**用户点确认**的当前工作区执行；横幅/菜单文案写明后果；不做任何静默自动修复 |

## 六、落地结果（2026-09-24，全部完成）

**C4-a · 工作区取向 + 探针 + 提示**
- 产物：`dsh_workspace.rs`（工作区解析 / 启动探测+通知 / 一键修复；自 `dsh_shell.rs` 拆出，满足 400 行门禁）+ `workspace_probe.rs`（`CreateFileW(WRITE_OWNER | READ_CONTROL)` + `FILE_FLAG_BACKUP_SEMANTICS` 的无副作用探针；手写 FFI，与 `dsh_pipe_io.rs` 同模式，**无新依赖**）。宿主 `current_dir` 改指工作区；`WORLDSEA_WORKSPACE` 可覆盖。
- **验收（真机）**：`工作区探测：可供给 —— C:\Users\LINGTIAN303\WorldSea` · `spawn … workspace=C:\Users\LINGTIAN303\WorldSea` · 目录自动建立 · 页面正常（index 47608B、无横幅）· 全 api 200。
- **反证（真机）**：`WORLDSEA_WORKSPACE=D:\A` → `工作区探测：不可供给（缺 WRITE_OWNER）—— D:\A（… 修复：icacls "D:\A" /grant "DESKTOP-LRGSUML\LINGTIAN303:(OI)(CI)F" …）` + `工作区不可供给：…` 一行 + 横幅注入（index **50932B**，较基线 +3324B）+ 页内探针原文 `PROBE-BANNER yes size=149 text=工作区不可供给：D:\A（dsh 沙箱需要目录上的 WRITE_OWNER；修复：icacls "D:\A" /grant "DESKTOP-LRGSUML\LINGTIAN303…`。
- **探针与实测双向一致**：`cargo test --lib -- --ignored probe_live_dirs`（`WORLDSEA_PROBE_GOOD=%USERPROFILE%` → `可供给`；`WORLDSEA_PROBE_BAD=D:\A` → `不可供给（缺 WRITE_OWNER）`）；而 `D:\A` 此前实测命令确以 `SetNamedSecurityInfoW failed (Win32 5): grantWrite(D:\A)` 收场。
- **修复链可证（批外一次性实验）**：同型 ACL 弃置目录上直跑 dsh runner → 复现 `Win32 5`（exit 127）；`icacls … /grant "<用户>:(OI)(CI)F"` 后**同一命令立刻成功**（`hi` / exit 0），目录出现 dsh 供给痕迹（能力 SID + `Everyone:(CI)(DENY)(DC)` + `Mandatory Label\Low`）。

**C4-b · 横幅 + 一键修复**
- 产物：`dsh_workspace_notice.js`（顶部横幅：目录 + 修复命令 + 后果说明；「修复工作区权限」按钮调命令，**用户点击才执行**）· `cmd_fix_workspace_acl`（`shell_bridge.rs`）· `permissions/worldsea-shell.toml` 白名单（7 → 8 条）· 「设置 → 修复工作区权限（授当前用户完全控制）」菜单项（结果走系统通知）· `ProxyCfg.workspace_notice` 注入链（`dsh_inject.rs`）。

**用户真机走查：通过（2026-09-24）**——默认工作区（`%USERPROFILE%\WorldSea`）路径、反证路径（不可供给时的通知/横幅/一键修复）、菜单路径与旧会话回归四项均无误。

**后续（G2，2026-09-29 查实）：本批的壳侧一键修复无需对齐上游 PS1。** dsh 0.2.0 起 `sandbox-windows-acl` 自带**给 Agent 用**的 `diagnose-windows-sandbox-acl` 技能，且在 win32、未配 `runnerCommand` 时**无条件注册**（`sandbox-local/src/index.ts:301-303`）→ 开箱即开；它的 `-GrantFullControl` 与我们这条 `icacls /grant` **功能等价**，而它那套备份/回滚是为 `-Fix`（删别包 ACE）准备的，与上游「workspace grant 永不撤销」的设计相撞；资源目录还是临时目录（无稳定路径可调）。→ **两者互补不重叠**（壳横幅＝不可供给时的第一道自助；Agent 技能＝命令失败后的深诊）。完整证据与撤案理由见 [运行手册「工作区与可供给性」](../details/架构/dsh-运行手册.md)，登记项 G2 已据此撤销。**无代码改动。**
