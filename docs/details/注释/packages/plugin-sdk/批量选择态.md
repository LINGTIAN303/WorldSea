# 批量选择态（EntityBatchMode）

> 代码内简要注释见 `packages/plugin-sdk/src/composables/useBatchDelete.ts`（状态本体）、
> `packages/plugin-sdk/src/components/GenericEntityView.vue`（按钮/路由/槽属性）、
> `packages/ui-kit/src/components/entity/GenericTreeView.vue`（树路由）。本文承载「为什么」。

status: 已完成（2026-10-01 施工；真机走查待用户）

## 提案与三裁定

用户观察：常驻复选框把「浏览」与「选择」两种语义挤在同一界面——卡片左上角永远挂勾选框，
与「点击卡片＝打开详情」的默认语义冲突。**复选框全量退役**，改为显式批量态。三裁定（均取推荐项）：

1. **范围＝全部批量面**（卡片网格 / 区域树 / 区域卡片 / 势力树 / 时间线事件卡）；
2. **批量态下必须先退出才能看详情**（点击一律＝选中切换）；
3. **清空 ≠ 退出**：「取消选择」只清空选中、留在态内继续选；退出走「批量选择」按钮或 Esc。

## 状态机（`useBatchDelete`）

| 动作 | selecting | selectedIds |
|---|---|---|
| `toggleSelectMode()` | 翻转 | **清空**（进出都清） |
| `clearSelection()` | **不变** | 清空 |
| `batchDelete()` 成功后 | 不变（留在态内） | 清空 |

- 选中项只活在批量会话内：进出批量态都清空，避免退出后工具条残留「删除 (n)」而卡片已是浏览态。
- `selecting` / `enterSelectMode` 在改造前已存在于该 composable 但**全仓零使用**——本批直接启用，不新造状态。
- 原 `clearSelection` 会顺带置 `selecting=false`，与裁定 3 冲突 → 已改（这是本批最容易踩的语义回归点，单测锁死）。

## Esc 分工（详情优先）

GEV 与其芽视图已注册 `${entityType}.close`（view 层 escape）；本批把 handler 改为两级：
**有详情先关详情，否则退批量态**。时间线补注册 `timeline.close`（同规则）。
不新增独立 Esc 条目，避免与视图层其它 escape（区域擦除 `region.erase-cancel`、战术板 `tactical.cancel`、大纲白板）叠冲突。

## 五个面与驱动源

| 面 | 路由点 |
|---|---|
| 实体卡片网格 | `GenericEntityView.onCardActivate`（两分支：翻转卡 / 普通卡） |
| 区域·卡片模式 | `RegionList.activateCard` |
| 区域·树视图 | `RegionList.activateTreeItem` |
| 势力·树视图 | `GenericTreeView.onRowActivate`（`OrgTreeNode` 接线） |
| 时间线·事件卡 | `EventCard.onActivate`（`TimelineView → TimelineChart → TreeNode/EventCard` 四层下传） |

批量态经 **GEV 的 `#list` 槽属性 `batch-mode`** 与时间线各自 props 链下传（复用既有 `selected-ids`/`toggle-select` 通道）。

## 可见性三件（防「点了没反应」）

1. 工具条「批量选择」按钮 **active 高亮**（accent 描边 + 浅底）+ `aria-pressed`；
2. 批量态下卡片/树行 **hover 虚线 accent 描边**（树行用浅 accent 底）；
3. 选中项沿用既有 `.batch-selected`（accent 实描边 + 浅底）。**时间线事件卡原先只有复选框没有选中视觉**，本批补 `.batch-selected`。

无障碍：卡片/树行在批量态 `aria-label` 改述为「选择/选中 X」，并给 `aria-pressed`；移除 checkbox 不丢语义。

## 两个坑（施工期实证）

- **scoped 插槽**：`#list` 插槽内容带**父组件** scope id → GEV 的卡片样式作用不到区域手写卡片
  （详见 [实体视图滚动链.md](实体视图滚动链.md) 的「残留登记」段）。
- **`useSlots()` 非响应式**：`computed(() => !!slots.list)` 在**动态插槽**（`<template v-if #list>`）下
  不会翻回——判据实验：插槽撤掉后 `Object.keys(slots)` 已空但 computed 仍缓存 `true`。
  故「按视图模式动态摘插槽」方案被否，区域改走「自包 grid + 自带样式」。
