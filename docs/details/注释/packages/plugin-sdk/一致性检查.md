# 一致性检查（consistencyRules / useConsistencyChecker）

> 代码：`packages/plugin-sdk/src/composables/consistencyRules.ts`（纯规则）+ `useConsistencyChecker.ts`（composable 包装）
> 消费方：`apps/tauri/src/ui/data/ConsistencyReportPanel.vue`（面板）· 入口：AppMenu「一致性检查」

## 为什么住在 plugin-sdk（2026-10-02 自 entity-core 迁入）

引用/选项类检查需要 `normalizeFieldType`（`src/detail/fieldType.ts`）做字段类型归一——它是
「字段类型漂移的唯一定义处」，归一表在 plugin-sdk。依赖方向 plugin-sdk → entity-core，
entity-core 不能反向 import，故 schema 派生逻辑整体迁入。

## 架构：纯函数 + 纯数据入参

- `runConsistencyChecks(input)` 吃纯数据（entities / relations / schemas / relationTypes 四张表），吐 issue 数组——**单测不依赖 pinia**（见 `__tests__/consistencyRules.spec.ts`）。
- `useConsistencyChecker.runFullCheck()` 只负责解包：stores 取实体与关系、`entitySchemaRegistry.getAll()` 归拢 schema（**fields + customFields 合并**）、`relationshipRegistry.getAll()` 归拢关系类型，然后喂纯函数。

## 十类检查（category → severity）

| category | 级别 | 判定 |
|---|---|---|
| `dangling_relation` | error | 关系端点实体不存在（源/目标各报一条，relationId 支持一键修复） |
| `dangling_ref` | error | `entityRef` 字段值指向不存在的实体（经 normalizeFieldType 归一，与 EntityRefControl「引用已失效」同口径） |
| `empty_name` | error | 名称 trim 后为空（名称是列表/搜索/引用的唯一直观身份） |
| `missing_required` | warning | 必填字段缺值。**真空值才算缺**：0 / false 是合法值（旧实现 `!value` 会误报） |
| `invalid_select` | warning | select / multiSelect 值不在 options 集内 |
| `type_mismatch` | warning | 关系两端实体类型不在声明允许集 |
| `unregistered_type` | warning | 关系类型不在注册表（旧版/导入残留；此类关系原实现会被类型校验静默跳过） |
| `self_loop` | warning | 关系源 = 目标 |
| `duplicate_name` | warning | 同类型内名称 trim+忽略大小写重复（与 useDuplicateNameCheck 同口径） |
| `orphan_entity` | info | 无任何关系 |

## 面板接线要点

- 「查看关系」= 跳转到该关系的**源实体**（关系无专属视图，旧实现只关面板）。
- 「一键修复悬空关系」走 `useConfirm` danger + `armedConfirmText` 两段式确认键（原 window.confirm 与全应用弹窗体系不一致）。
