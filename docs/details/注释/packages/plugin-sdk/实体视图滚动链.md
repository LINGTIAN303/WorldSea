# 实体视图滚动链（GenericEntityView 卡片网格）

> 代码内简要注释见 `packages/plugin-sdk/src/components/GenericEntityView.vue` 的 `.entity-grid` 与 `.entity-grid.has-custom-list` 两处。本文承载「为什么」。

status: 已完成（2026-10-01 修复并真机待走查）

## 症状

所有走 `GenericEntityView` 默认卡片网格的实体视图（角色 / 概念 / 道具 / 服饰 …）：
实体卡片被压成 2~22px 的「残片」，全部塞进一屏，**容器不出滚动条**。
走自定义 `#list` 插槽的视图（区域卡片模式）更甚：卡片压到 ~2px。

## 根因（两条同型机制）

Chromium 的「自动最小尺寸」规则：**flex / grid 子项若 `overflow` 非 `visible`，其自动最小尺寸为 0**。
`.entity-card-wrapper` 自带 `overflow: hidden`（裁翻转面与出血封面），于是：

1. **grid 支**：`.entity-grid` 是「定高容器（`flex:1` 拿到确定高度）+ `grid-auto-rows: auto`」。
   `auto` 行 = `minmax(auto, auto)`，其 min 取子项自动最小尺寸 = **0** → 行轨道被压到内容高以下；
   压完总量恰好塞进容器 → `overflow-y:auto` 永远不触发 → 「无滚动容器 + 挤压卡片」。
2. **flex 列支**（`.has-custom-list`）：列向 flex 的子项同理被 `flex-shrink` 压扁，压到刚好塞满，同样不出滚动条。

**反直觉点**：`align-content: start`、`min-height: 0`、外层 `overflow:auto` 都救不了——断点在**行轨道/子项的 min 端**，不在容器链。
高度链 `.shell → .shell-body → .view-container → .view-content → wrapper → .gev-root` 经审计与实测**完好**，勿再动。

## 修复（两行 CSS）

```css
.entity-grid { grid-auto-rows: min-content; }          /* 行 min 端改取内容高，行高复原 → 总量溢出 → 滚动条出现 */
.entity-grid.has-custom-list > * { flex-shrink: 0; }   /* 列向 flex 子项禁止压扁；总量溢出 → 滚动条出现 */
```

- 选 `min-content` 而非 `max-content`：min-content 高按**最窄宽**算，对会换行的 `.card-footer` 是**高估**（多留白、不裁切）；max-content 按最宽宽算会**低估**（换行内容被裁）。宁留白不裁切。
- `flex-shrink: 0` 对树/图视图安全：`.tree-view` / `.org-tree` 是 `flex:1`（基尺寸 0、靠 grow 撑满容器）+ 自带 `overflow-y:auto` 自滚，从不依赖 shrink。

## 取证与反证（复现台）

`.workbuddy/scroll-harness.html`（已 gitignore）：链接**同一份构建产物 CSS** + 复刻 DOM 链（scope id 取自产物），
`?mode=grid|list&patch=0|1&n=87` 四组对照，Chromium 实测：

| 用例 | 卡片高 | 容器滚动 |
|---|---|---|
| grid · 无补丁 | 21.65px（内容需 67.76） | 否（bug 复现） |
| grid · 有补丁 | 67.76px | 是（scroll 1436 / client 606） |
| list · 无补丁 | 1.78px | 仅 gap 溢出 |
| list · 有补丁 | 67.76px | 是（scroll 6939 / client 606） |
| list · 有补丁 · 树型单子项 | 撑满 594px 且自滚 | 不双滚动条 |

二分过程留档：克隆卡片到任意容器均 67.76px（元素无病）→ 真 grid 内 21.65px（位置有病）→
关 `contain: layout style` 无效（排除）→ grid 高度改 `auto` 即复原（锁定「定高 + auto 行」）。
