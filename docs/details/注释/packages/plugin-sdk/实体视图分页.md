# 实体视图分页

> 代码内简要注释见 `packages/plugin-sdk/src/components/GenericEntityView.vue`（分页状态与快捷键）与
> `EntityPager.vue`（控件本体）。本文承载「为什么」。

status: 已完成（2026-10-01 施工；真机走查待用户）

## 背景与裁定

「概念/设定库」341 项触发过「>200 项」警告条；规模议题曾挂账（虚拟滚动被暂缓）。用户改判：**做分页**。
四裁定（AskUserQuestion，均取推荐项）：

1. **范围＝只做 GEV 实体视图**（走 `GenericEntityView` 的 20+ 个芽；时间线/大纲等自有列表登记后议）；
2. **控件＝多页才出现**（单页保持工具条干净）；
3. **跨页保持选中**（批量态下翻页不清空，删除作用于全部选中）；
4. **「>200 项」警告条随分页退役**（其建议已被分页取代）。

## 口径

- **每页 100 条**（`pageSize` prop，默认 100，可按芽覆写）。
- **`filteredList` 仍是全量过滤结果**；分页只切「渲染哪一段」（`pagedList`）。因此：
  批量删除取名、跨页选中、计数、空态都基于全量，**不随翻页变化**。
- **高亮/变暗按当前页算**（`pagedHighlight`）——与 `v-for` 下标一一对应；此前模板里两处
  `listHighlight.applyToList(filteredList)[idx]` 也借此收敛为一次计算。
- 页码收敛：过滤/排序变化把当前页挤出范围 → 收敛到末页；**搜索词变化 → 回第 1 页**。
- 快捷键 **`Ctrl+←/→`**（view 层，id 为 `${entityType}.page-prev|next` 动态 id ⇒ 不进快捷键目录，
  与既有的 `.delete/.new/.close` 同政策）。

## ★ 边界：插槽消费方不参与分页

区域/势力通过 `#list` 插槽**自绘**（区域是树 + 卡片 + 地图、势力是树）。
若把分页子集传进插槽，**树会丢页外节点**（子节点可能不在当前页）——故：

- `#list` 的 `:entities` 仍是**全量 `filteredList`**；
- 分页控件仅在 `!hasListSlot` 时渲染（即只服务 GEV 默认卡片网格）。

这是刻意的口径边界，不是遗漏：树的分页语义与列表不同，若日后要给树做「懒加载/虚拟化」应另立议题。

## 结构

- `EntityPager.vue`（新）：控件本体（左右箭头 + 「当前页 / 总页数」），抽独立组件保持 GEV 主线精简、
  且时间线/大纲等自有列表日后可直接复用；按钮规格走共享源 `toolbar-buttons.css`（含 `:disabled` 态）。
- `GenericEntityView.vue`：`page/totalPages/pagedList/pagedHighlight` + 两个快捷键 + 页码收敛 watch；
  同时撤掉 `n-alert` 警告条与其样式（连带移除 `NAlert` 导入）。

## 插槽消费方分页（2026-10-01 追加：区域图谱）

区域芽默认视图改为**卡片**（原默认树），并给卡片模式接分页。做法＝**GEV 把页状态下放给插槽**：
`#list` 新增 `paged-entities / page / total-pages / set-page` 四个槽属性，消费方自绘 `EntityPager`
并渲染 `paged-entities`。好处：**页状态与 `Ctrl+←/→` 注册仍只在 GEV 一处**，区域不自建第二套。

- **树/地图仍用全量 `entities`**（分页子集会让树丢页外子节点）——分页只作用于卡片模式；
  控件也只在卡片模式渲染（`v-if="viewMode === 'grid' && totalPages > 1"`）。
- 区域文件顺带去重：本地 `fields` 数组与 `regionConfig.regionFields` **逐字节相同** → 改引用（-30 行，
  RegionList 403→377 行，回到 400 行上限内）。
