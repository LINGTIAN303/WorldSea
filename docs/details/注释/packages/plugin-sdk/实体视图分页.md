# 实体视图分页

> 代码内简要注释见 `packages/plugin-sdk/src/components/GenericEntityView.vue`（分页状态与快捷键）与
> `EntityPager.vue`（控件本体）。本文承载「为什么」。

status: 已完成（2026-10-01 GEV 分页 · 2026-10-02 口径下沉 + 时间线时序表接入；真机走查通过，三条风险点裁定为正常）

## 背景与裁定

「概念/设定库」341 项触发过「>200 项」警告条；规模议题曾挂账（虚拟滚动被暂缓）。用户改判：**做分页**。
四裁定（AskUserQuestion，均取推荐项）：

1. **范围＝只做 GEV 实体视图**（走 `GenericEntityView` 的 20+ 个芽；时间线/大纲等自有列表登记后议）；
2. **控件＝多页才出现**（单页保持工具条干净）；
3. **跨页保持选中**（批量态下翻页不清空，删除作用于全部选中）；
4. **「>200 项」警告条随分页退役**（其建议已被分页取代）。

## 口径

- **每页 100 条**（`pageSize` prop，默认 100，可按芽覆写）。
- **`filteredList` 仍是全量过滤结果**；分页只切「渲染哪一段」（`pagedList`）。因此：
  批量删除取名、跨页选中、计数、空态都基于全量，**不随翻页变化**。
- **高亮/变暗按当前页算**（`pagedHighlight`）——与 `v-for` 下标一一对应；此前模板里两处
  `listHighlight.applyToList(filteredList)[idx]` 也借此收敛为一次计算。
- 页码收敛：过滤/排序变化把当前页挤出范围 → 收敛到末页；**搜索词变化 → 回第 1 页**。
- 快捷键 **`Ctrl+←/→`**（view 层，id 为 `${entityType}.page-prev|next` 动态 id ⇒ 不进快捷键目录，
  与既有的 `.delete/.new/.close` 同政策）。

## ★ 边界：插槽消费方不参与分页

区域/势力通过 `#list` 插槽**自绘**（区域是树 + 卡片 + 地图、势力是树）。
若把分页子集传进插槽，**树会丢页外节点**（子节点可能不在当前页）——故：

- `#list` 的 `:entities` 仍是**全量 `filteredList`**；
- 分页控件仅在 `!hasListSlot` 时渲染（即只服务 GEV 默认卡片网格）。

这是刻意的口径边界，不是遗漏：树的分页语义与列表不同，若日后要给树做「懒加载/虚拟化」应另立议题。

## 结构

- `EntityPager.vue`（新）：控件本体（左右箭头 + 「当前页 / 总页数」），抽独立组件保持 GEV 主线精简、
  且时间线/大纲等自有列表日后可直接复用；按钮已随按钮族统一改走 `TuiButton`（ghost/sm + `:disabled` 态）。
- `GenericEntityView.vue`：`page/totalPages/pagedList/pagedHighlight` + 两个快捷键 + 页码收敛 watch；
  同时撤掉 `n-alert` 警告条与其样式（连带移除 `NAlert` 导入）。

## 插槽消费方分页（2026-10-01 追加：区域图谱）

区域芽默认视图改为**卡片**（原默认树），并给卡片模式接分页。机制＝**GEV 侧一个开关 + 一个槽属性**：

- 新 prop `paginate-slot`：为真时 GEV 的工具条分页器对插槽消费方也显示（页状态与 `Ctrl+←/→` 注册仍只在 GEV 一处）；
- 新槽属性 `paged-entities`：当前页切片，消费方卡片分支渲染它（树/地图仍渲染全量 `entities`）。
- 区域传 `:paginate-slot="viewMode === 'grid'"` —— **分页只作用于卡片模式**；树/地图保持全量且无分页器。

**走过的弯路（留档）**：曾把 `page/total-pages/set-page` 作为槽属性下放、让消费方自绘 `EntityPager`——
但工具条与列表是**两个插槽作用域**，`#toolbar-extra` 里取不到 `#list` 的槽属性；而把控件放进 `#list`
又会沉到滚动容器底部够不着。故收敛为「GEV 持有控件与页状态、消费方只声明开关」。

- 区域文件顺带去重：本地 `fields` 数组与 `regionConfig.regionFields` **逐字节相同** → 改引用（-30 行，
  RegionList 403→377 行，回到 400 行上限内）。

## 口径下沉 + 时间线接入（2026-10-01 追加）

GEV 的分页逻辑抽成共享 composable，让「自有列表」视图不必再抄一份：

- `packages/plugin-sdk/src/composables/useEntityPaging.ts`（新）：`useEntityPaging(source, pageSize)` →
  `{ page, totalPages, pagedList, pagePrev, pageNext, resetPage }`，末页收敛 watch 内置。
  `pageSize` 收 `MaybeRefOrGetter`（GEV 传 `() => props.pageSize`，时间线传常量 100）。
  **`resetPage` 交给调用方接线**：什么算「过滤条件变了」只有视图自己知道
  （GEV＝搜索词；时间线＝搜索词 + 纪元 + 重要度）。
- GEV 改为消费它（净减 14 行；arch 门禁长期点名 GEV「拆分为宜」，这是顺势减压）。
- 口径由 `useEntityPaging.spec.ts` 6 例锁住（切片 / 首末页边界 / 源缩短收敛 / resetPage /
  pageSize getter / 空源兜底 1 页）。反证已做：删掉收敛 watch → 第 3 例报红。

### 时间线（时序表）

- 可分页形态 **＝竖向 + 时序表**（`pageable`）。另两种形态**刻意不分页**：
  - **横向画布**：泳道/时间轴/缩略图必须基于**全量时间跨度**，切页会让轴与缩略图失真；
  - **大纲树**：分页子集会让树丢页外子节点（与 §★ 同一边界）。
- 机制：`TimelineChart` 新 prop `pagedEvents`，内部 `verticalEvents` 只在
  `sortMode === 'chrono'` 时改吃分页子集；`eraGroups` 的构建抽成纯函数
  `composables/eraGroups.ts`（调用方决定喂全量还是喂当前页），顺带把 TimelineChart 压回冻结基线内。
- 离开可分页形态即 `resetPage()`：否则从横向切回竖向会停在上次那页，像是「事件少了」。
- 快捷键 `timeline.page-prev|next`（`Ctrl+←/→`，view 层）。**id 是字面量 ⇒ 必须进快捷键目录**
  （`packages/ui-kit/src/components/settings/utils.ts`），否则 `shortcutCatalog.spec.ts` 报红；
  这与 GEV 的动态 id（`${entityType}.page-*`）政策不同。
- 附带修：时间线此前 `register` 了 `timeline.undo/redo/close` 却从不注销（注册表按 id 去重、
  不随组件销毁清理）→ 补 `onBeforeUnmount` 逐条注销全部 5 个 id。

### 大纲侧核查结论：不分页（有据）

大纲芽只有一个视图（`outline` → BoardView），三处自有列表逐一核查后**都不该分页**：

| 列表 | 结论 | 依据 |
| --- | --- | --- |
| 白板卡片网格（BoardListView） | 不分页 | 白板是用户手工建的画布级文档，量级个位数；100/页永不触发＝死代码。且 `.blv` 本身可滚 |
| 右栏「节点」tab（NodeSidebar） | 不分页 | 树形（`role="tree"` + 展开/折叠 + 拖拽重排父级）——页外子节点会丢，同 §★ 边界 |
| 右栏「章节」tab | 不分页 | 它是**拖拽调色板**（拖章节入画布）；调色板的正确交互是滚动，分页会给拖拽加摩擦。且 `revealNode` 依赖 `scrollIntoView` 定位 |

真正该给大纲做的是**虚拟化**（右栏数百章节行）而非分页 —— 已并入「数千实体虚拟滚动」挂账项。
