# codeHighlight 注释（Prism 语法高亮 + 内容键 memo）

> 位置：`packages/shared-ui/src/markdown/codeHighlight.ts`
> 上游：[批次 D 走查后修复·流式帧率](../../../../../plans/已完成/2026-09-18-对话区对齐dsh/03-对照与建议清单.md)（C7 代码高亮移出流式热路径）

## 一、模块职责

按需引入 Prism 核心 + 13 个高频语言，向渲染管线暴露单一入口 `highlightCode(code, lang)`；未命中语言返回 `null`，由调用方降级为转义原文（`markdownStream.renderCodeContent`）。

注入方式：模块加载即 `setCodeHighlighter(highlightCode)`，避免 `markdownStream` 反向依赖 Prism。

## 二、为什么需要内容键 memo（2026-09-20 帧率修复）

`Prism.highlight` 的代价与源码长度成正比（**实测 60 行 TS ≈ 1.6ms**）。而渲染管线会在**内容未变**时重复请求同一份代码——用调用计数取证得到两条热路径：

| 场景 | 修复前 Prism 调用 | 说明 |
|---|---|---|
| 闭合代码围栏**停留在活动尾块** | **1 次/帧** | 尾块每帧重渲；代码块后追加空行/空白时，末代码块长时间是尾 token |
| **整段回退路径**（文档含 def/html） | **N 次/帧**（N = 代码块数） | 回退路径每帧整段重渲，故每帧重高亮全部块 |
| 打字机（未闭合围栏期） | 0 次 | 尾块降级纯文本，本就无 Prism（设计已对） |
| 增量渲染器稳定段 | 每块 1 次 | token 缓存已生效 |

修复后两条热路径的 Prism 调用均降到「**每块一次**」的下限（实测 10 帧 10 次 → 1 次；30 次 → 3 次）。

## 三、设计决策

- **缓存放在 Prism 层而非渲染层**：memo 是「Prism 结果的函数式缓存」，属本模块职责；`markdownStream` 保持纯管线（只调注入的高亮器）。副作用：`ToolRow` 对 JSON 的重复高亮请求同样受益。
- **键 = `归一化语言 + \u0000 + 源码`**：用 `\u0000` 作分隔符（源码中不可能出现的字符），避免语言名与源码拼接产生歧义键。语言别名先归一（`ts` 与 `typescript` 共用同一条目）。
- **失败结果（`null`）一并缓存**：同一份坏输入不再反复走 `try/catch`。用 `Map.get() === undefined` 区分「未命中」与「命中且值为 null」。
- **上限 64 条 FIFO 淘汰（一次删 20%）**：单条键值合计约数 KB → 上限约数百 KB，不随会话增长。淘汰是摊销 O(1)（不是每次插入都扫描）。
- **`referenceHighlightCode`（参考实现）刻意保留在源码内**：门禁需要它做**判别力自证**——参考实现耗时必须超出预算，证明「预算真的能捕获去掉缓存的回归」，而不是永不红的空门槛（同 `thinkSummary.referenceThinkSummary` 模式）。
- **`clearHighlightCache()` 仅供测试**：生产无调用方（缓存无需手动失效——键含源码，内容变即新键）。

## 四、约束

- 输出必须与直接调 Prism **逐字节一致**：缓存只影响「是否重算」，不得影响结果（契约测试锁定）。
- 缓存是**模块级**（跨组件共享）：同一份代码在多个消息行出现时也只高亮一次。
- 新增语言需同时补 `LANG_ALIAS` 别名与 `prismjs/components/*` 的 import 副作用。
