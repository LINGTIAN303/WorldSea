# 启动链（Tauri 产品域）

> 状态：现行（2026-10-22 批 4）
> 计划：[2026-10-22-加载反馈机制.md](../../../../plans/已完成/2026-10-22-加载反馈机制.md)
> 代码：`apps/tauri/src/main.ts` · `apps/tauri/src/App.vue` · `apps/tauri/src/boot/backendBoot.ts` · `apps/tauri/src/ui/boot/SplashScreen.vue` · `packages/entity-core/src/stores/uiStore.ts`

## 1. 为什么要拆 backendBoot

原实现 `initializeBackend()` 在 `app.mount()` 之后 fire-and-forget，而 `App.vue` 的项目初始化还会立刻开始；项目/Store 装配依赖后端注册已完成。拆成 `startBackendBoot()` 并返回同一个 Promise：

- 入口与 App 启动链可同时等待，避免「项目先于后端」的竞态；
- 重复调用复用同一 Promise，不会重复注册；
- 失败可被启动链捕获，交给 BootErrorScreen，而不是只打 console。

## 2. 真实阶段

| 阶段 | 文案 | 实际步骤 |
|---|---|---|
| `backend` | 初始化核心 | `startBackendBoot()`：AutoLink 装配 / canvas 后端 / 校验 API / keyframes |
| `project` | 恢复项目 | `useProjectSwitcher.initialize()`：迁移、工作区同步、存储根绑定、文件监听 |
| `shell` | 装配界面 | `bootstrapShell()`：视图同步、章节迁移、首屏默认视图、schema 快照 |
| `bridge` | 系统桥接 | `useSystemBridge.setup()`：托盘监听、最近项目同步、页面就绪补投 |
| `ready` | 就绪 | `markReady()` → Splash 淡出 |

- 关键步骤超时 30s（桥接 10s），避免底层 Promise 悬挂导致 Splash 永久停留。
- 系统桥接是非关键步骤：失败只 `console.warn`，不进入错误页。

## 3. Splash 只展示，不模拟

- 删除随机进度与虚构英文状态；`SplashScreen.vue` 只读 `uiStore.bootStage`。
- 进度是阶段式：4 个节点，星头停在当前节点，1px 线程按阶段推进；不显示百分比。
- 启动极快时直接走到 `ready`，不会补动画。
- **显式离场窗口**：`App.vue` 用 `splashVisible` 保留 Splash 750ms，让 600ms 淡出真正播放；`bootState === 'error'` 时立即让位给 BootErrorScreen。

## 4. 错误与恢复

- 任一关键阶段抛错或超时 → `uiStore.markBootError([{ id: 'boot', name: '启动', error }])`，显示 BootErrorScreen。
- 「重试启动」= `location.reload()`，走完整启动链。
- 「继续进入」= `recoverFromError()`：只把状态置 ready，不回滚已完成的步骤；可能功能不完整，这是显式取舍。
- `markReady` / `markBootError` / `recoverFromError` 同时维护 `bootState` 与 `bootStage`，避免两者分叉。

## 5. 不做

- 不在 Splash 里做真实百分比（拿不到总步骤耗时）。
- 不为启动链加取消（冷启动不可中断）。
- 不把桥接失败升级为启动失败（托盘不可用不应挡住工作台）。
