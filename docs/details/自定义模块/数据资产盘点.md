# 自定义模块 · 数据资产盘点

> 目的：在重新设计与重构「自定义模块」编辑器之前，盘点当前已拥有的**数据资产**（可复用的数据结构、组件、槽位、运行时能力），作为新设计的输入，避免资产流失。
> 更新：2026-08-11

---

## 一、核心数据模型

### 1. `CustomModule`（模块本体）
字段：`id / name / icon / description / entityTypes[] / relationTypes[] / views[] / dependencies? / createdAt / updatedAt / layoutSchema`。
持久化于 `localStorage('worldsea_custom_modules')`，经 `ModuleSerializer` 支持导入导出（overwrite/merge 策略）。

### 2. `layoutSchema`（v2 槽位模型）
```
{ version: 2, root: Slot }
```
`Slot` 为**递归结构单元**：
```
Slot {
  id, name?
  arrangement: 'horizontal'|'vertical'|'tabs'|'grid'|'accordion'|'carousel'|'split'|'free'
  kind: 'container' | 'leaf'        // container 内含子槽位；leaf 内含组件
  size?: { width?, height?, flex?, minWidth?, minHeight? }
  options?: Record<string, unknown>  // 形态专属配置（grid.columns / tabs.labels …）
  children?: Slot[]                  // container
  components?: PlacedComponent[]     // leaf
}
```
关键约定：**组件只存在于 leaf 槽位**，删除槽位级联清组件（不再平铺+zoneId+order）。

### 3. `PlacedComponent`（组件实例）
```
{ id, type: ComponentTypeId, config, order, x?, y?, width?, height?, expanded?, childSlot?, linkTo? }
```
- `config`：组件配置（与 componentType.defaultConfig 合并）
- `linkTo`：组件联动目标（搜索/筛选 → 列表，列表 → 详情等）
- `childSlot`：可展开容器的子槽位（Slot）

### 4. 数据构件
- `ModuleEntityType`：`{ name, label, icon, color, fields: ModuleField[] }`
- `ModuleRelationType`：`{ name, label, sourceTypes, targetTypes, directed, properties, icon? }`
- `ModuleField`：`{ key, label, type: FieldType, required?, defaultValue?, placeholder?, helpText?, options?, min?, max?, step?, regex?, showInList?, refType? }`

### 5. `FieldType`（字段类型全集）
`text / textarea / rich-text / markdown / number / boolean / date / datetime / time / select / multi-select / tags / image / url / email / color / rating / slider / entity-ref / entity-refs / formula / computed / template / location / file`

### 6. 运行时上下文 `ModuleRuntimeContext`
共享数据层 + 事件总线：`entityList / filteredList / searchQuery / filters / sortConfig / selectedEntityId / selectedEntity`；方法 `setSearchQuery / setFilters / setSortConfig / getFilteredByType / createEntity / updateEntity / deleteEntity / getEntitiesByType / emit / on / off / initialize / dispose`。
- `getFilteredByType(entityType)`：在全局搜索/筛选/排序基础上按 `custom.{modId}.{entityType}` 过滤（多实体类型隔离）。

## 四、迁移资产

`migration.migrateLayoutSchema(old)`：将旧 v1（`{layout: LayoutSlot树, components: 平铺}`）自动转换为 v2 槽位树。
- 旧 `slot` 节点 → container 槽位（arrangement = direction）
- 旧 `zone` 节点 → leaf 槽位（组件按 order 归入）
- 旧 `childSlot` → 递归迁移
- 旧数据作为**可用资源**，不丢弃。

## 五、运行时资产

- `RuntimeSlotRenderer`：渲染 v2 槽位树（container 按 arrangement 布局，leaf 渲染组件真实预览，含 ErrorBoundary）。
- 组件渲染器（`runtime/ComponentRenderers/*`，27 个文件）：DetailPanel / EditForm / PropertyPanel / FieldGroup / Toolbar / ActionButton / BatchActions / ContextMenu / QuickActions / SearchBox / FilterBar / SortControl / EntityList / EntityGrid / EntityTable / KanbanBoard / EntityCard / ChartBar / ChartPie / ChartLine / RelationGraph / TabContainer / AccordionContainer / SplitPanel（+ AI 组件 AiAssistant / AutoFill / SmartSuggest，**无事件接收方，暂未注册**）。
- `getFilteredByType` 按类型过滤（已接入 7 个集合类渲染器）。

## 六、发布资产

- `ModuleRuntime.registerModule(mod)`：注册实体/关系 schema 到注册表（`custom.{modId}.{type}` 前缀），先 unregister 再 register。
- `ModuleRuntime.unregisterModule(modId)`：反注册 schema。
- `ModuleRuntime.getCustomModuleViews(mod)`：统一发布为单一运行时视图 `custom.{modId}.main`。
- 发布流程：`confirmPublish`（发布模态框确认）→ registerModule → unpublishModuleViews（去重）→ 注册视图到 pluginAPI + pluginStore（侧边栏，pluginId 归一 `official.module-builder`）。
- 删除模块：`unpublishModule`（反注册 schema + 清理视图 + 视图数据）。

## 八、设计要点沉淀（重构时的约束/线索）

1. **槽位是一等公民**：先定义槽位（栏/组件容器、形态、宽高、位置），再填充组件；组件只进 leaf 槽位。
2. **两阶段交互**：定义槽位骨架 → 填充组件。
3. **8 种排列 + 槽位可拖拽**（位置/大小/嵌套）。
4. **旧数据自动迁移**，不丢弃。
5. **AI 渲染器（3 个）已有 UI + 事件协议但缺后端**，后续接 AI 时一并启用。
6. **运行时按类型过滤**已就绪，多实体类型模块数据隔离。
