# WorldSea 桌面端视觉审查报告（2026-08-07）

> 审查范围：`docs/details/截图/` 现存 42 张截图（b34-b80）。
> **素材缺口声明**：任务指定的 b1-b33（含 b23 深色遍历、b26 空状态统一、b28 输入 focus、b43 终端 hover）在目录中不存在，本次审查无法覆盖这些批次。现存截图以深色模式为主，浅色模式仅 7 张（b66/b67×3/b68/b69/b70/b71-input），浅色覆盖不完整。
> 审查方式：4 路并行逐张目检 + 交叉验证；以下结论均经至少一次复核，跨批次复现的问题已合并为单一条目。

---

## 一、总览

**整体评价**：设计令牌体系与"弱提示/克制"语言执行到位，空状态、表单层级、焦点环等基础素质良好；主要失分点集中在**对话输入框的占位文本叠印缺陷（双主题稳定复现）**与**终端视图的错误条/会话列表质量明显落后于其他三视图**。

| 视图/组件 | 评分（1-5） | 主要失分点 |
|---|---|---|
| 对话区 | 3.0 | 输入框 placeholder 与快捷键提示叠印（P1）；header 按钮组形态混排 |
| 终端 | 2.5 | 会话列表空态与记录并存、meta 溢出、首行被裁切（P1×3）；错误条形态陈旧 |
| 子Agent | 3.5 | 错误条挤出主按钮（P1）；tag 配色不一致；"清空实例"缺禁用态 |
| 记忆面板 | 4.0 | 仅 P3 级打磨项（pulse 圆点间距、搜索框与按钮高度差） |
| 基础组件库 | 3.5 | toast 关闭 × 对比度、toast 双主题宽度不一、复选框勾选态不可辨 |
| 全局（深浅色） | 3.5 | 深色下幽灵按钮/错误条关闭图标对比度；浅色下空态图标近隐形 |

### 明确通过的维度

- **键盘导航焦点环**（b38 TuiSelect、b39 TuiSegmented、b40 灯泡按钮）：焦点描边清晰，符合已闭环标准。
- **TuiSegmented 双态区分**（b39）：active 填充与 focus 描边区分清晰。
- **子Agent 表单结构**（b56-inputs、b58）：label/输入框/说明三级层级清晰，focus 紫边正常，标题字号统一已生效。
- **空状态组件 TuiEmpty**（b60、b59、b67）：图标+标题+描述结构跨视图统一（仅浅色图标对比度问题，见 #14）。
- **860px 对话列宽**（b72）：居中与留白正确。
- **send 按钮 on-accent**（b71-dark）：深色下白箭头换深字方案生效，对比度达标。
- **Markdown/列表/头部字号统一**（b57、b58、b60-sessionlist）：除叠印缺陷外均通过。
- **圆角/阴影令牌化**：未发现肉眼可辨的硬编码色值或越令牌的圆角/阴影（纯视觉范围）。

## 三、优先级排序（建议实施顺序 Top 5）

1. **#1 输入框 placeholder/hint 叠印**（P1）——双主题、14 张截图稳定复现，且 b71 验证修复未闭环；位于用户每次输入的必经路径，是当前对"不好看"评价贡献最大的单一缺陷，且一处修复即可全部闭环。
2. **#2/#3/#4 终端会话列表三连**（P1）——空态与记录并存是逻辑级视觉矛盾，meta 溢出与首行裁切直接损失信息可读性；终端视图是当前质量洼地（2.5 分）。
3. **#5 子Agent 错误条挤出主按钮**（P1）——表单出错时主操作不可见，直接阻断任务流。
4. **#7+#8+#9 错误条/toast 组件统一**（P2 打包）——终端直角条、× 对比度、双主题宽度分裂同属一个组件族，合并重构一次完成，消除最大的一致性噪音源。
5. **#6+#10 header 按钮组**（P1/P2）——先核实 #6 的禁用态前提，再统一按钮变体；header 是每屏第一眼位置，混排形态对精致度影响与工作量比最高。
