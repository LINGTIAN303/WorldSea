# 场景底座（Router 场景会话装配体系）

> 架构级文档（docs/details/架构 层）。范围：会话创建时如何按「场景」装配身份/工具/技能/工作区，
> 以及场景与消息级「管线判型」的分工。2026-09-09 用户拍板实施（全量：trait 扩展 + 5 场景实体化 +
> 严格隔离 + 会话隔离）。2026-09-10 深入核验与两轮修复（见 §八）：场景 id 改名 world、restore 链路
> 补装配、主权规则施工（方案A）、新建按钮继承、ScenarioContext 注入收口。

## 一、双层结构：场景定身、管线定势

```
会话创建（用户滑块选场景）
  └─ 场景层 Scenario（会话级静态装配）【本文档主体】
       id / display_name        → 滑块 5 段（世界/小说/通用/编程/设计）
       build_system_prompt      → 身份 prompt（+ 项目实体摘要注入）
       tool_ids                 → WhitelistToolBus 工具白名单（基础 ∪ 场景）
       builtin_skills           → 技能加载意图
       memory_policy            → 记忆强度（standard / entity_rich / light）
       confirmation_policy      → 危险操作确认强度（缺省 dangerous_only）
       extra_system_prompt_blocks → 场景钩子（场景级额外 prompt 段）
       workspace_hint           → 场景工作区根（严格隔离落点）
消息发送（自动判型，管线层维持现状）
  └─ 管线层 Pipeline（消息级执行风格）
       force_pipeline(/plan) → LLM 判型(3s 降级关键词) → directive + max_tool_rounds
ReAct 骨架：在场景装配与管线指引下执行
```

**分工**：场景层管「这个会话是谁、会什么」（长期，创建时定）；管线层管「这条消息怎么干」
（短期，每轮判型）。两者正交，互不取代。

## 二、装配面（`Scenario` trait，agent-kernel/src/scenario.rs）

| 装配面 | 方法 | 默认 | 消费方 |
|---|---|---|---|
| 身份 prompt | `build_system_prompt(ctx)` | — | AgentLoop `build_prompt_options`（agent/memory.rs） |
| 工具白名单 | `tool_ids()` | — | `effective_tool_bus`（WhitelistToolBus：基础 ∪ 场景） |
| 内置技能 | `builtin_skills()` | — | TS 技能体系（意图登记） |
| 记忆策略 | `memory_policy()` | `Standard` | 数据意图（MVP 展示/未来消费） |
| 确认策略 | `confirmation_policy()` | `dangerous_only()` | `AgentLoopConfig.confirmation_policy`（new_agent） |
| 场景钩子 | `extra_system_prompt_blocks(ctx)` | 空 | `build_prompt_options` 身份 prompt 之后依次追加 |
| 工作区根 | `workspace_hint()` | `None` | 命令层 `new_session` 场景根派生 + `update_session_workdir` 校验 |
| 消息钩子 | `on_message(msg, ctx)` | 空 | 保留（MVP 未接线消费） |

`ScenarioContext`：project_id / query_text / entity_summary / workspace_id（链式注入）。

## 四、严格隔离规则（用户拍板：工作区硬隔离 + 会话不互通）

1. **工作区主权规则**（2026-09-10 拍板施工，取代 09-09 全量硬覆盖）：
   - 全局模式（project_id=None）：`new_session` workdir 强制绑定 `scenes_root/<hint>`（场景根懒创建）。
   - 项目模式（project_id=Some）：保留用户项目目录不被覆盖；工作区身份 =（root×scene）复合去重
     （方案A：workspaces 表加 scene_id 列 + 复合唯一索引 + 旧库检测重建迁移 + hint 目录名回填），
     同一项目目录在不同场景下=「新项目目录」，跨场景仍可打开同一目录。
   - `update_session_workdir`：仅拦截落在**其它**场景根内的目录；本场景根/项目目录放行。
     切目录时为新目录 `ensure_workspace` 同步写穿 workspace_id（workdir/workspace_id 一并落库，
     None 一并清空；2026-09-10 断链修复——否则 workspace_id 残留旧实体，重启恢复回退旧目录），
     回归测试 `update_session_workdir_syncs_workspace_id`。
   - `scenes_root` 未配置（单测/未注入）时不强制路径，仅记录 scene_id（兼容）。
2. **会话隔离**（前端过滤 + 后端持久化）：
   - `SessionRecord.scene_id` 列（SQLite 迁移幂等补列），`SessionInfo.scene_id` 透出。
   - 前端侧边栏会话列表按当前场景过滤（`normalizeSceneId(scene_id) === 当前场景`，
     空值兜底 world），切滑块只看该场景会话——场景间会话不互通。
3. **空会话治理与恢复自愈**（2026-09-10 症状修复）：
   - **切场景滑块改草稿语义**：`onSceneSlide` 不再 `newSession('新会话',…)`（旧链路每次切换
     落库 0 消息空会话 + system_prompt 污染为字面量），改 `newDraftSession(scenarioId)` 暂存
     `draftSceneId`，首条消息 `ensureSession` 按目标场景创建（完整装配 prompt）。
   - **启动物理清理**：`restore_sessions` 开头 `purge_empty_sessions`——删「无任何消息行 &&
     非固定 && chat」（按 messages 表实况判定，不依赖 message_count 列；group/固定/有消息保留）。
   - **恢复领地自愈**：`restore_sessions` 对 workdir 落在**其它**场景根内的有场景会话矫正回
     本场景根（共用 helper `workdir_in_other_scene_root`，与 new_session/update_session_workdir
     同口径），`ensure_workspace` 实体化后两参写穿；无场景旧会话与项目目录不矫正。
   - 回归测试：`purge_empty_sessions_keeps_meaningful_rows` / `restore_sessions_self_heals_cross_scene_workdir`
     / `update_session_workdir_syncs_workspace_id`（commands 132/132）。
4. **全局模式 workdir 传递修正**（2026-09-10 症状：会话全落「默认工作区」组）：
   - 根因：全局模式（默认项目/无项目）下前端把 `~/.WorldSea/agent` 当 workdir 传入，该路径
     不在 `scenes_root`（%APPDATA%/com.worldsea.app/scenes）领地内 → 后端领地判据误判为
     「用户项目目录」保留 → 场景会话 workdir ≡ 前端 defaultDir → 树分组全命中「默认工作区」。
   - 修复：`newSession` 全局模式 workdir 传 null（后端 `workdir.is_none()` 分支强制
     `scenes/<hint>`），entityStorageRoot 显式传 worlddata（后端无 workdir 可回退）；
     普通项目不变（dirPath=项目模式）。分组 label 兜底链增加「场景根 hint → 中文场景名」。
   - **翻转修复**（用户实测：切场景回来后「默认工作区」条目变成正确项目目录名）：根因 =
     ①`defaultDir` 每次 refresh 重算 `resolveWorkspaceDir()`（跟随当前项目），项目状态变化
     使同一会话在「默认工作区」⇄ 真实目录名间翻转——语义固定为 `resolveDefaultWorkspaceDir()`
     （恒 ~/.WorldSea/agent），「默认工作区」组 = 落在全局 Agent 工作区的会话；
     ②项目模式 `newSession` 不再吃 `currentWorkdir` 残留（可能属于其它项目/全局工作区），
     恒取当前项目目录——新会话不再重复落「默认工作区」组。
5. **会话标题兜底**（2026-09-10 症状：重启标题回退默认 / 生成成功率极低）：
   - 成功率根因：`generate_session_title` 的 `max_tokens=64` 被推理型模型（deepseek-v4 系列）
     reasoning 消耗殆尽 → 正文空响应；改 512 + `silent: true`（流式碎片不入会话事件流）。
   - 重启回退根因：LLM 失败返回「新会话」不写穿，运行期靠前端首条消息兜底显示、重启缓存
     清空即露馅；改为失败时用首条消息截断 24 字写穿（标题锁定口径不变），回归测试
     `generate_session_title_falls_back_to_first_message`（commands 133/133）。
