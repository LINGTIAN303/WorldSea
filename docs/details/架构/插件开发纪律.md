# 插件开发纪律（产品域 world 树）

> 对齐 dsh 侧插件开发纪律（dsh/packages/AGENTS.md：导出约定 / 真实组合测试 / HMR-safety disposal），
> 结合我方体系（双贡献位 view/overlay + 声明式身份 + 常驻/启停双语义）固化成本仓约定。
> 适用：内置插件（world/plugins/*/index.ts）与外部插件（worlddata/.worldsea/plugins/<id>.js）。

## 一、身份与清单（manifest）

1. **id 域**：内置芽 `official.*`；内置功能件 `official.*` + `kind: 'utility'`；外部插件强制 `ws.` 前缀（装载器双重校验：前缀 + 文件名一致）。
2. **kind 声明**：有侧栏视图 = sprout（默认，可省）；纯 overlay/能力贡献 = `kind: 'utility'`（**常驻装载，无启停**）。声明式为准——卸载态下运行时证据全撤，禁止运行时猜身份。
3. **description 是用户可见面**（功能插件卡直接展示）：只写功能表述，**禁止**开发行话（批次号/迁移史/「原 Shell 固定挂载」类）——迁移史进批计划文档。

## 二、贡献位契约

| 贡献位 | 契约 | 生命周期 |
|---|---|---|
| `api.registerView(view)` | 侧栏视图；pluginId 自动锁定 | 卸载自动反注册 |
| `api.registerOverlay({ id, label, component, menu? })` | 全局弹窗；打开 = `ws-open-<id>` 事件；组件契约 `{show}` + `@close`；`menu` 声明则 AppMenu 自动渲染入口（order 升序，1.5 被 L0「导出」占位，99 = 尾段设置位） | 卸载自动撤登记（含菜单项与事件监听） |
| `api.registerEntityV2 / registerRelationV2 / registerFacet` | 类型元数据 | 卸载**不注销**（避免关系查询断裂） |
| `api.capabilities.register(list)` | 壳能力桥（ACL = 窗口级） | 卸载自动撤登记 |

- overlay 组件**禁止绕过 `{show}`/`@close` 契约**——OverlayHost 与既有事件入口（快捷键/菜单/Agent）都依赖它。
- 菜单声明（`menu`）只给「需要更多操作菜单入口」的 overlay；入口在别处的（实体右键等）不声明。

## 三、代码与实现

1. **外部插件形态**：单文件 `<id>.js`，内容 = `(require) => ({ manifest, apply })` 箭头函数表达式；依赖只经 `require`（vue / @worldsea/entity-core / @worldsea/shared-ui），组件用 `h()` 渲染函数。
2. **原子写**：任何写盘（插件文件/数据）走「临时文件 + 同卷 rename」，禁止半截文件。
3. **写入静默**：依赖 `.worldsea/` 目录的 watcher 语义时，确认自身写入不触发误装载（内置插件写数据走 fsb 自写静默期）。
4. **错误隔离不豁免纪律**：装载失败隔离是兜底，插件自身仍须 fail loud（可读 reason），不静默吞错。

## 四、测试纪律（对齐 dsh：真实组合 + disposal 必测）

1. **真实组合测试**：apply 用真 `createPluginApi(id)` 驱动（参照 batch3/batch5-plugins.spec 模式），禁止只测假 api——登记/归属/清理三断言最少集。
2. **disposal 必测**：每个贡献位都要有「清理函数执行 → 真源清空」断言（`runPluginCleanups(id)` 后 getOverlays/getViews 为空）。
3. **常驻语义用例**：utility 插件须断言「isEnabled 全关仍装载、不进 skipped」（参照 tree-external.spec 的 utility 用例）。
4. **用户可见面审查**：manifest.name/description/menu.label 上真机过一眼——禁止开发行话。
