# 存储后端

> 回答「三个 `StorageBackend` 实现各在什么时候生效、切换条件是什么」。
> 实现：`packages/entity-core/src/core/StorageBackend.ts`（选择与工厂）· `FileStorageBackend.ts`（主实现）· `TauriStorageBackend.ts` / `database.ts`（两个回退）。

## 一、三个实现与触发条件

| 后端 | 触发条件 | 落点 | 定位 |
|---|---|---|---|
| `FileStorageBackend` | `isTauri() && hasTauriInvoke()`（`StorageBackend.ts:579-583`） | `<projectDir>` 下 JSON 文件 | **主实现** |
| `TauriStorageBackend` | 同上，但**未绑定 projectDir** 时被 `FileStorageBackend` 内部委托 | 应用数据目录 `entities.db`（SQLite） | 启动期兜底 |
| `WebStorageBackend` | 非 Tauri，或 Tauri 标志在但 `invoke` 缺失 | IndexedDB `WorldSea-Project-<id>` | 浏览器预览 |

选择逻辑只有一处（`getStorageBackend()`），其余代码一律经它取，不直接 new。

## 二、`isReady` 分支：启动竞态的高发区

`FileStorageBackend` 每个方法开头都是：

```ts
if (!this.isReady) return this._fallback!.xxx(...)
```

`isReady` 在 `setStorageProjectDir()` 绑定项目目录后转真。绑定前的一切读写都落到 SQLite 兜底。

这个分支在代码注释里记了两次实战事故：**boot 竞态导致实体更新进 SQLite 而磁盘 JSON 保持旧值**。表现是「改了没生效，重启后又变回来」——因为下次启动读的是磁盘 JSON，而那次改动只进了 SQLite。

排查口径：遇到「数据莫名不一致」，先确认当时的 `isReady` 是真是假，再判断数据落在哪。

## 三、项目目录绑定

```text
setStorageProjectDir(dir)   // StorageBackend.ts:601-605
  → 通知 FileStorageBackend 重新扫盘建索引
  → isReady = true
```

绑定时机在 `useProjectSwitcher` 的切项目流程里。切项目时：

1. `reloadStores()` —— 重载实体 / 关系 / 文件
2. schema 注册表**全清 + 逐插件 unload→load 重播种**

第 2 步是必要的：schema 注册是内存态，不清会让上一个项目的类型残留。

## 四、索引与落盘

`FileStorageBackend` 维护一份**内存索引**（id → 文件路径、type → id 列表），起时扫盘全量建立（`:263-332`）。之后所有查询先走内存，只有写与读正文才碰磁盘。

落盘路径拼装（`:336-339`）：

```text
<projectDir>/worlddata/entities/<type>/<safeName>_<id 前 8 位>.json
```

`safeName` 由 `toSafeFileName()` 处理（`:16-25`），把文件名非法字符替换掉。改实体名会改文件名，所以 `updateEntity` 里有「改路径时删旧文件」的逻辑（`:433-475`）。

关系是**单文件整表**：`relations/_index.json`，写时全量 flush，由 `requestIdleCallback` 防抖（`:642-670`）。

## 五、失败与回滚

| 场景 | 行为 |
|---|---|
| 实体写失败 | 内存态回滚到写前快照（`:405-431`） |
| 读正文失败 | 抛错，不返回空内容（空内容会被上层当成「文件是空的」） |
| 索引扫描遇到坏 JSON | 跳过该文件并记日志，不让整个索引起不来 |
| `isReady` 为假 | 委托 `_fallback`（SQLite） |

## 六、与 dsh 侧的关系

dsh 插件（`dsh-plugin-worldsea`）**不走这套后端**——它用 Node `fs` 直读写同一个 `worlddata/` 目录。

含义：同一份数据、两套写者。后果与防护见 [数据链路](数据链路.md) §六。dsh 侧的写前守卫是 `requireWorkspaceRoot`（会话 cwd 必须正好等于某个已登记工作区的根），读操作不拦。
