# 架构层入口

> 本层回答**系统级**问题：由哪些部分组成、机制怎么运作、边界在哪、哪些是历史件。
> 分组依据是「读者要解决的问题」，不是文件大小或写作时间。

## 按问题找文档

| 你想知道 | 去哪 |
|---|---|
| 这个系统整体长什么样 | [总览](总览.md) |
| 插件怎么写、怎么装载、怎么启停、该拆还是该合 | [插件系统](插件系统/README.md) |
| 数据怎么从界面落到磁盘、存储后端怎么切换、能力桥怎么走 | [机制](机制/README.md) |
| 当前状态与冻结面、架构检查器、门禁、一致性 | [系统](系统/README.md) |
| 与 dsh（Agent 面）怎么接、ACL 怎么分、注入什么 | [dsh](dsh/README.md) |
| 仓库与协作配置 | [工程](工程/GitHub仓库配置现状与待办.md) |
| 芽（侧栏插件）生态诊断 | [芽生态](芽生态/README.md)（专题） |
| 已收口 / 已作废的历史件 | [归档](归档/README.md) |

## 分组口径

| 分组 | 收什么 | 不收什么 |
|---|---|---|
| `插件系统/` | 插件协议、装载启停、粒度划分、开发纪律 | 具体某个插件的实现（那在 `apps/tauri/src/world/plugins/`） |
| `机制/` | 跨插件的通用机制（数据链路、存储、能力桥、快捷键、图标、字体、背景、风格、AutoLink） | 只服务一个插件的内部机制 |
| `系统/` | 全局状态、治理、门禁、字段矩阵 | 会随时间消失的进度记录（那进 `plans/`） |
| `dsh/` | 与 dsh 仓的接缝、运行手册、fork 台账 | dsh 自身文档（那在仓根 `dsh/`） |
| `工程/` | 仓库配置、协作约定 | 代码风格（那在 `docs/` 之外的配置里） |
| `归档/` | 已收口、已作废、被取代的件，只读 | 仍在维护的任何东西 |

## 写作口径

- 每篇文档头部写清 `status` 与「面向谁」
- 数字给复现方式，不给「约」「大概」
- 已作废的结论不要删，移进 [归档](归档/README.md) 并注明被谁取代
