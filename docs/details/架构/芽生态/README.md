# 芽生态研究

> 研究对象：**仅芽类**（27 个有侧栏入口的 `official.*` 插件）。10 个 `kind: 'utility'` 内置插件只作为边界对照，不进入生态成员统计。
> 数据口径：2026-10-18 初版静态取证，2026-10-20 复核；字段数取自 [芽字段矩阵](../芽字段矩阵.md)（276 实例 / 156 唯一键），关系数取自 `packages/entity-core/src/relations/`（104 条 / 16 域）。
> 结论性质：诊断 + 建模 + 建议，不含施工代码，也不替代任何批计划。
> HTML 阅读版：[芽生态研究阅读版](./阅读版/index.html)

## 一、一句话结论

**芽目前是一份“平铺的能力清单”，还不是一个“有生态位的系统”。** 27 个芽共享同一层清单、同一套开关、同一条侧栏；但它们在依赖、状态、语义上的差异，系统几乎没有记录。

## 二、五个核心结论

1. **平铺是四处叠加的结果**：侧栏平铺（`sidebarOrder`）、设置平铺（芽管理卡）、清单平铺（`DEFAULT_SPROUTS` 27 条）、身份平铺（sprout / utility / external 混在同一词汇里）。只改其中一处，不会改变“无层级”的观感。
2. **旧 6 类语义域不可信**：现有 `世界观 / 角色 / 物品 / 叙事 / 视觉 / 系统` 混合了“内容本体、媒介形态、功能职能”三种轴。按“芽对 × 关系类型”实测，跨域 93 个组合，域内仅 9 个（10.33 倍），说明真实的芽生态是**跨域网状**，不是六个抽屉。
3. **三种依赖声明全部未生效**：`manifest.requires` 无任何插件使用（本树只提供 `world.info`）；`SproutToggle.dependencies` 与 `manifest.defaultEnabled` 是死字段。真正存在的芽间依赖只有**实体关系**（104 条）和少量字符串 ID 字段。
4. **生态呈“一网 + 十一岛”**：16 个芽组成一个连通关系网，11 个芽在网外（含写作三芽中的正文与笔记本；新增的字段矩阵为纯观测视图）。大纲是唯一的跨域消费者（出度 15、入度 0）。
5. **状态语义分散在四套词表**：持久化 `active`、运行时 `loaded/skipped/rejected`、身份 `builtin/external`、类型 `sprout/utility`；UI 只展示其中一部分，用户无法从界面判断“这个芽现在到底处于什么状态”。

## 五、边界与未决

- 本文只覆盖**内置芽类**（27 个）；外部插件只描述其装载与状态机制，不统计其生态位。
- 关系数据是**类型级**（schema 声明的 sourceTypes/targetTypes），不是实际实体实例的边数；因此“度”反映的是**设计意图**，不是用户当前项目的数据分布。
- 语义域方案已于 2026-10-18 **拍板通过**，并于 2026-10-20 写入 27 个芽 manifest（R1/R2）；字段矩阵芽已声明 `domain: 'tool'`。旧 `category` 仍保留为过渡筛选，待 R4 退役。
- 芽的“生态层级”不存在唯一正确答案；本文选择的是**可验证、可落地**的四轴模型，而不是穷举所有可能的分类。
