纯视图芽内部还要再分两类，否则会被误当成同一级生态成员：

- **变体视图**：`apparel`、`weapons` —— 展示的是 `item` 的子集（按 Facet 过滤），不是独立实体。
- **工具视图**：`graph`、`mindmap`、`custom`、`field-matrix` —— 前三者操作“已有实体”或“空白画布”；`field-matrix` 是字段/关系/视图/AutoLink 的观测视图。它们都不拥有实体类型。

## 1.6 单个芽的解剖结构

一个芽最多由五层组成；27 个芽的覆盖并不均匀：

| 层 | 组成 | 覆盖 | 说明 |
|---|---|---|---|
| 身份层 | `manifest`：id / name / version / description / kind | 27/27（含 utility 37/37） | 唯一必填层；域信息目前缺失 |
| 贡献层 | `registerView` | 27/27 | 侧栏入口；变体视图也在此层 |
| 贡献层 | `registerOverlay` | 0/27（10 个 utility 才有） | 芽类不贡献全局弹窗 |
| 数据层 | `registerEntityV2`（Trait + ownFields） | 21/27 | 6 个纯视图芽无实体 |
| 数据层 | `registerFacet` | 1/27（道具） | 只有 `item` 有 weapon / apparel |
| 能力层 | `capabilities.register` | 1/27（思维导图） | 经壳能力桥暴露 |
| 关系层 | `defineRelation` 参与 | 16/27 | 其余 11 个为孤岛；关系不归属芽 |

> 这解释了为什么“芽”难以用一个维度描述：它既是**身份**、又是**视图**、又可能是**数据模式**、还可能参与**关系网**。任何层级模型都必须同时容纳这四种角色。

## 1.7 现状一句话

> 27 个芽在**能力上**已经各就各位，但在**描述上**仍是同一排抽屉：没有域、没有层级、没有依赖声明、没有统一状态。下一批文档分别补这四件事。
