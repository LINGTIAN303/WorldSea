# 插件系统入口

> 产品域内部的**世界语义插件树**（第二棵树）。它是本仓「一切皆插件」的落点。
> 树本体在 `apps/tauri/src/world/`，41 个插件在 `apps/tauri/src/world/plugins/`。

## 三条一句话结论

1. **形态已经对了**：清单 + `apply(ctx, api)` + 六贡献位 + 服务目录 + 真启停，与 dsh 的 cordis 模型同构。
2. **粒度是双峰极端**：4 个巨型插件占 55% 代码，其余 37 个多在 1000 行以下；41 个插件的「数量」不是问题，「分布」才是。
3. **覆盖不全的是贡献位而非数量**：`relationType` 插件贡献 **0**、`facet` 只有 1 个插件在用、`form` 刚提升为平台位。这三处是「一切皆插件」的真正缺口。

## 与 dsh 的对照

| 维度 | dsh 侧 | 产品域侧 |
|---|---|---|
| 插件形态 | `export const name` + `export const inject` + `apply(ctx, config)` | `export default { manifest, apply(ctx, api) }` |
| 依赖声明 | `inject`（服务名，cordis 原生） | `manifest.requires`（服务名，装载器预检） |
| 注册回滚 | `ctx.effect`（卸载即全回滚） | `ctx.effect`（view / overlay / form / capability）；类型**有意不注销** |
| 插件数 | 373 个叶包（其中 117 带 `dsh` 字段） | 41 个 |
| 贡献位 | 客户端槽位制（71 个 client 包各占槽位） | 6 个显式贡献位 |

差异的根源：dsh 是**平台**（插件扩展它），产品域是**应用**（插件扩展它但地基不可换）。判定线见 [粒度划分](粒度划分.md) §四。
