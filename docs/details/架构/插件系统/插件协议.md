# 插件协议

> 对象：`apps/tauri/src/world/` 第二棵树的插件形态。实现见 `manifest.ts`（96 行）与 `api.ts`（162 行）。
> 协议**自定，不与 dsh 版本绑定**——dsh 的 `dsh.bundle.patch` / `dsh.client.inject` 等字段只作参照。

## 一、插件形状

```ts
// apps/tauri/src/world/plugins/<id>/index.ts
export default {
  manifest: { id: 'official.xxx', name: '…', version: '1.0.0', description: '…', … },
  apply(ctx, api) { /* 只在这里向平台注册东西 */ },
} satisfies WorldPlugin
```

三个约束：

1. **清单是构建期静态的**：装载器用 `import.meta.glob('./plugins/*/index.ts')` 扫 `default` 导出，rolldown 按插件分包，零运行时 IO。
2. **`apply` 是唯一注册入口**：插件不直接 import 注册表单例，只经 `api`。`api` 的 `pluginId` 闭包在内部，插件无法冒名注册到别的插件名下。
3. **校验失败即拒**：清单非法 / `apply` 缺失 / id 重复 / 依赖服务缺失，都记进 `rejected` 并给可读原因，不静默跳过。

## 二、清单字段（`WorldPluginManifest`）

| 字段 | 必填 | 校验 | 说明 |
|---|---|---|---|
| `id` | 是 | `/^[a-z][a-z0-9_-]*(\.[a-z0-9_-]+)+$/` | 小写点分、≥2 段。官方芽用 `official.*`，外部插件用 `ws.*`，能力 id 用 `world.*` |
| `name` | 是 | 非空 | 用户可见名，中性描述不带引导词 |
| `version` | 是 | `/^\d+\.\d+\.\d+/` | 语义化版本 |
| `description` | 是 | 非空 | 一句话说明 |
| `requires` | 否 | 字符串数组 | **服务名**（不是插件 id）。装载前对照 `WORLD_SERVICE_NAMES` 预检，缺失即拒 |
| `kind` | 否 | `'sprout' \| 'utility'` | 插件身份。`sprout` 贡献侧栏视图（默认），`utility` 只贡献 overlay/能力、不受启停过滤 |
| `domain` | 否 | 非空字符串 | 主语义域。内置芽必填（测试守卫），外部插件可缺省 |
| `secondaryDomains` | 否 | 字符串数组 | 副语义域，不得与主域重复 |
| `entityTypes` | 否 | 字符串数组、不重复 | 该插件注册的实体 type；纯视图插件显式声明 `[]`。用于依赖图，独立于运行时注册表 |
| `defaultEnabled` | 否 | — | **预留字段，装载器不消费**（死字段，勿依赖） |

### `kind` 为什么必须显式声明

`utility` 插件常驻（`tree.ts` 的 `forceLoad` 判定 `manifest.kind === 'utility'`），不受芽开关过滤。这件事**不能靠运行时推断**：卸载态下视图与 overlay 的证据全部撤掉了，运行时看一个插件「有没有侧栏入口」是不可靠的。所以 `kind` 是声明式的，且有守卫测试强制 41 个插件全部声明。

### `requires` 的语义边界

`requires` 声明的是**服务名**，不是插件名。这意味着：

- 依赖关系是「插件 → 平台能力」，不是「插件 → 插件」——后者会让插件树退化成依赖图，卸载顺序变成拓扑排序问题。
- 服务由 `world/services.ts` 的 13 项经 `context.provide` 提供，插件经 `ctx.get(name)` 取。
- 缺失时的失败发生在**装载前**（`loader.ts` 的预检），不是运行时第一行报错。

## 三、六个贡献位

插件向平台注册的六类东西。前五类是历史存量，第六类（`form`）于 2026-11-13 从 `outline` 私有实现提升。

| 贡献位 | 方法 | 卸载时 | 当前用量 |
|---|---|---|---|
| 视图 | `api.registerView(view)` | 自动反注册 | **31 处 / 31 文件** |
| 覆盖层 | `api.registerOverlay(overlay)` | 自动反注册 | **13 处 / 10 文件** |
| 实体类型 | `api.registerEntityV2(params)` | **有意不注销** | **25 处 / 25 类型** |
| 关系类型 | `api.registerRelationV2(schema)` | **有意不注销** | **0 处**（全在 `entity-core/relations/`） |
| Facet | `api.registerFacet(facet)` | **有意不注销** | **2 处 / 1 文件** |
| 表现形式 | `api.registerForm(def)` | 自动反注册 | `outline` 经 `publishFormsToPluginApi` 登记 11 种 |
| 能力 | `api.capabilities.register(list)` | 自动撤登记 | **1 处**（mindmap 5 条） |

> 能力在实现上属于第六个注册面，但与 `form` 语义不同（`form` 是纯前端呈现，能力是跨进程暴露），故上表列七行、正文说「六个贡献位」时指 view / overlay / entityType / relationType / facet / form，能力单列为**跨面出口**。

### 为什么类型「有意不注销」

`api.ts:125` 的注释原文：类型元数据长期可查，关系查询会引用。

后果：停用 `official.faith` 后，`faith` 实体类型仍在注册表里，只有侧栏入口消失。这就是既有口径「关闭芽 = 隐藏入口、保留实体」的机制根源。

**这是设计而非缺陷**（明文契约）：类型是不可卸载的平台登记，插件只贡献视图与入口。要改成真正可回滚，得先解决「用户停用芽后已创建的实体怎么办」——那是数据模型决策，不是插件机制决策。

## 四、三条明文契约

写进代码注释与本文，供后续改动对照：

1. **视图 / overlay / form / 能力随插件回卷；实体 / 关系 / Facet 类型不注销。**
2. **`requires` 只声明服务名，不声明插件名。** 插件之间不允许有装载顺序依赖。
3. **`kind` 是声明式身份，不由运行时推断。** `utility` 常驻，`sprout` 受芽开关控制。

## 五、外部插件协议

运行时可从 `<工作区根>/worlddata/.worldsea/plugins/<id>.js` 装载插件，无需重新构建：

| 项 | 规则 |
|---|---|
| 形态 | 单文件，内容 = 箭头函数表达式 `(require) => ({ manifest, apply })` |
| 求值 | `new Function('return (' + code + ')')()`；两窗 CSP 均无 `script-src`，已核可执行 |
| id 约束 | 强制 `ws.` 前缀，且必须与文件名一致 |
| 模块种子表 | 3 个：`vue` · `@worldsea/entity-core` · `@worldsea/shared-ui`；未登记名报 `MODULE_UNKNOWN` |
| 热装载 | FsWatcher 感知目录变化（防抖 1s）→ diff（新增装 / 消失卸 / 变更重装） |
| 启停状态 | 走**独立键** `worldsea_external_plugins`，不并入内置清单 |
| id 冲突 | 与内置插件撞 id 时先到者生效，外部那条记进 `rejected` |

外部插件是「插件系统完整形态」的证明：写完即装、约 1 秒生效、模块种子表控制放权范围。
