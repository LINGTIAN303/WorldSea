### 2.2 冲突与不一致（带后果）

1. **近名双根**：`.WorldSea`（产品数据）vs `WorldSea`（dsh 沙箱工作区）——只差一个点；备份 / 迁移 / 排障走错根，用户以为「数据在 WorldSea」，其实在 `.WorldSea`。
2. **写边界与数据位置错位（已坐实）**：dsh 的 `workspace-write` 只放行 `cwd` + `/tmp` + `os.tmpdir()`（`sandbox/src/roots.ts:52-55`；`base/cordis.patch.yml:230-232`）；`~/.WorldSea\{worlddata,rules,agent}` 全在**可写集之外**（读不受限）→ **D2 的「Agent 写产品域」必被 `FS_SANDBOX_DENIED` 拦**（除非走审批升级 / `danger-full-access`）。
3. **应用数据根内命名不统一**：`worldsea\`（Rust）· `.worldsea\`（前端 KB）· `dsh-home\` · `scenes\` —— 四种写法同处一层。
4. **可能出现第三个工作区**：dsh 自身默认工作区在 `<Documents>\deepseek-harness\<name>`（代码路径存在、overlay 未禁）→ 真机若触发，「以为只有一个工作区」的错位。
5. **规则双真源窗口期**：旧 `<app_data>\worldsea\rules` 仍作回退读，迁移只在目标缺失时复制（失败/竞态则来源漂移）。
6. **记忆真库与用户可见面分离**：库在 `<app_data>\worldsea\memory`，用户在 `~/.WorldSea\rules\MEMORY.md` 只见派生结果 → 按路径备份会漏。
7. **两套项目模型无映射**：产品 = IndexedDB 记录 + `dirPath`（UUID）；dsh = workspace registry（键 = cwd 规范路径）+ 按 cwd 分目录的 sessions；壳从不向 dsh 传 `project_id`，`switch_project` 后端动作已删（`http_bridge/rpc.rs:1412`）→ dsh 会话无法按产品项目分组。
8. **同机两套写规则**：产品域 `cmd_fs_*` 不做 workdir 边界（仅拒 `~/.ssh` / `~/.gnupg` / `/etc` 等，`fs_commands.rs:11-40`），dsh 则是严沙箱 → 产品窗可写任意用户路径。「宽」未必是缺陷（本地创作工具语义），但**必须是一次显式裁定**。
9. **工作区位置影响功能可用性**：ACL 沙箱供给要求目录带 `WRITE_OWNER`，换盘符/换工作区即「命令秒死」（`workspace_probe.rs`）。

### 2.3 判据与成本

- **判据**：
  ① 每个根有唯一归属 + 命名规则统一（应用数据根内统一 `worldsea\`；用户侧二选一——倾向**保留 `~/.WorldSea` 作创作数据根**，把 dsh 沙箱工作区改为它的**子目录**，让「可写根 ⊇ 创作数据」）；
  ② 沙箱写边界与「Agent 要写的目录」对齐（D2 前置）；
  ③ 项目/会话两模型有显式映射，或明确判「不映射」；
  ④ dsh 默认工作区（`Documents\deepseek-harness`）显式处置（overlay 禁掉或改指向）；
  ⑤ 产品域写范围是否收窄 = 一次显式裁定。
- **成本**：路径常量 + 启动期目录创建 + 少量展示文案；**零数据迁移**（项目暂无在用用户）；真机验证 = 实体 CRUD 落盘位置 + Agent 在沙箱内对创作数据的写权限 + 换盘符时的 ACL 供给。
