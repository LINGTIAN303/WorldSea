# 归档

> 已收口、已作废、被取代的架构文档。**只读，不再维护。**
> 保留它们是为了可追溯——「当初为什么这么判断」和「后来为什么改了」是两件事，后者常在前者里。

## 为什么收在这里而不是删掉

删掉一份作废文档，等于让下一个人重新踩一遍同样的坑。收进归档并写清「被谁取代」，读者能在 30 秒内知道现状，同时保留追溯链。

## 归档不等于作废

两个词在本仓有明确区分：

| 词 | 含义 | 位置 |
|---|---|---|
| `历史留档` | 结论曾成立，对象已退场或已收口；不再维护，但内容本身没错 | 本目录 |
| `作废` | 结论被事实推翻，或所述对象已不存在；保留只为追溯 | 留在原位并显式标注（如 [场景底座](../系统/场景底座.md)） |

作废件**不搬进本目录**，因为搬走会降低它被看见的概率——读者更需要知道「这条现在不能信」，而不是「这里曾经有份文档」。
